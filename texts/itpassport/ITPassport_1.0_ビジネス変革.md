# ITパスポート テキスト 1.0 ビジネス変革

社会やビジネスが IT で大きく変わる中で、会社がどう考え、どう動くかを学びます。経営の考え方、ビジネスの仕組み、サービスやプロジェクトの進め方、利用者を中心にした設計、そして変化に向き合う姿勢までを扱います。

## 1.1 ビジネス変革の方法論

### 1. 社会の変化

| 用語 | 意味 |
|---|---|
| **データ駆動型社会** | データを集めて分析し、その結果をもとに判断や行動をする社会 |
| **デジタルトランスフォーメーション(DX)** | デジタル技術を使って、製品、サービス、業務、組織、働き方を変え、新しい価値を生み出すこと。道具を入れるだけでなく、**変えること**が中心 |
| **AI トランスフォーメーション(AX)** | AI を使って、業務やビジネスを変えること。DX の中で、AI の活用に重点を置いた言い方 |
| **SDGs**(持続可能な開発目標) | 2030 年までに、世界が取り組む 17 の目標。貧困、環境、働きがいなどを含む |
| **カーボンニュートラル** | 二酸化炭素などの温室効果ガスの排出量から、吸収や除去の量を引いて、全体をゼロにすること |
| **フロンティア AI の影響** | 最先端の高性能な AI が、仕事や社会に与える影響。業務の自動化や新しい仕事の誕生などがある(出題の対象は、影響の大まかな理解) |

**顧客価値の変化**: 商品を持つことより、使って得られる体験が重視されるようになりました。

| 用語 | 意味 |
|---|---|
| **顧客体験(CX)** | 顧客が、商品を知ってから使うまで、そして使った後の全体で感じる体験 |
| **体験価値の重視** | 商品の性能だけでなく、使いやすさや楽しさ、気持ちを評価する考え方 |
| **購買行動の変化** | 買う前に、ネットの口コミや比較サイトを調べ、スマートフォンで買うなど、買い方が変わっていること |

**競争環境の変化**: デジタル技術を使う新しい会社が、既存の業界のルールを変えることがあります。これを**デジタルディスラプション**(デジタルによる破壊)といいます。たとえば、配車アプリがタクシーの業界を変えたような例です。

### 2. イノベーションマネジメント

**イノベーション**は、新しい技術や考え方で、新しい価値を生み出すことです。**イノベーションマネジメント**は、イノベーションを組織として、継続して起こすための管理の仕組みです。

イノベーションマネジメントの原理原則には、価値の実現、未来志向のリーダー、戦略的方向性、組織文化、洞察の活用、不確実性のマネジメント、柔軟性、システムアプローチがあります。**価値を実現すること**と、**不確実さを前提に、柔軟に進めること**が中心です。

### 3. イノベーション戦略

| 用語 | 意味 |
|---|---|
| **プロダクトイノベーション** | 新しい製品やサービスを生み出すこと |
| **プロセスイノベーション** | 作り方や、提供の仕方を新しくすること。製造、販売、物流の工程の改革など |
| **オープンイノベーション** | 自社だけでなく、ほかの会社、大学、顧客などと協力して、新しい価値を生み出すこと |
| **イノベーションのジレンマ** | 成功している大企業が、今の顧客の要望に応えることに集中し、新しい技術の登場に対応が遅れてしまうこと |
| **リーンスタートアップ** | 最小限の製品(試作)を早く作り、顧客の反応を見て、作り直しながら進める方法 |
| **API エコノミー** | 会社が、自社の機能やデータを API(ソフトウェア同士をつなぐ窓口)で公開し、ほかの会社が組み合わせて、新しいサービスを作る経済の仕組み |
| **イノベータ理論** | 新しい商品を受け入れる人を、時期によって 5 つに分ける理論。イノベータ(革新者)、アーリーアダプタ(初期採用者)、アーリーマジョリティ(前期多数派)、レイトマジョリティ(後期多数派)、ラガード(遅滞者) |
| **キャズム** | 初期採用者と前期多数派の間にある、深い溝。ここを越えると、商品が広く普及する |
| **ベンチャーキャピタル** | 成長が見込める新しい会社に出資し、成長後の利益を得ることを目指す会社や投資の仕組み |
| **MOT(技術経営)** | 技術を、経営の中で生かして、事業の価値に変える考え方 |
| **価値創出** | 新しい価値を生み出し、顧客や社会に届けること |

研究から事業になるまでには、3 つの壁があるとたとえられます。

| 壁 | 場所 |
|---|---|
| **魔の川** | 研究から、開発に進む間 |
| **死の谷** | 開発から、事業化(製品にして売り出す)に進む間 |
| **ダーウィンの海** | 事業化の後、市場で、競争を勝ち残る段階 |

研究から事業になるまでの流れと、3 つの壁の場所を表した図です。

```text
研究
  |
  v   魔の川(研究から、開発に進む間)
開発
  |
  v   死の谷(開発から、事業化に進む間)
事業化
  |
  v   ダーウィンの海(事業化の後、市場で競争を勝ち残る段階)
市場で勝ち残る
```

**イノベーション戦略の立案**の手法です。

| 用語 | 意味 |
|---|---|
| **バックキャスティング** | 先に、あるべき未来の姿を決め、そこから逆算して、今やることを考える方法。今を出発点に未来を考える**フォアキャスティング**の反対 |
| **PoC(概念実証)** | 新しい考えが、実際にうまくいくかを、小さな規模で試して確かめること |
| **投資対効果** | かけた費用に対して、どれだけの効果があるか |
| **アイディアソン** | アイディアを出し合って、短い時間でまとめるイベント |
| **ハッカソン** | プログラマーなどが集まり、短い期間で、ソフトウェアやサービスを作るイベント |

### 4. 変革活動のマネジメント

**チェンジマネジメント**は、組織の変革を、人の面から進める考え方です。新しい仕組みを入れても、人が使わなければ成功しないからです。

- レベル: **個人**(一人ひとりの理解と行動の変化)、**プロジェクト**(1 つの変革の取組で、影響を受ける人たちの変化を、計画して支援する)、**組織**(会社全体の文化や仕組みの変化)の 3 つ。
- プロセス: 変革の目的を共有する → 現状と、あるべき姿の差を明らかにする → 計画して進める → 定着させる、という流れで進めます。

## 1.2 経営戦略・デジタル戦略

### 1. 経営戦略

**経営戦略の策定**に使う言葉です。

| 用語 | 意味 |
|---|---|
| **経営理念(企業理念)** | 会社が大切にする考え方や、存在する意義 |
| **MVV** | **ミッション**(果たす使命)、**ビジョン**(目指す将来の姿)、**バリュー**(大切にする価値観)の 3 つ |
| **ベンチマーキング** | 優れた他社や他部門と、自社を比べて、改善に生かすこと |
| **ベストプラクティス** | ある分野で、最も成果が出ているとされるやり方 |
| **VUCA** | 変化が激しく、先が読みにくい時代を表す言葉。Volatility(変動性)、Uncertainty(不確実性)、Complexity(複雑性)、Ambiguity(曖昧性)の頭文字 |

**全体戦略の策定**(会社全体として、どの事業にどれだけ資源を使うか)です。

| 用語 | 意味 |
|---|---|
| **プロダクトポートフォリオマネジメント(PPM)** | 市場の成長率と、市場での占有率(シェア)で、事業を 4 つに分け、資源の配分を決める。花形、金のなる木、問題児、負け犬 |
| **コアコンピタンス** | 他社がまねしにくい、その会社の中核になる強み |
| **アウトソーシング** | 自社の業務を、外部の会社に任せること |
| **M&A** | 企業の合併(Merger)と買収(Acquisition)。ほかの会社を取り込んで、成長する |
| **TOB(公開買付け)** | 株式を、期間、数、価格を公表して、市場の外で、多くの株主から買い取る方法 |
| **エコシステム** | 複数の会社や組織が協力して、全体で価値を作る関係。自然界の生態系にたとえた言葉 |
| **アライアンス** | 会社同士が、互いの強みを生かすために協力すること(提携)。業務提携や、出資を伴う資本提携などがある |

PPM の 4 つの区分です。

| 区分 | 市場の成長率 | シェア | 考え方 |
|---|---|---|---|
| 花形 | 高い | 高い | 投資を続けて、地位を守る |
| 金のなる木 | 低い | 高い | 収益を上げ、ほかの事業に資金を回す |
| 問題児 | 高い | 低い | 投資して育てるか、やめるかを判断する |
| 負け犬 | 低い | 低い | 撤退や縮小を考える |

**ビジネス戦略の策定**(1 つの事業で、どう勝つか)です。

| 用語 | 意味 |
|---|---|
| **SWOT 分析** | 内部環境の**強み**(Strengths)と**弱み**(Weaknesses)、外部環境の**機会**(Opportunities)と**脅威**(Threats)を整理する |
| **VRIO 分析** | 経営資源が競争力になるかを、価値(Value)、希少性(Rarity)、模倣の難しさ(Imitability)、組織(Organization)の 4 つの点で見る |
| **バリューチェーン分析** | 事業を、調達、製造、販売などの活動に分け、どの活動で価値を生み、費用がかかっているかを分析する |
| **成長マトリクス** | 市場と製品を、既存と新規に分け、成長の方向(市場浸透、新製品開発、新市場開拓、多角化)を考える |
| **競争戦略** | 競争に勝つための基本の方針。コストリーダーシップ、差別化、集中など |
| **ニッチ戦略** | 大企業が手を出さない、小さな市場に集中する |
| **ブルーオーシャン戦略** | 競争のない新しい市場を作る |
| **バランススコアカード** | 財務、顧客、業務プロセス、学習と成長の 4 つの視点で、戦略を目標と指標に落とす手法 |
| **CSF(重要成功要因)** | 目標を達成するために、特にうまくやらなければならないこと |
| **KGI(重要目標達成指標)** | 最終的な目標が、達成できたかを測る指標(例: 売上高) |
| **KPI(重要業績評価指標)** | 最終的な目標への途中の進み具合を測る指標(例: 商談の数) |
| **バリューエンジニアリング(VE)** | 製品やサービスの機能と費用を見直し、価値を高める方法 |
| **クラウドファンディング** | インターネットで、多くの人から、少しずつ資金を集める仕組み |

KGI と KPI の関係は、「目的地(KGI)と、途中の道しるべ(KPI)」と覚えます。

### 2. デジタル戦略

| 用語 | 意味 |
|---|---|
| **DX の推進による企業価値向上** | DX を進めて、会社の競争力と価値を高めること |
| **DX 戦略** | DX をどう進めるかの具体的な方針 |
| **DX ビジョン** | DX で目指す姿 |
| **デジタルガバナンス・コード** | 経済産業省が示した、会社が DX を進めるために、経営者が取り組むべきことをまとめた手引き |
| **デジタルスキル標準(DSS)** | 一人ひとりが DX を進めるために必要なスキルを整理した、経済産業省と IPA の標準 |
| **デジタルトランスフォーメーション** | デジタル技術で、ビジネスを変えること(1.1 を参照) |
| **BYOD** | 従業員が、私物の端末(スマートフォンやパソコン)を業務に使うこと。便利だが、情報漏えいの対策が必要 |
| **デジタルリテラシー** | デジタル技術を、正しく理解し、使いこなす力 |
| **デジタルディバイド** | 情報通信技術を使える人と、使えない人の間にできる格差 |

### 3. 情報システム戦略

| 用語 | 意味 |
|---|---|
| **情報システム戦略** | 経営戦略を実現するために、情報システムをどう使うかの方針 |
| **情報システム化基本計画** | 情報システム戦略をもとに、どのシステムを、いつまでに、どれだけの費用で作るかを決める計画 |
| **システム化計画** | 個々のシステムを、何のために、どの範囲で作るかを決める計画 |
| **SoR(Systems of Record)** | 記録のためのシステム。受注や会計など、正確な記録を残す |
| **SoE(Systems of Engagement)** | 顧客とつながるシステム。アプリや SNS など |
| **SoI(Systems of Insight)** | データから、気づきや洞察を得るためのシステム。分析や予測 |

**要件定義**は、システムに求められることを、決める工程です。

| 種類 | 内容 | 例 |
|---|---|---|
| **業務要件定義** | 業務の流れ、ルール | 受注から出荷までの流れ |
| **機能要件定義** | システムが持つ機能 | 注文を登録する |
| **非機能要件定義** | 機能以外の品質。性能、可用性、セキュリティなど | 3 秒以内に応答する |

要件定義で使う図や表です。

| 手法 | 内容 |
|---|---|
| **DFD** | データの流れ(データフローダイアグラム)を表す図 |
| **決定表** | 条件と、その結果の組み合わせを表にしたもの |
| **UML** | システムの構造や動きを、決まった記号で表す図の標準 |

**調達計画・実施**は、システムや部品、サービスを、外部から手に入れる活動です。

| 用語 | 意味 |
|---|---|
| **OEM** | 相手のブランドで売る製品を、製造すること(相手先ブランドによる生産) |
| **ファブレス** | 自社では工場を持たず、設計や開発だけを行い、製造は外部に任せる形 |
| **一般競争入札** | 条件を満たすすべての会社が参加できる入札 |
| **総合評価落札方式(加算方式)** | 価格だけでなく、技術や品質の点数も加えて、総合して落札者を決める方式 |
| **情報提供依頼書(RFI)** | 調達の前に、ベンダーに、技術や製品の情報の提供を依頼する文書 |
| **提案依頼書(RFP)** | ベンダーに、具体的な提案を依頼する文書。要件が書かれている |
| **提案書** | ベンダーが、RFP に応えて出す提案の文書 |
| **見積書** | 費用の見積もりを示す文書 |
| **グリーン調達** | 環境への負荷が小さい製品やサービスを、優先して買うこと |

流れは、RFI(情報の依頼)→ RFP(提案の依頼)→ 提案書 → 見積書、と覚えます。

調達で、発注する側とベンダーが出す文書の順番を表した図です。

```text
[1] RFI: 情報提供依頼書。発注する側が、ベンダーに技術や製品の情報を求める
     |
     v
[2] RFP: 提案依頼書。発注する側が、要件を示して提案を求める
     |
     v
[3] 提案書: ベンダーが、RFP に応えて出す
     |
     v
[4] 見積書: ベンダーが、費用の見積もりを示す
```

### 4. エンタープライズアーキテクチャ

**EA(エンタープライズアーキテクチャ)**は、組織全体の業務とシステムを、全体の視点で整理し、最適にする考え方です。

| 用語 | 意味 |
|---|---|
| **As-is モデル** | 現在の姿(現状) |
| **To-be モデル** | あるべき将来の姿 |

As-is と To-be の差が、これから取り組む課題になります。

## 1.3 ビジネスモデル・ビジネスプロセス

### 1. ビジネス調査・ビジネス分析

| 手法 | 内容 |
|---|---|
| **3C 分析** | 顧客(Customer)、競合(Competitor)、自社(Company)の 3 つで、市場を分析する |
| **PEST 分析** | 外部環境を、政治(Politics)、経済(Economy)、社会(Society)、技術(Technology)の 4 つで見る |
| **市場調査(マーケティングリサーチ)** | アンケートや統計などで、市場や顧客の情報を集めて分析する |
| **STP 分析** | **セグメンテーション**(市場を分ける)、**ターゲティング**(狙う層を決める)、**ポジショニング**(競合との位置づけを決める) |
| **サンプリング** | 全体から、一部を選び出して調査すること |
| **RFM 分析** | 顧客を、最近いつ買ったか(Recency)、どのくらいの頻度か(Frequency)、いくら使ったか(Monetary)で分ける |

### 2. ビジネスモデル

**ビジネスモデル**は、会社がどのように価値を提供し、どのように利益を得るかの仕組みです。利益を得る仕組みを**マネタイズモデル**といいます。

| モデル | 内容 |
|---|---|
| **広告モデル** | 利用者は無料で、広告の収入で成り立つ |
| **買い切りモデル** | 一度、代金を払って買う |
| **ライセンスモデル** | 使う権利に対して、料金を受け取る |
| **サブスクリプションモデル** | 月額や年額で、継続して利用する権利を提供する |
| **フリーミアム** | 基本の機能は無料で、高度な機能を有料にする |

そのほかの言葉です。

| 用語 | 意味 |
|---|---|
| **e-ビジネス** | インターネットなどを使った、電子的な取引や事業 |
| **シェアリングエコノミー** | 場所、乗り物、ものなどを、共有して使う経済の仕組み |
| **BtoB** | 企業と企業の間の取引 |
| **BtoC** | 企業と一般の消費者の間の取引 |
| **ロングテール** | 売れ行きが少ない商品も、種類が多ければ、全体で大きな売上になるという考え方。ネットの店舗で成り立ちやすい |

**ビジネスモデルキャンバス**は、ビジネスモデルを 1 枚の図で表す方法です。主な要素は次のとおりです。

| 要素 | 内容 |
|---|---|
| **カスタマーセグメント** | 誰に提供するか(顧客の層) |
| **バリュープロポジション** | 顧客に、どんな価値を提供するか |
| 収益の流れ、主要な活動、主要なパートナーなど | 稼ぎ方、必要な活動、協力する相手 |

作ったビジネスモデルは、**仮説検証**(仮説を立て、試して確かめる)で、うまくいくかを確かめます。

### 3. ビジネスプロセス

| 用語 | 意味 |
|---|---|
| **ビジネスプロセスマネジメント(BPM)** | 業務の流れ(プロセス)を、継続して分析、改善する管理の方法 |
| **ビジネスプロセスリエンジニアリング(BPR)** | 業務の流れを、根本から見直して、設計し直すこと |
| **ビジネスプロセスアウトソーシング(BPO)** | 業務の一部を、外部の会社に任せること |
| **RPA** | 人がパソコンで行う定型の作業を、ソフトウェアのロボットで自動化すること |
| **業務プロセスの可視化** | 業務の流れを図にして見えるようにすること。BPMN(業務プロセスを表す記号の標準)、E-R モデル(データの関係を表す図)、フローチャート(処理の流れを表す図)など |

BPM は「継続して改善」、BPR は「根本から作り直す」と区別します。

### 4. プロダクトのマネジメント

| 用語 | 意味 |

| **コモディティ化** | 製品の差がなくなり、価格だけの競争になること |
| **カニバリゼーション** | 自社の製品が、自社のほかの製品の売上を奪ってしまうこと(共食い) |

| **ダイレクトマーケティング** | 企業が、顧客に直接、働きかけて、反応を得る |
| **プッシュ戦略** | 企業から、顧客に、売り込む(営業や広告) |

## 1.4 サービスマネジメント

### 1. サービスマネジメントの目的と考え方

**サービスマネジメント**は、顧客が、サービスを安定して使えるように、提供者が行う管理の仕組みです。

| 用語 | 意味 |
|---|---|
| **サービス** | 顧客が望む成果を実現しやすくし、顧客が、特定の費用やリスクを自分で管理しなくてすむようにする手段 |
| **サービスカタログ** | 提供しているサービスの一覧と内容 |
| **SLA** | 提供者と顧客の間で、サービスの内容と品質(稼働率、応答時間など)の水準を、決めた合意 |
| **事業関係管理、顧客関係** | 顧客との良い関係を作り、維持する活動 |
| **顧客満足** | サービスに対して、顧客がどれだけ満足しているか |
| **サービスレベル管理** | SLA で決めた水準を、守れているかを確かめ、改善する活動 |
| **変更管理** | システムやサービスの変更を、事前に評価し、承認して、影響を抑えて行う活動 |
| **サービス受入れ基準** | 新しいサービスや変更したサービスを、運用に受け入れるかを判断する基準 |
| **減価償却** | 設備やシステムの購入費用を、使える期間にわたって、少しずつ費用にしていく会計の考え方 |
| **需要管理** | サービスへの要求の量を予測し、調整する活動 |
| **サービスデスク** | 利用者からの問合せや障害の連絡を受け付ける窓口 |
| **SPOC(Single Point Of Contact)** | 問合せの窓口を、1 つにまとめること。利用者は、迷わず連絡できる |
| **インシデント管理** | サービスの停止や品質の低下(インシデント)から、**できるだけ早く復旧**させる活動 |
| **エスカレーション** | 窓口で解決できない問題を、より専門の担当者や、上位の管理者に引き継ぐこと |

利用者の問合せが、サービスデスクを通って、専門の担当者に引き継がれる流れを表した図です。

```text
User: 利用者。問合せや障害の連絡をする
  |
  v
Service Desk: サービスデスク。窓口を 1 つにまとめる(SPOC)
  |
  |  窓口で解決できないとき(エスカレーション)
  v
Specialist: より専門の担当者や、上位の管理者
```

インシデント管理は、原因の追及より、サービスを**元の状態に戻すこと**を優先します。原因を取り除く活動は、別に**問題管理**といいます。

## 1.5 プロジェクトマネジメント

### 1. プロジェクトマネジメントの目的と考え方

| 用語 | 意味 |
|---|---|
| **プロジェクト** | 期間と目的が決まった、1 回かぎりの仕事 |
| **プロジェクトマネジメント** | プロジェクトの目的を、期限と予算の中で達成するための管理 |
| **プロジェクトマネージャ** | プロジェクトの責任者 |
| **プロジェクトチーム** | プロジェクトのために集められたメンバー |
| **PMO(Project Management Office)** | 複数のプロジェクトを支援し、管理の標準や進捗の把握を担う組織 |
| **プロジェクト憲章** | プロジェクトの目的、目標、責任者などを示し、正式に開始を認める文書 |
| **ステークホルダ** | プロジェクトに利害関係のある人や組織。顧客、メンバー、経営者、利用者など |
| **WBS** | 作業を、細かく分解して、階層の図にしたもの(作業分解構成図) |
| **スコープ** | プロジェクトで行う範囲。範囲が際限なく広がることを防ぐ |
| **スケジュール** | 作業の日程の計画 |
| **アローダイアグラム** | 作業の順番と日数を、矢印で表した図。最も日数がかかる道すじ(**クリティカルパス**)で、全体の日数が決まる |
| **ガントチャート** | 横軸を日付、縦軸を作業にして、作業の期間を棒で表した図。進捗の確認に向く |
| **コミュニケーションのマネジメント** | 関係者に、必要な情報を、適切な時期と方法で伝える管理 |
| **リスクの対応策** | 問題になりうる不確かなことへの対応。回避、軽減、移転、受容の 4 つ |

アローダイアグラムの考え方です。作業 A(3 日)の後に、B(4 日)と C(2 日)を並行して行い、その両方が終わったら D(1 日)を行う場合を考えます。

作業 A、B、C、D のつながりを表した図です。箱の中の数字は、日数です。

```text
          +--> [B 4] --+
          |            |
[A 3] ----+            +--> [D 1]
          |            |
          +--> [C 2] --+
```

A の後に、B と C を並行して行い、両方が終わったら D を行います。次の ①〜③ で、いちばん長い道すじを探します。

① A → B → D の日数は、3 + 4 + 1 = 8 日です。
② A → C → D の日数は、3 + 2 + 1 = 6 日です。
③ 長い方の 8 日がプロジェクト全体の日数で、A → B → D がクリティカルパスです。

クリティカルパス上の作業が遅れると、プロジェクト全体が遅れます。

## 1.6 デザインのアプローチ

| **ペルソナ** | 典型的な利用者を、年齢、仕事、悩みなどの具体的な人物像として、作り上げたもの |

デザイン思考の進め方を、順番に並べた図です。

```text
     |

     |

     |

```

### 2. デザインプロセスマネジメント

**顧客理解・ユーザー理解**の手法です。

| 手法 | 内容 |
|---|---|
| **ユーザーニーズ調査** | 利用者が求めていることを調べる |
| **アンケート** | 多くの人に、同じ質問で回答を集める。数を集めやすい |
| **インタビュー** | 話を聞く。**構造化**は、質問を決めて、その順番で聞く。**半構造化**は、質問を決めておき、話に応じて深掘りする。**非構造化**は、質問を決めずに、自由に話してもらう |
| **フィールドワーク** | 利用者が実際に使っている現場に行って、観察する |
| **親和図** | 集めた情報を、似たもの同士でグループにまとめた図 |

**仮説・構想**の手法です。

| 手法 | 内容 |
|---|---|
| **カスタマージャーニーマップ** | 顧客が、サービスを知り、使い、使い終わるまでの行動、考え、感情を、時間の順に表した図 |
| **サービスブループリント** | 顧客に見える部分と、裏側の業務(見えない部分)を、まとめて図にしたもの |
| **構造化シナリオ法** | 利用の場面を、決まった形で、物語として書き出す |
| **KJ 法** | 情報をカードに書いて、似たものを集めてグループ化し、整理する |
| **ブレインストーミング** | 数人で、他人の意見を批判せず、できるだけ多くのアイディアを出す |

**プロトタイプ**(試作)の手法です。

| 手法 | 内容 |
|---|---|
| **サービスプロトタイプ** | サービスの流れを、簡単に、試す |
| **デザインプロトタイプ** | 画面や製品の見た目を、試作する |
| **デスクトップウォークスルー** | 机の上に、サービスの要素を、模型や紙で並べ、流れを確かめる |

**評価**の手法です。

| 手法 | 内容 |
|---|---|
| **ビジュアル表現** | 図や絵で、分かりやすく伝える |
| **ストーリーテリング** | 物語の形で、伝える |
| **プレゼンテーション手法** | 相手に、分かりやすく伝え、理解を得る方法 |
| **ユーザビリティテスト** | 実際の利用者に使ってもらい、使いやすさの問題を見つける |

## 1.7 マインド・スタンス

**マインド・スタンス**は、不確実で変化の大きい環境で、新しい価値を生み出すための、意識、姿勢、行動です。この項目は、状況の中での行動を問います。

### 1. マインド・スタンス(行動例)

| 行動 | 内容 |
|---|---|
| **変化への適応** | 環境や働き方の変化を受け入れ、自分から進んで学ぶ。今の価値観の良いところは尊重しつつ、新しい行動、知識、スキルを身に付ける |
| **コラボレーション** | 価値を作るために、いろいろな専門性を持つ人と、社内外を問わず協働する。多様性を尊重する |
| **顧客・ユーザーへの共感** | 顧客や利用者の立場に立って、ニーズや課題を見つけようとする |
| **常識にとらわれない発想** | 既存の考え方にとらわれず、アイディアを出す。従来のやり方の理由を自分で問い、より良い方法を考える |
| **反復的なアプローチ** | 失敗しても許される小さなサイクルで、取り組みを行い、フィードバックを得て、改善を繰り返す。失敗しても、学びがあれば成果と考える |
| **柔軟な意思決定** | 今までの価値観では判断が難しいときも、価値を生むために必要なら、状況に応じて決める |
| **事実に基づく判断** | 勘や経験だけでなく、客観的な事実やデータに基づいて判断する。適切なデータの入力を意識する |

たとえば、新機能をいきなり全員に出さず、一部の利用者に試してもらい、反応を見て直すのは、反復的なアプローチです。

### 2. アジャイルなふるまい

**アジャイル**は、短い期間で、動くものを作って見せ、フィードバックを受けて、方向を調整しながら進める考え方です。ソフトウェアの開発から広まりましたが、ふだんの仕事にも使えます。

| 用語 | 意味 |
|---|---|
| **アジャイルマインド** | 変化を歓迎し、顧客との協力と、素早い改善を大切にする心構え |
| **仮説検証** | 仮説を立て、小さく試して、結果で確かめ、次に生かす |
| **スプリント** | 期間を決めた作業の繰り返しの単位(1〜4 週間など)。この期間で、計画、作業、確認を行う |
| **ふりかえり** | スプリントの終わりに、チームで、進め方を振り返り、改善する場 |
| **KPT** | ふりかえりの方法。**Keep**(続けること)、**Problem**(問題)、**Try**(次に試すこと)の 3 つで整理する |
| **価値駆動** | 顧客にとって価値の高いものから、順に作る考え方 |
| **アジャイルの原則** | アジャイルの考え方を 12 の原則にしたもの。早く、継続して、価値のあるものを届ける、変化を歓迎する、など |
| **アジャイルソフトウェア開発宣言** | アジャイルの価値観を述べた宣言 |

アジャイルソフトウェア開発宣言は、次の 4 つの価値を挙げています。右側にも価値はありますが、**左側をより重視**します。

| より重視すること | それよりも |
|---|---|
| 個人と対話 | プロセスやツール |
| 動くソフトウェア | 包括的なドキュメント |
| 顧客との協調 | 契約交渉 |
| 変化への対応 | 計画に従うこと |
