# ITパスポート テキスト 6.0 セキュリティ

情報セキュリティの脅威、守る考え方と組織の仕組み、具体的な対策を学びます。出題範囲は、2027 年度からの新しい試験制度のシラバス案(Ver.0.1)に合わせています。

## 6.1 情報セキュリティの脅威

### 1. 脅威の種類

| 脅威 | 内容 |
|---|---|
| 不正アクセス | 利用する権限のない人が、システムに入り込む |
| 盗聴 | 通信の内容を、盗み見る |
| なりすまし | 他人のふりをして、その人の権限を使う |
| 改ざん | データを、権限なく書き換える |
| ビジネスメール詐欺(BEC) | 取引先や経営者になりすましたメールで、偽の口座に送金させる |
| ソーシャルエンジニアリング | 人の心理や行動のすきを突いて、情報を盗む。盗み見(ショルダーハッキング)や、管理者を装った電話など |
| 情報漏えい | 秘密の情報が、外部に出てしまう |
| 内部不正 | 組織の内部の人が、権限を使って情報を持ち出したり、不正に操作したりする |
| SNS の悪用 | 企業や人になりすましたアカウントで、偽の情報を広めたり、不正なサイトに誘導したりする |
| 迷惑メール(スパム) | 受信者が望んでいないのに、広告や詐欺のために、不特定多数に送られるメール |

### 2. マルウェア(不正プログラム)

**マルウェア**は、利用者に害を与える不正なプログラムの総称です。

| 名前 | 内容 |
|---|---|
| ボット | 外部から遠隔操作されるマルウェア。感染したパソコンの集まりを、ボットネットという |
| C&C サーバー | ボットに命令を出す、攻撃者のサーバー(Command and Control) |
| トロイの木馬 | 便利なソフトに見せかけて入手させ、実行すると裏で不正な動作をする |
| スパイウェア | 利用者に気付かれずに、情報を集めて外部に送る |
| ランサムウェア | ファイルを暗号化し、元に戻す代わりに身代金を要求する。盗んだ情報の公開を脅しに使うこともある |
| キーロガー | キーボードの入力を記録して、パスワードなどを盗む |
| バックドア | 攻撃者が、後から侵入するための裏口 |
| ファイルレスマルウェア | 実行ファイルをディスクに残さず、メモリ上や OS の標準機能を使って動く。ファイルを調べるだけでは見つけにくい |

ボットネットが、攻撃者の命令で標的に大量の要求を送る様子を表した図です。

```text
[Attacker]  攻撃者
    |
    v
[C&C]       C&C サーバー: ボットに命令を出す
    |
    +--------+--------+
    |        |        |
    v        v        v
[Bot 1]  [Bot 2]  [Bot 3]   ボット(感染したパソコン)。この集まりがボットネット
    |        |        |
    +--------+--------+
             |
             v
         [Target]   標的。DDoS 攻撃では、多数のボットから同時に大量の要求が届く
```

### 3. 脆弱性と不正の動機

- **脆弱性**(セキュリティホール)は、ソフトウェアや設定の欠陥で、攻撃に悪用できるものです。
- **シャドー IT** は、会社が把握も許可もしていない IT の機器やサービスを、従業員が業務に使うことです。管理の目が届かず、情報漏えいの原因になります。
- **ダークウェブ**は、専用のソフトで接続する、匿名性の高いネットワークの領域です。盗まれた情報の取引に使われることがあります。
- **リークサイト**は、ランサムウェアの攻撃者が、身代金を払わない被害組織から盗んだ情報を公開するサイトです。
- **不正のトライアングル**は、不正が起きる条件を、「動機・プレッシャー」「機会」「正当化」の 3 つで表したものです。3 つがそろうと、不正が起きやすくなります。

### 4. 攻撃手法

| 分類 | 攻撃 | 内容 |
|---|---|---|
| 認証の不備 | ブルートフォース攻撃 | 考えられるパスワードを、片端から試す(総当たり) |
| 認証の不備 | パスワードリスト攻撃 | 他のサービスから漏れた ID とパスワードの組で、別のサービスにログインを試みる。パスワードの使い回しが狙われる |
| アプリケーションの不備 | SQL インジェクション | 入力欄に SQL 文の一部を入れて、データベースを不正に操作する。対策は、入力値を SQL 文として扱わないこと(プレースホルダ) |
| アプリケーションの不備 | クロスサイトスクリプティング(XSS) | Web サイトの不備を突き、悪意のあるスクリプトを閲覧者のブラウザで実行させる |
| アプリケーションの不備 | バッファオーバーフロー | 想定より長いデータを送って、メモリを溢れさせ、プログラムを乱す |
| アプリケーションの不備 | ドライブバイダウンロード | 改ざんされたサイトなどを開くだけで、マルウェアをダウンロードさせる |
| 信頼の悪用 | 中間者攻撃(MITM) | 通信の途中に割り込み、盗聴や改ざんをする |
| 信頼の悪用 | MITB(Man-in-the-browser)攻撃 | ブラウザに潜んだマルウェアが、画面の表示や送信内容を書き換える。ネットバンキングの送金先の書き換えなど |
| 信頼の悪用 | 第三者中継(オープンリレー) | 認証なしに外部のメールを中継するメールサーバーが、迷惑メールの送信に悪用される |
| 信頼の悪用 | フィッシング | 本物そっくりの偽のメールや偽サイトで、ID やパスワードを入力させる |
| 信頼の悪用 | 標的型攻撃 | 特定の組織を狙い、業務に関係するように見せかけたメールなどで侵入し、長い期間をかけて情報を盗む |
| 妨害 | DoS 攻撃 | 大量の要求を送るなどして、サービスを使えなくする攻撃の総称。1 つの攻撃元から行うものを指すことが多い |
| 妨害 | DDoS 攻撃 | 多数の端末(ボットネットなど)から、同時に大量の要求を送る |

### 5. AI を悪用した攻撃と、特殊・高度な攻撃

- AI を悪用すると、標的型攻撃やフィッシングの文面、なりすましが巧妙になります。マルウェアの亜種(バリアント)も、大量に作られます。
- **ディープフェイク**は、AI で、実在する人の顔や声に似せた偽の動画や音声を作る技術です。経営者の声に似せた電話での、送金の指示などに悪用されます。
- **ゼロデイ攻撃**は、脆弱性が公表されたり、修正プログラムが出たりする前に、その脆弱性を突く攻撃です。パッチがないので、防ぐのが難しくなります。
- **プロンプトインジェクション**は、AI への指示文(プロンプト)に、巧妙な指示を混ぜて、制限を無視させたり、意図しない出力をさせたりする攻撃です。
- **攻撃の準備**として、攻撃者は、対象の情報を集めます。IP アドレス、公開サービス、OS などを調べるのが**フットプリンティング**です。開いているポートを調べる**ポートスキャン**も、その一つです。

## 6.2 情報セキュリティマネジメント

### 1. 情報セキュリティの考え方

情報セキュリティの 3 つの特性(CIA)です。

| 特性 | 意味 | 損なわれる例 |
|---|---|---|
| **機密性**(Confidentiality) | 許可された人だけが、情報を見られる | 情報漏えい |
| **完全性**(Integrity) | 情報が正確で、改ざんや欠落がない | データの書き換え |
| **可用性**(Availability) | 許可された人が、必要なときに使える | サーバーの停止 |

- **ゼロトラスト**は、「社内のネットワークだから安全」とは考えず、すべてのアクセスを、そのつど確認してから許可する考え方です。テレワークやクラウドの利用が増え、境界で守りきれなくなったことが背景です。
- **セキュリティバイデザイン**(セキュアバイデザイン)は、システムの企画や設計の段階から、セキュリティを考えて作り込む考え方です。
- **プライバシーバイデザイン**は、企画や設計の段階から、個人情報の保護を組み込む考え方です。
- **サイバー攻撃**は、コンピュータやネットワークを狙う、悪意のある攻撃の総称です。

### 2. 情報セキュリティマネジメントの考え方

組織は、**情報セキュリティポリシー**に基づいて情報を管理します。守る対象を**情報資産**といいます。リスクを管理する活動が**リスクマネジメント**で、情報セキュリティを脅かす事象が起きたら、それを**情報セキュリティインシデント**として扱い、手順に沿って対応します。

### 3. リスクマネジメント

**情報資産**は、情報システム、データ、文書などです。

- **情報資産台帳**に、情報資産の名称、管理者、保管場所、重要度の区分などを記録して、管理します。
- **情報資産の分類**は、重要度に応じて「極秘」「社外秘」「公開」などに区分することです。区分ごとに取扱いの規則や、対策の強さを決めます。

**リスクアセスメント**は、リスクマネジメントの一部で、次の順に進めます。判断には、あらかじめ決めた**リスク基準**を使います。

1. リスク特定: どんなリスクがあるかを見つける
2. リスク分析: 起きやすさと、影響の大きさを見積もる
3. リスク評価: 対応が必要かを判断する

**リスク対応**の選択肢です。

| 対応 | 内容 | 例 |
|---|---|---|
| リスク低減 | 対策をして、リスクを小さくする | パッチの適用、アクセス権の見直し |
| リスク回避 | リスクの原因になる活動をやめる | リスクの大きなサービスの提供をやめる |
| リスク共有(リスク移転) | 損害の負担を、他者に移す | サイバー保険、外部への委託 |
| リスク共有(リスク分散) | 拠点や資産を分け、被害を分散させる | データセンターを複数に分ける |
| リスク保有 | 対策をせず、リスクを受け入れる | 影響が小さく、対策の費用に見合わない |

リスクアセスメント(1〜3)から、リスク対応(4)までの流れを表した図です。

```text
[1] リスク特定: どんなリスクがあるかを見つける
     |
     v
[2] リスク分析: 起きやすさと、影響の大きさを見積もる
     |
     v
[3] リスク評価: 対応が必要かを判断する
     |
     v
[4] リスク対応: 次のどれかを選ぶ
     +-- リスク低減
     +-- リスク回避
     +-- リスク共有(リスク移転、リスク分散)
     `-- リスク保有
```

### 4. 情報セキュリティ諸規程

| 規程 | 内容 |
|---|---|
| 情報セキュリティ方針(情報セキュリティポリシー) | 経営者が示す、基本的な考え方と取り組みの方針。一番上に置く |
| 情報セキュリティ対策基準 | 方針を実現するための、具体的な守るべき規則(パスワードの長さ、持ち出しの手続など) |
| マルウェア感染時の対応 | 感染の疑いがあるときは、ネットワークから切り離し、担当部署にすぐ報告する。電源は、調査のため、むやみに切らない |
| プライバシーポリシー(個人情報保護方針) | 個人情報を集める目的や、取扱い、問い合わせ先を、社会に向けて示す |
| ソーシャルメディアガイドライン(SNS 利用ポリシー) | 従業員が SNS を使うときの、守ることを定める(機密を書かない、会社の発言と誤解されないようにする、など) |

情報セキュリティポリシーという言葉は、方針だけを指す場合と、方針・対策基準・実施手順をまとめて指す場合があります。

### 5. 情報セキュリティの制度

組織や機関です。

| 名前 | 内容 |
|---|---|
| 情報セキュリティ委員会 | 経営層や各部門の代表が集まり、方針や重要な事項を決める |
| CSIRT | インシデントの発生時に、報告の受付、原因の調査、復旧の支援、再発の防止を担う、組織内のチーム |
| SOC(Security Operation Center) | ネットワークやシステムを常時監視し、攻撃や異常を見つけて分析する組織や拠点 |
| サイバーレスキュー隊(J-CRAT) | IPA が、標的型攻撃を受けた組織の、被害の把握、拡大の防止、再発の防止を支援する活動 |

基準や制度です。

| 名前 | 内容 |
|---|---|
| コンピュータ不正アクセス届出制度 | 不正アクセスの被害を、IPA に届け出る制度 |
| コンピュータウイルス届出制度 | ウイルスの発見や被害を、IPA に届け出る制度 |
| コンピュータウイルス対策基準、コンピュータ不正アクセス対策基準 | 組織が取り組む対策を、国(経済産業省)が示した基準 |
| ISMAP | 政府情報システムのためのセキュリティ評価制度。政府機関などが利用するクラウドサービスを、あらかじめ評価して登録する |
| SECURITY ACTION | 中小企業が、自社の情報セキュリティ対策に取り組むことを、自ら宣言する、IPA の制度 |
| サイバーセキュリティ経営ガイドライン | 経営者が認識すべき原則と、実施すべき指示事項を示した、経済産業省と IPA のガイドライン |
| 中小企業の情報セキュリティ対策ガイドライン | 中小企業が、対策に取り組むための、IPA の指針 |
| PCI DSS | クレジットカードの会員情報を扱う事業者が守る、カード業界の国際的なセキュリティ基準 |

## 6.3 情報セキュリティ対策

### 1. マルウェア対策

- **マルウェア対策ソフト**を導入し、**定義ファイル**(パターンファイル)を常に最新に更新します。新しいマルウェアは次々に出るためです。

| 検出方法 | 内容 | 特徴 |
|---|---|---|
| パターンマッチング法 | 既知のマルウェアのパターンと、ファイルを照らし合わせる | 既知のものは確実。未知のものは見つけられない |
| ビヘイビア法(振る舞い検知) | 実行したときの動作を監視し、不審な動作を検出する | 未知のものも見つけられる可能性がある |
| ヒューリスティック法 | プログラムの構造や命令の特徴から、マルウェアらしさを推測する | 未知のものも見つけられる可能性がある。誤検出もある |

**ランサムウェア対策**は、バックアップが基本です。ただし、つながっているバックアップは、一緒に暗号化されるおそれがあります。

- データのバックアップを取る
- バックアップの分離: ネットワークから切り離した別の場所に保管する
- イミュータブルバックアップ: 書き換えや削除ができないバックアップ

### 2. 暗号技術

データを読めない形に変えるのが**暗号化**(暗号鍵を使う)、元に戻すのが**復号**(復号鍵を使う)です。

| 方式 | 鍵 | 特徴 |
|---|---|---|
| **共通鍵暗号方式** | 暗号化と復号に、同じ鍵(共通鍵)を使う | 処理が速い。鍵を安全に渡す必要がある |
| **公開鍵暗号方式** | 公開鍵と秘密鍵のペア。公開鍵で暗号化し、秘密鍵で復号する | 鍵の受け渡しが楽。処理は遅い |

公開鍵暗号方式で、A さんが B さんに秘密の内容を送る流れを表した図です。

```text
[A]       A さん: 秘密の内容(平文)を用意する
 |
 |  暗号化: B さんの公開鍵を使う
 v
[Cipher]  暗号文: B さん以外は、復号できない
 |
 |  復号: B さんの秘密鍵を使う
 v
[B]       B さん: 元の内容に戻る
```

- 公開鍵暗号方式で、A さんが B さんに秘密の内容を送るときは、B さんの公開鍵で暗号化します。復号できるのは、B さんの秘密鍵を持つ B さんだけです。
- 共通鍵暗号方式で、n 人が、2 人ずつの組み合わせごとに別の鍵を使うと、鍵の数は n × (n − 1) ÷ 2 です。10 人なら、10 × 9 ÷ 2 = 45 個です。人数が増えると、急に増えます。
- **RSA 暗号**は、大きな数の素因数分解の難しさを根拠にした、公開鍵暗号方式の代表です。
- **耐量子計算機暗号(PQC)**は、量子コンピュータでも解読が難しいとされる暗号です。量子コンピュータで、現在の公開鍵暗号が解読されるおそれに備えます。
- **ハッシュ関数**は、元のデータから、固定長のハッシュ値を作ります。元のデータが少し違うだけで、ハッシュ値は大きく変わります。ハッシュ値から元のデータを復元するのは難しくなっています。改ざんの検知に使います。
- **ブロックチェーン**は、取引の記録をまとめたブロックを、前のブロックのハッシュ値でつなぎ、複数の参加者で共有して管理する技術です。過去の記録を書き換えにくくなっています。暗号資産(仮想通貨)の基盤にも使われています。

### 3. 公開鍵基盤とデジタル証明書

公開鍵が本当にその人のものかを確かめる仕組みが、**公開鍵基盤(PKI)**です。

- **認証局(CA)**: 公開鍵の持ち主を確認し、**デジタル証明書**(公開鍵証明書)を発行する機関です。
- **ルート証明書**: 認証局自身の証明書です。他の証明書の正しさを確かめる起点になります。
- **サーバ証明書**: Web サイトの運営者の身元と公開鍵を示します。HTTPS で、ブラウザが本物のサイトかを確かめます。
- **クライアント証明書**: 利用者や端末が正規であることを、サーバーに示します。
- **証明書失効リスト(CRL)**: 有効期間内でも、秘密鍵の漏えいなどで無効になった証明書の一覧です。

### 4. 認証技術

- **デジタル署名**: 送信者が、自分の秘密鍵(署名鍵)で、文書のハッシュ値を暗号化して付けます。受信者は、送信者の公開鍵(検証鍵)で確かめます。送信者が本人であることと、改ざんがないことを確かめられます。
- **タイムスタンプ**(時刻認証): 第三者の機関が、文書が、ある時刻に存在したことと、その後に改ざんされていないことを証明します。
- **リスクベース認証**: 普段と違う場所や端末からのログインなど、リスクが高いと判断したときだけ、追加の認証を求めます。

デジタル署名を付ける流れと、確かめる流れを表した図です。

```text
Sender
  [Doc]     文書
    |
    v
  [Hash]    文書のハッシュ値を求める
    |
    v
  [Sign]    送信者の秘密鍵で、ハッシュ値を暗号化する
    |
    |  署名を付けて送る
    v
Receiver
  [Verify]  送信者の公開鍵で、署名を確かめる
```

確かめられると、送信者が本人であることと、改ざんがないことが分かります。

### 5. 利用者認証

**ログイン**は、利用者 ID とパスワードで行うのが基本です。誰に、どの情報や機能を使わせるかを管理するのが**アクセス管理**です。

認証に使う要素は、3 種類あります。

| 要素 | 例 |
|---|---|
| 記憶 | パスワード、PIN コード |
| 所有 | IC カード、スマートフォン、ワンタイムパスワードを表示する機器 |
| 生体 | 指紋、顔、静脈 |

- **多要素認証**: 異なる種類の要素を、2 つ以上組み合わせます。パスワード(記憶)とスマートフォン(所有)など。
- **多段階認証**: 認証を何段階かに分けます。種類が同じでも構いません(パスワードと秘密の質問など)。
- **ワンタイムパスワード**: 1 回しか使えないパスワードです。盗まれても、再利用できません。
- **パスキー**: パスワードの代わりに、端末の生体認証や PIN で本人を確かめ、公開鍵暗号でログインします。秘密鍵は端末から出ず、鍵は登録した本物のサイトにだけ使われます。そのため、偽サイトにだまされても、ログインの情報を盗まれず、フィッシングに強くなります。
- **シングルサインオン(SSO)**: 1 回の認証で、複数のサービスを使えるようにします。
- **eKYC**: オンラインで、本人確認書類の画像や、顔の撮影などで、本人確認をします。

**生体認証**です。

- 身体的特徴: 指紋、静脈パターン認証、虹彩認証、顔認証、網膜認証 など
- 行動的特徴: 筆跡、キーボードを打つ速さやリズム など
- **本人拒否率(FRR)**: 登録された本人が、誤って拒否される割合です。
- **他人受入率(FAR)**: 他人が、誤って本人と受け入れられる割合です。
- 判定を厳しくすると、FAR は下がり、FRR は上がります。片方を下げると、もう片方が上がる関係です。

### 6. ネットワークと端末の対策

- **URL フィルタリング**(Web フィルタリング): 閲覧するサイトの URL をもとに、閲覧を制限します。危険なサイトや、業務に関係のないサイトを防ぎます。
- **脆弱性管理**: OS のアップデートと、脆弱性を修正するプログラム(**セキュリティパッチ**)の適用です。メーカーや、IPA、JPCERT/CC などが出す脆弱性の情報を確認します(脆弱性情報の取得)。
- **脆弱性検査**: 専用のツールで、システムに既知の脆弱性が残っていないかを調べます。

| 製品 | 内容 |
|---|---|
| マルウェア対策ソフト | マルウェアを検出し、駆除する |
| EDR(Endpoint Detection and Response) | パソコンやサーバーなどの端末の動きを監視し、不審な動きを検知して、対応を支援する |
| ファイアウォール | ネットワークの境界で、IP アドレスやポート番号などをもとに、通信を許可したり遮断したりする |
| WAF(Web Application Firewall) | Web アプリケーションへの通信の内容を調べ、SQL インジェクションや XSS などを防ぐ |
| 侵入検知システム(IDS) | 不正な侵入や通信を検知して、管理者に通知する。遮断はしない |
| 侵入防止システム(IPS) | 不正な侵入や通信を検知して、自動で遮断する |
