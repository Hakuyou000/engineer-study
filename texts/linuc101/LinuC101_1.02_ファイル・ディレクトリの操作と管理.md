# LinuC 101 テキスト 1.02 ファイル・ディレクトリの操作と管理

ファイルの所有者とパーミッション、ファイルの基本の操作(コピー、移動、削除、圧縮、検索)、ハードリンクとシンボリックリンク、ファイルの置き場所の決まり(FHS)を学びます。

## 1.02.1 ファイルの所有者とパーミッション (重要度3)

### 1. ls -l の読み方

```bash
$ ls -l /etc/hosts
-rw-r--r--. 1 root root 158  6月 23  2024 /etc/hosts
```

| 部分 | 意味 |
|---|---|
| `-` | ファイルの種類(`-` 普通のファイル、`d` ディレクトリ、`l` シンボリックリンク、`c` と `b` デバイス) |
| `rw-r--r--` | パーミッション。3 文字ずつ、所有者(user)、グループ(group)、その他(other) |
| `1` | ハードリンクの数 |
| `root root` | 所有者と、所有するグループ |
| `158` | 大きさ(バイト) |

### 2. パーミッションの意味

| 記号 | 数字 | ファイル | ディレクトリ |
|---|---|---|---|
| `r` | 4 | 中身を読める | 中のファイルの名前の一覧を見られる |
| `w` | 2 | 中身を書き換えられる | 中にファイルを作る、消す、名前を変える |
| `x` | 1 | 実行できる | 中に入れる(`cd`)、中のファイルにアクセスできる |

数字は 3 つの組ごとに足します。`rwxr-xr--` は 7(4+2+1)、5(4+1)、4 で `754` です。

ディレクトリの `w` があると、中のファイルの書き込みの権限がなくても、そのファイルを**消せます**。ファイルを消すのはディレクトリの中身の変更だからです。

### 3. chmod

```bash
chmod 644 file.txt          # 数字(8 進数)で指定する
chmod u+x script.sh         # 所有者に実行を加える
chmod go-w file.txt         # グループとその他から書き込みを外す
chmod a=r file.txt          # 全員を読み取りだけにする(a は all)
chmod -R 755 dir/           # ディレクトリの中もまとめて変える
```

記号の書き方は「対象(`u`、`g`、`o`、`a`)」「操作(`+` 加える、`-` 外す、`=` そのとおりにする)」「権限(`r`、`w`、`x`)」の順です。

### 4. 特別なパーミッション

| 名前 | 数字 | 付く場所 | 意味 | 表示 |
|---|---|---|---|---|
| **SUID** | 4000 | 実行ファイル | 実行した人ではなく、**ファイルの所有者**の権限で動く | 所有者の x が `s` |
| **SGID** | 2000 | 実行ファイル | ファイルのグループの権限で動く | グループの x が `s` |
| **SGID** | 2000 | ディレクトリ | 中に作ったファイルのグループが、ディレクトリのグループになる | グループの x が `s` |
| **スティッキービット** | 1000 | ディレクトリ | 中のファイルは、その所有者(と root)しか消せない | その他の x が `t` |

```bash
$ ls -l /usr/bin/passwd
-rwsr-xr-x. 1 root root 32648 /usr/bin/passwd      # SUID。一般ユーザーも /etc/shadow を書き換えられる
$ ls -ld /tmp
drwxrwxrwt. 20 root root 4096 /tmp                  # スティッキービット。誰でも書けるが、他人のファイルは消せない
chmod 4755 prog            # SUID を付ける(u+s)
chmod 2775 shared/         # SGID を付ける(g+s)
chmod 1777 public/         # スティッキービットを付ける(o+t)
```

実行の権限がないのに特別なビットが付いていると、大文字の `S` や `T` で表示されます。

### 5. 所有者とグループを変える

```bash
chown sato file.txt            # 所有者を sato に
chown sato:dev file.txt        # 所有者とグループを同時に(sato.dev とも書ける)
chown :dev file.txt            # グループだけ
chgrp dev file.txt             # グループだけ
chown -R sato:dev dir/         # 中もまとめて
```

所有者を変えられるのは root だけです。一般ユーザーは、自分のファイルのグループを、自分が入っているグループにだけ変えられます。

### 6. umask

**umask** は、新しく作るファイルとディレクトリから**外す**権限を決める値です。

| | 元の値 | umask 022 のとき | umask 027 のとき |
|---|---|---|---|
| ファイル | 666 | 644 | 640 |
| ディレクトリ | 777 | 755 | 750 |

ファイルは最初から実行の権限を付けないので、元の値は 666 です。

```bash
umask          # 今の値(0022 のように 4 桁で表示される)
umask 027      # このシェルの間だけ変える(ずっと使うなら ~/.bashrc などに書く)
```

## 1.02.2 基本的なファイル管理の実行 (重要度3)

### 1. 基本の操作

| コマンド | 主なオプション | 動き |
|---|---|---|
| `ls` | `-l` 詳しく、`-a` 隠しファイルも、`-d` ディレクトリそのもの、`-R` 中も、`-t` 新しい順、`-h` 読みやすい大きさ | 一覧 |
| `file` | | ファイルの中身の種類(テキスト、ELF、画像など)を調べる |
| `touch` | `-t` 時刻を指定 | 空のファイルを作る。あれば更新の時刻を今にする |
| `cp` | `-r`(`-R`) ディレクトリごと、`-p` 所有者や時刻を保つ、`-a` すべての属性を保って中も、`-i` 上書きの前に確かめる | コピー |
| `mv` | `-i`、`-f` | 移動、名前の変更 |
| `rm` | `-r` ディレクトリごと、`-f` 確かめずに、`-i` 1 つずつ確かめる | 削除 |
| `mkdir` | `-p` 途中のディレクトリも作る、`-m` パーミッションを指定 | ディレクトリを作る |
| `rmdir` | `-p` 親も | **空の**ディレクトリを消す |

```bash
mkdir -p project/src/lib        # project と src がなくても作る
cp -a /etc/nginx /backup/       # 属性を保ってディレクトリごとコピー
rm -rf old/                     # 中身ごと確かめずに消す(取り消せない)
```

### 2. ファイル名のパターン(グロブ)

| 記号 | 意味 | 例 |
|---|---|---|
| `*` | 0 文字以上の任意の文字 | `*.log` |
| `?` | 任意の 1 文字 | `file?.txt` → file1.txt、fileA.txt |
| `[abc]` | 中の 1 文字 | `file[123].txt` |
| `[a-z]` | 範囲の 1 文字 | `[0-9]*` |
| `[!abc]`、`[^abc]` | 中の文字以外の 1 文字 | `[!0-9]*` |
| `{a,b}` | 並べたものに展開する(bash のブレース展開) | `cp file.{txt,bak}` |

グロブはシェルが展開します。`*` は、`.` で始まる隠しファイルには一致しません。

### 3. アーカイブと圧縮

**tar** は、複数のファイルを 1 つにまとめる(アーカイブ)コマンドです。オプションで圧縮もできます。

| オプション | 意味 |
|---|---|
| `c` | 作る(create) |
| `x` | 取り出す(extract) |
| `t` | 中身の一覧(list) |
| `f ファイル` | アーカイブのファイル名 |
| `v` | 処理したファイルを表示する |
| `z` / `j` / `J` | gzip / bzip2 / xz で圧縮、展開する |
| `C ディレクトリ` | そのディレクトリで取り出す |

```bash
tar cvf backup.tar dir/            # まとめる
tar czvf backup.tar.gz dir/        # gzip で圧縮してまとめる
tar tzvf backup.tar.gz             # 中身を見る
tar xzvf backup.tar.gz -C /tmp     # /tmp に取り出す
tar xJf backup.tar.xz              # xz の展開
```

1 つのファイルを圧縮するコマンドです。圧縮すると、元のファイルは置き換えられます。

| 圧縮 | 展開 | 拡張子 | 特徴 |
|---|---|---|---|
| `gzip file` | `gunzip file.gz`(`gzip -d`) | `.gz` | 速い。最も広く使われる |
| `bzip2 file` | `bunzip2 file.bz2`(`bzip2 -d`) | `.bz2` | gzip より縮むが遅い |
| `xz file` | `unxz file.xz`(`xz -d`) | `.xz` | 最もよく縮むが遅い |

`-k` を付けると元のファイルを残します(gzip は新しい版から対応)。`-c` は結果を標準出力に書きます(`gzip -c file > file.gz`)。圧縮したファイルを展開せずに見るには `zcat`、`bzcat`、`xzcat` を使います。

### 4. dd

**dd** は、ブロックの単位でデータをコピーします。ディスクの丸ごとのコピーや、決まった大きさのファイルを作るのに使います。

```bash
dd if=/dev/zero of=test.img bs=1M count=100       # 100MB のファイルを作る
dd if=/dev/sda of=/dev/sdb bs=4M status=progress  # ディスクを丸ごとコピーする
dd if=ubuntu.iso of=/dev/sdc bs=4M                # ISO を USB メモリに書く
```

`if` は入力、`of` は出力、`bs` は 1 回に読み書きする大きさ、`count` は回数です。`of` を間違えると、そのディスクの中身が消えます。

### 5. find

```bash
find /var/log -name "*.log"            # 名前で(-iname は大文字と小文字を区別しない)
find / -type f -size +100M             # 100MB より大きい普通のファイル
find /home -user sato                  # 所有者で
find . -mtime -7                       # 7 日より新しく変更された(+7 は 7 日より古い)
find . -mmin -30                       # 30 分より新しく変更された
find / -perm -4000                     # SUID が付いたもの
find /tmp -type f -mtime +30 -delete   # 30 日より古いものを消す
find . -name "*.tmp" -exec rm {} \;    # 見つけたものに 1 つずつ rm を実行する
find . -type d -empty                  # 空のディレクトリ
```

| 条件 | 意味 |
|---|---|
| `-type f` / `d` / `l` | 普通のファイル / ディレクトリ / シンボリックリンク |
| `-size +100M` / `-10k` | より大きい / より小さい(`c` バイト、`k`、`M`、`G`) |
| `-mtime n` | 中身を変更してからの日数(`-atime` は読んだ日、`-ctime` は属性を変えた日) |
| `-perm 644` / `-perm -4000` | ちょうど一致 / 指定のビットをすべて含む |
| `-maxdepth 1` | 何階層まで探すか |

## 1.02.3 ハードリンクとシンボリックリンク (重要度2)

### 1. inode

ファイルの中身と属性(所有者、パーミッション、時刻、データの場所)は、**inode** という管理の情報に記録されています。ファイル名は、ディレクトリの中で「名前と inode の番号の組」として記録されているだけです。

```bash
ls -i file.txt         # inode の番号を表示する
ls -li                 # 番号と詳しい情報
```

### 2. 2 つのリンク

```bash
ln file.txt hard.txt          # ハードリンク
ln -s file.txt sym.txt        # シンボリックリンク
```

| | ハードリンク | シンボリックリンク |
|---|---|---|
| 仕組み | 同じ inode に別の名前を付ける | 元のファイルのパスを中身に持つ、別のファイル |
| inode の番号 | 元と同じ | 元と違う |
| 元を消すと | 中身は残り、使い続けられる(リンクの数が 0 になるまで残る) | リンク切れになり、使えない |
| ディレクトリ | 作れない | 作れる |
| 別のファイルシステム | 作れない(inode の番号はファイルシステムごと) | 作れる |
| `ls -l` の表示 | 普通のファイルと同じ。リンクの数が増える | `l` で始まり、`sym.txt -> file.txt` |

- `ls -F` は、名前の後ろに種類の記号を付けます(`/` ディレクトリ、`*` 実行できる、`@` シンボリックリンク)。
- シンボリックリンクを相対パスで作ると、**リンクの置き場所から見た**相対パスになります。

## 1.02.4 ファイルの配置と検索 (重要度2)

### 1. FHS(Filesystem Hierarchy Standard)

ディレクトリの役割を決めた標準です。

| ディレクトリ | 内容 |
|---|---|
| `/bin`、`/sbin` | 基本のコマンド(最近は `/usr/bin`、`/usr/sbin` へのリンク) |
| `/boot` | カーネル、initramfs、ブートローダーの設定 |
| `/dev` | デバイスファイル |
| `/etc` | 設定ファイル |
| `/home` | 一般ユーザーのホームディレクトリ |
| `/root` | root のホームディレクトリ |
| `/lib`、`/lib64` | 共有ライブラリ、カーネルのモジュール |
| `/media` | USB メモリや CD などの、取り外せる媒体のマウントポイント |
| `/mnt` | 一時的なマウントポイント |
| `/opt` | 追加のソフトウェア(パッケージ管理の外のもの) |
| `/proc` | プロセスとカーネルの情報(メモリの上の仮想のファイルシステム) |
| `/sys` | デバイスとカーネルの情報(sysfs) |
| `/run` | 起動してからの実行時の情報(PID のファイルなど。再起動で消える) |
| `/tmp` | 一時ファイル(再起動で消えることがある) |
| `/usr` | プログラムとライブラリ(読み取りだけでよいもの) |
| `/usr/local` | その機械で独自に入れたもの |
| `/var` | 変わるデータ(ログ `/var/log`、メールやキュー `/var/spool`、キャッシュ `/var/cache`) |

### 2. コマンドの場所を探す

| コマンド | 内容 |
|---|---|
| `which ls` | PATH の中から、実行される実行ファイルのパスを表示する |
| `type ls` | シェルがその名前をどう扱うか(エイリアス、組み込みのコマンド、関数、ファイル)を表示する |
| `whereis ls` | 実行ファイル、ソース、マニュアルの場所をまとめて表示する |

```bash
$ type cd
cd はシェル組み込み関数です
$ type ll
ll は `ls -l --color=auto' のエイリアスです
```

### 3. locate と updatedb

```bash
locate nginx.conf        # データベースから名前で探す(速い)
sudo updatedb            # データベースを今の状態に更新する
```

- **locate** は、ファイルシステムを直接探さず、あらかじめ作ったデータベースから探すので速いです。
- データベースは普通 1 日に 1 回、自動で更新されます。作ったばかりのファイルは、`updatedb` を実行するまで見つかりません。
- 探さない場所(`/tmp` など)は `/etc/updatedb.conf` の `PRUNEPATHS` などで決めます。
- 今の状態を確実に探すときは `find` を使います。
