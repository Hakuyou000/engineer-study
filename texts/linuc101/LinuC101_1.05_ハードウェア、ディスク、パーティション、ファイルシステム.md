# LinuC 101 テキスト 1.05 ハードウェア、ディスク、パーティション、ファイルシステム

Linux がハードウェアをどう認識して扱うか(カーネルのモジュール、デバイスファイル、/proc と /sys、udev)、ディスクの分け方(パーティション、LVM)、ファイルシステムの作成とマウントを学びます。

## 1.05.1 ハードウェアの基礎知識と設定 (重要度3)

### 1. 記憶装置

| 種類 | 特徴 |
|---|---|
| HDD | 円盤を回して磁気で記録する。容量あたりが安い。動く部品があり、衝撃に弱い |
| SSD | フラッシュメモリに記録する。速く、音がしない。書き込める回数に上限がある |
| 光学ストレージ | CD、DVD、Blu-ray。`/dev/sr0` などとして見える |

### 2. デバイスファイル(/dev)

Linux は、ハードウェアを `/dev` の下の**デバイスファイル**として扱います。

| ファイル | 内容 |
|---|---|
| `/dev/sda`、`/dev/sdb` | SATA、SCSI、USB のディスク(1 台目、2 台目) |
| `/dev/sda1` | 1 台目のディスクの 1 番目のパーティション |
| `/dev/nvme0n1`、`/dev/nvme0n1p1` | NVMe の SSD と、その 1 番目のパーティション |
| `/dev/vda` | 仮想マシンの virtio のディスク |
| `/dev/sr0` | 光学ドライブ |
| `/dev/null` | 書いたものは捨てられ、読むと空 |
| `/dev/zero` | 読むと 0 が続く |

名前は、ディスクの下にパーティションが並ぶ形になっています。

```text
/dev/sda              1 台目のディスク(SATA、SCSI、USB)
  +-- /dev/sda1       その 1 番目のパーティション
  +-- /dev/sda2       その 2 番目のパーティション
/dev/sdb              2 台目のディスク
/dev/nvme0n1          NVMe の SSD(コントローラー 0 の、名前空間 1)
  +-- /dev/nvme0n1p1  p の後ろがパーティションの番号
```

### 3. /proc と /sys

| 場所 | 内容 |
|---|---|
| `/proc/cpuinfo` | CPU の情報 |
| `/proc/meminfo` | メモリの情報 |
| `/proc/interrupts` | 割り込み(IRQ)の使用の状況 |
| `/proc/ioports` | I/O ポートのアドレス |
| `/proc/modules` | 読み込まれているカーネルのモジュール |
| `/proc/<PID>/` | プロセスごとの情報 |
| `/sys/` | **sysfs**。デバイスとドライバーの情報を、木の形で見せる |

どちらもメモリの上の仮想のファイルシステムで、ディスクには保存されていません。

### 4. デバイスを調べる

| コマンド | 内容 |
|---|---|
| `lspci` | PCI のデバイス(ネットワークカード、グラフィック、ストレージのコントローラー)。`-k` で使っているドライバーも |
| `lsusb` | USB のデバイス。`-t` で木の形 |
| `lsblk` | ブロックデバイス(ディスクとパーティション)の一覧 |
| `dmesg` | カーネルのメッセージ(デバイスを認識したときの記録) |

### 5. カーネルのモジュール

ドライバーなどの機能は、必要なときにカーネルに読み込む**モジュール**として用意されています。

| コマンド | 動き |
|---|---|
| `lsmod` | 読み込まれているモジュールの一覧(`/proc/modules` を見やすくしたもの) |
| `modinfo e1000` | モジュールの情報 |
| `modprobe e1000` | 読み込む。**依存するモジュールも**一緒に読み込む |
| `modprobe -r e1000` | 外す(依存するものも) |
| `insmod /path/e1000.ko` | ファイルを指定して読み込む。依存関係は解決しない |
| `rmmod e1000` | 外す。依存関係は考えない |

依存関係を考えてくれる `modprobe` を普段は使います。起動のときに読み込む設定は `/etc/modules-load.d/`、読み込みの設定やさせない設定(blacklist)は `/etc/modprobe.d/` に書きます。

### 6. udev と D-Bus

- **udev** は、デバイスがつながったり外れたりしたときに、`/dev` のデバイスファイルを自動で作ったり消したりする仕組みです。名前の付け方などの規則は `/etc/udev/rules.d/` に書きます。`udevadm monitor` で動きを見られます。
- **D-Bus** は、プログラム同士が情報をやり取りする仕組みです。USB メモリをつないだことをデスクトップに知らせる、といったことに使われます。

USB メモリをつないだときは、次の順に伝わります。

```text
USB メモリをつなぐ
  |
  v
カーネル: 認識して、必要なモジュール(ドライバー)を読み込む。/sys に情報が現れ、dmesg に記録が残る
  |
  |  uevent(デバイスがつながったという知らせ)
  v
udev: /etc/udev/rules.d/ などの規則に従い、/dev のデバイスファイルを整える(権限、/dev/disk/by-uuid/ の別名など)
  |
  |  D-Bus
  v
デスクトップ環境: つながったことを知り、/media/<ユーザー>/ の下に自動でマウントする
```

## 1.05.2 ハードディスクのレイアウトとパーティション (重要度4)

### 1. パーティションの方式

| | MBR | GPT |
|---|---|---|
| 使う機械 | BIOS(UEFI でも互換の動きで使える) | UEFI |
| ディスクの大きさの上限 | 2 TiB | 実際には上限なし |
| パーティションの数 | 基本パーティションは 4 つまで。それ以上は 1 つを拡張パーティションにし、その中に論理パーティション | 128 個まで(既定) |
| 番号 | 基本と拡張は 1〜4、論理は 5 から | 1 から順に |

MBR で 5 つ以上に分けるときの形です。基本と拡張は合わせて 4 つまでです。拡張パーティションは論理パーティションを入れる箱で、そこに直接ファイルシステムは作りません。

```text
/dev/sda(MBR)
  +-- sda1        基本パーティション
  +-- sda2        基本パーティション
  +-- sda3        基本パーティション
  +-- sda4        拡張パーティション(論理パーティションの入れ物)
        +-- sda5  論理パーティション(番号は 5 から)
        +-- sda6  論理パーティション
        +-- sda7  論理パーティション

/dev/sdb(GPT)
  +-- sdb1        ESP(FAT。/boot/efi にマウントする)
  +-- sdb2        基本と拡張の区別はない。1 から順に番号が付く
  +-- sdb3
```

UEFI で起動するには、**ESP**(EFI システムパーティション)が必要です。FAT(VFAT)でフォーマットし、`/boot/efi` にマウントして、ブートローダーを置きます。

### 2. パーティションを作る道具

| コマンド | 対象 | 特徴 |
|---|---|---|
| `fdisk` | MBR(新しい版は GPT も) | 対話式。`p` 表示、`n` 作る、`d` 消す、`t` 種類を変える、`w` 書き込んで終わる、`q` 書き込まずに終わる |
| `gdisk` | GPT | fdisk と似た操作 |
| `parted` | MBR と GPT | 対話式とコマンドの 1 行の両方。**変更はすぐに反映される** |

```bash
sudo fdisk -l                  # すべてのディスクのパーティションを表示する
sudo fdisk /dev/sdb            # sdb を対話式で編集する
sudo parted /dev/sdb print
```

fdisk と gdisk は `w` を押すまでディスクに書き込みません。parted は 1 つずつの操作がすぐに書き込まれるので注意します。

### 3. パーティションの分け方

| 場所 | 分ける理由 |
|---|---|
| `/` | ルート。必須 |
| `/boot` | カーネルを置く。ブートローダーが読める形式にしておく |
| `/boot/efi` | ESP(UEFI のとき) |
| `/home` | ユーザーのデータ。OS を入れ直してもデータを残せる |
| `/var` | ログなどで増える。いっぱいになっても `/` を巻き込まない |
| スワップ | メモリが足りないときに、使っていないメモリの中身を書き出す場所 |

### 4. LVM

**LVM**(Logical Volume Manager)は、複数のディスクやパーティションをまとめ、そこから好きな大きさの領域を切り出す仕組みです。後から大きさを変えられます。

| 用語 | 意味 | 作るコマンド |
|---|---|---|
| **物理ボリューム**(PV) | LVM に使うパーティションやディスク | `pvcreate /dev/sdb1` |
| **ボリュームグループ**(VG) | PV をまとめた、容量の入れ物 | `vgcreate vg01 /dev/sdb1 /dev/sdc1` |
| **論理ボリューム**(LV) | VG から切り出した領域。ここにファイルシステムを作る | `lvcreate -L 10G -n lv_data vg01` |
| **PE**(物理エクステント) | 割り当ての最小の単位(既定 4MiB) | ― |

下から順に積み上げます。ディスクを PV にし、PV を集めて VG を作り、VG から LV を切り出します。

```text
/dev/sdb1      /dev/sdc1      ディスクのパーティション
    |              |
    | pvcreate     | pvcreate
    v              v
  [PV]           [PV]         物理ボリューム
    |              |
    +------+-------+
           |  vgcreate vg01 /dev/sdb1 /dev/sdc1
           v
        [vg01]                ボリュームグループ(PV の容量を PE の単位でまとめたもの)
           |
    +------+-------+
    |              |
    | lvcreate     | lvcreate
    v              v
 [lv_data]      [lv_log]      論理ボリューム(/dev/vg01/lv_data として見える)
    |              |
    | mkfs.xfs     | mkfs.ext4
    v              v
  /data         /var/log      マウントして使う
```

容量が足りなくなったら、`vgextend` で VG に PV を足し、`lvextend` で LV を広げます。LV はディスクの境目をまたいでいてもかまいません。

```bash
pvs; vgs; lvs                              # 一覧(pvdisplay などで詳しく)
mkfs.xfs /dev/vg01/lv_data                 # LV にファイルシステムを作る
lvextend -L +5G -r /dev/vg01/lv_data       # 5GB 広げ、-r でファイルシステムも広げる
vgextend vg01 /dev/sdd1                    # VG にディスクを足す
```

**スナップショット**は、ある時点の LV の状態を保存した LV です(`lvcreate -s -L 1G -n snap /dev/vg01/lv_data`)。変更された部分だけを記録するので、作るのは一瞬です。バックアップを取る間、元の LV を止めずに一貫した状態を読むのに使います。

## 1.05.3 ファイルシステムの作成と管理、マウント (重要度4)

### 1. ファイルシステムの種類

| 種類 | 特徴 |
|---|---|
| **ext4** | Linux で広く使われる。ジャーナルを持つ。ext3 の後継 |
| ext3 | ext2 にジャーナルを加えたもの |
| **XFS** | 大きなファイルと大きな容量に強い。RHEL の既定。**縮められない** |
| **Btrfs** | スナップショット、圧縮、複数のディスクをまとめる機能を持つ |
| **VFAT** | Windows と共通の FAT。USB メモリ、ESP |
| **tmpfs** | メモリの上に作る。再起動で消える(`/run`、`/tmp` など) |

**ジャーナル**は、書き込みの前に変更の予定を記録しておく仕組みです。途中で電源が落ちても、短い時間で整合性を取り戻せます。

### 2. 作る

```bash
mkfs -t ext4 /dev/sdb1         # mkfs.ext4 /dev/sdb1 と同じ
mkfs.xfs /dev/sdb2
mkfs.vfat /dev/sdc1
mkswap /dev/sdb3               # スワップの領域にする
swapon /dev/sdb3               # スワップを使い始める(swapon -s、free で確かめる)
swapoff /dev/sdb3              # やめる
```

ファイルに対して `mkswap` と `swapon` を行えば、パーティションを作らずにスワップを増やせます。

### 3. マウント

ファイルシステムを、ディレクトリの木の中の場所(**マウントポイント**)につなぐことを**マウント**と呼びます。

```text
/               <-- /dev/sda2(xfs)
|-- boot        <-- /dev/sda1(ext4)
|   `-- efi     <-- /dev/sda3(vfat。ESP)
|-- home        <-- /dev/sdb1(ext4)
|-- data        <-- /dev/vg01/lv_data(xfs)
|-- etc             何もつないでいないので、/ と同じファイルシステムの中
`-- mnt
    `-- usb     <-- /dev/sdc1(vfat。mount /dev/sdc1 /mnt/usb でつないだもの)
```

ディスクがいくつあっても、見えるのは `/` から始まる 1 本の木です。`/home/a.txt` に書くと `/dev/sdb1` に、`/etc/hosts` に書くと `/dev/sda2` に保存されます。マウントポイントに元からあったファイルは、外すまで見えなくなります。

```bash
mount /dev/sdb1 /mnt/data              # マウントする(種類は自動で判定)
mount -t xfs /dev/sdb2 /data           # 種類を指定する
mount -o ro /dev/sdb1 /mnt             # 読み取りだけで
mount -o remount,rw /                  # マウントしたまま設定を変える
mount                                  # マウントの一覧(findmnt、df -h でも)
umount /mnt/data                       # 外す(使用中なら外せない)
mount -a                               # /etc/fstab のものをまとめてマウントする
```

使用中で `umount` できないときは、`lsof /mnt/data` や `fuser -m /mnt/data` で使っているプロセスを探します。USB メモリなどは、デスクトップ環境が `/media/<ユーザー>/` の下に自動でマウントします。

### 4. /etc/fstab

起動のときに自動でマウントするファイルシステムを書きます。

```
UUID=3f6e...b2c1  /         xfs   defaults        0 0
UUID=9a1d...77e0  /home     ext4  defaults        0 2
/dev/vg01/lv_data /data     xfs   defaults,noatime 0 0
UUID=5c2b...0d41  none      swap  defaults        0 0
```

| 欄 | 内容 |
|---|---|
| 1 | デバイス(`/dev/sdb1`、`UUID=…`、`LABEL=…`) |
| 2 | マウントポイント(スワップは `none` か `swap`) |
| 3 | ファイルシステムの種類 |
| 4 | マウントのオプション(`defaults` は rw、suid、dev、exec、auto、nouser、async) |
| 5 | dump でバックアップするか(0 しない) |
| 6 | 起動のときに fsck で調べる順番(0 調べない、1 ルート、2 そのほか) |

- `/dev/sdb1` のような名前は、ディスクをつなぐ順番で変わることがあります。変わらない **UUID** で書くのが安全です。UUID は `blkid` や `lsblk -f` で調べます。
- 主なオプション: `noauto`(`mount -a` と起動のときにマウントしない)、`user`(一般ユーザーもマウントできる)、`ro`、`noexec`(実行できない)、`nofail`(なくても起動を止めない)。
- 書き間違えると起動できなくなることがあります。書いたら `mount -a` で確かめます。

### 5. 使用量と修復

| コマンド | 内容 |
|---|---|
| `df -h` | ファイルシステムごとの使用量(`-i` で inode の使用量) |
| `du -sh /var/log` | ディレクトリの使用量 |
| `fsck /dev/sdb1` | 調べて直す(**マウントしていない状態で**実行する)。ext 系は `e2fsck` |
| `xfs_repair /dev/sdb2` | XFS を直す |
| `tune2fs -l /dev/sdb1` | ext 系の設定を見る、変える |
| `xfs_info /data` | XFS の情報 |

空き容量があるのに「No space left on device」になるときは、inode を使い切っていないかを `df -i` で確かめます(小さいファイルが大量にあるとき)。
