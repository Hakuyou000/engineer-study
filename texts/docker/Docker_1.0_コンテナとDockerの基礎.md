# Docker テキスト 1.0 コンテナと Docker の基礎

コンテナとは何か、Docker がどんな部品でできているか、最初に使う基本のコマンドを学びます。

## 1.1 コンテナとは何か

### 1. コンテナと仮想マシン

**コンテナ**は、アプリケーションと、それが動くのに必要なもの(ライブラリ、設定、実行環境)をまとめ、ほかから**分離して動かす**仕組みです。

| | 仮想マシン(VM) | コンテナ |
|---|---|---|
| 仮想化するもの | ハードウェア(ハイパーバイザーの上でゲスト OS を動かす) | OS(ホストのカーネルの上でプロセスを分離する) |
| OS | VM ごとにゲスト OS(カーネル)を持つ | **ホストのカーネルを共有する** |
| 大きさ | GB 単位 | MB 単位 |
| 起動 | 分単位 | 秒以下 |
| 分離の強さ | 強い | VM より弱い(カーネルを共有するため) |
| 別の OS | 動かせる | ホストと同じ系統のカーネルだけ(Linux のコンテナには Linux のカーネル) |

Windows や Mac の Docker Desktop は、内部で小さな Linux の VM を動かし、その中で Linux のコンテナを動かしています。

### 2. コンテナを実現する Linux の機能

コンテナは特別な仮想化ではなく、Linux カーネルの機能を組み合わせた、**分離されたプロセス**です。

| 機能 | 役割 | 例 |
|---|---|---|
| **namespace**(名前空間) | 見えるものを分ける | PID(プロセス番号)、NET(ネットワーク)、MNT(マウント)、UTS(ホスト名)、IPC、USER |
| **cgroups**(コントロールグループ) | 使える資源を制限する | CPU、メモリ、プロセスの数、ディスクの I/O |
| ユニオンファイルシステム(overlay2 など) | 読み取り専用の層を重ねて 1 つのファイルシステムに見せる | イメージの層 + コンテナの書き込み層 |

- コンテナの中から見ると、自分のプロセスが PID 1 で、ほかのコンテナやホストのプロセスは見えません(PID namespace)。
- ホストから見ると、コンテナは普通のプロセスです(`ps` で見えます)。

### 3. コンテナの利点

| 利点 | 内容 |
|---|---|
| どこでも同じように動く | 開発者の PC、CI、本番で、同じイメージを使える(「自分の環境では動いた」問題を減らす) |
| 軽くて速い | 起動が速く、1 台のホストに多く載せられる |
| 依存関係の分離 | アプリごとに別のバージョンのライブラリを使える |
| 不変(イミュータブル) | 変更は新しいイメージを作って入れ替える。手作業の変更が積み重ならない |

## 1.2 Docker の構成要素

### 1. 全体の構成

```text
docker(CLI)
  |
  |  REST API
  v
dockerd(Docker デーモン)
  |
  v
containerd(コンテナの管理)
  |
  v
runc(コンテナを実際に作る。OCI の実装)
```

| 部品 | 役割 |
|---|---|
| **Docker クライアント**(`docker` コマンド) | 利用者の命令を、API でデーモンに送る |
| **Docker デーモン**(`dockerd`) | イメージ、コンテナ、ネットワーク、ボリュームを管理する。API を待ち受ける |
| **containerd** | コンテナの実行と、イメージの取得・保存を管理する(Kubernetes からも使われる) |
| **runc** | namespace と cgroups を設定して、コンテナのプロセスを起動する低レベルのランタイム |
| **レジストリ** | イメージを保存し配る場所(Docker Hub、Amazon ECR、GitHub Container Registry など) |

- クライアントとデーモンは別のプログラムです。クライアントは、ローカルのソケット(`/var/run/docker.sock`)や、ネットワーク越しのデーモンに接続できます。
- `docker version` で、クライアント(Client)とサーバー(Server)の両方のバージョンが表示されます。

### 2. OCI

**OCI(Open Container Initiative)** は、コンテナのイメージの形式と、ランタイムの仕様を決めている標準です。Docker で作ったイメージは OCI の形式なので、Podman、containerd、Kubernetes など、ほかのツールでも動かせます。

### 3. イメージとコンテナ

| 用語 | 意味 | 例え |
|---|---|---|
| **イメージ** | コンテナを作るための、読み取り専用のテンプレート(ファイルシステムと設定) | クラスや設計図 |
| **コンテナ** | イメージから作った、動いている(または止まっている)実体。書き込みのできる層を持つ | インスタンス |

- 1 つのイメージから、いくつでもコンテナを作れます。
- コンテナの中での変更は、そのコンテナの書き込み層に入り、**イメージは変わりません**。コンテナを削除すると、その変更も消えます(残すにはボリュームを使う。分野 5)。

## 1.3 基本のコマンドと流れ

### 1. 最初の流れ

```bash
docker pull nginx:1.27          # イメージを取得する
docker run -d -p 8080:80 --name web nginx:1.27   # コンテナを作って起動する
docker ps                       # 動いているコンテナの一覧
docker logs web                 # ログを見る
docker stop web                 # 止める
docker rm web                   # 削除する
docker images                   # ローカルのイメージの一覧
docker rmi nginx:1.27           # イメージを削除する
```

`docker run` は、ローカルにイメージがなければ自動で pull してから、コンテナを作って起動します。

### 2. コマンドの体系

Docker のコマンドには、対象ごとにまとめた書き方もあります。

| 短い書き方 | 対象ごとの書き方 |
|---|---|
| `docker ps` | `docker container ls` |
| `docker images` | `docker image ls` |
| `docker rm` | `docker container rm` |
| `docker rmi` | `docker image rm` |

どちらも同じ動きです。

### 3. 状態を確かめる

| コマンド | 表示するもの |
|---|---|
| `docker version` | クライアントとデーモンのバージョン |
| `docker info` | デーモンの設定(ストレージドライバー、コンテナとイメージの数など) |
| `docker ps -a` | 止まっているものも含めた全コンテナ |
| `docker system df` | イメージ、コンテナ、ボリュームが使っているディスクの量 |

### 4. まとめ: よく出る判断

| 問われ方 | 答え |
|---|---|
| コンテナと VM の一番の違い | コンテナはホストのカーネルを共有する |
| 見えるものを分ける機能 / 資源を制限する機能 | namespace / cgroups |
| イメージとコンテナの関係 | イメージは読み取り専用のテンプレート、コンテナはそこから作った実体 |
| コンテナの中で変えたファイルはイメージに残るか | 残らない |
| `docker` コマンドが命令を送る相手 | Docker デーモン(dockerd) |
