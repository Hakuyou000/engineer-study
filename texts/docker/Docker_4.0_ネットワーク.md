# Docker テキスト 4.0 ネットワーク

コンテナがどのようにネットワークにつながり、外から、またコンテナ同士でどう通信するかを学びます。「つながらない」の原因の多くはこの分野にあります。

## 4.1 ネットワークドライバー

| ドライバー | 動き | 用途 |
|---|---|---|
| **bridge**(既定) | ホストの中の仮想スイッチ(`docker0` など)にコンテナをつなぐ。コンテナは専用の IP(例: 172.17.0.x)を持つ | 1 台のホストでの普通の使い方 |
| **host** | ホストのネットワークをそのまま使う。分離しない。`-p` は意味がない | 性能を優先する、多くのポートを使う |
| **none** | ネットワークなし(ループバックだけ) | 通信させない処理 |
| overlay | 複数のホストをまたぐネットワーク | Swarm などのクラスター |
| macvlan | コンテナに物理ネットワークの MAC アドレスと IP を持たせる | 既存の LAN に直接つなぎたいとき |

```bash
docker network ls                     # 一覧(最初から bridge、host、none がある)
docker network create appnet          # ユーザー定義のブリッジネットワークを作る
docker network inspect appnet         # 設定とつながっているコンテナ
docker network connect appnet web     # 動いているコンテナを追加でつなぐ
```

## 4.2 ポートの公開

### 1. -p の書き方

コンテナの IP はホストの中だけのものなので、外からつなぐには**ポートの公開**(ポートフォワード)が必要です。

| 書き方 | 意味 |
|---|---|
| `-p 8080:80` | ホストの**全インターフェース**の 8080 を、コンテナの 80 に転送する |
| `-p 127.0.0.1:8080:80` | ホストの 127.0.0.1(自分自身)からだけ受ける |
| `-p 80` | ホスト側のポートは空いているものを自動で選ぶ |
| `-p 8080:80/udp` | UDP |
| `-P` | `EXPOSE` に書いた全ポートを、ホストの空いているポートに公開する |

`-p 8080:80` で公開したポートに、外からつながるまでの道すじです。

```text
client
  |
  |  http://HOST_IP:8080
  v
[host: port 8080]
  |
  |  -p 8080:80      <- ホストの 8080 を、コンテナの 80 に転送する
  v
[bridge network]     <- ホストの中の仮想スイッチ
  +-- [web  172.17.0.x : 80]
  `-- [db   172.17.0.x : 5432]     <- -p がないので、外からはつながらない
```

- 順番は **ホスト:コンテナ** です。逆に覚えないようにします。
- `EXPOSE` は説明だけで、公開はしません。公開するのは `-p` です。
- 同じホストのポートを 2 つのコンテナで公開することはできません(`port is already allocated`)。
- `docker port 名前` で、今の対応を確認できます。

### 2. 公開とファイアウォールの注意

- `-p 8080:80` は、既定で**すべてのインターフェース(0.0.0.0)**に公開します。管理用の画面やデータベースを誤って外に公開しないように、必要なら `127.0.0.1:` を付けます。
- Linux の Docker は、公開のために iptables(nftables)のルールを自分で追加します。そのため、ufw などで閉じたつもりのポートでも、Docker で公開すると外から届くことがあります。

## 4.3 コンテナ同士の通信と名前解決

### 1. 既定の bridge とユーザー定義のブリッジ

| | 既定の `bridge` | ユーザー定義のブリッジ(`docker network create`) |
|---|---|---|
| コンテナ名での名前解決 | **できない**(IP でしか通信できない) | **できる**(組み込みの DNS) |
| 分離 | ネットワークを指定しない全コンテナが同じ場所に入る | 同じネットワークにつないだコンテナだけ |
| 推奨 | 使わない | アプリごとに作って使う |

```bash
docker network create appnet
docker run -d --name db  --network appnet postgres:17
docker run -d --name web --network appnet -p 8080:80 myweb
# web の中から db という名前で接続できる: postgres://db:5432/...
```

ユーザー定義のブリッジネットワークでの通信です。同じネットワークの中では名前で通信でき、別のネットワークとは通信できません。

```text
network: appnet (user-defined bridge)
  +-- [web]  ---> db:5432        <- コンテナの名前で接続する。DNS 127.0.0.11 が名前を IP に変える
  `-- [db]

network: other
  `-- [batch]  --x--> db         <- 別のネットワークとは通信できない
```

- ユーザー定義のネットワークでは、組み込みの DNS サーバー(コンテナの中から見て `127.0.0.11`)が、コンテナの名前(と `--network-alias` の別名)を IP に変えます。
- Compose は、プロジェクトごとにユーザー定義のネットワークを自動で作るので、サービス名で通信できます(分野 6)。

### 2. よくある誤解

| 誤解 | 正しくは |
|---|---|
| コンテナ同士はホストの公開ポートで通信する | 同じネットワークなら、**コンテナのポート**(例: `db:5432`)に直接つなぐ。`-p` は不要 |
| コンテナの中の `localhost` はホストのこと | **そのコンテナ自身**のこと。別のコンテナには名前でつなぐ |
| 違うネットワークのコンテナとも通信できる | できない。両方を同じネットワークにつなぐ(`docker network connect`) |

### 3. コンテナからホストのサービスにつなぐ

- Docker Desktop では `host.docker.internal` という名前でホストにつなげます。
- Linux では `--add-host=host.docker.internal:host-gateway` を付けると、同じ名前が使えます。

## 4.4 ネットワークの調査

つながらないときは、外側から内側へ順に確かめます。

1. コンテナは動いているか: `docker ps`
2. ポートは公開されているか(外からの場合): `docker ps` の PORTS、`docker port`
3. アプリは**コンテナの中で** 0.0.0.0 で待ち受けているか: アプリが `127.0.0.1` で待ち受けていると、コンテナの外(ほかのコンテナや公開ポート)からは届きません
4. 同じネットワークにいるか: `docker network inspect`
5. 中から確かめる: `docker exec -it web sh` → `curl http://db:5432` や `nslookup db`

| 症状 | よくある原因 |
|---|---|
| ホストからは `curl localhost:8080` がつながるが、ほかの PC からはつながらない | `127.0.0.1:8080:80` で公開している、またはクラウドのセキュリティグループで閉じている |
| `-p 8080:80` なのに `Connection reset` | アプリがコンテナの中で 127.0.0.1 だけで待ち受けている |
| `db` という名前が解決できない | 既定の bridge を使っている、または別のネットワークにいる |
| `port is already allocated` | ホストのそのポートを別のコンテナやプロセスが使っている |

### まとめ: よく出る判断

| 問われ方 | 答え |
|---|---|
| `-p 8080:80` の 8080 は | ホスト側のポート |
| コンテナ名で通信したい | ユーザー定義のブリッジネットワークにつなぐ |
| 同じネットワークのコンテナ同士の通信に `-p` は必要か | 不要。コンテナのポートに直接つなぐ |
| ホストの自分自身からだけ受けたい | `-p 127.0.0.1:8080:80` |
| ネットワークを分離しない | host ドライバー |
