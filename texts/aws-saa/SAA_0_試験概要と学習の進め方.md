# AWS SAA 0 試験概要と学習の進め方

作成: 2026-11-18
対象: AWS Certified Solutions Architect - Associate(**SAA-C03**)

## 1. 試験の概要

| 項目 | 内容 |
|---|---|
| 試験コード | SAA-C03 |
| 問題数 | 65問(採点対象 50問 + 採点されない 15問。どれが採点対象かは分かりません) |
| 試験時間 | 130分 |
| 受験料 | 150 USD(日本では税込の円建て。申込前に公式で確認してください) |
| 形式 | 単一選択(正解1つ・不正解3つ)と複数選択(5つ以上の選択肢から2つ以上を選ぶ) |
| 合格ライン | 1,000点満点中 **720点**(スケールスコア) |
| 採点方式 | 補償型。分野ごとの足切りはなく、全体の点数で合否が決まります |
| 有効期間 | 3年 |
| 想定受験者 | AWS でクラウドの設計を1年以上経験した人 |

- 空欄は不正解として扱われ、誤答による減点はありません。分からない問題も必ずどれかを選びましょう。
- 「SAA-C04 が出た」という記事がありますが、2026-11-18 時点で AWS 公式の試験ガイドは SAA-C03 のみです。受験前に公式ページで最新の版を確認してください。

## 3. この試験で問われること

SAA は「サービスの名前を覚えているか」ではなく、「要件に合うサービスと構成を選べるか」を問う試験です。問題文はほとんどが次の形をしています。

> ある会社が〇〇をしたい。条件は △△ である。**最も運用の手間が少ない**(または **最もコスト効率が良い**)方法はどれか。

問題文の最後にある条件が、正解を決める決め手になります。よく出る条件と、そのとき選ばれやすい方向は次のとおりです。

| 条件の言い方 | 選ばれやすい方向 |
|---|---|
| 運用の手間を最小にする / 管理のオーバーヘッドを減らす | マネージドサービス、サーバーレス(Lambda、Fargate、DynamoDB、Aurora Serverless など) |
| 最もコスト効率が良い | 必要十分な性能の安いサービス、使った分だけの課金、ライフサイクルで安い層に移す |
| 高可用性 / 耐障害性 | 複数の AZ(アベイラビリティーゾーン)に分散する、単一障害点をなくす |
| 災害対策(DR) / リージョン障害に備える | 別リージョンへの複製(クロスリージョンレプリケーション、グローバルテーブルなど) |
| 疎結合にする | SQS、SNS、EventBridge で部品の間にキューやイベントを挟む |
| アプリケーションのコードを変更できない | インフラ側の工夫(ロードバランサー、RDS Proxy、ストレージの切り替えなど) |
| 最小権限 | 必要な操作だけを許可する IAM ポリシー、IAM ロール |

### 用語の基本

| 用語 | 意味 |
|---|---|
| リージョン | 世界各地にある AWS の拠点。東京(ap-northeast-1)など。リージョン同士は独立しています |
| AZ(アベイラビリティーゾーン) | リージョンの中にある、電源やネットワークが独立したデータセンター群。1つのリージョンに通常3つ以上あります |
| エッジロケーション | CloudFront や Route 53 が使う、利用者の近くにある配信拠点。リージョンより数が多いです |
| マネージドサービス | OS の更新やバックアップなどを AWS が代わりに行うサービス |
| サーバーレス | サーバーの用意や台数の管理が不要で、使った分だけ課金されるサービス |
| AWS Management Console / AWS CLI | ブラウザの管理画面 / コマンドラインから AWS を操作する方法。どちらも裏では同じ API を呼んでいます |
| スケールアウト / スケールイン | 台数を増やす / 減らす(水平スケーリング) |
| スケールアップ / スケールダウン | 1台の性能を上げる / 下げる(垂直スケーリング) |
| RPO | 目標復旧時点。障害時に「どの時点までのデータを失ってよいか」 |
| RTO | 目標復旧時間。障害から「どれくらいの時間で復旧するか」 |

## 4. AWS Well-Architected フレームワーク

AWS が示す「良い設計」の考え方です。試験全体の土台になっています。柱は6つあります。

| 柱 | 主な考え方 |
|---|---|
| 運用上の優秀性 | 運用をコード化し、小さく頻繁に変更し、失敗から学ぶ |
| セキュリティ | 最小権限、すべての層での防御、追跡可能性、データの暗号化 |
| 信頼性 | 障害からの自動復旧、水平スケーリング、変更の自動化 |
| パフォーマンス効率 | 目的に合ったサービスを使い、サーバーレスを活用し、実験する |
| コスト最適化 | 使った分だけ払い、需要に合わせて規模を変え、費用を見える化する |
| 持続可能性 | 必要な分だけ使い、効率の良いハードウェア(Graviton など)を選ぶ |

試験の4分野は、このうち「セキュリティ」「信頼性」「パフォーマンス効率」「コスト最適化」に対応しています。AWS Well-Architected Tool を使うと、自分のワークロードをこの観点で点検できます。

## 5. 前提の知識

SAA は、AWS の各サービスを組み合わせて設計する力を問います。次の知識があると、テキストが読みやすくなります。足りないところは、この学習アプリの LinuC と CCNA のテキストから先に読みましょう。

| 分野 | 知っておきたいこと | 参考になるテキスト |
|---|---|---|
| ネットワーク | IP アドレスと CIDR(`10.0.0.0/16` が何個のアドレスか)、サブネット、ルーティング、NAT、DNS、TCP と UDP、ポート番号 | CCNA 1.0、計算ドリルのサブネット |
| Web の仕組み | HTTP と HTTPS、ロードバランサー、TLS の証明書 | CCNA 4.0、LinuC 102 1.07 |
| Linux | SSH でログインする、パッケージを入れる、ログを見る | LinuC 102 1.06〜1.09 |
| セキュリティ | 認証と認可の違い、公開鍵と秘密鍵、暗号化(保存時と転送時) | LinuC 102 1.10 |
| データベース | テーブルと SQL、読み取りと書き込み、バックアップの基本 | なし(テキストの中で説明します) |

AWS を触ったことがなくても始められます。最初の数日は、2026 年時点の無料の仕組み(この章の「演習環境の作り方」)で、VPC と EC2 と S3 を一度作ってみると、テキストの図が実物と結び付きます。

## 6. 学習の進め方

1. 各分野のテキストを、1節ずつ読みます。知らないサービスは、「何を解決するサービスか」を一言で言えるようにします。
2. 節を読んだら、その節の問題を解きます。間違えた問題は解説を読み、「なぜ他の選択肢がだめなのか」まで確認します。
3. よく似たサービスの違いを表で覚えます(例: SQS と SNS、ALB と NLB、Gateway 型と Interface 型の VPC エンドポイント)。
4. 可能なら AWS の無料利用枠で実際に触ります。VPC、EC2、S3、IAM は手を動かすと理解が早まります。
5. 最後に模擬試験(このアプリの「本番形式」)で時間配分を確認します。1問あたり2分が目安です。

## 7. 問題を解くときのコツ

- 問題文の最後の一文(何を最優先するか)に線を引くつもりで読みます。
- 「技術的には動くが、手間やコストが余計にかかる」選択肢は不正解です。
- 要件にない機能を足している選択肢は、たいてい不正解です。
- 「〜を2つ選べ」の問題は、それぞれの選択肢が独立して正しいかを判断します。

## 8. 演習環境の作り方

SAA は設計の試験ですが、VPC、EC2、S3、IAM は一度は自分で作ると理解が早まります。AWS は使った分だけ料金がかかるので、**作る前に費用の守りを固める**ことが大切です。

### 1. アカウントの作り方と無料のプラン

2025-07-15 より後に作るアカウントは、次の仕組みです(それより前のアカウントは、以前の「12 か月の無料利用枠」のまま)。

| 項目 | 内容 |
|---|---|
| プラン | 作るときに「無料プラン」か「有料プラン」を選ぶ |
| クレジット | 最初に 100 ドル。決められた操作をすると、さらに最大 100 ドル(合計 200 ドル) |
| 無料プランの期限 | 作ってから 6 か月か、クレジットを使い切ったときの早いほう。期限が来ると**アカウントは閉じられ、中のリソースとデータも使えなくなる** |
| 無料プランの制限 | 費用の大きい一部のサービスは使えない |

学習だけなら無料プランが安全です。続けて使いたくなったら、有料プランに切り替えます。

> **【要確認】** 無料の仕組みは変わることがあります。AWS の Free Tier のページで確認してください。

### 2. 最初の 30 分でやること

1. **ルートユーザーに MFA を付ける**。ルートユーザーは、この後は普段使いません。
2. **作業用のユーザーを作る**(IAM Identity Center のユーザー、または IAM ユーザー)。MFA を付け、普段はこのユーザーで操作します。
3. **予算のアラートを作る**。Billing の Budgets で「ゼロ支出予算」か、月 5 ドルなどの予算を作り、メールで知らせるようにします。
4. **使うリージョンを 1 つに決める**(東京 ap-northeast-1 など)。リソースが別のリージョンに散らばると、消し忘れの原因になります。

### 3. 費用がかかりやすいもの

| リソース | かかり方(東京リージョン、2026 年の目安) | 注意 |
|---|---|---|
| NAT ゲートウェイ | 1 時間 0.062 ドル + 通った量。置いておくだけで月 45 ドル前後 | 練習が終わったらすぐに消す |
| パブリック IPv4 アドレス | 1 個 1 時間 0.005 ドル(月 3.6 ドル前後)。EC2、ALB、NAT、使っていない Elastic IP も | 使わない Elastic IP は解放する |
| ALB / NLB | 時間の料金 + 使った量 | 消し忘れが多い |
| RDS / Aurora | インスタンスの時間の料金 + ストレージ | 停止しても 7 日で自動で起動する。消すときは最後のスナップショットを取るかを選ぶ |
| EBS のボリュームとスナップショット | 保存した量 | EC2 を消してもボリュームやスナップショットが残ることがある |

### 4. 後片付けの確認

練習が終わったら、次を確かめます。

1. EC2 のインスタンス、ロードバランサー、NAT ゲートウェイ、RDS が残っていないか
2. Elastic IP、EBS のボリューム、スナップショットが残っていないか
3. 翌日、Billing のページで、思わぬ料金が増えていないか

手で作ると消し忘れやすいので、慣れたら Terraform で作り、`terraform destroy` で消すと確実です(Terraform のテキストを参照)。
