# K8s 0 試験概要と学習の進め方

作成: 2026-11-19
対象: CKA(Certified Kubernetes Administrator)の試験範囲 + 実務の Kubernetes

このテキストは、CKA の試験範囲を網羅し、そのうえで SRE やインフラの実務で必要になる Kubernetes の知識まで扱います。どこが試験の範囲で、どこが実務の知識かを、見出しと問題のタグで見分けられるようにしています。

## 1. タグの見方

| タグ | 意味 |
|---|---|
| **〔CKA〕** / `[CKA]` | CKA の公式の試験範囲(Curriculum)に入っている内容 |
| **〔実務〕** / `[実務]` | 試験の範囲の外だが、本番の運用でよく使う内容 |

- テキストでは、見出しの最後に〔CKA〕〔実務〕を付けています。
- 問題では、問題 ID の横に `CKA` / `実務` のタグが表示されます。
- 試験の直前は〔CKA〕だけ、実務に入る前は〔実務〕も、のように使い分けます。

## 2. CKA の試験の概要

| 項目 | 内容 |
|---|---|
| 実施 | CNCF / The Linux Foundation |
| 形式 | **実技**。ブラウザの中のターミナルで、実際のクラスタを操作して課題を解く。オンラインで監督付きの受験 |
| 問題の数 | 15〜20 問ほどの作業 |
| 試験時間 | 2 時間 |
| 合格ライン | 66% |
| 受験料 | US$445 前後。再受験 1 回と、模擬試験の環境(killer.sh)2 回分が付く |
| 参照できる資料 | Kubernetes の公式ドキュメント(kubernetes.io/docs など)、Helm のドキュメント、Gateway API のドキュメント |
| 対象のバージョン | 最新のマイナーバージョンに合わせて、リリースの 4〜8 週間後に更新される(2026-11 時点は v1.37) |
| 有効期間 | 2 年 |

> **【要確認】** 受験料、対象のバージョン、参照できるサイトは変わります。申し込む前に Linux Foundation の公式のページで確認してください。

## 3. 出題の分野と配点

| 分野 | 配点 | テキスト |
|---|---|---|
| 1 クラスタのアーキテクチャ、インストール、設定 | 25% | `K8s_1.0_…` |
| 2 ワークロードとスケジューリング | 15% | `K8s_2.0_…` |
| 3 サービスとネットワーク | 20% | `K8s_3.0_…` |
| 4 ストレージ | 10% | `K8s_4.0_…` |
| 5 トラブルシューティング | **30%** | `K8s_5.0_…` |
| 6 実務の運用(試験の範囲外) | - | `K8s_6.0_…` |

2025 年 2 月の改訂で、次の項目が加わりました。古い教材には載っていないことがあります。

- Helm と Kustomize でクラスタの部品を入れる
- 拡張のインターフェース(CNI、CSI、CRI)の理解
- CRD とオペレーター
- Gateway API で外からの通信を管理する
- ワークロードのオートスケーリング

## 4. 試験は実技なので

このアプリの問題は選択式ですが、CKA は実技の試験です。問題では、試験で打つコマンドや YAML、出力の読み方を問い、手で打つときに迷わないようにしています。

| 試験で大切なこと | 対策 |
|---|---|
| 速さ | YAML を一から書かず、`kubectl create … --dry-run=client -o yaml` で下書きを作る |
| 正しいクラスタで作業する | 問題ごとに `kubectl config use-context …` が指定される。必ず実行する |
| ドキュメントを引く | 公式ドキュメントのどこに何があるか(Tasks の各ページ)を覚えておく |
| 確認 | 作ったら `kubectl get`、`describe` で動いているか確かめる |

## 5. 前提の知識

Kubernetes は、Linux、コンテナ、ネットワークの上に乗った仕組みです。次の知識がないと、エラーの原因を追えません。足りないところは、この学習アプリのテキストから先に読みましょう。

| 分野 | 知っておきたいこと | 参考になるテキスト |
|---|---|---|
| Linux | systemd(`systemctl`、`journalctl`)、ファイルのパーミッション、プロセス、`vi` での編集 | LinuC 102 1.08〜1.09 |
| コンテナ | イメージとコンテナの違い、タグ、ポートの公開、ボリューム、`docker logs` | Docker 1.0〜5.0 |
| ネットワーク | IP アドレスと CIDR、ポート番号、DNS、ロードバランサー、TLS の証明書 | CCNA 1.0、LinuC 102 1.07 |
| YAML | インデントで入れ子を表す、`key: value` の対応、`- ` で始まる配列 | 下の例 |

YAML は、Kubernetes のマニフェストの書き方です。インデントは**スペース**で揃え、タブは使えません。

```yaml
apiVersion: v1          # key: value
kind: Pod
metadata:
  name: web             # metadata の中の name(2 つのスペースで入れ子)
  labels:
    app: web
spec:
  containers:           # containers は配列
    - name: web         # "- " で配列の要素が始まる
      image: nginx:1.27
      ports:
        - containerPort: 80
```

試験の端末は Linux で、エディターは `vi`(`vim`)です。挿入(`i`)、保存して終了(`Esc` の後に `:wq`)、行の削除(`dd`)、検索(`/文字`)は手が覚えるまで練習しておきます。

## 6. 学習の進め方

1. **クラスタを用意する**: kind や minikube で手元に作る。CKA は kubeadm のクラスタなので、仮想マシン 2〜3 台で kubeadm のクラスタも一度は作る。
2. **分野 1〜4 を読んで手を動かす**: Pod → Deployment → Service → PVC の順に、作る・壊す・直すを繰り返す。
3. **分野 5(トラブルシューティング)を重点的に**: 配点が最も大きい。わざとノードの kubelet を止める、イメージ名を間違える、などで障害を起こして直す。
4. **問題を解く**: 〔CKA〕のタグの問題をすべて解けるようにする。
5. **模擬試験**: 受験料に付く killer.sh で、時間を計って解く。
6. **分野 6(実務)**: 合格の後、または実務に入る前に読む。

## 7. 演習環境の作り方

分野によって、向いている環境が違います。2 つを使い分けます。

| 環境 | 向いている分野 | 用意の手間 |
|---|---|---|
| kind(Docker の中にクラスタを作る) | 2 ワークロード、3 ネットワーク、4 ストレージ、5 のアプリの障害 | 数分 |
| 仮想マシン 2〜3 台 + kubeadm | 1 の kubeadm の構築とアップグレード、etcd のバックアップ、5 のノードと部品の障害 | 1〜2 時間 |

ほかに、ブラウザだけで使える Killercoda の CKA のシナリオ(無料)と、受験料に付く killer.sh(本番に近い模擬試験)があります。


2 つの環境は、ノードの正体が違います。kind ではノードが Docker のコンテナ、kubeadm の練習ではノードが仮想マシンです。

```text
kind
[PC]
  +-- Docker
        +-- [node: control-plane]   コンテナ
        +-- [node: worker]          コンテナ
        +-- [node: worker]          コンテナ

kubeadm(Multipass)
[PC]
  +-- Multipass
        +-- [VM cp1]   コントロールプレーン
        +-- [VM w1]    ワーカー
```
### 1. kind で手早く作る

先に Docker を入れておきます(Docker のテキストの「演習環境の作り方」)。

| OS | kind と kubectl の入れ方 |
|---|---|
| Windows | `winget install Kubernetes.kind` と `winget install Kubernetes.kubectl` |
| Mac | `brew install kind kubectl` |

ノードを 3 台(コントロールプレーン 1、ワーカー 2)にすると、スケジューリングや taint を試せます。

```yaml
# kind.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
```

```bash
kind create cluster --name cka --config kind.yaml
kubectl get nodes          # 3 台が Ready になれば準備完了
kind delete cluster --name cka   # 片付け
```

kind の既定の CNI は NetworkPolicy に対応していません。NetworkPolicy を試すときは、`networking.disableDefaultCNI: true` にして、Calico などを入れます。Kubernetes の版は、kind のリリースノートにある `kindest/node` のイメージで選べます(`kind create cluster --image kindest/node:<版>`)。

### 2. 仮想マシンで kubeadm のクラスタを作る

CKA は kubeadm で作ったクラスタで出題されます。一度は自分で作ると、静的 Pod、証明書、kubelet の場所が分かります。ここでは Multipass(`winget install Canonical.Multipass`、Mac は `brew install multipass`)で Ubuntu 24.04 を 2 台作ります。

```bash
multipass launch 24.04 --name cp1 --cpus 2 --memory 4G --disk 20G
multipass launch 24.04 --name w1  --cpus 2 --memory 2G --disk 20G
multipass shell cp1
```

**両方のノードで**、次を実行します(`v1.37` は使いたい版に合わせる)。

```bash
# カーネルのモジュールと、ネットワークの設定
cat <<'EOF' | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
sudo modprobe overlay && sudo modprobe br_netfilter
cat <<'EOF' | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sudo sysctl --system
sudo swapoff -a                       # swap が有効なら止める(/etc/fstab の swap の行も消す)

# コンテナランタイム(containerd)。cgroup ドライバーを systemd に合わせる
sudo apt-get update && sudo apt-get install -y containerd
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml >/dev/null
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo systemctl restart containerd

# kubeadm、kubelet、kubectl(Kubernetes の公式のパッケージのリポジトリ)
sudo apt-get install -y apt-transport-https ca-certificates curl gpg
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.37/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.37/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list
sudo apt-get update && sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl   # 勝手に上がらないようにする
```

**cp1 だけで**、クラスタを作ります。

```bash
sudo kubeadm init --pod-network-cidr=192.168.0.0/16
mkdir -p ~/.kube && sudo cp /etc/kubernetes/admin.conf ~/.kube/config && sudo chown $(id -u):$(id -g) ~/.kube/config
kubectl get nodes        # NotReady(CNI がまだない)
```

続けて CNI を入れます。Calico の公式ドキュメントの「Quickstart for Calico on Kubernetes」にある、`kubectl create -f` のマニフェストの URL を使います(CNI の版は頻繁に上がるので、ここには固定の URL を書きません)。入れると、ノードが Ready になります。

**w1 で**、`kubeadm init` の最後に表示された `kubeadm join …` を `sudo` を付けて実行します。表示を失くしたら、cp1 で `kubeadm token create --print-join-command` を実行します。

### 3. 作ったクラスタで練習すること

- etcd のスナップショットを取り、復元する(1.4)
- `kubeadm upgrade` でマイナーバージョンを 1 つ上げる(1.4)
- `/etc/kubernetes/manifests/` の YAML をわざと壊し、`crictl` で調べて直す(5.2)
- `sudo systemctl stop kubelet` でノードを NotReady にし、直す(5.1)

壊す前に `multipass snapshot cp1`(仮想マシンを止めてから)でスナップショットを取ると、すぐに戻せます。終わったら `multipass delete --purge cp1 w1` で消します。
