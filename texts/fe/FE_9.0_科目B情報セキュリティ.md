# FE テキスト 9.0 科目B情報セキュリティ

科目 B の情報セキュリティの問題で必要になる、管理策の考え方と、日々の運用の進め方を学びます。科目 B では、架空の会社の状況と規程が問題文に書かれ、「最も適切な対策」「規程に違反している行為」「原因として考えられるもの」を選びます。

## 科目 B の情報セキュリティの解き方

1. 守る対象(**情報資産**)と、守りたいこと(機密性、完全性、可用性のどれか)をつかみます。
2. 規程や条件を、問題文から拾います。規程に書いてあることが、正解を決める根拠です。
3. 選択肢の対策が、どの脅威に効くのかを考えます。目的の違う対策(例: バックアップで、盗み見を防ぐ)は誤りです。
4. 「過剰」「不足」「関係がない」選択肢を外します。

### 情報セキュリティの三つの特性

| 特性 | 意味 | 損なわれた例 | 主な対策 |
|---|---|---|---|
| **機密性** | 許された人だけが情報を使える | 顧客の個人情報が漏れる | アクセス制御、暗号化、認証 |
| **完全性** | 情報が正確で、改ざんされていない | 見積書の金額が書き換えられる | 電子署名、ハッシュ値、変更の記録 |
| **可用性** | 必要なときに使える | 障害でシステムが止まる | 冗長化、バックアップ、UPS |

### 管理策の 4 つの分類

情報セキュリティ管理策は、国際規格(ISO/IEC 27001:2022、ISO/IEC 27002:2022)で次の 4 つに分けられます。この 4 つの分け方は 2022 年版からで、それより前の版とは分け方が違います。

| 分類 | 内容 | 例 |
|---|---|---|
| 組織的管理策 | 規程、役割、手順、供給者との関係 | 情報セキュリティポリシー、事故の報告手順、アクセス制御の方針、アクセス権の決め方、供給者の管理 |
| 人的管理策 | 人に関する決まりと教育 | 研修、秘密保持の契約、リモートワークの決まり |
| **物理的管理策** | 建物、部屋、機器を守る | 入退管理、施錠、監視カメラ、装置の処分 |
| **技術的管理策** | システムの機能で守る | 情報へのアクセス制限、認証の仕組み、暗号化、ログ、マルウェア対策 |

どれか 1 つで守りきるのではなく、複数を重ねる**多層防御**を使います。

## 9.1 情報セキュリティ要求事項の提示

### 1. 情報セキュリティ要求事項とは

担当するシステムや業務で、何を、どの程度まで守る必要があるかを、具体的に書いたものです。上長や情報システム部の支援を受けて、システムの開発や利用の前に提示します。

良い要求事項の条件は次のとおりです。

- 守る対象(情報資産)が分かる。例: 顧客の個人情報
- 守りたいこと(機密性、完全性、可用性)が分かる。
- 満たしたかどうかを確かめられる。例: 「役割に応じてアクセスを制限する」「操作のログを 1 年保管する」

「とにかく安全にする」は、確かめられないので、要求事項になりません。

**例**: 顧客管理システムの要求事項

- 利用者ごとの ID で認証し、多要素認証を使う。
- 営業は自分の担当の顧客だけ、管理者は全件を見られるように、役割でアクセスを制限する。
- 保存するデータと通信を暗号化する。
- 操作のログを記録して、一定期間保管する。

### 2. 利用者アクセスの管理

情報システムを使う人に、必要な権限だけを与えます。

| 考え方 | 内容 |
|---|---|
| **最小権限** | 業務に必要な、最小限の権限だけを与える |
| **need-to-know の原則** | 知る必要のある人にだけ、情報を知らせる |
| 職務の分離 | 申請する人と承認する人を分けるなど、1 人で不正が完結しないようにする |
| ID の個人ごとの発行 | 共有 ID を使わず、誰が操作したか分かるようにする |
| 特権 ID の管理 | 管理者の権限を持つ ID を、使う人と時間を限って使わせ、操作を記録する |

#### 認証の 3 要素

| 要素 | 例 |
|---|---|
| 知識 | パスワード、PIN、秘密の質問の答え |
| 所持 | IC カード、スマートフォン、ワンタイムパスワードのトークン |
| 生体 | 指紋、顔、虹彩、静脈 |

- **多要素認証**は、**種類の違う**要素を 2 つ以上組み合わせます。パスワードと秘密の質問は、どちらも知識なので、多要素になりません。指紋と顔も、どちらも生体です。
- 「何も信用せず、毎回確かめる」ゼロトラストの考え方でも、多要素認証が基本です。

### 3. データの暗号化

データを、鍵がないと読めない形に変えて、機密性を守ります。

| 種類 | 守る場面 | 例 |
|---|---|---|
| 保存時の暗号化 | 保存しているデータ | ノート PC のストレージ全体の暗号化、データベースの暗号化 |
| 通信時の暗号化 | 通信している途中のデータ | TLS(HTTPS)、VPN、メールの S/MIME |

- **共通鍵暗号**は、暗号化と復号に同じ鍵を使います。速い一方で、鍵を安全に相手に渡す必要があります。
- **公開鍵暗号**は、公開鍵で暗号化し、対になる秘密鍵で復号します。鍵の渡し方の問題が小さくなります。
- **鍵管理**: 暗号は、鍵が守られていて初めて意味があります。鍵は、データとは別の場所に置き、使う人を限ります。
- ノート PC を持ち出すときは、紛失に備えて、ストレージ全体を暗号化します。OS のパスワードだけでは、ストレージを取り外されると読まれます。

### 4. 物理的な管理策: 入退管理

建物や部屋に、許された人だけが入れるようにします。

| 用語 | 内容 |
|---|---|
| **物理的セキュリティ境界** | 守る領域を壁や扉で区切った線 |
| **セキュリティゾーニング** | 受付、執務室、サーバー室のように、区域ごとに入れる人を分ける |
| **入退管理システム** | IC カードや生体認証で、入退室の記録を残す |
| **アンチパスバック** | 入室の記録がないカードでは退室できず、退室の記録がないカードでは再入室できない。共連れや、入室した人が中からカードを渡して別の人を入れる行為を見つけやすくする |
| 共連れ | 認証した人に続いて、認証しないで入ること |
| クリアデスク・クリアスクリーン | 離席するときに、机の上に書類や媒体を置かず、画面もロックする |

**例**: サーバー室の規程

- 入室できるのは登録された社員だけにする。
- 登録されていない人は、登録された社員が同行し、記録する。
- 登録された社員は、自分に発行された IC カードで入室する。

規程の違反は、「カードを貸す」「同行しない」「記録しない」のように、規程の 1 行と照らして見つけます。

### 5. 物理的な管理策: 機器の持込み・持出し

| 対象 | 管理策 |
|---|---|
| 記憶媒体(USB メモリなど) | 貸出し制、暗号化機能付きのものだけを許す、持出し簿、上長の承認、私物の接続の禁止 |
| ノート PC、モバイル機器 | ストレージの暗号化、**MDM**(Mobile Device Management。遠隔のロックとデータの消去) |
| 装置の処分 | データを復元できないように、専用のツールで消去するか、物理的に破壊する。証明書を受け取る |

- ファイルの削除や OS の再インストールでは、データの本体が残ることがあります。廃棄や再利用の前には、**確実な消去**が必要です。
- HDD は上書きで消去できます。SSD は上書きしても消えない領域があるので、SSD の消去機能(セキュアイレースなど)か、物理的な破壊を使います。
- 持出しは、「誰が、いつ、何を、何のために」を記録します。事故が起きたとき、追跡できます。

## 9.2 情報セキュリティの維持と運用

### 1. マルウェアからの保護

**マルウェア**は、利用者に害を与える不正なプログラムの総称です。

| 種類 | 特徴 |
|---|---|
| ウイルス | ほかのファイルやプログラムに寄生して、自分を複製する |
| **ワーム** | 単独で動き、ネットワークを通じて自分で広がる |
| **トロイの木馬** | 便利なソフトなどに見せかけて実行させ、裏で悪い動作をする |
| **スパイウェア** | 利用者に気付かれないように、情報を集めて外部に送る |
| **ボット** | 感染した PC を外部の指令で動かす。多数のボットのネットワークが、DDoS 攻撃などに使われる |
| **ランサムウェア** | ファイルを暗号化して使えなくし、元に戻すことと引き換えに金銭を要求する |

#### 対策

- **マルウェア対策ソフト**を入れ、**パターンファイル**(既知のマルウェアの特徴)を常に最新にする。パターンファイルとの照合は、未知のマルウェアには効きにくい。
- **ふるまい検知**は、プログラムの動きを見て、怪しい動作を検知する。未知のマルウェアにも使える。
- **EDR**(Endpoint Detection and Response)は、端末の動きを監視して、不審な動きを検知し、調査と対応を助ける。
- 修正プログラム(パッチ)の適用、メールの添付ファイルや URL への注意、権限の最小化を重ねる。

### 2. 脆弱性管理

**脆弱性**は、ソフトウェアや設定の弱点です。攻撃に使われる前に直します。

流れ: ①機器とソフトの一覧を持つ → ②脆弱性の情報を集める → ③自社への影響を評価する → ④修正プログラムを検証して適用する → ⑤適用したことを確かめる

- 評価には、深刻度の指標の **CVSS** を使います。ただし、自社で使っているか、外部から攻撃されるかも見て、優先度を決めます。
- 業務システムは、検証用の環境で動作を確認してから適用します。適用しないまま放置すると、攻撃を受ける危険が続きます。
- 適用の確認には、**脆弱性診断**(ツールで弱点を探す)や**ペネトレーションテスト**(攻撃者の立場で侵入を試す)も使います。

### 3. バックアップ

重要なデータが消えたときに、元に戻せるようにします。可用性を守る対策です。

#### 3 つの方式

| 方式 | 保存するもの | 取得 | 復元 |
|---|---|---|---|
| **フルバックアップ** | すべてのデータ | 時間も容量も大きい | 1 つで復元できる |
| **差分バックアップ** | 直近のフルバックアップからの変更分すべて | 日がたつほど大きくなる | フル + 最新の差分の 2 つ |
| **増分バックアップ** | 前回のバックアップ(種類を問わない)からの変更分 | 小さくて速い | フル + そのあとの増分のすべて |

**例**: 日曜にフル、月曜から土曜は毎晩バックアップを取り、木曜の昼に故障。水曜の夜の状態に戻す。

- 増分: 日曜のフル + 月・火・水の増分 = 4 つ
- 差分: 日曜のフル + 水曜の差分 = 2 つ

#### 3-2-1 ルール

- データのコピーを **3 つ**持つ(元のデータ + バックアップ 2 つ)。
- **2 種類**の媒体に保存する(例: ディスクとテープ)。
- **1 つ**は遠隔地に置く(建物ごとの災害に備える)。

#### ランサムウェアへの備え

- バックアップをネットワークから切り離して保管する(**オフライン**)。または、一定期間は書き換えも削除もできない設定(**イミュータブル**)にする。
- 同じ管理者アカウントでつなぎっぱなしにしない。
- 定期的に**復元テスト**をして、実際に戻せることを確かめる。取れているのに戻せないバックアップは、意味がありません。

#### 目標の考え方

- **RPO**(目標復旧時点): どの時点のデータまで戻せればよいか。バックアップの間隔を決める。例: RPO が 4 時間なら、4 時間以内の間隔で取る。
- **RTO**(目標復旧時間): 障害から、どれだけの時間で復旧するか。

### 4. ログの取得と監視

**ログ**は、システムの動作や操作の記録です。

#### 取得する目的

- 事故や不正の**原因の究明**
- 不正の**抑止**(記録が残ると知っていると、不正をしにくくなる)
- 不審な動きの**監視**と、運用状況の確認

#### 主なログ

| ログ | 内容 |
|---|---|
| 認証ログ | ログインの成功と失敗、日時、接続元 |
| アクセスログ | Web サーバーなどへの接続の記録 |
| 操作ログ(監査ログ) | 誰が、いつ、何を操作したか(ファイルの削除、設定の変更など) |
| 通信ログ | ファイアウォールなどの、通信の許可と拒否の記録 |

#### ログを活かす条件

- **時刻の同期**: 複数の機器のログを突き合わせるため、**NTP** で同じ時刻源に合わせる。
- **改ざんの防止**: ログを別のサーバーに集めて、管理者でも書き換えも削除もできないようにする。
- **保管期間**: 規程で決めた期間、保管する。
- **監視**: **SIEM** は、複数の機器のログを集めて、相関を分析し、不審な動きを見つけて知らせる。

### 5. 情報の転送における情報セキュリティの維持

情報が社外や社内の別の場所へ移るときに、守ります。

| 場面 | 対策 |
|---|---|
| 通信の途中の盗み見 | TLS、VPN などで通信を暗号化する |
| メールの内容 | S/MIME などでメール自体を暗号化し、署名を付ける |
| ファイルを送る | ファイルを暗号化し、**パスワードは別の経路**で伝える |
| 誤送信 | 送信前に宛先を第三者が確認する。宛先の候補の表示に注意する |
| 受け渡しの記録 | 何を、誰に、いつ送ったかを残す |

暗号化したファイルとパスワードを同じメールで送ると、メールを盗み見た人に、両方を読まれます。

### 6. 利用者アクセスの管理と、運用状況の点検

- **入社、異動、退職**の手続きに、アカウントの作成、権限の変更、無効化を含める。
- 定期的に**アカウントの棚卸し**をして、不要なアカウント、過大な権限、使われていない特権 ID を見つける。
- 運用状況の点検は、規程どおりに運用されているかを、記録と現場で確かめる活動です。点検の結果は、**内部監査**などで確認され、規程や手順の改善につながります。

**例**: 在籍者の一覧とアカウントの一覧を突き合わせたら、退職者のアカウントが残っていた。

- 原因: 退職の手続きにアカウントの無効化がない。
- 対策: 手続きに入れる。突合せを続ける。

### 7. 情報セキュリティ事故が起きたときの流れ

| 段階 | 内容 | 例 |
|---|---|---|
| ①発見と報告 | 気付いたら直ちに、規程で決めた窓口(**CSIRT** や情報システム部)に報告する | 感染のおそれがある PC を見つけたら、すぐ連絡する |
| ②封じ込め | 被害を広げないために、影響を受けた機器をネットワークから切り離す | LAN ケーブルを抜く、無線 LAN を切る |
| ③調査 | 原因と範囲を調べる。証拠を保全する | ログ、感染した PC の状態を残す |
| ④駆除と復旧 | 原因を取り除き、バックアップから戻す | マルウェアの駆除、復元 |
| ⑤再発の防止 | 原因を直して、規程や手順を見直す | パッチの適用、手続きの追加 |

- ①と②の順番や、誰が切り離すかは、規程で決めておき、それに従います。報告と切り離しは、どちらも遅らせないようにします。
- 自分だけで解決して、報告しないのは避けます。ほかの機器への感染や、法令に基づく報告が遅れます。
- 勝手に再起動や電源断をすると、調査に必要な情報が消えることがあります。窓口の指示に従います。
- 感染した PC から、ほかの人にメールで知らせるのは避けます。感染を広げるおそれがあります。
