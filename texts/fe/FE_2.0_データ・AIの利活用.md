# FE テキスト 2.0 データ・AI の利活用

データを組織の資産として管理する考え方、データを集めて分析する方法と計算、AI を業務で活用する考え方を学びます。

## 2.1 データマネジメント

### 1. データマネジメントの目的と考え方

**データドリブン経営**は、経験や勘だけでなく、集めて分析したデータを根拠に、経営の判断をすることです。データの質が低いと判断を誤るので、データを組織の**資産**として管理します。これが**データマネジメント**です。

| 用語 | 意味 |
|---|---|
| データマネジメント | データの品質、整合性、安全性を保ちながら、データを管理して活用できる状態にする活動全体 |
| データガバナンス | データの扱いの方針やルールを決め、守られているかを監視する仕組み |
| データライフサイクル | データの生成から廃棄までの流れ |
| DIKW モデル | データ(Data)、情報(Information)、知識(Knowledge)、知恵(Wisdom)の 4 段階 |
| データスペース | 組織の枠を越えて、提供側が利用条件を管理したまま、信頼できる形でデータを共有・流通させる仕組み |

**DIKW モデル**の例:

| 段階 | 例 |
|---|---|
| データ | 日別の売上の数値 |
| 情報 | 曜日ごとに集計して、金曜日が高いと読み取れる状態 |
| 知識 | 金曜日は客が増えるので、仕入れを増やすと売り切れを防げる、という一般化した理解 |
| 知恵 | 天候やイベントなどの状況も踏まえて、今回の仕入れ量を最善に判断すること |

### 2. データマネジメントの機能

データマネジメントは、いくつかの機能で成り立ちます。国に例えると、次の関係です。

| 機能の例 | 例え | 内容 |
|---|---|---|
| データガバナンス | 司法・立法 | 方針とルールを決め、守られているかを監視する |
| マネジメント(データ品質管理など) | 行政 | 決められた方針に沿って、実際に運用する |
| データアーキテクチャ | 都市の設計 | データの構造や流れの全体を設計する |

- **データ品質管理**: データの品質を、正確性(実際と合っている)、完全性(欠けがない)、一貫性(矛盾がない)、適時性(必要な時点で最新)、一意性(重複がない)などの観点で確認して、直します。
- **メタデータ管理**: メタデータは「データについてのデータ」で、データの意味、型、更新日時、出どころ、責任者などの説明です。データカタログに集めて、利用者が目的のデータを探して理解できるようにします。

### 3. データライフサイクル

| 段階 | 内容 | 注意すること |
|---|---|---|
| 生成 | データを作る、取り込む | 正確に入力する、収集の同意を取る |
| 保管 | データを蓄える | アクセス制御、暗号化、バックアップ |
| 処理 | 加工、変換、集計する | 変換の誤りを防ぐ、品質を確認する |
| 活用 | 分析や業務で使う | 利用目的に沿って使う |
| 廃棄 | 不要になったデータを削除する | 保存期間を守る、復元できないように消す |

### 4. データガバナンス

データガバナンスの**基本行動**は、次の 3 つです。

1. **評価**: 現状のデータの扱いを評価する
2. **方針又は指示**: 方針を定め、実行を指示する
3. **監視**: 実施の状況を監視し、結果を次の評価に生かす

運営体制の役割:

| 役割 | 内容 |
|---|---|
| 最高データ責任者(CDO) | 全社のデータ戦略とデータガバナンスに責任を持つ役員 |
| データマネジメントオフィス(DMO) | データマネジメントの活動を全社で推進し、調整する専任の組織 |
| データガバナンス委員会 | 方針や重要な問題を審議して決める会議体 |
| データオーナー | 特定のデータの責任者。利用の可否や、アクセスの方針を決める |
| データスチュワード | 現場の運用担当。データの定義の整備、品質の点検、問合せ対応 |
| データエンジニア | データを集めて加工するパイプラインや基盤を開発、運用する |
| データアーキテクト | データの構造や流れの全体を設計する |

## 2.2 データ分析・データ利活用

### 1. データ基盤

| 用語 | 内容 |
|---|---|
| データレイク | 生のデータを、元の形のまま大量に蓄積する。使うときに加工する |
| データウェアハウス(DWH) | 分析のために、整理して統合したデータを、時間の流れに沿って蓄積する |
| データマート | DWH などから、部門や用途ごとに必要なデータだけを切り出した小さな集まり |
| ETL | Extract(抽出)、Transform(変換)、Load(読み込み)の順に、変換してから格納先へ入れる |
| ELT | 抽出して、先に格納先へ読み込み、その後に格納先の処理能力で変換する |
| BI ツール | データを集計して、図表で見せ、分析を助けるツール |

データ基盤の部品が、どうつながるかを表した図です。

```text
業務システム、ログ、センサーなど(元のデータ)
  |
  +--> [Data Lake]       生のデータを、元の形のまま大量に蓄積する
  |
  +--> [DWH]             分析のために、整理、統合して、時間の流れに沿って蓄積する
         |
         `--> [Data Mart]   部門や用途ごとに、必要なデータだけを切り出す
```

データレイクは、生のデータをそのまま置く場所です。DWH とデータマートは、使いやすく整えたデータを置く場所です。

BI ツールでの多次元分析では、時間、地域、商品などの軸でデータを見ます。粗い集計から細かい集計へ掘り下げる操作が**ドリルダウン**、その逆が**ドリルアップ**です。

### 2. データの種類と特徴

- **量的データ**: 数値で表せるデータ(売上、気温、年齢)。
- **質的データ**: 言葉や分類で表すデータ(感想、性別、血液型)。
- **1 次データ**: 今回の目的のために自分で直接集めたデータ(今回の目的のために行うアンケート、観察の記録)。
- **2 次データ**: 他の目的のためにすでに集められた既存のデータ(官公庁の統計、業界団体の調査、社内に以前からある販売記録など)。

収集の方法:

| 方法 | 内容 |
|---|---|
| クローリング | Web のリンクをたどって、ページを巡回して集める |
| スクレイピング | Web ページから、必要な情報を抽出する |
| バッチ | 一定の期間ごと、まとめて集める |
| ポーリング | 一定の間隔で、変化がないか問い合わせて集める |

尺度は、情報の性質を 4 つに分けます。

| 尺度 | 内容 | 例 |
|---|---|---|
| 名義尺度 | 区別するだけ | 性別、血液型 |
| 順序尺度 | 順序に意味があるが、間隔は等しいと限らない | 満足度の 5 段階 |
| 間隔尺度 | 差に意味がある。0 は「何もない」ではない | 摂氏の温度、西暦 |
| 比例尺度 | 0 が「何もない」で、比にも意味がある | 身長、売上、重さ |

### 3. データの加工

| 用語 | 内容 |
|---|---|
| 名寄せ | 表記ゆれや重複を整理して、同じ対象のデータを 1 つにまとめる |
| 欠損値 | 空白や入力漏れ。削除するか、平均値などで補う |
| 外れ値・異常値 | 他と大きくかけ離れた値。原因(入力ミスか、実際の現象か)を確かめて扱う |
| 標準化 | 平均 0、標準偏差 1 に変換して、尺度をそろえる |
| 二値化 | しきい値を境に、0 と 1 の 2 つの値にする |
| 離散化 | 連続する値を、いくつかの区間に分ける |
| アノテーション | 機械学習のために、データに正解のラベルなどを付ける |
| 季節調整 | 季節による周期的な変動を取り除いて、傾向を見る |
| 移動平均 | 直近の複数の期間の平均を、ずらしながら求めて、変動をならす |
| アソシエーション分析 | 「A を買う人は B も買う」のような、同時に起きる関係を見つける |
| シミュレーション | モデルを使って、条件を変えたときの結果を試す |
| パターン発見 | データの中の規則性や傾向を見つける |

**偏差値**は、平均を 50、標準偏差を 10 にそろえた値です。偏差値 = 50 + 10 ×(得点 − 平均)÷ 標準偏差。

**3 か月移動平均**の例: 売上が 100、120、110、130 のとき、4 つ目の時点の 3 か月移動平均は、(120 + 110 + 130)÷ 3 = 120。

### 4. 統計的手法

**確率**

- **条件付き確率** P(B | A): A が起きたときに B が起きる確率。
- **全確率の定理**: 原因ごとの確率を重みづけして足す。P(不良) = Σ P(工場) × P(不良 | 工場)。
- **ベイズの定理**: 結果から原因の確率を求める。P(A | B) = P(B | A) × P(A) ÷ P(B)。

例: 工場 A が 60%(不良率 2%)、工場 B が 40%(不良率 5%)のとき、不良品である確率は 0.6 × 0.02 + 0.4 × 0.05 = 0.032。不良品が B のものである確率は、0.02 ÷ 0.032 = 0.625。

**確率分布**

| 分布 | 内容 | 例 |
|---|---|---|
| 二項分布 | 成功か失敗の試行を n 回行ったときの成功回数 | 10 回の抽選の当たりの数 |
| 正規分布 | 平均を中心に左右対称の釣り鐘の形。平均 ± 標準偏差 1 つぶんに約 68% が入る | 身長のばらつき |
| 指数分布 | 次の事象が起きるまでの待ち時間 | 次の電話が来るまでの時間、故障までの時間 |

二項分布の確率は、n 回のうち k 回成功する確率 = (選び方の数)× p の k 乗 ×(1 − p)の(n − k)乗。不良率 0.1 の工程から 3 個取り出して、ちょうど 1 個が不良である確率は、3 × 0.1 × 0.9 × 0.9 = 0.243。

**回帰分析**

予測したい値を**目的変数**、予測に使う値を**説明変数**と呼びます。

| 手法 | 内容 |
|---|---|
| 単回帰分析 | 説明変数が 1 つ。y = ax + b の直線で予測する |
| 重回帰分析 | 説明変数が複数 |
| ロジスティック回帰分析 | 結果が「する・しない」の 2 値のとき、その確率を予測する |

係数は、予測と実際の差の二乗の合計が最小になるように決めます(最小二乗法)。

**推定と仮説検定**

- **推定**: 標本から、母集団の値(平均など)を推し量る。
- **仮説検定**: 主張したいこと(**対立仮説**)と反対の**帰無仮説**を立て、データがそれと矛盾するかを調べる。p 値が**有意水準**(5% など)より小さいとき、帰無仮説を棄却して、対立仮説を採用する。
- **統計的バイアス**: 標本が母集団を偏って代表しているために生じる、結果の偏り。

### 5. データの可視化

| 図表 | 内容 |
|---|---|
| 箱ひげ図 | 最小値、第 1 四分位数、中央値、第 3 四分位数、最大値で、分布を表す。外れ値は点で示すことがある |
| ヒートマップ | 数値の大きさを、色の濃さで表す |
| クロス集計表 | 2 つの項目の組合せごとの件数を表にする。分割表とも呼ぶ |
| デンドログラム | 似たものを階層的にまとめた結果(クラスタ分析)を、木の形で表す |

### 6. 業務分析

- **線形計画法**: 制約(材料、時間など)を満たしたうえで、利益を最大にする(または費用を最小にする)組合せを求める。図に描くと、制約で囲まれた領域の頂点のどれかで最大になる。
- **日程計画**: 作業の順序と日数から、全体の期間を求める。
- **ゲーム理論**: 複数の主体が互いの行動を考えて意思決定するときの、最適な行動を分析する。
- **QC 七つ道具**: パレート図、特性要因図、チェックシート、ヒストグラム、散布図、管理図、層別。管理図は、時間の順に打点して、管理限界線で工程の異常を見つける。
- **新 QC 七つ道具**: 言葉のデータを整理する手法(親和図法、連関図法、系統図法、マトリックス図法、アローダイアグラム法など)。
- **需要予測**: 最小二乗法(回帰直線)、移動平均法、指数平滑法。指数平滑法は、今期の予測 = α × 前期の実績 + (1 − α)× 前期の予測。α = 0.3、前期の実績 200、前期の予測 180 なら、0.3 × 200 + 0.7 × 180 = 186。

**在庫管理**

- **定量発注方式**: 在庫が発注点まで減ったら、決まった量を発注する。発注点 = 調達期間中の使用量 + 安全在庫。1 日 40 個、調達 5 日、安全在庫 60 個なら、40 × 5 + 60 = 260 個。
- **経済的発注量(EOQ)**: 発注費用と保管費用の合計が最小になる 1 回の発注量。√(2DS ÷ H)(D: 年間の需要、S: 1 回の発注費用、H: 1 個あたりの年間の保管費用)。

## 2.3 AI 利活用

### 1. AI 利活用の原則及び指針

| 用語 | 内容 |
|---|---|
| 人間中心の AI 社会原則 | AI を、人間の尊厳を尊重し、人の能力を拡張するために使う社会の基本の考え方 |
| AI-Ready な社会 | AI が使われることを前提に、社会の仕組みを整えた社会 |
| AI 事業者ガイドライン | 総務省と経済産業省が示した、AI の開発者、提供者、利用者向けの指針。法的拘束力はなく、自主的な取組を促す |
| Ethically Aligned Design | IEEE が公表した、AI の倫理を設計に組み込むための指針の文書 |
| AI マネジメントシステム(ISO/IEC 42001) | 組織が AI を責任を持って開発、提供、利用するための、マネジメントシステムの国際規格(2023 年発行) |

### 2. 識別 AI の活用

| 用語 | 内容 |
|---|---|
| 特化型 AI | 画像の判定、翻訳など、特定の課題に絞った AI。現在の実用の AI の多く |
| 汎用 AI | 人間のように、幅広い課題に対応できる AI。研究の途上 |
| チューリングテスト | 人間が、対話の相手が機械か人間かを見分けられなければ、その機械は知的だとみなす考え方 |

機械学習の種類:

| 学習 | 内容 | 例 |
|---|---|---|
| 教師あり学習 | 入力と正解のラベルの組から、新しい入力の答えを予測する | 解約の予測、迷惑メールの判定、売上の予測 |
| 教師なし学習 | ラベルのないデータから、構造やグループを見つける | 似た顧客のグルーピング |
| 強化学習 | 試行錯誤して行動し、得られる報酬が最大になる行動を学ぶ | ゲーム AI、ロボットの制御 |

AI の活用の目的は、認識(画像や音声の理解)、自動化(定型作業の置き換え)、予測、グルーピング、支援(最適な行動の提案)などです。

### 3. 生成 AI の活用

- **マルチモーダル AI**: 文章、画像、音声、動画など、複数の種類のデータを扱える。
- **ランダム性の制御**:
  - **Temperature**: 低いと確率の高い語が選ばれて回答が安定する。高いと多様になる。
  - **Top-k**: 確率の高い上位 k 個の候補から選ぶ。
  - **Top-p**: 確率の高い順に候補を足して、合計が p に達するまでの候補から選ぶ。
- **RAG(検索拡張生成)**: 質問に関係する文書を検索し、その内容をプロンプトに加えて、回答させる。再学習をせずに、最新の社内情報を使える。事実と違う内容(ハルシネーション)も減らしやすい。
- **プロンプトエンジニアリング**: 指示(プロンプト)を工夫して、望む回答を得る。役割、条件、出力の形式、例を書く。

### 4. AI エージェントの活用

**AI エージェント**は、目標を与えると、自分で手順を計画し、ツールを使って実行する AI です。

- **自律性と人間の関与**: 自律性が高いほど便利だが、誤りの影響も大きい。支払いや削除などの重要な操作は、人間が最終承認する。想定外の場合は、人間に引き継ぐ(例外処理)。
- **ガードレール**: AI が危険な出力や行動をしないように設ける制約。安全性への配慮、倫理的配慮、法令順守を守らせる。
