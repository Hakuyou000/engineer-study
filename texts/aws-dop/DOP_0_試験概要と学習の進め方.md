# AWS DOP 0 試験概要と学習の進め方

作成: 2026-11-20
対象: AWS Certified DevOps Engineer - Professional(**DOP-C02**)

## 1. 試験の概要

| 項目 | 内容 |
|---|---|
| 試験コード | DOP-C02 |
| 問題数 | 75問(採点対象 65問 + 採点されない 10問。どれが採点対象かは分かりません) |
| 試験時間 | 180分 |
| 受験料 | 300 USD(為替や税で変わることがあります。申込前に公式で確認してください) |
| 形式 | 単一選択(正解1つ・不正解3つ)と複数選択(5つ以上の選択肢から2つ以上を選ぶ) |
| 合格ライン | 100〜1,000点のスケールスコアで **750点** |
| 採点方式 | 補償型。分野ごとの足切りはなく、全体の点数で合否が決まります |
| 言語 | 英語、日本語、韓国語、簡体字中国語(韓国語版は 2026-12-31 の後に終了すると公式ページにあります) |
| 有効期間 | 3年 |
| 想定受験者 | AWS 環境の構築・運用・管理を2年以上経験した人 |

- 空欄は不正解として扱われ、誤答による減点はありません。分からない問題も必ずどれかを選びましょう。
- 1問あたり 2 分強です。問題文が長いので、SAA より時間に余裕がありません。
- 公式の試験ガイドの対象外とされているもの: 高度なネットワーク(高度なルーティングのアルゴリズム、フェイルオーバーの手法)、開発者向けの深いセキュリティの助言、データベースの設計・クエリ・最適化、フルスタックのアプリケーションコードの開発。

> 受験料や言語は変わることがあります。AWS の認定ページで確認してください。

## 3. この試験で問われること

DOP は「サービスを知っているか」ではなく、「場面を読んで、自動化された最適な構成と手順を選べるか」を問う試験です。問題文は SAA より長く、複数のサービスが出てきます。たいていは次の形です。

> ある会社は〇〇のパイプラインを運用している。△△ の問題が起きている(または □□ を実現したい)。**最も運用の手間が少ない**(または **最も早く復旧できる**、**ダウンタイムなし**)方法はどれか。

よく出る条件と、選ばれやすい方向は次のとおりです。

| 条件の言い方 | 選ばれやすい方向 |
|---|---|
| 運用の手間が最小 | マネージドサービスの組み合わせ(CodePipeline、CodeDeploy、Systems Manager、Control Tower など)。自作のスクリプトや常時稼働のサーバーは避ける |
| ダウンタイムなし / すぐ戻せる | blue/green、カナリア、イミュータブル。ロールバックの自動化(CloudWatch アラーム連動) |
| 手作業をなくす | コード化(CloudFormation、CDK)、自動化(EventBridge、Systems Manager Automation、Lambda) |
| 複数のアカウントとリージョンに展開 | CloudFormation StackSets、Organizations、Control Tower |
| 設定の逸脱を検出して自動で直す | AWS Config ルール + Systems Manager Automation による自動修復 |
| 認証情報をコードに埋め込まない | Secrets Manager、Parameter Store、IAM ロール |
| 既存の仕組みを変えずに | 最小限の変更で目的を満たす選択肢(新しいサービスへの作り直しは避ける) |

### 用語の基本

| 用語 | 意味 |
|---|---|
| SDLC | ソフトウェア開発のライフサイクル(計画、開発、テスト、デプロイ、運用) |
| CI(継続的インテグレーション) | コードを変えるたびに、自動でビルドとテストを行うこと |
| CD(継続的デリバリー / デプロイ) | テストを通ったものを、自動で環境に届けること。本番の前に人の承認を挟むのが「デリバリー」、挟まないのが「デプロイ」 |
| パイプライン | ソース取得、ビルド、テスト、デプロイの流れを自動で実行する仕組み |
| アーティファクト | ビルドの成果物(実行ファイル、zip、コンテナイメージなど) |
| IaC | インフラをコードで定義して作ること |
| イミュータブル | 動いているサーバーを書き換えず、新しいものに丸ごと入れ替える方式 |

## 4. 前提の知識

DOP は、SAA の範囲(VPC、EC2、IAM、S3、ELB、Auto Scaling、RDS など)を理解している前提で、その上に自動化を重ねる試験です。足りないところは、先にこの学習アプリのテキストで補いましょう。

| 分野 | 知っておきたいこと | 参考になるテキスト |
|---|---|---|
| AWS の基本 | VPC、EC2、IAM ロール、S3、ELB、Auto Scaling、RDS、KMS、CloudWatch | AWS SAA 1.0〜4.0 |
| IaC | 宣言的にインフラを書く考え方、状態管理、差分の確認 | Terraform 1.0〜3.0(CloudFormation は DOP 2.0 で学びます) |
| コンテナ | イメージとコンテナの違い、Dockerfile、レジストリ、ECS と EKS の土台 | Docker 1.0〜3.0、7.0、K8s 1.0〜2.0 |
| Linux とシェル | シェルスクリプト、終了コード(0 は成功、それ以外は失敗)、systemd、ログの見方 | LinuC 102 1.06、1.08、1.09 |
| Git | リポジトリ、ブランチ、コミット、プルリクエスト、マージ | このアプリにはありません。Git の公式ドキュメントなどで、ブランチとマージまで |
| CI/CD の基本 | ビルド、テスト、デプロイの流れ、環境(開発、ステージング、本番)の分け方 | DOP 1.0 で学びます |
| YAML と JSON | CloudFormation、buildspec、appspec は YAML か JSON で書きます | Docker 6.0(Compose の YAML)、K8s 2.0 |

AWS の実務経験がなくても進められますが、SAA の知識がないまま読むと、1つの問題に出てくる 3〜4 個のサービスが全部初見になります。SAA の範囲を先に固めることを勧めます。

## 5. 学習の進め方

1. 分野 1 から順に、1節ずつ読みます。サービスごとに「何を自動化するか」「どこで動くか」「何が入力で何が出力か」を言えるようにします。
2. 節を読んだら、その節の問題を解きます。間違えた問題は、解説の「他の選択肢がなぜだめか」まで読みます。
3. 似たサービスの使い分けを表で覚えます(例: CodeDeploy と Elastic Beanstalk と CloudFormation の更新方法、Systems Manager の Run Command と State Manager と Automation、Config と CloudTrail)。
4. 小さく手を動かします(この章の「演習環境の作り方」)。パイプラインとスタックを1回作ると、問題文の場面が実物と結び付きます。
5. 全分野を読んだら、模擬試験で時間配分を確認します。1問 2 分を超えそうな問題は、いったん答えを仮置きして先に進みます。

目安は、SAA を終えた人で 4〜6 週間です。公式の「Exam Prep」(無料の学習計画)も使えます。

## 6. 問題を解くときのコツ

- 問題文の最後の一文(最優先の条件)から読みます。長い場面の説明は、その後で必要なところだけ拾います。
- 「最も運用の手間が少ない」なら、自作より AWS の機能を選びます。
- 「新しい仕組みを作る」選択肢より、「すでにあるサービスの設定で足りる」選択肢が正解になりやすいです。
- 手作業が残る選択肢(コンソールで確認して手で直す、など)は、自動化を問う問題では不正解です。
- 2つ選ぶ問題は、各選択肢が単独で正しいかを見ます。
- 選択肢のうち、サービスの役割が違うもの(ログを集めるサービスで設定の変更を追う、など)は、まず外します。
- 公式の用語の違いに注意します。「ロールバック」は前の状態に戻す、「ロールフォワード」は修正を足して先へ進む、です。

## 7. 演習環境の作り方

SAA の 0 章の「演習環境の作り方」(アカウント、MFA、予算のアラート、リージョンを 1 つに決める)を済ませたことを前提にします。ここでは、CodeBuild、CodePipeline、CloudFormation を小さく試す手順を示します。

### 1. 作るもの

「S3 バケットに置いたコードを CodeBuild でビルドし、CloudFormation でバケットを作る」までを、小さく体験します。

| 順 | 操作 | 学べること |
|---|---|---|
| 1 | CloudFormation で S3 バケット 1 つのスタックを作る | テンプレート、スタック、変更セット |
| 2 | テンプレートを少し変えて、変更セットを見てから実行する | 差分の確認、更新の動き |
| 3 | わざと間違えたテンプレートで更新して、ロールバックを見る | ロールバックの動き |
| 4 | CodeBuild のプロジェクトを作り、`buildspec.yml` で `echo` だけ実行する | buildspec のフェーズ、ログ |
| 5 | CodePipeline で「S3 のソース → CodeBuild」の2段のパイプラインを作る | ステージ、アクション、アーティファクトの受け渡し |
| 6 | 手動承認のアクションを足す | 承認の動き |

### 2. 手順の例(ステップ 1〜2)

次の内容を `bucket.yaml` に保存します。

```yaml
AWSTemplateFormatVersion: "2010-09-09"
Resources:
  Bucket:
    Type: AWS::S3::Bucket
```

```bash
aws cloudformation deploy --template-file bucket.yaml --stack-name dop-lab
aws cloudformation describe-stack-events --stack-name dop-lab
```

テンプレートに `Tags` を足してから、変更セットだけを作って内容を確認します。

```bash
aws cloudformation deploy --template-file bucket.yaml --stack-name dop-lab --no-execute-changeset
```

コンソールの「変更セット」を開き、何が変わるか(変更、置換の有無)を見て、実行します。

### 3. 費用と後片付けの注意

| 対象 | かかり方 | 注意 |
|---|---|---|
| CodeBuild | ビルドの時間(分)に応じて課金。オンデマンドの EC2 では、general1.small か arm1.small で月 100 分の無料枠があります(12 か月で終わりません) | 無料枠を超えないようにします |
| CodePipeline | V1 は有効なパイプライン 1 本につき月 1 USD(月 1 本は無料)。V2 はアクションの実行時間 1 分につき 0.002 USD(月 100 分は無料。手動承認は課金されない) | 使わないパイプラインは消します |
| S3(成果物のバケット) | 保存した量 | パイプラインを消してもバケットは残ります。空にして消します |
| CloudWatch Logs | 保存した量 | ビルドのログが溜まります。ロググループの保持期間を決めるか、消します |
| ビルドが使う IAM ロール | 無料 | パイプラインやプロジェクトを消した後、ロールも消します |

料金は 2026-11 時点の公式の料金ページの値です。変わることがあります。

後片付けは、作ったときと逆の順で行います。

1. CodePipeline のパイプラインを削除する
2. CodeBuild のプロジェクトを削除する
3. CloudFormation のスタックを削除する(`aws cloudformation delete-stack --stack-name dop-lab`)。バケットの中身があると、削除に失敗します。先に空にします
4. 成果物のバケット、CloudWatch のロググループ、IAM ロールを消す
5. 翌日に Billing のページを見て、思わぬ料金がないかを確認する

> CodeCommit は、作らなくても学習できます。CodePipeline のソースには、S3 や、GitHub などの外部のリポジトリ(CodeConnections 経由)も使えます。CodeCommit の今の状態は、DOP 1.0 の 1.1 を見てください。

Terraform が使えるなら、同じ構成を Terraform で作り、`terraform destroy` で消すと確実です。ただし試験で問われるのは CloudFormation です。
