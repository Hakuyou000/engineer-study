# LinuC 202 0 試験概要と学習の進め方

作成: 2026-11-25
対象: LinuC レベル2 202 試験(Version 10.0)

LinuC レベル2は、201 試験と 202 試験の両方に合格し、有効な LinuC レベル1 の認定を持っていると認定されます。202 試験は、ネットワークのサービス(DHCP、LDAP、DNS、Web、プロキシ、メール、ファイル共有)の設定と、サーバーのセキュリティ、システムの構成(高可用、スケール、クラウド)を扱います。サーバーを立てて、サービスとして提供するための試験です。

## 1. 試験の概要

| 項目 | 内容 |
|---|---|
| 試験 | LinuC レベル2 202 試験(Version 10.0) |
| 試験時間 | 90 分 |
| 問題の数 | 60 問前後 |
| 形式 | 選択式(1 つを選ぶ、複数を選ぶ)と、コマンド名などを入力する問題 |
| 受験料 | 16,500 円(税込、1 試験あたり)【要確認】 |
| 会場 | ピアソン VUE のテストセンター、またはオンライン |
| 認定の条件 | 有効な LinuC レベル1 の認定を持ち、201 試験と 202 試験の両方に合格する(順番は問わない) |

> **【要確認】** 受験料と受験の規則は変わることがあります。申し込む前に、LinuC 公式のページで確認してください。

## 2. 出題の分野と重要度

| 主題 | 重要度の合計 |
|---|---|
| 2.07 ネットワーククライアントの管理 | 9 |
| 2.08 ドメインネームサーバー | 7 |
| 2.09 HTTPサーバーとプロキシサーバー | 11 |
| 2.10 電子メールサービス | 5 |
| 2.11 ファイル共有サービス | 7 |
| 2.12 システムのセキュリティ | 12 |
| 2.13 システムアーキテクチャ | 9 |

重要度は、小項目ごとに示された値の合計です。2.12 と 2.09 が大きいので、ここを先に固めます。

## 3. 前提の知識

LinuC レベル1 の範囲と、LinuC 201 の範囲です。特に次のものを使います。

- TCP/IP、ポート番号、DNS の名前解決の流れ(LinuC 102 1.07)
- systemctl でサービスを起動、停止、有効にする操作(LinuC 101 1.01)
- ユーザーとグループ、パーミッション(LinuC 101 1.02、LinuC 102 1.08)
- 公開鍵暗号と SSH の基本(LinuC 102 1.10)
- ネットワークの設定と切り分け(LinuC 201 2.03)

## 4. 学習の進め方

1. **演習環境を作る**(次の章)。202 試験は設定ファイルの書き方を多く問うので、サーバーを実際に立て、設定を書いて動かします。
2. **2.08(DNS)と 2.09(Web)から読む**。ほかのサービスも、名前解決と HTTP の上で動くことが多いからです。
3. **設定ファイルは、検査のコマンドとセットで覚えます。** named-checkconf、apachectl configtest、nginx -t、testparm、sshd -t のように、多くのサービスに書いた設定を確かめるコマンドがあります。
4. **2.13(システムアーキテクチャ)は考え方の問題です。** コマンドより、構成の長所と短所を説明できるようにします。
5. **問題を解く**。入力で解くモードで、ディレクティブの名前を思い出す練習もします。

## 5. 演習環境の作り方

102 試験と同じ仮想マシンを使います。作り方は LinuC 102 0 の「演習環境の作り方」を読んでください。202 試験に関係する注意だけをまとめます。

- **サーバー役とクライアント役の 2 台以上を用意します。** 同じ内部のネットワークにつなぎ、固定の IP アドレスを付けます。DHCP サーバーを試すときは、家のルーターの DHCP と混ざらないよう、仮想マシンだけの内部ネットワークを使います。
- **パッケージの名前が Red Hat 系と Debian 系で違います。** 例えば Apache は `httpd`(AlmaLinux)と `apache2`(Ubuntu)、BIND は `bind`(AlmaLinux)と `bind9`(Ubuntu)です。
- **ファイアウォールと SELinux に注意します。** AlmaLinux では、サービスを動かしてもクライアントからつながらないとき、firewalld でポートが開いていないことがよくあります。試すときは `firewall-cmd` でサービスを許可します。SELinux は止めずに、ログで原因を確かめる習慣を付けます。
- **ドメイン名と IP アドレスは、文書用の値を使います。** ドメイン名は `example.com`、IP アドレスは `192.0.2.0/24` などです。本物のドメインを勝手に使わないでください。
- **メール(2.10)は外に送らない設定で試します。** 仮想マシンの中だけでやり取りし、インターネットのメールサーバーには送らないようにします。
- 練習の前に仮想マシンのスナップショットを取り、壊したら戻します。
