# CCNA テキスト 1.0 ネットワークインフラストラクチャと接続(25%)

対象: 200-301 CCNA v2.0

## 1.1 インターフェースとケーブルの障害診断

出題範囲: コリジョン、エラー、デュプレックス不一致、速度、距離、インターフェース、信号レベル、ピン配列、ケーブル種別(銅線・光ファイバ)。

### 1. イーサネット規格

| 規格 | IEEE | 速度 | 媒体 | 最大距離 |
|---|---|---|---|---|
| 10BASE-T | 802.3 | 10 Mbps | UTP Cat3以上 | 100 m |
| 100BASE-TX | 802.3u | 100 Mbps | UTP Cat5以上 | 100 m |
| 1000BASE-T | 802.3ab | 1 Gbps | UTP Cat5e以上 | 100 m |
| 1000BASE-SX | 802.3z | 1 Gbps | MMF | 220〜550 m |
| 1000BASE-LX | 802.3z | 1 Gbps | SMF(MMFも可) | SMF 5 km |
| 10GBASE-T | 802.3an | 10 Gbps | UTP Cat6a(Cat6は55 m) | 100 m |
| 10GBASE-SR | 802.3ae | 10 Gbps | MMF | OM3 300 m / OM4 400 m |
| 10GBASE-LR | 802.3ae | 10 Gbps | SMF | 10 km |
| 10GBASE-ER | 802.3ae | 10 Gbps | SMF | 40 km |

インターフェース名: `FastEthernet`(100M)、`GigabitEthernet`(1G)、`TenGigabitEthernet`(10G)。

### 2. 銅線(UTP)

| カテゴリ | 対応速度 | 備考 |
|---|---|---|
| Cat5 | 100 Mbps | |
| Cat5e | 1 Gbps | |
| Cat6 | 1 Gbps(10 Gbps は 55 m まで) | |
| Cat6a | 10 Gbps | 100 m |

- コネクタは RJ-45。8芯4対
- 10BASE-T / 100BASE-TX は2対(ピン1,2 と 3,6)を使う。1000BASE-T は4対すべてを使い、双方向同時に送受信する
- 最大長は 100 m。超えると減衰で CRC エラーや断が出る
- 電磁ノイズ(EMI)の強い場所では STP(シールド付き)か光ファイバを使う

**ピン配列とケーブル種別**

| 種別 | 両端の配列 | 用途 |
|---|---|---|
| ストレート | 同じ(T568B-T568B など) | 異種機器間。PC-スイッチ、ルータ-スイッチ |
| クロス | T568A-T568B(1↔3、2↔6) | 同種機器間。スイッチ-スイッチ、PC-PC、ルータ-ルータ、PC-ルータ |
| ロールオーバー | 1↔8、2↔7 … 完全反転 | コンソール接続(RJ-45 - シリアル/USB) |

| 送信ピン | 機器 |
|---|---|
| 1,2 で送信(MDI) | PC、ルータ、サーバ、AP |
| 3,6 で送信(MDI-X) | スイッチ、ハブ |

送信ピンが同じ機器同士はクロス、違う機器同士はストレート。**Auto-MDIX** が有効ならどちらのケーブルでも自動で合わせる。Auto-MDIX は speed と duplex が auto のときに確実に動く。

> **【ひっかけ】** PC とルータは同じ MDI。直結はクロス。「ルータはネットワーク機器だからスイッチと同種」ではない。

### 3. 光ファイバ

| | マルチモード(MMF) | シングルモード(SMF) |
|---|---|---|
| コア径 | 50 / 62.5 µm | 9 µm |
| 光源 | LED、VCSEL | レーザー |
| 距離 | 短い(〜550 m 程度) | 長い(10 km 以上) |
| 費用 | 安い | 高い |
| 規格の例 | SX、SR | LX、LR、ER |

- モード分散のため MMF は長距離に向かない
- コネクタは LC(小型、SFP で一般的)、SC。送信(TX)と受信(RX)で2芯使う
- トランシーバ: SFP(1G)、SFP+(10G)、SFP28(25G)、QSFP+(40G)、QSFP28(100G)
- EMI の影響を受けない。盗聴されにくい

**光ファイバの障害**

| 原因 | 症状 |
|---|---|
| TX/RX の芯が逆 | リンクが上がらない |
| MMF 用と SMF 用のトランシーバ・ケーブルの不一致 | リンクが上がらない、エラー多発 |
| 両端のトランシーバの規格・波長不一致(SR と LR) | リンクが上がらない |
| 距離超過、曲げすぎ、端面の汚れ | 受信光レベル低下、CRC エラー |
| 短距離で長距離用(ER など)を使用 | 受信光レベル過大。アッテネータが必要 |

信号レベルは dBm で表す。`show interfaces transceiver` で Tx Power / Rx Power と、しきい値(high/low alarm、warning)を確認する(DOM 対応トランシーバ)。

```
Switch# show interfaces te1/0/1 transceiver
                 Optical   Optical
       Temp      Tx Power  Rx Power
Port   (Celsius) (dBm)     (dBm)
Te1/0/1  31.2     -2.3     -18.9
```

Rx Power が low alarm しきい値を下回っていれば、ケーブル・コネクタ・距離を疑う。

### 4. 速度とデュプレックス

| | 半二重(half) | 全二重(full) |
|---|---|---|
| 送受信 | 同時にできない | 同時にできる |
| CSMA/CD | 使う | 使わない |
| コリジョン | 起きる | 起きない |
| 相手 | ハブ | スイッチ、ルータ、PC |

**オートネゴシエーション**(IEEE 802.3u): 両端が対応する最高の速度とデュプレックスを選ぶ。

片側だけオートネゴシエーションを無効(固定設定)にした場合:

- 速度: auto 側は信号から検出できる
- デュプレックス: 検出できない。auto 側は 10/100 Mbps なら **half**、1000 Mbps なら full を選ぶ

結果、片側 full 固定・反対側 auto(half になる)で**デュプレックス不一致**が起きる。リンクは up のまま、通信が極端に遅くなる。

| 側 | 増えるカウンタ |
|---|---|
| half 側 | collisions、**late collisions** |
| full 側 | **CRC**、runts、input errors(FCS エラー) |

```
interface GigabitEthernet0/1
 speed 100
 duplex full
```

> **【原則】** 両端とも auto、または両端とも同じ値に固定。片側だけ固定しない。

速度不一致の場合はリンクが上がらない(down/down)。

**1行目(物理層 / データリンク層の状態)**

| 表示 | show interfaces status | 意味・原因 |
|---|---|---|
| up / up | connected | 正常 |
| administratively down / down | disabled | `shutdown` されている |
| down / down | notconnect | ケーブル未接続、断線、対向が shutdown、速度不一致 |
| down / down (err-disabled) | err-disabled | ポートセキュリティ違反、BPDU ガードなどで自動停止 |
| up / down | — | L2 の問題。カプセル化不一致、キープアライブ不達(主にシリアル) |

**カウンタ**

| カウンタ | 意味 | 主な原因 |
|---|---|---|
| runts | 64 バイト未満のフレーム | コリジョン、デュプレックス不一致、NIC 故障 |
| giants | 最大長(1518 バイト。タグ付きは 1522)超過 | MTU 不一致、NIC 故障 |
| CRC | FCS が合わない | ケーブル不良、ノイズ、距離超過、デュプレックス不一致 |
| input errors | runts、giants、CRC、frame、overrun、ignored などの合計 | |
| frame | バイト境界が合わない不正フレーム | コリジョン、物理層の不良 |
| collisions | コリジョン回数 | 半二重では正常な範囲で発生 |
| late collisions | 最初の 64 バイト(512 ビット)送信後のコリジョン | **デュプレックス不一致**、ケーブル長超過 |
| output errors | 送信失敗の合計 | コリジョン過多 |
| input queue drops / output drops | キューあふれ | 輻輳、処理能力超過 |
| interface resets | インターフェースのリセット回数 | |

関連コマンド:

```
show interfaces status              ! ポート一覧。状態、VLAN、デュプレックス、速度
show ip interface brief             ! IP と状態の一覧
show interfaces g0/1 counters errors
show controllers ethernet-controller g0/1
clear counters g0/1                 ! カウンタを消して増え方を見る
```

`show interfaces status` の Duplex / Speed 列で `a-full`、`a-1000` の `a-` はオートネゴシエーションで決まった値。

> **【1.1 まとめ】**
>
> - 同種(送信ピンが同じ)はクロス、異種はストレート。PC-ルータはクロス
> - MMF は短距離・安価、SMF は長距離・レーザー
> - 片側固定・片側 auto → auto 側は half(10/100)→ デュプレックス不一致
> - late collisions は half 側、CRC/runts は full 側に出る
> - administratively down は shutdown、err-disabled は保護機能による停止
> - 光の信号レベルは `show interfaces transceiver` の Rx Power

## 1.2 ハイパーバイザ、仮想マシン、コンテナ

### 1. サーバ仮想化

1台の物理サーバ(ホスト)上で、複数の仮想マシン(VM)を動かす技術。CPU、メモリ、ストレージ、NIC を**ハイパーバイザ**が抽象化して各 VM に割り当てる。

| 種類 | 動く場所 | 例 | 用途 |
|---|---|---|---|
| Type 1(ベアメタル、ネイティブ) | ハードウェア上で直接 | VMware ESXi、Microsoft Hyper-V、KVM、Xen | データセンター、本番 |
| Type 2(ホスト型) | ホスト OS の上 | VirtualBox、VMware Workstation / Fusion | 検証、個人利用 |

Type 1 はホスト OS を介さないため、オーバーヘッドが小さい。

### 2. 仮想マシン(VM)

- VM ごとに**ゲスト OS**(カーネルを含む)を持つ
- 仮想 NIC(vNIC)を持ち、ハイパーバイザ内の**仮想スイッチ(vSwitch)**に接続する
- vSwitch は物理 NIC(アップリンク)を通じて物理スイッチにつながる。複数 VLAN を通すため、物理スイッチ側は通常トランクにする(→ 2.2.d)
- 利点: サーバ集約、分離、スナップショット、ライブマイグレーション、迅速な展開

```
[VM1][VM2][VM3]   ← それぞれゲストOS + vNIC
   |    |    |
 [  vSwitch   ]   ← ハイパーバイザ内
       |
 [ 物理NIC ] ── トランク ── [物理スイッチ]
```

### 3. コンテナ

- ホスト OS の**カーネルを共有**し、アプリケーションとその依存物(ライブラリなど)だけをまとめて分離する
- ゲスト OS を持たない。軽量で、起動が秒単位
- コンテナエンジン(Docker、containerd、Podman)が実行する。多数のコンテナの管理は Kubernetes などのオーケストレータ
- Linux の namespace(分離)と cgroups(資源制限)で実現する
- イメージで配布するため、環境による差が出にくい

| | 仮想マシン | コンテナ |
|---|---|---|
| 分離の単位 | ハードウェアを仮想化 | OS を仮想化(プロセス分離) |
| OS | VM ごとにゲスト OS | ホストのカーネルを共有 |
| サイズ | GB 単位 | MB 単位 |
| 起動 | 分単位 | 秒単位 |
| 分離の強さ | 強い | VM より弱い |
| 異なる OS | 動かせる(Linux 上で Windows など) | ホストと同じカーネル系のみ |
| 集約密度 | 低い | 高い |

> **【ひっかけ】** コンテナはハイパーバイザを必要としない。必要なのはコンテナエンジン。「コンテナごとにゲスト OS を持つ」は誤り。

### 4. ネットワーク機能の仮想化

- ルータ、ファイアウォール、WLC などを VM やコンテナとして動かす(仮想アプライアンス、NFV)。例: Catalyst 8000V
- **VRF**: 1台のルータの中でルーティングテーブルを論理的に分離する技術。サーバ仮想化とは別の「ネットワークの仮想化」

> **【1.2 まとめ】**
>
> - Type 1 はハードウェア直上、Type 2 はホスト OS 上
> - VM はゲスト OS を持つ。コンテナはホストのカーネルを共有
> - VM は vNIC → vSwitch → 物理 NIC で外部につながる
> - コンテナは軽量・高速起動、VM は分離が強い

## 1.3 IPv4 アドレスの設定・割り当て・サブネット化のトラブルシュート

### 1. 基礎

- 32 ビット。ネットワーク部とホスト部をサブネットマスク(プレフィックス長)で分ける
- ホスト部すべて 0 がネットワークアドレス、すべて 1 がブロードキャストアドレス。ホストには割り当てない

| クラス | 先頭オクテット | 既定マスク | 用途 |
|---|---|---|---|
| A | 1〜126 | /8 | |
| B | 128〜191 | /16 | |
| C | 192〜223 | /24 | |
| D | 224〜239 | — | マルチキャスト |
| E | 240〜255 | — | 実験用 |

0.0.0.0/8 と 127.0.0.0/8 は特殊用途。

**プライベートアドレス(RFC 1918)**

| 範囲 | CIDR |
|---|---|
| 10.0.0.0 〜 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 〜 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 〜 192.168.255.255 | 192.168.0.0/16 |

プライベートアドレスはインターネット上でルーティングされない。外へ出るには NAT でパブリック(グローバル)アドレスに変換する。

| 特殊アドレス | 意味 |
|---|---|
| 127.0.0.0/8 | ループバック |
| 169.254.0.0/16 | リンクローカル(APIPA)。DHCP 取得失敗時に自動で付く |
| 0.0.0.0 | 未指定。デフォルトルートの宛先 |
| 255.255.255.255 | リミテッドブロードキャスト |
| 100.64.0.0/10 | キャリアグレード NAT 用の共有アドレス |
| 192.0.2.0/24、198.51.100.0/24、203.0.113.0/24 | 文書用 |

### 2. サブネット計算

| プレフィックス | マスク | ブロックサイズ | ホスト数 |
|---|---|---|---|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |
| /31 | 255.255.255.254 | 2 | 2(ポイントツーポイント専用、RFC 3021) |
| /32 | 255.255.255.255 | 1 | 1(ホストルート、ループバック) |

第3オクテットで区切る場合も同じ考え方。

| プレフィックス | マスク | 第3オクテットのブロック | ホスト数 |
|---|---|---|---|
| /16 | 255.255.0.0 | 256 | 65,534 |
| /17 | 255.255.128.0 | 128 | 32,766 |
| /18 | 255.255.192.0 | 64 | 16,382 |
| /19 | 255.255.224.0 | 32 | 8,190 |
| /20 | 255.255.240.0 | 16 | 4,094 |
| /21 | 255.255.248.0 | 8 | 2,046 |
| /22 | 255.255.252.0 | 4 | 1,022 |
| /23 | 255.255.254.0 | 2 | 510 |

> **【手順】** 例: 172.16.45.200/20
> ① /20 は第3オクテットで区切る。ブロックサイズは 256 − 240 = 16
> ② 16 の倍数: 0、16、32、48 … 45 は 32〜47 の範囲
> ③ ネットワークアドレス 172.16.32.0、ブロードキャスト 172.16.47.255
> ④ ホスト範囲 172.16.32.1 〜 172.16.47.254、ホスト数 2^12 − 2 = 4,094

- ホスト数: 2^(ホスト部ビット数) − 2
- サブネット数: 2^(借りたビット数)
- 必要ホスト数からプレフィックスを決める: 50 台なら 2^6 − 2 = 62 ≥ 50 → ホスト部 6 ビット → /26

### 3. VLSM

サブネットごとに異なる長さのマスクを使い、アドレスを無駄なく割り当てる。**大きいサブネットから順に**割り当てる。

例: 192.168.10.0/24 を、100 台、50 台、20 台、ルータ間リンク2本に分ける。

| 用途 | 必要数 | 割り当て | 範囲 |
|---|---|---|---|
| LAN A | 100 | 192.168.10.0/25 | .0 〜 .127 |
| LAN B | 50 | 192.168.10.128/26 | .128 〜 .191 |
| LAN C | 20 | 192.168.10.192/27 | .192 〜 .223 |
| リンク1 | 2 | 192.168.10.224/30 | .224 〜 .227 |
| リンク2 | 2 | 192.168.10.228/30 | .228 〜 .231 |

### 4. IOS での設定と確認

```
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown
!
interface GigabitEthernet0/0
 ip address 192.168.2.1 255.255.255.0 secondary   ! セカンダリアドレス
```

```
show ip interface brief
show ip interface g0/0
show running-config interface g0/0
show ip route connected
```

L2 スイッチの管理用アドレスは SVI に付け、`ip default-gateway` を設定する(→ 2.1.d)。

### 5. よくある障害

| 症状 | 原因 |
|---|---|
| 同じ LAN の一部のホストとだけ通信できない | サブネットマスクの誤り。相手を別ネットワークと判断している |
| 同じ LAN は通るが外に出られない | デフォルトゲートウェイの誤り・未設定。ゲートウェイが別サブネットのアドレス |
| 断続的に切れる。`%IP-4-DUPADDR` のログ | IP アドレスの重複 |
| `% 192.168.1.0 overlaps with GigabitEthernet0/0` | 同じルータの別インターフェースとサブネットが重複 |
| `Bad mask /24 for address 192.168.1.0` | ネットワークアドレスやブロードキャストアドレスをホストに設定しようとした |
| ホストが 169.254.x.x | DHCP サーバに届いていない |
| インターフェースが administratively down | `no shutdown` 忘れ(ルータの物理ポートは既定で shutdown) |
| 外部と通信できない(内部は可) | プライベートアドレスのまま。NAT の未設定・誤り |

> **【ひっかけ】** ホストとゲートウェイのマスクが違っても、片方向だけ通ることがある。10.1.1.200/24 のホストと 10.1.1.1/25 のルータでは、ルータは 10.1.1.200 を自分のサブネット外と判断し、直接返せない。

> **【1.3 まとめ】**
>
> - ブロックサイズ = 256 − マスクの値。その倍数がネットワークアドレス
> - ホスト数 2^n − 2。/30 は 2 台、/31 は p2p 専用で 2 台
> - VLSM は大きいサブネットから割り当てる
> - プライベート: 10/8、172.16/12、192.168/16
> - 169.254.x.x は DHCP 失敗
> - マスク誤り・ゲートウェイ誤り・重複・overlaps が定番の原因

## 1.4 IPv6 アドレスの設定・割り当て・プレフィックスサイズのトラブルシュート

### 1. 表記

128 ビット。16 ビットずつ 8 ブロックを 16 進数で書き、`:` で区切る。

- 各ブロックの先頭の 0 は省略できる
- 連続する 0 のブロックは `::` に置き換えられる。**1か所だけ**
- `::` を使える場所が複数あるときは、最も長い 0 の連続に使う。同じ長さなら左側(RFC 5952)

```
2001:0db8:0000:0000:00a0:0000:0000:0001
→ 2001:db8::a0:0:0:1
```

### 2. アドレスの種類

| 種類 | プレフィックス | 説明 |
|---|---|---|
| グローバルユニキャスト(GUA) | 2000::/3 | インターネットで一意。IPv4 のパブリックに相当 |
| ユニークローカル(ULA) | fc00::/7(実際に使うのは fd00::/8) | 組織内用。IPv4 のプライベートに相当 |
| リンクローカル(LLA) | fe80::/10 | 同一リンク内のみ。ルータは転送しない。IPv6 有効なインターフェースに必ず付く |
| マルチキャスト | ff00::/8 | グループあて |
| エニーキャスト | (ユニキャストと同じ空間) | 複数機器に同じアドレス。最も近い1台に届く |
| ループバック | ::1/128 | |
| 未指定 | ::/128 | アドレス未取得時の送信元 |
| デフォルトルート | ::/0 | |
| 文書用 | 2001:db8::/32 | |

IPv6 に**ブロードキャストはない**。

**主なマルチキャストアドレス**

| アドレス | あて先 |
|---|---|
| ff02::1 | リンク上の全ノード |
| ff02::2 | リンク上の全ルータ |
| ff02::5 / ff02::6 | OSPFv3 全ルータ / DR・BDR |
| ff02::1:2 | DHCPv6 サーバ・リレー |
| ff02::1:ffXX:XXXX | 要請ノードマルチキャスト。ユニキャストアドレスの下位 24 ビットから作る。NS のあて先 |

### 3. プレフィックスサイズ

| プレフィックス | 用途 |
|---|---|
| /32 | ISP への割り当て(一般的) |
| /48 | 1サイト(組織)への割り当て。65,536 個の /64 が取れる |
| /56 | 小規模サイト。256 個の /64 |
| **/64** | 1つの LAN(サブネット)。SLAAC と EUI-64 は /64 が前提 |
| /127 | ルータ間のポイントツーポイントリンク(RFC 6164) |
| /128 | ホストルート、ループバック |

GUA の構造(/48 割り当ての場合): グローバルルーティングプレフィックス 48 ビット + サブネット ID 16 ビット + インターフェース ID 64 ビット。

サブネット分割は 4 ビット(16 進 1 桁、ニブル)単位にすると読みやすい。

```
2001:db8:acad::/48 から /64 を切り出す
2001:db8:acad:0000::/64
2001:db8:acad:0001::/64
 …
2001:db8:acad:ffff::/64
```

> **【ひっかけ】** /64 以外のプレフィックスでは SLAAC が動かない。LAN に /65 以降を設定してホストが自動設定できない、という出題に注意。

### 4. Modified EUI-64

48 ビットの MAC アドレスから 64 ビットのインターフェース ID を作る方法。

1. MAC アドレスを前半 24 ビットと後半 24 ビットに分ける
2. 中央に `fffe` を挿入する
3. 先頭から 7 ビット目(U/L ビット)を反転する

```
MAC:      0c1a.2b3c.4d5e
① fffe 挿入: 0c1a:2bff:fe3c:4d5e
② 7ビット目反転: 0c = 0000 1100 → 0000 1110 = 0e
IF ID:    0e1a:2bff:fe3c:4d5e
アドレス: 2001:db8:1:1:e1a:2bff:fe3c:4d5e
```

> **【計算のコツ】** 先頭バイトの 2 桁目(16 進)に注目する。7 ビット目は「2 の位」。2 桁目が 0,1,4,5,8,9,c,d なら +2、2,3,6,7,a,b,e,f なら −2。
> 例: `00` → `02`、`0c` → `0e`、`a6` → `a4`、`52` → `50`

中央に `ff:fe` があれば EUI-64 由来と判断できる。

### 5. IOS での設定

```
ipv6 unicast-routing                          ! IPv6 ルーティングを有効化(RA の送信も開始)
!
interface GigabitEthernet0/0
 ipv6 address 2001:db8:1:1::1/64              ! 手動
 ipv6 address 2001:db8:1:1::/64 eui-64        ! プレフィックス手動 + IF ID は EUI-64
 ipv6 address fe80::1 link-local              ! リンクローカルを手動指定
 ipv6 address autoconfig                      ! SLAAC で取得
 ipv6 address dhcp                            ! DHCPv6 で取得
 ipv6 enable                                  ! リンクローカルのみ生成
 no shutdown
```

- グローバルアドレスを設定すると、リンクローカルは自動生成される(既定は EUI-64)
- 1つのインターフェースに複数の IPv6 アドレスを持てる。`ipv6 address` を追加しても上書きされない(IPv4 は `secondary` が要る)
- `ipv6 unicast-routing` がないと、ルータは IPv6 パケットを転送せず、RA も送らない。自身あての通信はできる

```
Router# show ipv6 interface brief
GigabitEthernet0/0     [up/up]
    FE80::E1A:2BFF:FE3C:4D5E
    2001:DB8:1:1::1
```

```
show ipv6 interface g0/0      ! 参加マルチキャストグループ、ND の設定も表示
show ipv6 route
show ipv6 neighbors           ! IPv4 の ARP テーブルに相当
ping 2001:db8:1:1::2
ping fe80::2                  ! リンクローカルあては出力インターフェースの指定を求められる
```

### 6. 近隣探索(NDP)とアドレス自動設定

NDP は ICMPv6 を使う。ARP の役割も NDP が担う。

| メッセージ | ICMPv6 タイプ | 役割 |
|---|---|---|
| RS(Router Solicitation) | 133 | ホストがルータに RA を要求。あて先 ff02::2 |
| RA(Router Advertisement) | 134 | ルータがプレフィックスとデフォルトゲートウェイを通知。あて先 ff02::1。既定 200 秒周期 |
| NS(Neighbor Solicitation) | 135 | MAC アドレスの問い合わせ(ARP 要求に相当)、DAD |
| NA(Neighbor Advertisement) | 136 | NS への応答(ARP 応答に相当) |

**DAD(重複アドレス検出)**: アドレスを使う前に、自分が使おうとするアドレスあてに NS を送る。NA が返れば重複。

| 方式 | RA のフラグ | アドレス | DNS などの情報 |
|---|---|---|---|
| SLAAC | M=0、O=0 | RA のプレフィックス + 自分で作る IF ID | RA(RDNSS)または手動 |
| ステートレス DHCPv6 | M=0、**O=1** | SLAAC | DHCPv6 |
| ステートフル DHCPv6 | **M=1** | DHCPv6 | DHCPv6 |

**デフォルトゲートウェイは常に RA から得る**(ルータのリンクローカルアドレス)。DHCPv6 はゲートウェイを配らない。

### 7. よくある障害

| 症状 | 原因 |
|---|---|
| ホストが SLAAC でアドレスを得られない | ルータで `ipv6 unicast-routing` 未設定。プレフィックスが /64 でない |
| リンクローカルしか持っていない | RA が届いていない。`ipv6 enable` だけ設定 |
| 同一リンクは通るが他セグメントに届かない | `ipv6 unicast-routing` 未設定。経路なし |
| アドレスに `[DUP]` 表示 | DAD で重複を検出。`show ipv6 interface` で確認 |
| アドレスが `[TEN]`(tentative)のまま | インターフェースが down、DAD 未完了 |
| 手動設定のプレフィックスが隣と違う | 入力ミス。`::` の位置、桁の誤り |
| EUI-64 の結果が想定と違う | 7 ビット目の反転忘れ |

> **【1.4 まとめ】**
>
> - GUA 2000::/3、ULA fc00::/7、LLA fe80::/10、マルチキャスト ff00::/8
> - LAN は /64。SLAAC と EUI-64 は /64 前提。p2p は /127
> - EUI-64: 中央に fffe、7 ビット目反転
> - `ipv6 unicast-routing` がないと転送も RA 送信もしない
> - RS 133、RA 134、NS 135、NA 136。ARP の代わりが NS/NA
> - ゲートウェイは RA から。M フラグ=ステートフル、O フラグ=ステートレス DHCPv6

## 1.5 無線の原理

### 1.5.a 帯域とチャネル選択

| 帯域 | 特徴 |
|---|---|
| 2.4 GHz | 遠くまで届き、障害物に強い。チャネルが少なく混雑する。電子レンジ、Bluetooth と干渉 |
| 5 GHz | チャネルが多く高速。到達距離は短く、障害物に弱い。一部チャネルは DFS(レーダー回避)の対象 |
| 6 GHz | Wi-Fi 6E 以降。広い帯域で干渉が少ない。WPA3 必須 |

**2.4 GHz のチャネル**: チャネル間隔は 5 MHz、チャネル幅は 20 MHz(802.11b は 22 MHz)。隣り合うチャネルは重なる。重ならない組み合わせは **1、6、11**。

**5 GHz のチャネル**: 20 MHz 幅で重ならないチャネルが多数ある(36、40、44、48 …)。チャネルボンディングで 40 / 80 / 160 MHz 幅にすると高速になるが、使えるチャネル数が減り、干渉しやすくなる。

**チャネル設計の原則**

- 隣接する AP は重ならないチャネルにする
- セル(カバー範囲)は 10〜20% 重ねてローミングを滑らかにする
- 2.4 GHz では 20 MHz 幅を使う。ボンディングしない
- 高密度の環境では送信出力を下げ、セルを小さくする

| 規格 | 世代名 | 帯域 | 最大速度(理論値) | 主な技術 |
|---|---|---|---|---|
| 802.11b | — | 2.4 GHz | 11 Mbps | DSSS |
| 802.11a | — | 5 GHz | 54 Mbps | OFDM |
| 802.11g | — | 2.4 GHz | 54 Mbps | OFDM |
| 802.11n | Wi-Fi 4 | 2.4 / 5 GHz | 600 Mbps | MIMO、40 MHz |
| 802.11ac | Wi-Fi 5 | 5 GHz | 6.9 Gbps | MU-MIMO(下り)、160 MHz |
| 802.11ax | Wi-Fi 6 / 6E | 2.4 / 5 / 6 GHz | 9.6 Gbps | OFDMA、MU-MIMO(上下) |
| 802.11be | Wi-Fi 7 | 2.4 / 5 / 6 GHz | 46 Gbps | MLO、320 MHz |

### 1.5.b RF の特性

| 用語 | 意味 |
|---|---|
| 周波数 | 1秒間の波の数(Hz)。高いほど波長が短く、減衰しやすい |
| 振幅 | 波の強さ |
| 吸収 | 壁、水、人体などが電波のエネルギーを吸収して弱める |
| 反射 | 金属やガラスで跳ね返る。マルチパスの原因 |
| 屈折 | 密度の異なる媒質を通るときに曲がる |
| 回折 | 障害物の縁を回り込む |
| 散乱 | 凹凸のある面で不規則に拡散する |
| 減衰 | 距離や障害物で信号が弱まること |
| 自由空間伝搬損失 | 障害物がなくても距離と周波数に応じて弱まること |

| 指標 | 意味 |
|---|---|
| dBm | 1 mW を基準にした電力の絶対値。0 dBm = 1 mW |
| dB | 相対値。+3 dB で約2倍、+10 dB で 10 倍、−3 dB で約半分 |
| RSSI | 受信信号強度。−50 dBm は強い、−80 dBm は弱い |
| ノイズフロア | 背景雑音のレベル |
| SNR | 信号とノイズの差(dB)。大きいほど良い。25 dB 以上が目安 |
| EIRP | 送信出力 + アンテナ利得 − ケーブル損失 |

SNR = RSSI − ノイズフロア。例: RSSI −65 dBm、ノイズ −90 dBm → SNR 25 dB。

**サービスセット**

| 用語 | 意味 |
|---|---|
| SSID | 無線 LAN の名前 |
| BSS | 1台の AP とそのクライアントの集まり |
| BSSID | BSS の識別子。AP の無線の MAC アドレス |
| ESS | 同じ SSID を持つ複数の BSS を有線(DS)でつないだもの。ローミングできる |
| IBSS | AP なしの端末同士(アドホック) |
| DS | AP 同士をつなぐ有線ネットワーク(ディストリビューションシステム) |

無線は半二重。CSMA/CA(衝突回避)を使う。同じチャネルの端末は帯域を共有する。

### 1.5.c セキュリティプロトコル

| 規格 | 暗号化 | 完全性 | 認証 | 評価 |
|---|---|---|---|---|
| WEP | RC4 | CRC | 共有鍵 | 破られている。使用不可 |
| WPA | TKIP(RC4) | MIC | PSK / 802.1X | 非推奨 |
| WPA2 | **AES-CCMP** | CBC-MAC | PSK / 802.1X | 現行の最低線 |
| WPA3 | AES-GCMP / CCMP | GMAC | **SAE** / 802.1X | 推奨 |

| モード | 認証 | 用途 |
|---|---|---|
| パーソナル | WPA2: PSK(4ウェイハンドシェイク)。WPA3: SAE | 家庭、小規模 |
| エンタープライズ | 802.1X / EAP。RADIUS サーバでユーザごとに認証 | 企業 |

**WPA3 の要点**

- SAE(Simultaneous Authentication of Equals): PSK のオフライン辞書攻撃に強い
- 前方秘匿性(forward secrecy): パスワードが後で漏れても、過去の通信は復号できない
- PMF(管理フレーム保護、802.11w)が必須
- エンタープライズは 192 ビットモードを選べる
- OWE(Enhanced Open): パスワードなしのオープン SSID でも暗号化する
- WPA2/WPA3 移行(混在)モード: 両方の端末を収容する

**802.1X の3要素**: サプリカント(端末)、オーセンティケータ(AP / WLC)、認証サーバ(RADIUS)。EAP の種類: PEAP、EAP-TLS(証明書)、EAP-FAST。

### 1.5.d 干渉の原因

| 種類 | 内容 | 対策 |
|---|---|---|
| 同一チャネル干渉(CCI) | 近くの AP が同じチャネルを使う。互いに待ち合うため速度が落ちる | チャネル再設計、送信出力を下げる |
| 隣接チャネル干渉(ACI) | 重なるチャネル(1 と 3 など)を使う。ノイズとして作用し、CCI より悪い | 1、6、11 だけを使う |
| 非 Wi-Fi 機器 | 電子レンジ、Bluetooth、コードレス電話、ワイヤレスカメラ、ベビーモニタ(主に 2.4 GHz) | 5 GHz / 6 GHz に移す、機器を離す |
| レーダー | 5 GHz の DFS チャネルで気象・航空レーダーを検出すると、AP はチャネルを変える | 非 DFS チャネルを使う |
| 物理的な障害物 | コンクリート、金属、水(水槽、人体)、鏡 | AP の位置・台数を見直す |
| マルチパス | 反射波が時間差で届く | MIMO はこれを利用する。アンテナ配置 |

> **【1.5 まとめ】**
>
> - 2.4 GHz の非重複チャネルは 1、6、11。届くが混む
> - 5 GHz はチャネルが多く速い。届きにくい。DFS あり
> - 周波数が高いほど減衰が大きい。+3 dB で2倍、+10 dB で10倍
> - SNR = RSSI − ノイズ。大きいほど良い
> - WEP(RC4)→ WPA(TKIP)→ WPA2(AES-CCMP)→ WPA3(SAE、GCMP、PMF 必須)
> - パーソナルは PSK / SAE、エンタープライズは 802.1X + RADIUS

## 1.6 有線・無線クライアントの接続トラブルシュート

出題範囲: Windows、macOS、Linux での IP 設定、到達性、無線セキュリティパラメータ。

### 1. 確認コマンド

| 目的 | Windows | macOS | Linux |
|---|---|---|---|
| IP 設定の表示 | `ipconfig`、`ipconfig /all` | `ifconfig`、`ipconfig getifaddr en0`、`networksetup -getinfo Wi-Fi` | `ip addr`、`ip -br addr` |

| ルーティングテーブル | `route print`、`netstat -r` | `netstat -rn` | `ip route` |
| ARP テーブル | `arp -a` | `arp -a` | `ip neigh` |
| 疎通 | `ping`(4回) | `ping`(止めるまで) | `ping`(止めるまで) |
| 経路 | `tracert`(ICMP) | `traceroute`(UDP) | `traceroute`(UDP)、`tracepath` |

`ipconfig /all` で分かること: IPv4 アドレス、サブネットマスク、デフォルトゲートウェイ、DHCP 有効/無効、DHCP サーバ、リース取得・期限、DNS サーバ、物理(MAC)アドレス。

### 2. 切り分けの順序

| 段階 | 確認 | 失敗時に疑うもの |
|---|---|---|
| 1 | 物理・無線の接続。リンクランプ、SSID への接続 | ケーブル、ポートの shutdown、VLAN、SSID・認証 |
| 2 | IP 設定(アドレス、マスク、ゲートウェイ、DNS) | DHCP、手動設定の誤り |
| 3 | `ping 127.0.0.1` | TCP/IP スタック |
| 4 | 自分の IP に ping | NIC |
| 5 | デフォルトゲートウェイに ping | LAN 内、VLAN、マスク |
| 6 | 外部の IP に ping(例: 8.8.8.8) | ルーティング、NAT、ACL |
| 7 | 名前で ping / nslookup | DNS |
| 8 | アプリケーションのポート | ファイアウォール、サービス停止 |

### 3. 症状と原因

| 症状 | 原因 |
|---|---|
| アドレスが 169.254.x.x | DHCP サーバに届かない。VLAN 誤り、リレー未設定、プール枯渇、サーバ停止 |
| アドレスは正しいが、ゲートウェイに ping 不可 | ポートの VLAN 誤り、マスク誤り、ゲートウェイのアドレス誤り |
| ゲートウェイには通るが外に出られない | ルータ側の経路、NAT、ACL |
| IP では通るが名前で通らない | DNS サーバの設定誤り、DNS サーバ不達、レコードなし |
| `ping` の結果が「宛先ホストに到達できません」 | 経路なし、または同一サブネット内で ARP 解決不可 |
| `ping` の結果が「要求がタイムアウトしました」 | 返信が戻らない。相手の停止、戻りの経路なし、ファイアウォール |
| 想定外のサブネットのアドレスを取得 | 不正 DHCP サーバ、ポートの VLAN 誤り |
| IPv6 がリンクローカル(fe80::)だけ | RA が届いていない |

### 4. 無線クライアント固有の障害

| 症状 | 原因 |
|---|---|
| SSID が見えない | 帯域非対応(5 GHz 専用 SSID に 2.4 GHz 専用端末)、SSID ブロードキャスト無効、電波圏外、WLAN が無効 |
| 認証に失敗する | PSK(パスフレーズ)の誤り。大文字小文字も区別 |
| 接続できない(古い端末) | セキュリティ方式の不一致。WPA3 専用 SSID に WPA2 までの端末。PMF 必須設定に非対応 |
| エンタープライズ認証に失敗 | ユーザ名・パスワード誤り、EAP 方式の不一致、サーバ証明書を信頼していない、端末の時刻ずれ、RADIUS サーバ不達 |
| 接続済みだが「インターネットなし」 | 認証は成功、DHCP に失敗(169.254.x.x)。WLAN に対応する VLAN・DHCP を確認 |
| 遅い、切れる | RSSI・SNR が低い、同一チャネル干渉、非 Wi-Fi 干渉、低速レートの端末 |
| 移動すると切れる | セルの重なり不足、ローミング失敗 |

> **【1.6 まとめ】**
>
> - Windows は `ipconfig /all`、`tracert`、`netsh wlan show interfaces`
> - Linux は `ip addr`、`ip route`、`resolvectl`、`iw`
> - 近くから遠くへ: ループバック → 自分 → ゲートウェイ → 外部 IP → 名前
> - 169.254.x.x は DHCP 失敗
> - IP で通り名前で通らない → DNS
> - 無線の接続失敗は PSK 誤り、方式不一致(WPA2/WPA3)、帯域非対応を疑う

## 1.7 IOS 機器での DHCPv4 クライアント、サーバ、リレーのトラブルシュート

### 1. DHCP の動作(DORA)

| 順 | メッセージ | 方向 | あて先 |
|---|---|---|---|
| 1 | **D**iscover | クライアント → サーバ | ブロードキャスト(255.255.255.255) |
| 2 | **O**ffer | サーバ → クライアント | ユニキャスト(またはブロードキャスト) |
| 3 | **R**equest | クライアント → サーバ | ブロードキャスト |
| 4 | **A**ck | サーバ → クライアント | ユニキャスト(またはブロードキャスト) |

- UDP を使う。サーバは **67**、クライアントは **68**
- Discover の送信元 IP は 0.0.0.0
- リースの更新: 期間の 50%(T1)でユニキャストの Request、87.5%(T2)でブロードキャストの Request
- その他のメッセージ: Nak(拒否)、Release(返却)、Decline(重複検出時に辞退)、Inform

配布する情報: IP アドレス、サブネットマスク、デフォルトゲートウェイ、DNS サーバ、ドメイン名、リース期間、その他オプション(150: TFTP サーバ / 43: WLC のアドレス など)。

### 2. サーバの設定

```
ip dhcp excluded-address 192.168.10.1 192.168.10.10   ! 配布しない範囲。グローバルコンフィグ
!
ip dhcp pool VLAN10
 network 192.168.10.0 255.255.255.0                   ! /24 と書いてもよい
 default-router 192.168.10.1
 dns-server 8.8.8.8 8.8.4.4
 domain-name example.com
 lease 7                                              ! 日 [時 分]。既定は1日
```

- `ip dhcp excluded-address` はプールの中ではなく、グローバルコンフィグで設定する
- サーバは、要求を受けたインターフェース(またはリレーの giaddr)と同じサブネットのプールを選ぶ
- アドレスを配る前に ping で使用中かを確認し、応答があれば conflict として記録する

### 3. クライアントの設定

```
interface GigabitEthernet0/1
 ip address dhcp
 no shutdown
```

DHCP でデフォルトゲートウェイを受け取ると、ルータは AD 254 のデフォルトルートを自動で入れる。

```
show dhcp lease
show ip interface brief      ! Method 列が DHCP
```

### 4. リレーエージェント

Discover はブロードキャストなので、ルータを越えない。サーバが別サブネットにあるときは、クライアント側のインターフェースにリレーを設定する。

```
interface GigabitEthernet0/0          ! クライアントがいる側(L3 スイッチなら SVI)
 ip address 192.168.10.1 255.255.255.0
 ip helper-address 10.1.1.5           ! DHCP サーバのアドレス
```

- リレーは Discover を**ユニキャスト**に変えてサーバへ転送する
- その際、**giaddr**(ゲートウェイ IP アドレス)に受信インターフェースのアドレスを入れる。サーバは giaddr からプールを選び、giaddr あてに返信する
- `ip helper-address` は DHCP 以外も転送する。既定は UDP 37(Time)、49(TACACS)、53(DNS)、67 / 68(DHCP)、69(TFTP)、137 / 138(NetBIOS)

> **【ひっかけ】** `ip helper-address` を設定するのは**クライアント側**のインターフェース。サーバ側ではない。指定するアドレスはサーバのアドレス。

### 5. 確認コマンド

```
show ip dhcp binding               ! 貸し出し中のアドレスと MAC(クライアント ID)
show ip dhcp pool                  ! プールの範囲、貸出数、残り
show ip dhcp conflict              ! 重複を検出したアドレス
show ip dhcp server statistics     ! メッセージ種別ごとの送受信数
show running-config | section dhcp
show ip interface g0/0             ! "Helper address is 10.1.1.5"
debug ip dhcp server events
debug ip dhcp server packet
clear ip dhcp binding *
clear ip dhcp conflict *
```

### 6. トラブルシュート

| 症状・出力 | 原因 | 対処 |
|---|---|---|
| クライアントが 169.254.x.x | サーバに届いていない | 下の各項目を確認 |
| 別サブネットのクライアントだけ取得できない | リレー未設定。`ip helper-address` を設定するインターフェースの誤り。アドレスの誤り | クライアント側に正しく設定 |
| リレーは正しいが取得できない | サーバから giaddr のサブネットへの**戻りの経路**がない | サーバ・経路上に経路を追加 |
| 同上 | giaddr のサブネットに対応するプールがない。`network` の誤り | プールを修正 |
| 一部のクライアントだけ取得できない | プール枯渇。`show ip dhcp pool` で残りを確認 | リース短縮、範囲拡大、不要なバインディングを消去 |
| 同上 | `show ip dhcp conflict` に多数の登録。conflict のアドレスは配布されない | 原因の機器を特定し、`clear ip dhcp conflict *` |
| アドレスは取れるが外に出られない | `default-router` の誤り・未設定 | プールを修正 |
| 名前解決できない | `dns-server` の誤り・未設定 | プールを修正 |
| ルータや固定機器とアドレスが重複 | `ip dhcp excluded-address` の漏れ | 除外範囲を設定 |
| 誰も取得できない | `no service dhcp` で機能停止。ACL が UDP 67/68 を遮断。クライアント側ポートの VLAN 誤り | 有効化、ACL 修正 |
| 想定外のアドレスを取得 | 不正 DHCP サーバ | DHCP スヌーピング(→ 4.7) |
| スイッチ経由で取得に時間がかかる | STP の収束待ち(約30秒) | PortFast(→ 2.5) |

> **【1.7 まとめ】**
>
> - DORA。サーバ UDP 67、クライアント UDP 68。Discover はブロードキャスト
> - `ip dhcp excluded-address` はグローバルコンフィグ
> - プール内: `network`、`default-router`、`dns-server`、`lease`
> - クライアントは `ip address dhcp`
> - リレーは**クライアント側**インターフェースに `ip helper-address <サーバ>`
> - リレー時は giaddr でプールを選ぶ。サーバから giaddr への経路が要る
> - `show ip dhcp binding` / `pool` / `conflict`
