# LinuC 102 テキスト 1.07 ネットワークの基礎

## 1.07.1 インターネットプロトコルの基礎 （重要度4）

### 1. IPアドレス（IPv4）

ネットワーク上の住所。32ビットの数値を8ビットずつ4つに区切り、10進数で書く。各区切り（オクテット）は0〜255。

IPアドレスは**ネットワーク部**（どのネットワークか）と**ホスト部**（その中のどの機器か）に分かれる。境目を決めるのがサブネットマスク。

**［図1　ネットワーク部とホスト部］**

`192.168.1.10/24` では、`192.168.1` がネットワーク部（24ビット）、`10` がホスト部（8ビット）。サブネットマスクは `255.255.255.0`。255の部分がネットワーク部。

### 2. サブネットマスクとCIDR表記

サブネットマスクは、2進数で「1が並ぶ部分＝ネットワーク部」を示す。**CIDR表記**は、その1の個数を `/24` のように書く方法。

``` bash
255.255.255.0
= 11111111.11111111.11111111.00000000
= 1が24個 → /24
```

| CIDR  | マスク          | アドレス数 | 使えるホスト数 |
|-------|-----------------|------------|----------------|
| `/8`  | 255.0.0.0       | 約1677万   | 16,777,214     |
| `/16` | 255.255.0.0     | 65,536     | 65,534         |
| `/24` | 255.255.255.0   | 256        | 254            |
| `/25` | 255.255.255.128 | 128        | 126            |
| `/26` | 255.255.255.192 | 64         | 62             |
| `/27` | 255.255.255.224 | 32         | 30             |
| `/28` | 255.255.255.240 | 16         | 14             |
| `/29` | 255.255.255.248 | 8          | 6              |
| `/30` | 255.255.255.252 | 4          | 2              |

> **【計算のしかた】** ホスト部が n ビットなら、アドレス数は 2^n、使えるホスト数は **2^n − 2**。  
> 引く2は、ネットワークアドレス（先頭）とブロードキャストアドレス（末尾）。  
> マスクの最後の値は「256 − アドレス数」。/26 なら 256 − 64 = 192。

### 3. ネットワークアドレスとブロードキャストアドレス

| 名前                     | ホスト部 | 役割                                               |
|--------------------------|----------|----------------------------------------------------|
| ネットワークアドレス     | すべて0  | ネットワークそのものを表す。機器には割り当てない   |
| ブロードキャストアドレス | すべて1  | 同じネットワークの全機器あて。機器には割り当てない |

### 4. サブネット化

1つのネットワークを、マスクを長くして小さく分けること。`192.168.1.0/24` を `/26` にすると、64個ずつの4ブロックになる。

**［図2　サブネット化の例］**

| ブロック | ネットワーク | 割り当て可能 | ブロードキャスト |
|----------|--------------|--------------|------------------|
| 1        | .0           | .1〜.62      | .63              |
| 2        | .64          | .65〜.126    | .127             |
| 3        | .128         | .129〜.190   | .191             |
| 4        | .192         | .193〜.254   | .255             |

192.168.1.130/26 は3番目のブロックに属する。

> **【解き方（192.168.1.130/26 の場合）】** ① /26 のブロックの大きさは 64。  
> ② 64の倍数で区切る：0、64、128、192。  
> ③ 130 が入るのは 128〜191。  
> ④ 先頭 128 がネットワークアドレス、末尾 191 がブロードキャスト。

> **【ひっかけ】** `192.168.1.100/25` と `192.168.1.130/25` は別のネットワーク（0〜127 と 128〜255）。見た目が近くても、ルータなしでは通信できない。

### 5. アドレスクラスとプライベートアドレス

| クラス | 先頭オクテット | 標準のマスク     |
|--------|----------------|------------------|
| A      | 0〜127         | /8               |
| B      | 128〜191       | /16              |
| C      | 192〜223       | /24              |
| D      | 224〜239       | マルチキャスト用 |

**プライベートアドレス**は、社内や家庭内で自由に使える範囲。インターネットには直接出られず、NATでグローバル（パブリック）アドレスに変換して通信する。

| クラス | 範囲                           | CIDR             |
|--------|--------------------------------|------------------|
| A      | 10.0.0.0 〜 10.255.255.255     | `10.0.0.0/8`     |
| B      | 172.16.0.0 〜 172.31.255.255   | `172.16.0.0/12`  |
| C      | 192.168.0.0 〜 192.168.255.255 | `192.168.0.0/16` |

| 特別なアドレス   | 意味                                                   |
|------------------|--------------------------------------------------------|
| `127.0.0.1`      | ループバック。自分自身（localhost）                    |
| `169.254.0.0/16` | リンクローカル。DHCPで取得できなかったときに自動で付く |
| `0.0.0.0`        | 「すべて」や「未指定」。デフォルトルートの宛先など     |

> **【ひっかけ】** クラスBのプライベートは 172.**16**〜172.**31** だけ。`172.32.0.1` や `172.15.0.1` はグローバルアドレス。

### 6. ポート番号

IPアドレスが「建物の住所」なら、ポート番号は「部屋番号」。1台のサーバーの中で、どのサービスあての通信かを区別する。0〜65535。

| 範囲         | 名前                                                           |
|--------------|----------------------------------------------------------------|
| 0〜1023      | ウェルノウンポート。主要サービス用。待ち受けにはroot権限が必要 |
| 1024〜49151  | 登録済みポート                                                 |
| 49152〜65535 | 動的ポート。クライアント側が一時的に使う                       |

| 番号    | サービス               | プロトコル |
|---------|------------------------|------------|
| 20, 21  | FTP（データ, 制御）    | TCP        |
| **22**  | **SSH**                | TCP        |
| 23      | Telnet                 | TCP        |
| **25**  | **SMTP**（メール送信） | TCP        |
| **53**  | **DNS**                | UDP / TCP  |
| **80**  | **HTTP**               | TCP        |
| 110     | POP3（メール受信）     | TCP        |
| **123** | **NTP**（時刻同期）    | UDP        |
| 143     | IMAP（メール受信）     | TCP        |
| **443** | **HTTPS**              | TCP        |

太字の6つは公式範囲に明記されている。必ず覚える。サービス名とポート番号の対応表は `/etc/services` にある。

### 7. TCP・UDP・ICMP

|        | TCP                                | UDP                              |
|--------|------------------------------------|----------------------------------|
| 接続   | コネクション型。通信前に接続を確立 | コネクションレス型。いきなり送る |
| 信頼性 | 高い。到達確認・再送・順序制御あり | 低い。届いたか確認しない         |
| 速度   | 遅め                               | 速い。負荷が小さい               |
| 用途   | HTTP、SSH、SMTP                    | DNS、NTP、DHCP、動画・音声       |

TCPは通信を始める前に、3回のやり取りで接続を確立する（**3ウェイハンドシェイク**）。

**［図3　TCPの3ウェイハンドシェイク］**

1.  クライアント → サーバー：SYN
2.  サーバー → クライアント：SYN + ACK
3.  クライアント → サーバー：ACK

接続確立。ここからデータを送る。

**ICMP**は、通信の状態やエラーを伝えるためのプロトコル。データを運ぶのが目的ではない。**ポート番号を持たない**。

- `ping`：エコー要求を送り、エコー応答が返るかで疎通を確認する。
- `traceroute`：経路上のルータが返す「時間超過」メッセージを利用する。
- 「宛先到達不能」などのエラー通知もICMP。

### 8. IPv6

IPv4アドレスの枯渇に対応する次世代のIP。**128ビット**。16ビットずつ8つに区切り、**16進数**で書き、`:`（コロン）でつなぐ。

**省略ルール**は2つ。

``` bash
2001:0db8:0000:0000:0000:0000:0000:0001
① 各区切りの先頭の0は省略できる
2001:db8:0:0:0:0:0:1
② 0が続く区切りは :: にまとめられる
2001:db8::1
```

> **【ひっかけ】** `::` が使えるのは**1か所だけ**。2か所に使うと、それぞれ何個の0か分からなくなる。`2001::db8::1` は誤り。

| アドレス    | 意味                                               |
|-------------|----------------------------------------------------|
| `::1`       | ループバック（IPv4の 127.0.0.1）                   |
| `fe80::/10` | リンクローカル。同じリンク内だけで有効。自動で付く |
| `2000::/3`  | グローバルユニキャスト。インターネットで使う       |
| `fc00::/7`  | ユニークローカル（IPv4のプライベートに相当）       |
| `ff00::/8`  | マルチキャスト                                     |

|                  | IPv4               | IPv6                                    |
|------------------|--------------------|-----------------------------------------|
| 長さ             | 32ビット           | 128ビット                               |
| 表記             | 10進数、`.` 区切り | 16進数、`:` 区切り                      |
| ブロードキャスト | あり               | **なし**（マルチキャストで代用）        |
| 自動設定         | DHCPが必要         | ルータの情報から自動生成できる（SLAAC） |
| IPsec            | オプション         | 標準で対応                              |
| ヘッダ           | 可変長で複雑       | 固定長で簡素化                          |
| NAT              | 広く使われる       | 基本的に不要                            |

IPv6のプレフィックス長は通常 `/64`。前半64ビットがネットワーク、後半64ビットがインターフェースID。

> **【1.07.1 まとめ】**
>
> - ホスト数は 2^n − 2。/24=254、/26=62、/27=30
> - ホスト部がすべて0はネットワーク、すべて1はブロードキャスト
> - プライベート：10/8、172.16/12、192.168/16
> - 22 SSH、25 SMTP、53 DNS、80 HTTP、123 NTP、443 HTTPS
> - TCPは信頼性、UDPは速さ、ICMPは制御（ping）
> - IPv6は128ビット・16進数。`::` は1回だけ。ブロードキャストなし

## 1.07.2 基本的なネットワーク構成 （重要度4）

### 1. 新旧コマンドの対応

ネットワーク設定のコマンドは世代交代している。試験には両方出る。

| 用途          | 旧（net-tools）    | 新（iproute2）        |
|---------------|--------------------|-----------------------|
| IPアドレス    | `ifconfig`         | `ip addr`             |
| IFの有効/無効 | `ifconfig eth0 up` | `ip link set eth0 up` |
| ルーティング  | `route`            | `ip route`            |
| 接続・ポート  | `netstat`          | `ss`                  |

### 2. ip コマンド

``` bash
# アドレスを表示（ip a でも可）
ip addr show
ip addr show dev eth0
# アドレスを追加・削除
ip addr add 192.168.1.10/24 dev eth0
ip addr del 192.168.1.10/24 dev eth0
# インターフェースの有効・無効
ip link set eth0 up
ip link set eth0 down
# インターフェースの状態
ip link show
```

`ip addr show` の出力の読み方：

``` bash
2: eth0: <BROADCAST,UP,LOWER_UP>
   state UP
  link/ether 52:54:00:12:34:56
  inet 192.168.1.10/24
       brd 192.168.1.255
  inet6 fe80::5054:ff:fe12:3456/64
```

| 項目              | 意味                          |
|-------------------|-------------------------------|
| `UP` / `state UP` | インターフェースが有効        |
| `link/ether`      | MACアドレス                   |
| `inet`            | IPv4アドレス/プレフィックス長 |
| `brd`             | ブロードキャストアドレス      |
| `inet6`           | IPv6アドレス                  |

`lo` はループバックインターフェース（127.0.0.1）。

### 3. ifconfig / ifup / ifdown

``` bash
# 表示（-a で無効なIFも含む）
ifconfig
ifconfig -a
# アドレスを設定して有効化
ifconfig eth0 192.168.1.10 \
  netmask 255.255.255.0 up
# 無効化
ifconfig eth0 down
```

`ifup` / `ifdown` は、**設定ファイルの内容に従って**インターフェースを有効・無効にする。

``` bash
ifup eth0
ifdown eth0
```

| 系統      | 設定ファイル                                |
|-----------|---------------------------------------------|
| Debian系  | `/etc/network/interfaces`                   |
| Red Hat系 | `/etc/sysconfig/network-scripts/ifcfg-eth0` |

### 4. 手動設定（static）と自動設定（DHCP）

インターフェースの設定方法は2つ。公式範囲の「手作業および自動で行う」がこれにあたる。

| 方法           | 内容                                           |
|----------------|------------------------------------------------|
| 手動（static） | IPアドレスなどを自分で決めて書く。サーバー向き |
| 自動（DHCP）   | DHCPサーバーから受け取る。クライアント向き     |

DHCPで受け取る主な情報：IPアドレス、サブネットマスク、デフォルトゲートウェイ、DNSサーバー。

**Debian系**：`/etc/network/interfaces`

``` bash
# 自動（DHCP）
auto eth0
iface eth0 inet dhcp

# 手動（static）
auto eth0
iface eth0 inet static
    address 192.168.1.10
    netmask 255.255.255.0
    gateway 192.168.1.1
```

**Red Hat系**：`/etc/sysconfig/network-scripts/ifcfg-eth0`

``` bash
# 自動（DHCP）
DEVICE=eth0
BOOTPROTO=dhcp
ONBOOT=yes

# 手動（static）
DEVICE=eth0
BOOTPROTO=none
ONBOOT=yes
IPADDR=192.168.1.10
PREFIX=24
GATEWAY=192.168.1.1
DNS1=8.8.8.8
```

| 項目                                                | 意味                     |
|-----------------------------------------------------|--------------------------|
| `auto eth0` / `ONBOOT=yes`                          | 起動時に自動で有効にする |
| `inet dhcp` / `BOOTPROTO=dhcp`                      | DHCPで取得               |
| `inet static` / `BOOTPROTO=none`（または `static`） | 固定                     |

ファイルを書き換えたら `ifdown eth0`、`ifup eth0` で読み直す。

DHCPクライアントを手で動かすコマンドは `dhclient`。

``` bash
dhclient eth0      # 取得
dhclient -r eth0   # 解放
```

NetworkManagerの環境では、`nmcli` の `ipv4.method` で切り替える（次節）。

> **【ひっかけ：一時的か、永続的か】** `ip`、`ifconfig`、`route` での設定は**再起動すると消える**。永続化するには、設定ファイルに書くか `nmcli` を使う。

### 5. nmcli（NetworkManager）

NetworkManagerをコマンドで操作する。設定は保存され、再起動後も残る。

| 用語       | 意味                                              |
|------------|---------------------------------------------------|
| device     | ネットワークインターフェースそのもの（eth0 など） |
| connection | デバイスに適用する設定のまとまり                  |

``` bash
# デバイスの状態
nmcli device status
# 接続（設定）の一覧
nmcli connection show
# 接続の有効化・無効化
nmcli connection up eth0
nmcli connection down eth0
# 固定IPに変更
nmcli connection modify eth0 \
  ipv4.method manual \
  ipv4.addresses 192.168.1.10/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns 8.8.8.8
# 変更を反映
nmcli connection up eth0
# ホスト名の表示・変更
nmcli general hostname
nmcli general hostname web01
```

- `ipv4.method`：`manual` は固定、`auto` はDHCP。
- `modify` しただけでは反映されない。`up` し直す。
- 省略形も使える：`nmcli d`、`nmcli c`、`nmcli con mod`。

### 6. ホスト名

``` bash
# 表示
hostname
# 一時的に変更
hostname web01
# 永続的に変更
hostnamectl set-hostname web01
```

ホスト名は `/etc/hostname` に保存され、起動時に読み込まれる。

### 7. /etc/hosts

IPアドレスとホスト名の対応を書くファイル。DNSを使わずに名前解決できる。

``` bash
# IPアドレス  ホスト名  別名...
127.0.0.1    localhost
192.168.1.20 db01.example.com db01
```

書式は「**IPアドレスが先**、ホスト名が後」。別名は空白で区切って並べる。

### 8. /etc/nsswitch.conf

名前解決などで「何を、どの順番で調べるか」を決めるファイル。

``` bash
hosts: files dns
```

- `files` は `/etc/hosts`、`dns` はDNSサーバー。
- 左から順に調べる。上の例は「まず /etc/hosts、なければDNS」。

### 9. ping

ICMPのエコー要求を送り、相手に届くかを確認する。

``` bash
ping 192.168.1.1
# 4回送って終了
ping -c 4 192.168.1.1
# 2秒間隔で送る
ping -i 2 192.168.1.1
# IPv6
ping6 ::1
```

Linuxの ping は `-c` を付けないと止まらない。Ctrl+C で終了する。

### 10. デフォルトルート（デフォルトゲートウェイ）

同じネットワークの相手には直接送れる。それ以外あての通信は、出口となるルータに渡す。この出口が**デフォルトゲートウェイ**。

**［図4　デフォルトゲートウェイ］**

自分（192.168.1.10）から同じLANの機器（.20）へは直接送る。宛先が自分のネットワーク（192.168.1.0/24）の外なら、ゲートウェイ（.1）へ渡し、そこから他のネットワークへ届く。

``` bash
# 表示
ip route show
route -n
# デフォルトルートを追加
ip route add default via 192.168.1.1
route add default gw 192.168.1.1
# 削除
ip route del default
route del default gw 192.168.1.1
```

> **【ひっかけ】** ゲートウェイの指定は、`ip route` では **`via`**、`route` では **`gw`**。入れ替えた選択肢に注意。

> **【1.07.2 まとめ】**
>
> - `ip addr`（アドレス）、`ip link`（有効/無効）、`ip route`（経路）
> - `ip` や `ifconfig` の設定は再起動で消える。永続は設定ファイルか `nmcli`
> - `nmcli` は `modify` のあと `up` で反映
> - ホスト名は `/etc/hostname`、名前とIPの対応は `/etc/hosts`
> - `hosts: files dns` は /etc/hosts が先
> - デフォルトルート：`ip route add default via`、`route add default gw`
> - 自動設定はDHCP。`inet dhcp`、`BOOTPROTO=dhcp`、`ipv4.method auto`

## 1.07.3 基本的なネットワークの問題解決 （重要度4）

### 1. 切り分けの順番

つながらないときは、近いところから順に確認する。どの段階で失敗するかで、原因の場所が分かる。

**［図5　切り分けの流れ］**

| 順番 | 確認すること               | コマンド                          |
|------|----------------------------|-----------------------------------|
| ①    | 自分のIF・IPは正しいか     | `ip addr`、`ip link`              |
| ②    | ゲートウェイに届くか       | `ping 192.168.1.1`、`ip route`    |
| ③    | 外部のIPアドレスに届くか   | `ping 8.8.8.8`、`traceroute`      |
| ④    | 名前解決できるか           | `host`、`dig`、`/etc/resolv.conf` |
| ⑤    | 目的のポートは開いているか | `nc -zv`、`ss -tln`               |

| 症状                                                 | 疑う場所                                           |
|------------------------------------------------------|----------------------------------------------------|
| ②で失敗                                              | 自分のIP設定、ケーブル、LAN内                      |
| ②は成功、③で失敗（`Network is unreachable`）         | デフォルトルートがない・誤り                       |
| ③は成功、名前だと失敗（`Name or service not known`） | DNSの設定（/etc/resolv.conf）                      |
| pingは通るがサービスにつながらない                   | ポートが閉じている、ファイアウォール、サービス停止 |

### 2. traceroute / tracepath

宛先までに通過するルータを順に表示する。どこで止まっているかが分かる。

``` bash
traceroute www.example.com
# 名前解決しない（速い）
traceroute -n 8.8.8.8
# ICMPで送る
traceroute -I 8.8.8.8
# IPv6
traceroute6 2001:db8::1
tracepath 8.8.8.8
tracepath6 2001:db8::1
```

仕組み：TTL（通過できるルータ数の上限）を1、2、3…と増やしながら送る。TTLが0になったルータがICMPの「時間超過」を返すので、順に経路が分かる。

|              | traceroute                 | tracepath                   |
|--------------|----------------------------|-----------------------------|
| 送るパケット | 既定はUDP（`-I` でICMP）   | UDP                         |
| 権限         | 一部のオプションはroot必要 | 一般ユーザーで使える        |
| 特徴         | オプションが豊富           | 経路の**MTU**（PMTU）も表示 |

応答のないルータは `* * *` と表示される。

### 3. ss / netstat

開いているポートや接続の状態を表示する。`netstat` が旧、`ss` が新。主なオプションは共通。

| オプション | 意味                       |
|------------|----------------------------|
| `-t`       | TCP                        |
| `-u`       | UDP                        |
| `-l`       | 待ち受け中（LISTEN）のみ   |
| `-a`       | すべて（待ち受け＋接続中） |
| `-n`       | 名前に変換せず数値で表示   |
| `-p`       | 使っているプロセスを表示   |

``` bash
# 待ち受け中のTCPを数値で
ss -tln
netstat -tln
# プロセスも表示
ss -tlnp
# すべて
ss -an
# ルーティングテーブル
netstat -r
# インターフェースごとの統計
netstat -i
```

``` bash
State   Local Address:Port
LISTEN  0.0.0.0:22
LISTEN  127.0.0.1:25
```

- `0.0.0.0:22`：すべてのアドレスで22番を待ち受け。外部から接続できる。
- `127.0.0.1:25`：自分自身からしか接続できない。

> **【覚え方】** `-tln` ＝ **T**CP・**L**ISTEN・**N**umeric。`netstat -r` は `route` と同じ内容。

### 4. nc（netcat / ncat）

任意のポートに接続したり、待ち受けたりできる万能ツール。ポートの疎通確認に使う。

``` bash
# ポートが開いているか確認
nc -zv 192.168.1.20 22
# 1234番で待ち受け（サーバー側）
nc -l 1234
# 接続（クライアント側）
nc 192.168.1.20 1234
# UDPで確認
nc -zvu 192.168.1.20 53
```

| オプション | 意味                                 |
|------------|--------------------------------------|
| `-z`       | データを送らず、接続できるかだけ確認 |
| `-v`       | 結果を詳しく表示                     |
| `-l`       | 待ち受け（listen）                   |
| `-u`       | UDPを使う                            |

pingはICMPなのでポートの確認はできない。「22番ポートに届くか」は nc で調べる。

### 5. ルーティングテーブルの確認と修正

``` bash
$ ip route show
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0
```

- 1行目：デフォルトルート。それ以外あては 192.168.1.1 に渡す。
- 2行目：192.168.1.0/24 あては eth0 から直接送る。

`route -n` の出力（`-n` は名前に変換せず数値で表示）：

| Destination | Gateway     | Genmask       | Flags |
|-------------|-------------|---------------|-------|
| 0.0.0.0     | 192.168.1.1 | 0.0.0.0       | UG    |
| 192.168.1.0 | 0.0.0.0     | 255.255.255.0 | U     |

| フラグ | 意味                   |
|--------|------------------------|
| `U`    | 経路が有効（Up）       |
| `G`    | ゲートウェイを経由する |
| `H`    | 宛先がホスト単位       |

`route -n` では、Destination が `0.0.0.0` の行がデフォルトルート。

誤ったデフォルトルートを直す手順：

``` bash
ip route del default
ip route add default via 192.168.1.1
# 特定のネットワークあての経路を追加
ip route add 10.0.0.0/8 \
  via 192.168.1.254
route add -net 10.0.0.0 \
  netmask 255.0.0.0 gw 192.168.1.254
```

### 6. インターフェースの追加・起動・停止・再起動・削除・再設定

| 操作   | ip / ifconfig / ifup                                         | nmcli                                 |
|--------|--------------------------------------------------------------|---------------------------------------|
| 追加   | `ip addr add`（アドレスを追加）                              | `nmcli connection add`                |
| 起動   | `ip link set eth0 up`、`ifconfig eth0 up`、`ifup eth0`       | `nmcli connection up`                 |
| 停止   | `ip link set eth0 down`、`ifconfig eth0 down`、`ifdown eth0` | `nmcli connection down`               |
| 再起動 | `ifdown eth0` のあと `ifup eth0`                             | `down` のあと `up`                    |
| 削除   | `ip addr del`（アドレスを削除）                              | `nmcli connection delete`             |
| 再設定 | 設定ファイルを直して `ifdown`、`ifup`                        | `nmcli connection modify` のあと `up` |

``` bash
# 再起動（設定ファイルを読み直す）
ifdown eth0
ifup eth0
# 一時的に止める・動かす
ifconfig eth0 down
ifconfig eth0 up
ip link set eth0 down
ip link set eth0 up
# アドレスの付け替え
ip addr del 192.168.1.10/24 dev eth0
ip addr add 192.168.1.11/24 dev eth0
```

``` bash
# 接続（設定）を新規に追加
nmcli connection add type ethernet \
  ifname eth1 con-name eth1
# 接続を削除
nmcli connection delete eth1
# デバイスを切断・接続
nmcli device disconnect eth1
nmcli device connect eth1
# 設定ファイルを読み直す
nmcli connection reload
```

- `ifconfig eth0 down` と `ip link set eth0 down` は、設定ファイルを読まずにその場で止める。
- `ifdown` / `ifup` は設定ファイルに書かれたインターフェースだけ扱える。

`hostname` コマンドも確認に使う。`hostname -I` で自分のIPアドレス、`hostname -f` でFQDN（完全修飾ドメイン名）を表示する。

> **【1.07.3 まとめ】**
>
> - 切り分けは近くから：自分 → ゲートウェイ → 外部IP → 名前 → ポート
> - IPでは届くが名前で届かない → DNS
> - `traceroute` はTTLとICMP時間超過で経路を調べる。`tracepath` はMTUも表示
> - `ss -tln` で待ち受けポート。`-p` でプロセス
> - `nc -zv` でポート確認、`nc -l` で待ち受け
> - `route -n` の `G` はゲートウェイ経由、`0.0.0.0` はデフォルト
> - 接続の追加は `nmcli connection add`、削除は `delete`

## 1.07.4 クライアント側のDNS設定 （重要度2）

### 1. 名前解決の流れ

ホスト名からIPアドレスを調べることを**名前解決**という。調べる順番は `/etc/nsswitch.conf` で決まる。

**［図6　名前解決の流れ］**

1.  `ping www.example.com` などが名前解決を要求する。
2.  `/etc/nsswitch.conf` の `hosts: files dns` で順番を確認する。
3.  files：`/etc/hosts` を調べる。見つかればここで終了。
4.  dns：なければ `/etc/resolv.conf` に書かれたDNSサーバーへ問い合わせる。

### 2. /etc/resolv.conf

問い合わせ先のDNSサーバーを書くファイル。

``` bash
nameserver 192.168.1.1
nameserver 8.8.8.8
search example.com
```

| 項目         | 意味                                                  |
|--------------|-------------------------------------------------------|
| `nameserver` | DNSサーバーのIPアドレス。上から順に使う。**最大3つ**  |
| `search`     | ドメイン名を省略したときに補うドメイン。複数書ける    |
| `domain`     | 自分が属するドメイン名（`search` と同時には使わない） |

`search example.com` があると、`ping www` は `www.example.com` として調べられる。

> **【注意】** NetworkManagerなどが `/etc/resolv.conf` を自動で書き換える環境が多い。手で編集しても上書きされることがある。恒久的に変えるなら `nmcli` の `ipv4.dns` で設定する。

### 3. /etc/nsswitch.conf と /etc/hosts

``` bash
hosts: files dns   # /etc/hosts が先
hosts: dns files   # DNS が先
```

名前解決の**順番を変える**のは `/etc/nsswitch.conf`。**DNSサーバーを指定する**のは `/etc/resolv.conf`。役割を混同しない。

### 4. host

DNSサーバーに問い合わせる、簡潔なコマンド。

``` bash
# 正引き（名前 → IP）
host www.example.com
# 逆引き（IP → 名前）
host 192.0.2.10
# レコードの種類を指定
host -t MX example.com
# 問い合わせ先を指定
host www.example.com 8.8.8.8
```

### 5. dig

DNSの応答を詳しく表示する。調査の定番。

``` bash
dig www.example.com
# レコードの種類を指定
dig example.com MX
# 問い合わせ先のサーバーを指定
dig @8.8.8.8 example.com
# 逆引き
dig -x 192.0.2.10
# 結果だけ簡潔に
dig +short example.com
```

| 出力のセクション | 内容                              |
|------------------|-----------------------------------|
| `QUESTION`       | 問い合わせた内容                  |
| `ANSWER`         | 回答。ここにIPアドレスが出る      |
| `AUTHORITY`      | そのドメインを管理するDNSサーバー |
| `ADDITIONAL`     | 補足情報                          |

出力の末尾にある `SERVER:` で、実際に答えたDNSサーバーが分かる。

| レコード | 内容                            |
|----------|---------------------------------|
| `A`      | ホスト名 → IPv4アドレス         |
| `AAAA`   | ホスト名 → IPv6アドレス         |
| `PTR`    | IPアドレス → ホスト名（逆引き） |
| `MX`     | メールサーバー                  |
| `NS`     | そのドメインのDNSサーバー       |
| `CNAME`  | 別名                            |

> **【ひっかけ】** サーバーの指定は、dig は `@8.8.8.8` を付ける。host は末尾にそのまま書く。逆引きは dig なら `-x`、host はIPアドレスを書くだけ。

### 6. getent

`/etc/nsswitch.conf` の設定に従って情報を引くコマンド。

``` bash
getent hosts www.example.com
getent hosts db01
# ユーザー情報も引ける
getent passwd kuro
```

| コマンド                  | /etc/hosts | 調べ方                        |
|---------------------------|------------|-------------------------------|
| `host` / `dig`            | **見ない** | DNSサーバーに直接問い合わせる |
| `getent hosts`            | 見る       | nsswitch.conf の順番どおり    |
| `ping` など通常のコマンド | 見る       | nsswitch.conf の順番どおり    |

> **【ひっかけ】** `/etc/hosts` にだけ書いた名前は、`ping` や `getent hosts` では解決できるが、`dig` や `host` では見つからない。「実際にシステムがどう解決するか」を確かめるなら `getent hosts`。

> **【1.07.4 まとめ】**
>
> - DNSサーバーの指定は `/etc/resolv.conf` の `nameserver`（最大3つ）
> - 解決の順番は `/etc/nsswitch.conf` の `hosts:` 行
> - `dig @サーバー 名前 種類`、逆引きは `dig -x`
> - `host -t MX` で種類を指定
> - `host` と `dig` は /etc/hosts を見ない。`getent hosts` は見る
> - A＝IPv4、AAAA＝IPv6、PTR＝逆引き、MX＝メール
