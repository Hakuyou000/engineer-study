# LinuC 102 テキスト 1.07 ネットワークの基礎

IP アドレスの仕組み、Linux でのネットワークの設定、つながらないときの調べ方、DNS の設定を学びます。

## 1.07.1 インターネットプロトコルの基礎 (重要度4)

### 1. IP アドレス(IPv4)

IP アドレスは、ネットワーク上の住所です。32 ビットの数値を 8 ビットずつ4つに区切り、それぞれを 10 進数で書きます。区切りの1つ1つをオクテットと呼び、値は 0〜255 です。

IP アドレスは、**ネットワーク部**(どのネットワークか)と **ホスト部**(そのネットワークの中のどの機器か)に分かれます。その境目を決めるのがサブネットマスクです。

**［図1　ネットワーク部とホスト部］**

`192.168.1.10/24` では、`192.168.1` がネットワーク部(24 ビット)、`10` がホスト部(8 ビット)です。サブネットマスクは `255.255.255.0` で、255 の部分がネットワーク部を表します。

### 2. サブネットマスクと CIDR 表記

サブネットマスクを 2 進数で書くと、「1 が並ぶ部分がネットワーク部」になります。**CIDR 表記** は、その 1 の個数を `/24` のように書く方法です。

``` bash
255.255.255.0
= 11111111.11111111.11111111.00000000
= 1 が 24 個 → /24
```

| CIDR | マスク | アドレスの数 | 使えるホストの数 |
|---|---|---|---|
| `/8` | 255.0.0.0 | 約 1677 万 | 16,777,214 |
| `/16` | 255.255.0.0 | 65,536 | 65,534 |
| `/24` | 255.255.255.0 | 256 | 254 |
| `/25` | 255.255.255.128 | 128 | 126 |
| `/26` | 255.255.255.192 | 64 | 62 |
| `/27` | 255.255.255.224 | 32 | 30 |
| `/28` | 255.255.255.240 | 16 | 14 |
| `/29` | 255.255.255.248 | 8 | 6 |
| `/30` | 255.255.255.252 | 4 | 2 |

> **【計算のしかた】** ホスト部が n ビットなら、アドレスの数は 2 の n 乗、使えるホストの数は **2 の n 乗 − 2** です。
> 2 を引くのは、ネットワークアドレス(先頭)とブロードキャストアドレス(末尾)の2つは機器に割り当てられないからです。
> マスクの最後のオクテットの値は「256 − アドレスの数」で求められます。/26 なら 256 − 64 = 192 です。

### 3. ネットワークアドレスとブロードキャストアドレス

| 名前 | ホスト部 | 役割 |
|---|---|---|
| ネットワークアドレス | すべて 0 | ネットワークそのものを表す。機器には割り当てない |
| ブロードキャストアドレス | すべて 1 | 同じネットワークのすべての機器あて。機器には割り当てない |

### 4. サブネット化

1つのネットワークを、マスクを長くして小さく分けることをサブネット化といいます。`192.168.1.0/24` を `/26` にすると、64 個ずつの4つのブロックに分かれます。

**［図2　サブネット化の例］**

| ブロック | ネットワークアドレス | 割り当てられるアドレス | ブロードキャストアドレス |
|---|---|---|---|
| 1 | .0 | .1〜.62 | .63 |
| 2 | .64 | .65〜.126 | .127 |
| 3 | .128 | .129〜.190 | .191 |
| 4 | .192 | .193〜.254 | .255 |

192.168.1.130/26 は、3 番目のブロックに入ります。

> **【解き方(192.168.1.130/26 の場合)】** ① /26 のブロックの大きさは 64 です。
> ② 64 の倍数で区切ります: 0、64、128、192。
> ③ 130 が入るのは 128〜191 の範囲です。
> ④ 先頭の 128 がネットワークアドレス、末尾の 191 がブロードキャストアドレスです。

> **【ひっかけ】** `192.168.1.100/25` と `192.168.1.130/25` は、別のネットワーク(0〜127 と 128〜255)です。アドレスの見た目が近くても、ルーターを通さないと通信できません。

### 5. アドレスクラスとプライベートアドレス

昔は、先頭のオクテットの値で、アドレスをクラスに分けていました。

| クラス | 先頭のオクテット | 標準のマスク |
|---|---|---|
| A | 0〜127 | /8 |
| B | 128〜191 | /16 |
| C | 192〜223 | /24 |
| D | 224〜239 | マルチキャスト用 |

**プライベートアドレス** は、社内や家庭の中で自由に使える範囲のアドレスです。そのままではインターネットに出られないので、NAT という仕組みでグローバル(パブリック)アドレスに変換して通信します。

| クラス | 範囲 | CIDR |
|---|---|---|
| A | 10.0.0.0 〜 10.255.255.255 | `10.0.0.0/8` |
| B | 172.16.0.0 〜 172.31.255.255 | `172.16.0.0/12` |
| C | 192.168.0.0 〜 192.168.255.255 | `192.168.0.0/16` |

| 特別なアドレス | 意味 |
|---|---|
| `127.0.0.1` | ループバック。自分自身(localhost)を表す |
| `169.254.0.0/16` | リンクローカル。DHCP でアドレスを取得できなかったときに自動で付く |
| `0.0.0.0` | 「すべて」や「未指定」を表す。デフォルトルートのあて先など |

> **【ひっかけ】** クラス B のプライベートアドレスは 172.**16**〜172.**31** だけです。`172.32.0.1` や `172.15.0.1` はグローバルアドレスです。

### 6. ポート番号

IP アドレスが「建物の住所」なら、ポート番号は「部屋の番号」です。1台のサーバーの中で、どのサービスあての通信かを区別します。範囲は 0〜65535 です。

| 範囲 | 名前 |
|---|---|
| 0〜1023 | ウェルノウンポート。主なサービスが使う。このポートで待ち受けるには root の権限が必要 |
| 1024〜49151 | 登録済みポート |
| 49152〜65535 | 動的ポート。クライアント側が一時的に使う |

| 番号 | サービス | プロトコル |
|---|---|---|
| 20, 21 | FTP(データ, 制御) | TCP |
| **22** | **SSH** | TCP |
| 23 | Telnet | TCP |
| **25** | **SMTP**(メールの送信) | TCP |
| **53** | **DNS** | UDP / TCP |
| **80** | **HTTP** | TCP |
| 110 | POP3(メールの受信) | TCP |
| **123** | **NTP**(時刻の同期) | UDP |
| 143 | IMAP(メールの受信) | TCP |
| **443** | **HTTPS** | TCP |

太字の6つは、公式の出題範囲に書かれているので必ず覚えます。サービス名とポート番号の対応表は `/etc/services` にあります。

### 7. TCP・UDP・ICMP

| | TCP | UDP |
|---|---|---|
| 接続 | コネクション型。通信の前に接続を確立する | コネクションレス型。いきなりデータを送る |
| 信頼性 | 高い。届いたかの確認、再送、順番の制御がある | 低い。届いたかを確認しない |
| 速さ | やや遅い | 速い。処理の負担が小さい |
| 用途 | HTTP、SSH、SMTP | DNS、NTP、DHCP、動画や音声 |

TCP は、通信を始める前に3回のやり取りで接続を確立します(**3ウェイハンドシェイク**)。

**［図3　TCP の3ウェイハンドシェイク］**

1. クライアント → サーバー: SYN(接続したい)
2. サーバー → クライアント: SYN + ACK(了解、こちらからも接続したい)
3. クライアント → サーバー: ACK(了解)

これで接続が確立し、データを送れるようになります。

**ICMP** は、通信の状態やエラーを伝えるためのプロトコルです。データを運ぶことが目的ではなく、**ポート番号を持ちません**。

- `ping`: エコー要求を送り、エコー応答が返ってくるかで、相手に届くかを確かめます。
- `traceroute`: 経路の途中のルーターが返す「時間超過」のメッセージを使って、経路を調べます。
- 「宛先到達不能」のようなエラーの通知も ICMP で送られます。

### 8. IPv6

IPv6 は、IPv4 のアドレスが足りなくなる問題に対応するための、新しい IP です。アドレスは **128 ビット** で、16 ビットずつ8つに区切り、**16 進数** で書いて `:`(コロン)でつなぎます。

**省略のルール** は2つです。

``` bash
2001:0db8:0000:0000:0000:0000:0000:0001
① 各区切りの先頭の 0 は省略できる
2001:db8:0:0:0:0:0:1
② 0 だけの区切りが続く部分は :: にまとめられる
2001:db8::1
```

> **【ひっかけ】** `::` を使えるのは **1か所だけ** です。2か所に使うと、それぞれ何個の 0 を省略したのか分からなくなります。`2001::db8::1` は誤りです。

| アドレス | 意味 |
|---|---|
| `::1` | ループバック(IPv4 の 127.0.0.1 と同じ) |
| `fe80::/10` | リンクローカル。同じリンクの中だけで使える。自動で付く |
| `2000::/3` | グローバルユニキャスト。インターネットで使う |
| `fc00::/7` | ユニークローカル(IPv4 のプライベートアドレスにあたる) |
| `ff00::/8` | マルチキャスト |

| | IPv4 | IPv6 |
|---|---|---|
| 長さ | 32 ビット | 128 ビット |
| 書き方 | 10 進数、`.` で区切る | 16 進数、`:` で区切る |
| ブロードキャスト | ある | **ない**(マルチキャストで代用する) |
| 自動設定 | DHCP が必要 | ルーターからの情報で自動で作れる(SLAAC) |
| IPsec | オプション | 標準で対応 |
| ヘッダ | 長さが変わり、複雑 | 長さが固定で、簡単になった |
| NAT | 広く使われている | 基本的に不要 |

IPv6 のプレフィックス長は、普通 `/64` です。前半の 64 ビットがネットワーク、後半の 64 ビットがインターフェース ID(機器を表す部分)です。

> **【1.07.1 まとめ】**
>
> - ホストの数は 2 の n 乗 − 2。/24 は 254、/26 は 62、/27 は 30
> - ホスト部がすべて 0 ならネットワークアドレス、すべて 1 ならブロードキャストアドレス
> - プライベートアドレス: 10/8、172.16/12、192.168/16
> - 22 SSH、25 SMTP、53 DNS、80 HTTP、123 NTP、443 HTTPS
> - TCP は信頼性、UDP は速さ、ICMP は状態の通知(ping)
> - IPv6 は 128 ビットの 16 進数。`::` は1回だけ。ブロードキャストはない

## 1.07.2 基本的なネットワーク構成 (重要度4)

### 1. 古いコマンドと新しいコマンドの対応

ネットワークの設定のコマンドは、古い net-tools から新しい iproute2 に移り変わっています。試験には両方が出ます。

| 用途 | 古いコマンド(net-tools) | 新しいコマンド(iproute2) |
|---|---|---|
| IP アドレス | `ifconfig` | `ip addr` |
| インターフェースの有効・無効 | `ifconfig eth0 up` | `ip link set eth0 up` |
| ルーティング | `route` | `ip route` |
| 接続とポート | `netstat` | `ss` |

### 2. ip コマンド

``` bash
# アドレスを表示する(ip a でもよい)
ip addr show
ip addr show dev eth0
# アドレスを追加・削除する
ip addr add 192.168.1.10/24 dev eth0
ip addr del 192.168.1.10/24 dev eth0
# インターフェースを有効・無効にする
ip link set eth0 up
ip link set eth0 down
# インターフェースの状態を表示する
ip link show
```

`ip addr show` の出力の読み方:

``` bash
2: eth0: <BROADCAST,UP,LOWER_UP>
   state UP
  link/ether 52:54:00:12:34:56
  inet 192.168.1.10/24
       brd 192.168.1.255
  inet6 fe80::5054:ff:fe12:3456/64
```

| 項目 | 意味 |
|---|---|
| `UP` / `state UP` | インターフェースが有効 |
| `link/ether` | MAC アドレス |
| `inet` | IPv4 アドレスとプレフィックス長 |
| `brd` | ブロードキャストアドレス |
| `inet6` | IPv6 アドレス |

`lo` はループバックのインターフェース(127.0.0.1)です。

### 3. ifconfig / ifup / ifdown

``` bash
# 表示する(-a を付けると無効なインターフェースも表示)
ifconfig
ifconfig -a
# アドレスを設定して有効にする
ifconfig eth0 192.168.1.10 \
  netmask 255.255.255.0 up
# 無効にする
ifconfig eth0 down
```

`ifup` と `ifdown` は、**設定ファイルの内容に従って** インターフェースを有効・無効にします。

``` bash
ifup eth0
ifdown eth0
```

| 系統 | 設定ファイル |
|---|---|
| Debian 系 | `/etc/network/interfaces` |
| Red Hat 系 | `/etc/sysconfig/network-scripts/ifcfg-eth0` |

### 4. 手動の設定(static)と自動の設定(DHCP)

インターフェースの設定の方法は2つあります。公式の出題範囲の「手作業および自動で行う」がこれにあたります。

| 方法 | 内容 |
|---|---|
| 手動(static) | IP アドレスなどを自分で決めて書く。サーバーに向いている |
| 自動(DHCP) | DHCP サーバーから受け取る。クライアントに向いている |

DHCP で受け取る主な情報: IP アドレス、サブネットマスク、デフォルトゲートウェイ、DNS サーバー。

**Debian 系**: `/etc/network/interfaces`

``` bash
# 自動(DHCP)
auto eth0
iface eth0 inet dhcp

# 手動(static)
auto eth0
iface eth0 inet static
    address 192.168.1.10
    netmask 255.255.255.0
    gateway 192.168.1.1
```

**Red Hat 系**: `/etc/sysconfig/network-scripts/ifcfg-eth0`

``` bash
# 自動(DHCP)
DEVICE=eth0
BOOTPROTO=dhcp
ONBOOT=yes

# 手動(static)
DEVICE=eth0
BOOTPROTO=none
ONBOOT=yes
IPADDR=192.168.1.10
PREFIX=24
GATEWAY=192.168.1.1
DNS1=8.8.8.8
```

| 項目 | 意味 |
|---|---|
| `auto eth0` / `ONBOOT=yes` | 起動時に自動で有効にする |
| `inet dhcp` / `BOOTPROTO=dhcp` | DHCP でアドレスを取得する |
| `inet static` / `BOOTPROTO=none`(または `static`) | 固定のアドレスを使う |

ファイルを書き換えたら、`ifdown eth0` と `ifup eth0` で読み直します。

DHCP のクライアントを手で動かすコマンドは `dhclient` です。

``` bash
dhclient eth0      # アドレスを取得する
dhclient -r eth0   # アドレスを返す
```

NetworkManager を使う環境では、`nmcli` の `ipv4.method` で切り替えます(次の節)。

> **【ひっかけ: 一時的か、永続的か】** `ip`、`ifconfig`、`route` での設定は、**再起動すると消えます**。再起動後も残すには、設定ファイルに書くか `nmcli` を使います。

### 5. nmcli(NetworkManager)

NetworkManager をコマンドで操作します。設定は保存され、再起動後も残ります。

| 用語 | 意味 |
|---|---|
| device | ネットワークインターフェースそのもの(eth0 など) |
| connection | デバイスに適用する設定のまとまり |

``` bash
# デバイスの状態を表示する
nmcli device status
# 接続(設定)の一覧を表示する
nmcli connection show
# 接続を有効・無効にする
nmcli connection up eth0
nmcli connection down eth0
# 固定の IP アドレスに変更する
nmcli connection modify eth0 \
  ipv4.method manual \
  ipv4.addresses 192.168.1.10/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns 8.8.8.8
# 変更を反映する
nmcli connection up eth0
# ホスト名を表示・変更する
nmcli general hostname
nmcli general hostname web01
```

- `ipv4.method` は、`manual` が固定、`auto` が DHCP です。
- `modify` しただけでは反映されません。`up` で有効にし直します。
- `nmcli d`、`nmcli c`、`nmcli con mod` のような省略形も使えます。

### 6. ホスト名

``` bash
# 表示する
hostname
# 一時的に変更する
hostname web01
# 再起動後も残るように変更する
hostnamectl set-hostname web01
```

ホスト名は `/etc/hostname` に保存され、起動時に読み込まれます。

### 7. /etc/hosts

IP アドレスとホスト名の対応を書くファイルです。DNS を使わずに名前解決できます。

``` bash
# IP アドレス  ホスト名  別名...
127.0.0.1    localhost
192.168.1.20 db01.example.com db01
```

書き方は「**IP アドレスが先**、ホスト名が後」です。別名は空白で区切って並べます。

### 8. /etc/nsswitch.conf

名前解決などで、「何を、どの順番で調べるか」を決めるファイルです。

``` bash
hosts: files dns
```

- `files` は `/etc/hosts`、`dns` は DNS サーバーを表します。
- 左から順に調べます。この例は「まず /etc/hosts を調べ、なければ DNS」です。

### 9. ping

ICMP のエコー要求を送り、相手に届くかを確かめます。

``` bash
ping 192.168.1.1
# 4 回送って終了する
ping -c 4 192.168.1.1
# 2 秒の間隔で送る
ping -i 2 192.168.1.1
# IPv6
ping6 ::1
```

Linux の ping は、`-c` を付けないと止まりません。Ctrl+C で終了します。

### 10. デフォルトルート(デフォルトゲートウェイ)

同じネットワークの相手には、直接データを送れます。それ以外のネットワークあての通信は、出口になるルーターに渡します。この出口が **デフォルトゲートウェイ** です。

**［図4　デフォルトゲートウェイ］**

自分(192.168.1.10)から、同じ LAN の機器(.20)へは直接送ります。あて先が自分のネットワーク(192.168.1.0/24)の外なら、ゲートウェイ(.1)に渡し、そこから他のネットワークへ届けてもらいます。

``` bash
# 表示する
ip route show
route -n
# デフォルトルートを追加する
ip route add default via 192.168.1.1
route add default gw 192.168.1.1
# 削除する
ip route del default
route del default gw 192.168.1.1
```

> **【ひっかけ】** ゲートウェイの指定は、`ip route` では **`via`**、`route` では **`gw`** です。入れ替えた選択肢に注意します。

> **【1.07.2 まとめ】**
>
> - `ip addr`(アドレス)、`ip link`(有効・無効)、`ip route`(経路)
> - `ip` や `ifconfig` の設定は再起動で消える。残すには設定ファイルか `nmcli`
> - `nmcli` は `modify` の後に `up` で反映する
> - ホスト名は `/etc/hostname`、名前と IP アドレスの対応は `/etc/hosts`
> - `hosts: files dns` は /etc/hosts が先
> - デフォルトルート: `ip route add default via`、`route add default gw`
> - 自動の設定は DHCP。`inet dhcp`、`BOOTPROTO=dhcp`、`ipv4.method auto`

## 1.07.3 基本的なネットワークの問題解決 (重要度4)

### 1. 原因を絞り込む順番

つながらないときは、自分に近いところから順に確認します。どの段階で失敗するかで、原因の場所が分かります。

**［図5　原因を絞り込む流れ］**

| 順番 | 確認すること | コマンド |
|---|---|---|
| ① | 自分のインターフェースと IP アドレスは正しいか | `ip addr`、`ip link` |
| ② | デフォルトゲートウェイに届くか | `ping 192.168.1.1`、`ip route` |
| ③ | 外部の IP アドレスに届くか | `ping 8.8.8.8`、`traceroute` |
| ④ | 名前解決できるか | `host`、`dig`、`/etc/resolv.conf` |
| ⑤ | 目的のポートは開いているか | `nc -zv`、`ss -tln` |

| 症状 | 疑う場所 |
|---|---|
| ② で失敗する | 自分の IP アドレスの設定、ケーブル、LAN の中 |
| ② は成功し、③ で失敗する(`Network is unreachable`) | デフォルトルートがない、または誤っている |
| ③ は成功し、名前を使うと失敗する(`Name or service not known`) | DNS の設定(/etc/resolv.conf) |
| ping は通るが、サービスにつながらない | ポートが閉じている、ファイアウォール、サービスが止まっている |

### 2. traceroute / tracepath

あて先までに通るルーターを、順に表示します。どこで止まっているかが分かります。

``` bash
traceroute www.example.com
# 名前解決をしない(速い)
traceroute -n 8.8.8.8
# ICMP で送る
traceroute -I 8.8.8.8
# IPv6
traceroute6 2001:db8::1
tracepath 8.8.8.8
tracepath6 2001:db8::1
```

仕組み: TTL(通過できるルーターの数の上限)を 1、2、3…と増やしながらパケットを送ります。TTL が 0 になったルーターは ICMP の「時間超過」を返すので、それを順に集めると経路が分かります。

| | traceroute | tracepath |
|---|---|---|
| 送るパケット | 既定は UDP(`-I` で ICMP) | UDP |
| 権限 | 一部のオプションは root が必要 | 一般ユーザーで使える |
| 特徴 | オプションが多い | 経路の **MTU**(通れるパケットの最大の大きさ。PMTU)も表示する |

応答のないルーターは、`* * *` と表示されます。

### 3. ss / netstat

開いているポートや、接続の状態を表示します。`netstat` が古いコマンド、`ss` が新しいコマンドで、主なオプションは同じです。

| オプション | 意味 |
|---|---|
| `-t` | TCP |
| `-u` | UDP |
| `-l` | 待ち受け中(LISTEN)のものだけ |
| `-a` | すべて(待ち受け中と接続中) |
| `-n` | 名前に変換せず、番号で表示する |
| `-p` | 使っているプロセスを表示する |

``` bash
# 待ち受け中の TCP を番号で表示する
ss -tln
netstat -tln
# プロセスも表示する
ss -tlnp
# すべて表示する
ss -an
# ルーティングテーブルを表示する
netstat -r
# インターフェースごとの統計を表示する
netstat -i
```

``` bash
State   Local Address:Port
LISTEN  0.0.0.0:22
LISTEN  127.0.0.1:25
```

- `0.0.0.0:22`: すべてのアドレスで 22 番を待ち受けています。外部からも接続できます。
- `127.0.0.1:25`: 自分自身からしか接続できません。

> **【覚え方】** `-tln` は **T**CP・**L**ISTEN・**N**umeric(数値)です。`netstat -r` は `route` と同じ内容を表示します。

### 4. nc(netcat / ncat)

任意のポートに接続したり、待ち受けたりできる、便利なツールです。ポートに届くかの確認に使います。

``` bash
# ポートが開いているかを確かめる
nc -zv 192.168.1.20 22
# 1234 番で待ち受ける(サーバー側)
nc -l 1234
# 接続する(クライアント側)
nc 192.168.1.20 1234
# UDP で確かめる
nc -zvu 192.168.1.20 53
```

| オプション | 意味 |
|---|---|
| `-z` | データを送らず、接続できるかだけを確かめる |
| `-v` | 結果を詳しく表示する |
| `-l` | 待ち受ける(listen) |
| `-u` | UDP を使う |

ping は ICMP を使うので、ポートの確認はできません。「22 番ポートに届くか」は nc で調べます。

### 5. ルーティングテーブルの確認と修正

``` bash
$ ip route show
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0
```

- 1 行目: デフォルトルートです。他に当てはまらないあて先は、192.168.1.1 に渡します。
- 2 行目: 192.168.1.0/24 あては、eth0 から直接送ります。

`route -n` の出力(`-n` は名前に変換せず、番号で表示する):

| Destination | Gateway | Genmask | Flags |
|---|---|---|---|
| 0.0.0.0 | 192.168.1.1 | 0.0.0.0 | UG |
| 192.168.1.0 | 0.0.0.0 | 255.255.255.0 | U |

| フラグ | 意味 |
|---|---|
| `U` | 経路が有効(Up) |
| `G` | ゲートウェイを経由する |
| `H` | あて先が1台のホスト |

`route -n` では、Destination が `0.0.0.0` の行がデフォルトルートです。

誤ったデフォルトルートを直す手順:

``` bash
ip route del default
ip route add default via 192.168.1.1
# 特定のネットワークあての経路を追加する
ip route add 10.0.0.0/8 \
  via 192.168.1.254
route add -net 10.0.0.0 \
  netmask 255.0.0.0 gw 192.168.1.254
```

### 6. インターフェースの追加・起動・停止・再起動・削除・再設定

| 操作 | ip / ifconfig / ifup | nmcli |
|---|---|---|
| 追加 | `ip addr add`(アドレスを追加) | `nmcli connection add` |
| 起動 | `ip link set eth0 up`、`ifconfig eth0 up`、`ifup eth0` | `nmcli connection up` |
| 停止 | `ip link set eth0 down`、`ifconfig eth0 down`、`ifdown eth0` | `nmcli connection down` |
| 再起動 | `ifdown eth0` の後に `ifup eth0` | `down` の後に `up` |
| 削除 | `ip addr del`(アドレスを削除) | `nmcli connection delete` |
| 再設定 | 設定ファイルを直して `ifdown`、`ifup` | `nmcli connection modify` の後に `up` |

``` bash
# 再起動する(設定ファイルを読み直す)
ifdown eth0
ifup eth0
# 一時的に止める・動かす
ifconfig eth0 down
ifconfig eth0 up
ip link set eth0 down
ip link set eth0 up
# アドレスを付け替える
ip addr del 192.168.1.10/24 dev eth0
ip addr add 192.168.1.11/24 dev eth0
```

``` bash
# 接続(設定)を新しく追加する
nmcli connection add type ethernet \
  ifname eth1 con-name eth1
# 接続を削除する
nmcli connection delete eth1
# デバイスを切断・接続する
nmcli device disconnect eth1
nmcli device connect eth1
# 設定ファイルを読み直す
nmcli connection reload
```

- `ifconfig eth0 down` と `ip link set eth0 down` は、設定ファイルを読まずに、その場でインターフェースを止めます。
- `ifdown` と `ifup` は、設定ファイルに書かれたインターフェースだけを扱えます。

`hostname` コマンドも確認に使えます。`hostname -I` で自分の IP アドレスを、`hostname -f` で FQDN(ホスト名とドメイン名をつなげた名前)を表示します。

> **【1.07.3 まとめ】**
>
> - 原因は近くから絞り込む: 自分 → ゲートウェイ → 外部の IP アドレス → 名前 → ポート
> - IP アドレスでは届くが名前では届かない → DNS
> - `traceroute` は TTL と ICMP の時間超過で経路を調べる。`tracepath` は MTU も表示する
> - `ss -tln` で待ち受け中のポート。`-p` でプロセスも
> - `nc -zv` でポートの確認、`nc -l` で待ち受け
> - `route -n` の `G` はゲートウェイを経由、`0.0.0.0` はデフォルトルート
> - 接続の追加は `nmcli connection add`、削除は `delete`

## 1.07.4 クライアント側の DNS 設定 (重要度2)

### 1. 名前解決の流れ

ホスト名から IP アドレスを調べることを、**名前解決** といいます。調べる順番は `/etc/nsswitch.conf` で決まります。

**［図6　名前解決の流れ］**

1. `ping www.example.com` などのコマンドが、名前解決を要求します。
2. `/etc/nsswitch.conf` の `hosts: files dns` で、調べる順番を確認します。
3. files: まず `/etc/hosts` を調べます。見つかれば、ここで終わりです。
4. dns: 見つからなければ、`/etc/resolv.conf` に書かれた DNS サーバーに問い合わせます。

### 2. /etc/resolv.conf

問い合わせ先の DNS サーバーを書くファイルです。

``` bash
nameserver 192.168.1.1
nameserver 8.8.8.8
search example.com
```

| 項目 | 意味 |
|---|---|
| `nameserver` | DNS サーバーの IP アドレス。上から順に使う。**最大3つ** |
| `search` | ドメイン名を省略したときに補うドメイン。複数書ける |
| `domain` | 自分が属するドメイン名(`search` と一緒には使わない) |

`search example.com` があると、`ping www` は `www.example.com` として問い合わせられます。

> **【注意】** NetworkManager などが `/etc/resolv.conf` を自動で書き換える環境が多く、手で編集しても上書きされることがあります。ずっと変えておきたいときは、`nmcli` の `ipv4.dns` で設定します。

### 3. /etc/nsswitch.conf と /etc/hosts

``` bash
hosts: files dns   # /etc/hosts が先
hosts: dns files   # DNS が先
```

名前解決の **順番を変える** のは `/etc/nsswitch.conf`、**DNS サーバーを指定する** のは `/etc/resolv.conf` です。役割を混同しないようにします。

### 4. host

DNS サーバーに問い合わせる、シンプルなコマンドです。

``` bash
# 正引き(名前 → IP アドレス)
host www.example.com
# 逆引き(IP アドレス → 名前)
host 192.0.2.10
# レコードの種類を指定する
host -t MX example.com
# 問い合わせ先を指定する
host www.example.com 8.8.8.8
```

### 5. dig

DNS の応答を詳しく表示します。DNS を調べるときによく使います。

``` bash
dig www.example.com
# レコードの種類を指定する
dig example.com MX
# 問い合わせ先のサーバーを指定する
dig @8.8.8.8 example.com
# 逆引き
dig -x 192.0.2.10
# 結果だけを短く表示する
dig +short example.com
```

| 出力のセクション | 内容 |
|---|---|
| `QUESTION` | 問い合わせた内容 |
| `ANSWER` | 回答。ここに IP アドレスが表示される |
| `AUTHORITY` | そのドメインを管理する DNS サーバー |
| `ADDITIONAL` | 補足の情報 |

出力の最後のほうにある `SERVER:` で、実際に答えた DNS サーバーが分かります。

| レコード | 内容 |
|---|---|
| `A` | ホスト名 → IPv4 アドレス |
| `AAAA` | ホスト名 → IPv6 アドレス |
| `PTR` | IP アドレス → ホスト名(逆引き) |
| `MX` | メールサーバー |
| `NS` | そのドメインの DNS サーバー |
| `CNAME` | 別名 |

> **【ひっかけ】** 問い合わせ先のサーバーは、dig では `@8.8.8.8` のように `@` を付けて書き、host では最後にそのまま書きます。逆引きは、dig なら `-x`、host なら IP アドレスを書くだけです。

### 6. getent

`/etc/nsswitch.conf` の設定に従って、情報を引くコマンドです。

``` bash
getent hosts www.example.com
getent hosts db01
# ユーザーの情報も引ける
getent passwd sato
```

| コマンド | /etc/hosts | 調べ方 |
|---|---|---|
| `host` / `dig` | **見ない** | DNS サーバーに直接問い合わせる |
| `getent hosts` | 見る | nsswitch.conf の順番どおりに調べる |
| `ping` など普通のコマンド | 見る | nsswitch.conf の順番どおりに調べる |

> **【ひっかけ】** `/etc/hosts` だけに書いた名前は、`ping` や `getent hosts` では解決できますが、`dig` や `host` では見つかりません。「システムが実際にどう名前解決するか」を確かめるときは `getent hosts` を使います。

> **【1.07.4 まとめ】**
>
> - DNS サーバーの指定は `/etc/resolv.conf` の `nameserver`(最大3つ)
> - 名前解決の順番は `/etc/nsswitch.conf` の `hosts:` 行
> - `dig @サーバー 名前 種類`、逆引きは `dig -x`
> - `host -t MX` でレコードの種類を指定する
> - `host` と `dig` は /etc/hosts を見ない。`getent hosts` は見る
> - A は IPv4、AAAA は IPv6、PTR は逆引き、MX はメール
