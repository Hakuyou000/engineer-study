# LinuC 102 テキスト 1.08 システム管理

ユーザーとグループの管理、決まった時刻に処理を動かす仕組み(ジョブスケジューリング)、言語や文字コードの設定を学びます。

## 1.08.1 アカウント管理 (重要度5)

### 1. アカウントの情報を持つファイル

| ファイル | 内容 | 読める人 |
|---|---|---|
| `/etc/passwd` | ユーザーの基本の情報 | 全員 |
| `/etc/shadow` | 暗号化されたパスワードと有効期限 | root だけ |
| `/etc/group` | グループの情報 | 全員 |
| `/etc/gshadow` | グループのパスワード | root だけ |

### 2. /etc/passwd

1人のユーザーを1行で表し、`:` で区切った7つの項目(フィールド)が並びます。

``` bash
sato:x:1000:1000:Sato:/home/sato:/bin/bash
```

| 番号 | 内容 | 例 |
|---|---|---|
| 1 | ユーザー名 | sato |
| 2 | パスワード(`x` は /etc/shadow に保存されているという意味) | x |
| 3 | UID(ユーザーの番号) | 1000 |
| 4 | GID(プライマリグループの番号) | 1000 |
| 5 | コメント(GECOS。氏名など) | Sato |
| 6 | ホームディレクトリ | /home/sato |
| 7 | ログインシェル | /bin/bash |

- UID 0 は root です。1〜999 はシステム用のアカウント、1000 以降が一般ユーザーです(ディストリビューションによって違います)。
- シェルが `/sbin/nologin` や `/bin/false` のアカウントは、ログインできません。サービス用のアカウントに使います。

### 3. /etc/shadow

`:` で区切った9つの項目が並びます。

``` bash
sato:$6$abc...:20409:0:99999:7:::
```

| 番号 | 内容 |
|---|---|
| 1 | ユーザー名 |
| 2 | 暗号化されたパスワード |
| 3 | パスワードを最後に変更した日(1970年1月1日からの日数) |
| 4 | 次に変更できるようになるまでの最短の日数 |
| 5 | パスワードの有効期限(最長の日数) |
| 6 | 期限が切れる何日前から警告するか |
| 7 | 期限が切れてから、アカウントが無効になるまでの日数 |
| 8 | アカウントの失効日(1970年1月1日からの日数) |
| 9 | 予約(使われていない) |

パスワードの欄が `!` や `*` で始まるアカウントは、パスワードではログインできません(ロックされているか、パスワードが設定されていない状態)。

### 4. /etc/group

`:` で区切った4つの項目が並びます。

``` bash
sales:x:1001:sato,suzuki
```

| 番号 | 内容 |
|---|---|
| 1 | グループ名 |
| 2 | グループのパスワード(普通は `x`) |
| 3 | GID |
| 4 | このグループをセカンダリグループにしているユーザー(`,` で区切る) |

| 種類 | 記録されている場所 | 数 |
|---|---|---|
| プライマリグループ | `/etc/passwd` の4番目の項目 | 1つだけ |
| セカンダリグループ | `/etc/group` の4番目の項目 | 複数でもよい |

ユーザーが新しくファイルを作ったとき、そのファイルの所有グループはプライマリグループになります。

### 5. useradd

新しいユーザーを作るコマンドです。

``` bash
useradd sato
useradd -m -s /bin/bash -G sales sato
```

| オプション | 意味 |
|---|---|
| `-c` | コメント |
| `-d` | ホームディレクトリのパス |
| `-m` | ホームディレクトリを作る |
| `-s` | ログインシェル |
| `-u` | UID |
| `-g` | プライマリグループ |
| `-G` | セカンダリグループ(`,` で区切って複数指定できる) |
| `-e` | アカウントの失効日(YYYY-MM-DD) |
| `-k` | スケルトンディレクトリを指定する |
| `-D` | 既定値を表示・変更する |

- 作った直後はパスワードが設定されていないので、ログインできません。`passwd sato` で設定します。
- ホームディレクトリを自動で作るかどうかは環境によって違います。確実に作るには `-m` を付けます。

既定値は `/etc/default/useradd` に書かれていて、`useradd -D` で表示できます。

``` bash
$ useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel
CREATE_MAIL_SPOOL=yes
```

``` bash
# 既定のシェルを変更する
useradd -D -s /bin/zsh
```

UID の範囲や、パスワードの有効期限の既定値は `/etc/login.defs` にあります(`UID_MIN`、`PASS_MAX_DAYS` など)。

### 6. /etc/skel(スケルトンディレクトリ)

新しいユーザーのホームディレクトリに、ひな形としてコピーされるファイルを置く場所です。

``` bash
$ ls -a /etc/skel
.bash_logout  .bash_profile  .bashrc
```

- ホームディレクトリを作るときに、中身がそのままコピーされます。
- 全員に配りたい初期の設定ファイルは、ここに置きます。
- 中身を変えても、**すでにいるユーザーのホームディレクトリには反映されません**。

### 7. usermod

すでにいるユーザーの情報を変更します。オプションの多くは useradd と同じです。

``` bash
usermod -s /bin/zsh sato
usermod -aG wheel sato
usermod -L sato
```

| オプション | 意味 |
|---|---|
| `-c` `-s` `-u` `-g` `-e` | useradd と同じ |
| `-d パス` | ホームディレクトリを変更する(`-m` も付けると中身も移動する) |
| `-G` | セカンダリグループを **置き換える** |
| `-aG` | セカンダリグループに **追加する** |
| `-l` | ログイン名を変更する |
| `-L` | アカウントをロックする |
| `-U` | ロックを解除する |

> **【ひっかけ】**
>
> `usermod -G wheel sato` は、今のセカンダリグループからすべて外して、wheel だけにします。追加したいときは `-aG` を使います。

### 8. userdel

``` bash
userdel sato       # ホームディレクトリは残る
userdel -r sato    # ホームディレクトリも削除する
```

`-r` を付けると、ホームディレクトリとメールの保存場所(メールスプール)も削除します。

### 9. passwd

``` bash
passwd             # 自分のパスワードを変更する
passwd sato        # 他のユーザーのパスワードを変更する(root だけ)
```

| オプション | 意味 |
|---|---|
| `-l` | ロックする(一時的に使えなくする) |
| `-u` | ロックを解除する |
| `-d` | パスワードを削除する(空にする) |
| `-e` | 期限切れにして、次のログインでパスワードの変更を強制する |
| `-S` | 状態を表示する |

アカウントを一時的に止めるには、`passwd -l` か `usermod -L` を使います。どちらも /etc/shadow のパスワードの先頭に `!` を付けます。

### 10. グループの管理

``` bash
groupadd sales
groupadd -g 2000 dev
groupmod -n marketing sales
groupmod -g 2001 dev
groupdel dev
```

| コマンド | 意味 |
|---|---|
| `groupadd -g GID 名前` | GID を指定してグループを作る |
| `groupmod -n 新しい名前 古い名前` | グループ名を変更する |
| `groupmod -g GID 名前` | GID を変更する |
| `groupdel 名前` | グループを削除する |

- どこかのユーザーがプライマリグループにしているグループは、groupdel で削除できません。
- 補足: `gpasswd -a sato sales` でグループにユーザーを追加し、`gpasswd -d sato sales` で外せます。

### 11. id と getent

``` bash
$ id sato
uid=1000(sato) gid=1000(sato)
  groups=1000(sato),1001(sales)
```

| コマンド | 表示されるもの |
|---|---|
| `id` | 自分の UID、GID、所属するグループ |
| `id -u` / `id -g` / `id -G` | UID だけ / プライマリグループの GID だけ / すべてのグループの GID |
| `id -un` | ユーザー名 |
| `groups sato` | 所属するグループの名前 |

``` bash
getent passwd sato
getent group sales
getent passwd
```

`getent` は `/etc/nsswitch.conf` の設定に従って情報を引きます。`/etc/passwd` だけでなく、LDAP などで管理されているユーザーも表示できます。`grep sato /etc/passwd` では、ローカルのファイルしか見られません。

> **【1.08.1 まとめ】**
>
> - /etc/passwd は7項目、/etc/shadow は9項目、/etc/group は4項目
> - パスワードの実体は /etc/shadow にあり、root しか読めない
> - `useradd -m` でホームディレクトリを作る。ひな形は `/etc/skel`、既定値は `/etc/default/useradd`
> - `usermod -G` は置き換え、`-aG` は追加
> - `userdel -r` でホームディレクトリも削除する
> - 一時的に止めるのは `passwd -l` か `usermod -L`
> - `id` で所属を確認し、`getent` は nsswitch.conf に従って情報を引く

## 1.08.2 ジョブスケジューリング (重要度4)

### 1. 3つの仕組み

| 仕組み | 用途 | デーモン |
|---|---|---|
| cron | 決まった日時に **くり返し** 実行する | crond(cron) |
| anacron | 日単位でくり返す。電源が切れていて実行できなかった分を、起動後に実行する | なし(cron などから起動される) |
| at | 指定した日時に **1回だけ** 実行する | atd |

### 2. crontab コマンド

ユーザーごとの、くり返し実行するジョブを登録します。

| コマンド | 意味 |
|---|---|
| `crontab -e` | 編集する |
| `crontab -l` | 表示する |
| `crontab -r` | **すべて削除する** |
| `crontab -u sato -l` | 他のユーザーを指定する(root だけ) |
| `crontab ファイル` | ファイルの内容で置き換える |

- 登録した内容は、`/var/spool/cron/` の下にユーザー名のファイルとして保存されます(Debian 系は `/var/spool/cron/crontabs/`)。
- このファイルは直接編集せず、必ず `crontab -e` を使います。

> **【ひっかけ】**
>
> `crontab -r` は確認なしで、すべてのジョブを消します。キーボードで `-e` の e と r が隣なので、打ち間違えによる事故がよくあります。`-i` を付けると、削除の前に確認されます。

### 3. crontab の書き方

**［図1　crontab の書き方］**

左から **分(0-59)、時(0-23)、日(1-31)、月(1-12)、曜日(0-7。0 と 7 が日曜日)、コマンド** の順に書きます。例えば `30 2 * * 1 /usr/local/bin/backup.sh` は、毎週月曜日の 2:30 に実行されます。

| 記号 | 意味 | 例 |
|---|---|---|
| `*` | すべて | `* * * * *` 毎分 |
| `,` | 複数の指定 | `0,30` 0 分と 30 分 |
| `-` | 範囲 | `1-5` 月曜日から金曜日 |
| `/` | 間隔 | `*/10` 10 分ごと |

| 書き方 | 実行される日時 |
|---|---|
| `0 3 * * *` | 毎日 3:00 |
| `*/10 * * * *` | 10 分ごと |
| `0 9 * * 1-5` | 平日の 9:00 |
| `30 23 1 * *` | 毎月1日の 23:30 |
| `0 0,12 * * *` | 毎日 0:00 と 12:00 |
| `0 8-18/2 * * *` | 8 時から 18 時まで 2 時間ごと |

> **【ひっかけ】**
>
> 日と曜日の両方を指定すると、**どちらかに当てはまる日** に実行されます(OR)。`0 0 13 * 5` は「毎月 13 日」と「毎週金曜日」の両方です。

### 4. システム全体の cron

| ファイル・ディレクトリ | 内容 |
|---|---|
| `/etc/crontab` | システム用の crontab |
| `/etc/cron.d/` | システム用の crontab を、別々のファイルで置く場所 |
| `/etc/cron.hourly/` | 1時間ごとに実行する **スクリプト** を置く |
| `/etc/cron.daily/` | 毎日実行するスクリプトを置く |
| `/etc/cron.weekly/` | 毎週実行するスクリプトを置く |
| `/etc/cron.monthly/` | 毎月実行するスクリプトを置く |

`/etc/crontab` と `/etc/cron.d/` の書き方には、**実行するユーザーの欄が1つ多く** あります。

``` bash
# 分 時 日 月 曜日 ユーザー コマンド
0 4 * * * root /usr/local/bin/backup.sh
```

> **【ひっかけ】**
>
> ユーザーの欄があるのは `/etc/crontab` と `/etc/cron.d/` です。`crontab -e` で編集する個人の crontab にはありません。`/etc/cron.daily/` などには crontab の形式のファイルではなく、実行権のあるスクリプトそのものを置きます。

### 5. cron と at を使えるユーザーの制限

**［図2　cron.allow と cron.deny の判定］**

1. `/etc/cron.allow` があれば、そこに書かれたユーザーだけが使えます(cron.deny は見ません)。
2. cron.allow がなく、`/etc/cron.deny` があれば、そこに書かれたユーザー以外が使えます。
3. どちらもない場合は、環境によって違います(root だけ、または全員)。

- **allow が優先** です。allow があれば deny は見ません。
- root はいつでも使えます。
- at も同じ仕組みで、ファイルは `/etc/at.allow` と `/etc/at.deny` です。
- 1行に1人のユーザー名を書きます。

### 6. anacron

cron は、実行する時刻に電源が切れていたジョブを実行しません。anacron は「前回の実行から何日たったか」で判断し、実行できなかったジョブを起動後に実行します。いつも動いているとは限らないパソコンなどに向いています。

設定は `/etc/anacrontab` に書きます。

``` bash
# 間隔(日) 遅延(分) ジョブ名 コマンド
1 5 cron.daily run-parts /etc/cron.daily
7 25 cron.weekly run-parts /etc/cron.weekly
```

間隔には `@monthly`(毎月)も書けます。

| 項目 | 意味 |
|---|---|
| 間隔 | 何日ごとに実行するか |
| 遅延 | anacron が起動してから、実行するまでの待ち時間(分) |
| ジョブ名 | ジョブを見分ける名前。実行した日の記録に使う |
| コマンド | 実行する内容 |

- 間隔の最小の単位は **1日** です。時間や分の単位では指定できません。
- 最後に実行した日は `/var/spool/anacron/` に記録されます。
- `run-parts ディレクトリ` は、そのディレクトリにあるスクリプトを順に実行するコマンドです。

| | cron | anacron |
|---|---|---|
| 最小の単位 | 1分 | 1日 |
| 電源が切れていたときのジョブ | 実行されない | 起動後に実行される |
| 一般ユーザー | 使える | 普通は root だけ |

### 7. at

1回だけ実行するジョブを予約します。

``` bash
$ at 15:00
at> /usr/local/bin/report.sh
at> (Ctrl+D で確定する)
```

``` bash
at now + 1 hour
at 23:00 tomorrow
at 10:00 2026-12-01
at -f job.sh 10:00
```

| コマンド | 意味 |
|---|---|
| `at 時刻` | ジョブを予約する |
| `at -f ファイル 時刻` | ファイルに書いた内容を実行する |
| `atq`(`at -l`) | 予約の一覧を表示する |
| `atrm 番号`(`at -d 番号`) | 予約を取り消す |
| `batch` | システムの負荷が低いときに実行する |

at を使うには、デーモンの `atd` が動いている必要があります。

> **【1.08.2 まとめ】**
>
> - くり返しは cron、1回だけは at、電源を切ることがあるマシンは anacron
> - crontab の書き方は「分 時 日 月 曜日 コマンド」
> - `crontab -e` で編集、`-l` で表示、`-r` ですべて削除
> - /etc/crontab と /etc/cron.d/ にはユーザーの欄がある
> - cron.allow があれば、そこに書かれたユーザーだけ。なければ cron.deny を見る
> - anacron の最小の単位は1日。設定は /etc/anacrontab
> - `atq` で一覧、`atrm` で取り消し

## 1.08.3 ローカライゼーションと国際化 (重要度3)

### 1. i18n と l10n

| 用語 | 正式な名前 | 意味 |
|---|---|---|
| i18n | internationalization(国際化) | ソフトウェアを、複数の言語や地域に対応 **できる作り** にすること |
| l10n | localization(地域化) | ソフトウェアを、特定の言語や地域に **合わせる** こと(翻訳、日付や通貨の書き方など) |

数字は、最初と最後の文字の間の文字数です(i と n の間に 18 文字、l と n の間に 10 文字)。

### 2. ロケール

ロケールは、言語や地域ごとの設定のまとまりです。「言語_地域.文字コード」の形で書きます。

| ロケール | 意味 |
|---|---|
| `ja_JP.UTF-8` | 日本語・日本・UTF-8 |
| `en_US.UTF-8` | 英語・アメリカ・UTF-8 |
| `ja_JP.eucJP` | 日本語・日本・EUC-JP |
| `C`(`POSIX`) | 言語に依存しない標準の設定。英語で表示される |

### 3. ロケールの環境変数

| 変数 | 対象 |
|---|---|
| `LANG` | すべての項目の **既定値** |
| `LC_ALL` | すべての項目を **強制的に上書き** する |
| `LC_CTYPE` | 文字の種類と文字コード |
| `LC_COLLATE` | 並べ替えの順序 |
| `LC_MESSAGES` | メッセージの言語 |
| `LC_TIME` | 日付と時刻の書き方 |
| `LC_NUMERIC` | 数値の書き方 |
| `LC_MONETARY` | 通貨の書き方 |

**［図3　ロケールの変数の優先順位］**

優先順位は **LC_ALL ＞ LC\_\*(個別の項目) ＞ LANG** です。LC_ALL が設定されていれば、他はすべて無視されます。LC\_\* が設定されていない項目には、LANG の値が使われます。

``` bash
export LANG=ja_JP.UTF-8
export LC_TIME=en_US.UTF-8
```

この例では、全体は日本語で、日付の書き方だけが英語になります。

### 4. locale コマンド

``` bash
locale       # 現在の設定を表示する
locale -a    # 使えるロケールの一覧を表示する
locale -m    # 使える文字コードの一覧を表示する
```

コマンドの本体は `/usr/bin/locale` です。

### 5. LANG=C が役に立つ理由

コマンドの出力は、ロケールによって変わります。

``` bash
$ LANG=ja_JP.UTF-8 date
2026年 11月 17日 火曜日 14:30:00 JST
$ LANG=C date
Tue Nov 17 14:30:00 JST 2026
```

スクリプトでコマンドの出力を加工するとき、実行する人のロケールによって出力が変わると、正しく動かなくなります。`LANG=C`(または `LC_ALL=C`)にすると、次の点が固定されます。

- メッセージと日付が、英語の決まった書き方になります。
- 並べ替えが文字コードの順になります。
- 文字化けしません(ASCII の文字だけで表示されます)。

``` bash
# 1つのコマンドだけ変える
LANG=C ls -l
# スクリプト全体で固定する
export LC_ALL=C
```

> **【ひっかけ】**
>
> `LC_ALL` が設定されていると、`LANG` や `LC_TIME` を変えても効きません。確実に固定したいときは `LC_ALL=C` にします。

### 6. 文字コード

| 名前 | 特徴 |
|---|---|
| ASCII | 7 ビット。英数字と記号だけ |
| ISO-8859 | 8 ビット。ASCII に西ヨーロッパなどの文字を加えたもの。ISO-8859-1(Latin-1)が代表 |
| Unicode | 世界中の文字に番号を割り当てた **文字集合** |
| UTF-8 | Unicode の **符号化方式**。1〜4 バイトの可変長で、ASCII と互換性がある。Linux の標準 |
| ISO-2022-JP | 日本語の 7 ビットの符号(JIS コード)。電子メールで使われてきた |
| EUC-JP | 古い UNIX で使われていた日本語の符号 |
| Shift_JIS | Windows で使われてきた日本語の符号 |

### 7. iconv

文字コードを変換するコマンドです。

``` bash
iconv -f SHIFT_JIS -t UTF-8 \
  in.txt > out.txt
iconv -f EUC-JP -t UTF-8 \
  -o out.txt in.txt
iconv -l
```

| オプション | 意味 |
|---|---|
| `-f` | 変換元(from)の文字コード |
| `-t` | 変換先(to)の文字コード |
| `-o` | 出力するファイル |
| `-l` | 対応している文字コードの一覧 |

変換の結果は画面(標準出力)に出ます。ファイルに保存するには、リダイレクトか `-o` を使います。

> **【1.08.3 まとめ】**
>
> - i18n は対応できる作りにすること、l10n は特定の地域に合わせること
> - ロケールは「言語_地域.文字コード」の形。例: `ja_JP.UTF-8`
> - 優先順位は LC_ALL ＞ LC\_\* ＞ LANG
> - `locale` で現在の設定、`locale -a` で一覧
> - スクリプトでは `LANG=C` で出力を固定する
> - UTF-8 は Unicode の符号化方式。ISO-2022-JP はメールで使われてきた日本語の符号
> - `iconv -f 変換元 -t 変換先`
