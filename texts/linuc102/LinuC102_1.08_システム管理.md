# LinuC 102 テキスト 1.08 システム管理

## 1.08.1 アカウント管理 （重要度5）

### 1. アカウント情報のファイル

| ファイル       | 内容                             | 読める人 |
|----------------|----------------------------------|----------|
| `/etc/passwd`  | ユーザーの基本情報               | 全員     |
| `/etc/shadow`  | 暗号化されたパスワードと有効期限 | rootのみ |
| `/etc/group`   | グループ情報                     | 全員     |
| `/etc/gshadow` | グループのパスワード             | rootのみ |

### 2. /etc/passwd

1ユーザー1行。`:` 区切りで7フィールド。

``` bash
kuro:x:1000:1000:Kuro:/home/kuro:/bin/bash
```

| 番号 | 内容                                          | 例         |
|------|-----------------------------------------------|------------|
| 1    | ユーザー名                                    | kuro       |
| 2    | パスワード（`x` は /etc/shadow に格納の意味） | x          |
| 3    | UID                                           | 1000       |
| 4    | GID（プライマリグループ）                     | 1000       |
| 5    | コメント（GECOS）                             | Kuro       |
| 6    | ホームディレクトリ                            | /home/kuro |
| 7    | ログインシェル                                | /bin/bash  |

- UID 0 は root。1〜999 はシステムアカウント、1000以降が一般ユーザー（ディストリビューションにより異なる）。
- シェルが `/sbin/nologin` や `/bin/false` のアカウントは、ログインできない。サービス用アカウントに使う。

### 3. /etc/shadow

`:` 区切りで9フィールド。

``` bash
kuro:$6$abc...:20409:0:99999:7:::
```

| 番号 | 内容                                         |
|------|----------------------------------------------|
| 1    | ユーザー名                                   |
| 2    | 暗号化されたパスワード                       |
| 3    | 最終変更日（1970年1月1日からの日数）         |
| 4    | 変更可能になるまでの最短日数                 |
| 5    | 有効期限の最長日数                           |
| 6    | 期限切れ前の警告日数                         |
| 7    | 期限切れ後、アカウントが無効になるまでの日数 |
| 8    | アカウントの失効日（1970年1月1日からの日数） |
| 9    | 予約（未使用）                               |

パスワード欄が `!` や `*` で始まるアカウントは、パスワードでログインできない（ロック状態、または未設定）。

### 4. /etc/group

`:` 区切りで4フィールド。

``` bash
sales:x:1001:kuro,shiro
```

| 番号 | 内容                                                         |
|------|--------------------------------------------------------------|
| 1    | グループ名                                                   |
| 2    | グループのパスワード（通常 `x`）                             |
| 3    | GID                                                          |
| 4    | このグループをセカンダリグループとするユーザー（`,` 区切り） |

| 種類               | 記録場所                      | 数      |
|--------------------|-------------------------------|---------|
| プライマリグループ | `/etc/passwd` の第4フィールド | 1つだけ |
| セカンダリグループ | `/etc/group` の第4フィールド  | 複数可  |

ファイルを新規作成したときの所有グループは、プライマリグループになる。

### 5. useradd

``` bash
useradd kuro
useradd -m -s /bin/bash -G sales kuro
```

| オプション | 意味                                   |
|------------|----------------------------------------|
| `-c`       | コメント                               |
| `-d`       | ホームディレクトリのパス               |
| `-m`       | ホームディレクトリを作成する           |
| `-s`       | ログインシェル                         |
| `-u`       | UID                                    |
| `-g`       | プライマリグループ                     |
| `-G`       | セカンダリグループ（`,` 区切りで複数） |
| `-e`       | アカウントの失効日（YYYY-MM-DD）       |
| `-k`       | スケルトンディレクトリを指定           |
| `-D`       | デフォルト値の表示・変更               |

- 作成直後はパスワードが未設定でログインできない。`passwd kuro` で設定する。
- ホームディレクトリを自動で作るかは環境による。確実に作るなら `-m` を付ける。

デフォルト値は `/etc/default/useradd` に書かれている。`useradd -D` で表示する。

``` bash
$ useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel
CREATE_MAIL_SPOOL=yes
```

``` bash
# 既定のシェルを変更
useradd -D -s /bin/zsh
```

UIDの範囲やパスワード有効期限の既定値は `/etc/login.defs` にある（`UID_MIN`、`PASS_MAX_DAYS` など）。

### 6. /etc/skel（スケルトンディレクトリ）

新しいユーザーのホームディレクトリに、ひな形としてコピーされるファイルを置く場所。

``` bash
$ ls -a /etc/skel
.bash_logout  .bash_profile  .bashrc
```

- ホームディレクトリの作成時に、中身がそのままコピーされる。
- 全員に配りたい初期設定ファイルは、ここに置く。
- 変更しても、**既存ユーザーのホームには反映されない**。

### 7. usermod

既存ユーザーの情報を変更する。オプションは useradd とほぼ共通。

``` bash
usermod -s /bin/zsh kuro
usermod -aG wheel kuro
usermod -L kuro
```

| オプション               | 意味                                                    |
|--------------------------|---------------------------------------------------------|
| `-c` `-s` `-u` `-g` `-e` | useradd と同じ                                          |
| `-d パス`                | ホームディレクトリを変更（`-m` を併用すると中身も移動） |
| `-G`                     | セカンダリグループを**置き換える**                      |
| `-aG`                    | セカンダリグループに**追加する**                        |
| `-l`                     | ログイン名を変更                                        |
| `-L`                     | アカウントをロック                                      |
| `-U`                     | ロックを解除                                            |

> **【ひっかけ】**
>
> `usermod -G wheel kuro` は、既存のセカンダリグループをすべて外して wheel だけにする。追加したいときは `-aG`。

### 8. userdel

``` bash
userdel kuro       # ホームは残る
userdel -r kuro    # ホームも削除
```

`-r` はホームディレクトリとメールスプールも削除する。

### 9. passwd

``` bash
passwd             # 自分のパスワード
passwd kuro        # 他人（rootのみ）
```

| オプション | 意味                                       |
|------------|--------------------------------------------|
| `-l`       | ロック（一時停止）                         |
| `-u`       | ロック解除                                 |
| `-d`       | パスワードを削除（空にする）               |
| `-e`       | 期限切れにして、次回ログイン時に変更を強制 |
| `-S`       | 状態を表示                                 |

アカウントの一時停止は `passwd -l` または `usermod -L`。どちらも /etc/shadow のパスワード欄の先頭に `!` を付ける。

### 10. グループの管理

``` bash
groupadd sales
groupadd -g 2000 dev
groupmod -n marketing sales
groupmod -g 2001 dev
groupdel dev
```

| コマンド                | 意味              |
|-------------------------|-------------------|
| `groupadd -g GID 名前`  | GIDを指定して作成 |
| `groupmod -n 新名 旧名` | 名前を変更        |
| `groupmod -g GID 名前`  | GIDを変更         |
| `groupdel 名前`         | 削除              |

- いずれかのユーザーのプライマリグループになっているグループは、groupdel で削除できない。
- 補足：`gpasswd -a kuro sales` でグループに追加、`gpasswd -d kuro sales` で外す。

### 11. id と getent

``` bash
$ id kuro
uid=1000(kuro) gid=1000(kuro)
  groups=1000(kuro),1001(sales)
```

| コマンド                    | 表示                                          |
|-----------------------------|-----------------------------------------------|
| `id`                        | 自分のUID、GID、所属グループ                  |
| `id -u` / `id -g` / `id -G` | UIDのみ / プライマリGIDのみ / 全グループのGID |
| `id -un`                    | ユーザー名                                    |
| `groups kuro`               | 所属グループ名                                |

``` bash
getent passwd kuro
getent group sales
getent passwd
```

`getent` は `/etc/nsswitch.conf` に従って情報を引く。`/etc/passwd` だけでなく、LDAPなどで管理されているユーザーも表示できる。`grep kuro /etc/passwd` ではローカルのファイルしか見られない。

> **【1.08.1 まとめ】**
>
> - /etc/passwd は7フィールド、/etc/shadow は9フィールド、/etc/group は4フィールド
> - パスワードの実体は /etc/shadow。rootしか読めない
> - `useradd -m` でホーム作成。ひな形は `/etc/skel`、既定値は `/etc/default/useradd`
> - `usermod -G` は置き換え、`-aG` は追加
> - `userdel -r` でホームも削除
> - 一時停止は `passwd -l` か `usermod -L`
> - `id` で所属確認、`getent` は nsswitch.conf に従って検索

## 1.08.2 ジョブスケジューリング （重要度4）

### 1. 3つの仕組み

| 仕組み  | 用途                                                         | デーモン                 |
|---------|--------------------------------------------------------------|--------------------------|
| cron    | 決まった日時に**くり返し**実行                               | crond（cron）            |
| anacron | 日単位のくり返し。停止中に実行できなかった分を、起動後に実行 | なし（cronなどから起動） |
| at      | 指定した日時に**1回だけ**実行                                | atd                      |

### 2. crontab コマンド

ユーザーごとの定期ジョブを登録する。

| コマンド             | 意味                         |
|----------------------|------------------------------|
| `crontab -e`         | 編集                         |
| `crontab -l`         | 表示                         |
| `crontab -r`         | **すべて削除**               |
| `crontab -u kuro -l` | 他ユーザーを指定（rootのみ） |
| `crontab ファイル`   | ファイルの内容で置き換え     |

- 登録内容は `/var/spool/cron/` の下にユーザー名のファイルとして保存される（Debian系は `/var/spool/cron/crontabs/`）。
- このファイルは直接編集しない。必ず `crontab -e` を使う。

> **【ひっかけ】**
>
> `crontab -r` は確認なしで全ジョブを消す。`-e` とキーが隣なので事故が多い。`-i` を付けると確認が出る。

### 3. crontab の書式

**［図1　crontab の書式］**

左から **分（0-59）、時（0-23）、日（1-31）、月（1-12）、曜日（0-7。0と7が日曜）、コマンド**。例：`30 2 * * 1 /usr/local/bin/backup.sh` は毎週月曜の2:30に実行。

| 記号 | 意味     | 例               |
|------|----------|------------------|
| `*`  | すべて   | `* * * * *` 毎分 |
| `,`  | 複数指定 | `0,30` 0分と30分 |
| `-`  | 範囲     | `1-5` 月曜〜金曜 |
| `/`  | 間隔     | `*/10` 10分ごと  |

| 記述             | 実行される日時           |
|------------------|--------------------------|
| `0 3 * * *`      | 毎日 3:00                |
| `*/10 * * * *`   | 10分ごと                 |
| `0 9 * * 1-5`    | 平日 9:00                |
| `30 23 1 * *`    | 毎月1日 23:30            |
| `0 0,12 * * *`   | 毎日 0:00 と 12:00       |
| `0 8-18/2 * * *` | 8時から18時まで2時間ごと |

> **【ひっかけ】**
>
> 日と曜日の両方を指定すると、**どちらかに一致した日**に実行される（OR）。`0 0 13 * 5` は「13日」と「毎週金曜」の両方。

### 4. システムのcron

| ファイル・ディレクトリ | 内容                                      |
|------------------------|-------------------------------------------|
| `/etc/crontab`         | システム用のcrontab                       |
| `/etc/cron.d/`         | システム用crontabを個別ファイルで置く場所 |
| `/etc/cron.hourly/`    | 毎時実行する**スクリプト**を置く          |
| `/etc/cron.daily/`     | 毎日実行するスクリプトを置く              |
| `/etc/cron.weekly/`    | 毎週実行するスクリプトを置く              |
| `/etc/cron.monthly/`   | 毎月実行するスクリプトを置く              |

`/etc/crontab` と `/etc/cron.d/` の書式は、**実行ユーザーの欄が1つ多い**。

``` bash
# 分 時 日 月 曜日 ユーザー コマンド
0 4 * * * root /usr/local/bin/backup.sh
```

> **【ひっかけ】**
>
> ユーザー欄があるのは `/etc/crontab` と `/etc/cron.d/`。`crontab -e` で編集するユーザーのcrontabにはない。`/etc/cron.daily/` などに置くのはcrontab形式のファイルではなく、実行権のあるスクリプトそのもの。

### 5. cron と at の利用制限

**［図2　cron.allow と cron.deny の判定］**

1.  `/etc/cron.allow` があれば、そこに書かれたユーザーだけが使える（cron.deny は無視）。
2.  cron.allow がなく `/etc/cron.deny` があれば、そこに書かれたユーザー以外が使える。
3.  どちらもない場合は環境による（rootだけ、または全員）。

- **allow が優先**。allow があれば deny は見ない。
- root は常に使える。
- at も同じ仕組み。ファイルは `/etc/at.allow` と `/etc/at.deny`。
- 1行に1ユーザー名を書く。

### 6. anacron

cron は、実行時刻にマシンが止まっていたジョブを実行しない。anacron は「前回の実行から何日たったか」で判断し、未実行のジョブを起動後に実行する。常時稼働しないマシン向け。

設定は `/etc/anacrontab`。

``` bash
# 間隔(日) 遅延(分) ジョブ名 コマンド
1 5 cron.daily run-parts /etc/cron.daily
7 25 cron.weekly run-parts /etc/cron.weekly
```

間隔には `@monthly`（毎月）も書ける。

| フィールド | 意味                                     |
|------------|------------------------------------------|
| 間隔       | 何日ごとに実行するか                     |
| 遅延       | anacron 起動から実行までの待ち時間（分） |
| ジョブ名   | 識別名。実行日の記録に使う               |
| コマンド   | 実行する内容                             |

- 最小単位は**1日**。時・分単位の指定はできない。
- 最終実行日は `/var/spool/anacron/` に記録される。
- `run-parts ディレクトリ` は、ディレクトリ内のスクリプトを順に実行するコマンド。

|                | cron         | anacron            |
|----------------|--------------|--------------------|
| 最小単位       | 1分          | 1日                |
| 停止中のジョブ | 実行されない | 起動後に実行される |
| 一般ユーザー   | 使える       | 通常はrootのみ     |

### 7. at

1回だけ実行するジョブを予約する。

``` bash
$ at 15:00
at> /usr/local/bin/report.sh
at> （Ctrl+D で確定）
```

``` bash
at now + 1 hour
at 23:00 tomorrow
at 10:00 2026-12-01
at -f job.sh 10:00
```

| コマンド                    | 意味                           |
|-----------------------------|--------------------------------|
| `at 時刻`                   | ジョブを予約                   |
| `at -f ファイル 時刻`       | ファイルの内容を実行           |
| `atq`（`at -l`）            | 予約の一覧                     |
| `atrm 番号`（`at -d 番号`） | 予約を取り消し                 |
| `batch`                     | システムの負荷が低いときに実行 |

at を使うには、デーモン `atd` が動いている必要がある。

> **【1.08.2 まとめ】**
>
> - くり返しは cron、1回だけは at、止まることがあるマシンは anacron
> - crontab の書式は「分 時 日 月 曜日 コマンド」
> - `crontab -e` 編集、`-l` 表示、`-r` 全削除
> - /etc/crontab と /etc/cron.d/ はユーザー欄がある
> - cron.allow があれば、そこに書かれたユーザーだけ。なければ cron.deny
> - anacron の最小単位は1日。設定は /etc/anacrontab
> - `atq` で一覧、`atrm` で取り消し

## 1.08.3 ローカライゼーションと国際化 （重要度3）

### 1. i18n と l10n

| 用語 | 正式名                         | 意味                                                           |
|------|--------------------------------|----------------------------------------------------------------|
| i18n | internationalization（国際化） | ソフトウェアを、複数の言語や地域に対応**できる作り**にすること |
| l10n | localization（地域化）         | 特定の言語や地域に**合わせる**こと（翻訳、日付や通貨の書式）   |

数字は、先頭と末尾の間の文字数（i と n の間に18文字、l と n の間に10文字）。

### 2. ロケール

言語や地域ごとの設定のまとまり。書式は「言語_地域.文字コード」。

| ロケール       | 意味                                 |
|----------------|--------------------------------------|
| `ja_JP.UTF-8`  | 日本語・日本・UTF-8                  |
| `en_US.UTF-8`  | 英語・アメリカ・UTF-8                |
| `ja_JP.eucJP`  | 日本語・日本・EUC-JP                 |
| `C`（`POSIX`） | 言語に依存しない標準の設定。英語表示 |

### 3. ロケールの環境変数

| 変数          | 対象                           |
|---------------|--------------------------------|
| `LANG`        | 全カテゴリの**既定値**         |
| `LC_ALL`      | 全カテゴリを**強制的に上書き** |
| `LC_CTYPE`    | 文字の種類・文字コード         |
| `LC_COLLATE`  | 並べ替えの順序                 |
| `LC_MESSAGES` | メッセージの言語               |
| `LC_TIME`     | 日付・時刻の書式               |
| `LC_NUMERIC`  | 数値の書式                     |
| `LC_MONETARY` | 通貨の書式                     |

**［図3　ロケール変数の優先順位］**

優先順位は **LC_ALL ＞ LC\_\*（個別のカテゴリ） ＞ LANG**。LC_ALL が設定されていれば、他はすべて無視される。LC\_\* が未設定のカテゴリは LANG の値を使う。

``` bash
export LANG=ja_JP.UTF-8
export LC_TIME=en_US.UTF-8
```

上の例では、全体は日本語、日付の書式だけ英語になる。

### 4. locale コマンド

``` bash
locale       # 現在の設定を表示
locale -a    # 使えるロケールの一覧
locale -m    # 使える文字コードの一覧
```

コマンドの実体は `/usr/bin/locale`。

### 5. LANG=C が役立つ理由

コマンドの出力は、ロケールによって変わる。

``` bash
$ LANG=ja_JP.UTF-8 date
2026年 11月 17日 火曜日 14:30:00 JST
$ LANG=C date
Tue Nov 17 14:30:00 JST 2026
```

スクリプトで出力を加工するとき、実行者のロケールで結果が変わると誤動作する。`LANG=C`（または `LC_ALL=C`）にすると、次の点が固定される。

- メッセージと日付が英語の決まった書式になる。
- 並べ替えが文字コード順になる。
- 文字化けしない（ASCIIだけで表示される）。

``` bash
# 1つのコマンドだけ変える
LANG=C ls -l
# スクリプト全体で固定する
export LC_ALL=C
```

> **【ひっかけ】**
>
> `LC_ALL` が設定されていると、`LANG` や `LC_TIME` を変えても効かない。確実に固定したいときは `LC_ALL=C`。

### 6. 文字コード

| 名前        | 特徴                                                                  |
|-------------|-----------------------------------------------------------------------|
| ASCII       | 7ビット。英数字と記号のみ                                             |
| ISO-8859    | 8ビット。ASCIIに西欧などの文字を追加。ISO-8859-1（Latin-1）が代表     |
| Unicode     | 世界中の文字に番号を割り当てた**文字集合**                            |
| UTF-8       | Unicodeの**符号化方式**。1〜4バイトの可変長。ASCIIと互換。Linuxの標準 |
| ISO-2022-JP | 日本語の7ビット符号（JISコード）。電子メールで使われてきた            |
| EUC-JP      | 古いUNIXで使われた日本語の符号                                        |
| Shift_JIS   | Windowsで使われてきた日本語の符号                                     |

### 7. iconv

文字コードを変換する。

``` bash
iconv -f SHIFT_JIS -t UTF-8 \
  in.txt > out.txt
iconv -f EUC-JP -t UTF-8 \
  -o out.txt in.txt
iconv -l
```

| オプション | 意味                       |
|------------|----------------------------|
| `-f`       | 変換元（from）の文字コード |
| `-t`       | 変換先（to）の文字コード   |
| `-o`       | 出力ファイル               |
| `-l`       | 対応する文字コードの一覧   |

結果は標準出力に出る。ファイルに保存するにはリダイレクトか `-o` を使う。

> **【1.08.3 まとめ】**
>
> - i18n は対応できる作りにすること、l10n は特定の地域に合わせること
> - ロケールは「言語_地域.文字コード」。`ja_JP.UTF-8`
> - 優先順位は LC_ALL ＞ LC\_\* ＞ LANG
> - `locale` で現在の設定、`locale -a` で一覧
> - スクリプトでは `LANG=C` で出力を固定する
> - UTF-8 は Unicode の符号化方式。ISO-2022-JP はメール用の日本語符号
> - `iconv -f 変換元 -t 変換先`
