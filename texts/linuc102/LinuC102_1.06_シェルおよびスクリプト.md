# LinuC 102 テキスト 1.06 シェルおよびスクリプト

シェル(bash)の設定と、シェルスクリプトの書き方を学びます。シェルは、利用者が入力したコマンドを受け取って実行するプログラムです。

## 1.06.1 シェル環境のカスタマイズ (重要度4)

### 1. ログインシェルと非ログインシェル

bash は、どのように起動されたかによって、読み込む設定ファイルが変わります。試験で最もよく出るところです。

| 種類 | 起動される場面 |
|---|---|
| ログインシェル | ssh での接続、コンソールからのログイン、`su -`、`bash -l` |
| 非ログインシェル | ログインした後に `bash` と入力したとき、端末アプリを開いたとき、`su`(ハイフンなし) |

ログインシェルは「ログインの手続きを経て起動したシェル」と考えると分かりやすいです。

### 2. 読み込まれる設定ファイル

| ファイル | 読まれる場面 | 対象 |
|---|---|---|
| `/etc/profile` | ログインしたとき | 全ユーザー |
| `~/.bash_profile` | ログインしたとき(第1候補) | 自分だけ |
| `~/.bash_login` | ログインしたとき(第2候補) | 自分だけ |
| `~/.profile` | ログインしたとき(第3候補) | 自分だけ |
| `/etc/bash.bashrc` | bash が起動するたび(Debian 系) | 全ユーザー |
| `~/.bashrc` | bash が起動するたび | 自分だけ |
| `~/.bash_logout` | ログアウトするとき | 自分だけ |

ログイン時の3つの候補は、上から順に探し、**最初に見つかった1つだけ** を読み込みます。

**［図1　読み込まれる設定ファイルの流れ］**

ログインシェルと非ログインシェルが、どの設定ファイルを読むかを図にします。

```text
ログインシェル(ssh、su - など)
  |
  v
/etc/profile
  |
  v
次の 3 つを上から探し、最初に見つかった 1 つだけを読む
  1. ~/.bash_profile
  2. ~/.bash_login
  3. ~/.profile

非ログインシェル(端末アプリ、bash と入力したとき)
  |
  v
/etc/bash.bashrc(Debian 系)と ~/.bashrc
```

`~/.bashrc` はログインシェルでは自動では読まれません。`~/.bash_profile`(Debian 系では `~/.profile`)の中で `. ~/.bashrc` を実行しているときに、ログインシェルでも読まれます。

> **【覚え方】** 名前に `profile` が付くものはログイン時に1回、`rc` が付くものはシェルが起動するたびに読まれます。`/etc/` で始まるものは全員用、`~/`(ホームディレクトリ)で始まるものは自分用です。

実際の `~/.bash_profile` には、次のような記述が入っていることが多いです。ログイン時にも `~/.bashrc` の設定を使えるようにするためです。

``` bash
if [ -f ~/.bashrc ]; then
    . ~/.bashrc
fi
```

> **【ひっかけ】** `~/.bash_profile` と `~/.profile` が両方あるとき、ログイン時に読まれるのは `~/.bash_profile` だけです。

### 3. シェル変数と環境変数

変数には2種類あります。

``` bash
# シェル変数(いまのシェルの中だけで使える)
MYVAR=hello
# 環境変数にする
export MYVAR
# 代入と export をまとめて書くこともできる
export MYVAR=hello
```

いまのシェル(親)で `A=1`(シェル変数)と `export B=2`(環境変数)を定義したとします。このシェルから起動した子プロセス(新しい bash やスクリプトなど)からは、A は見えず、B=2 だけが見えます。子プロセスに引き継がれるのは、export した変数だけです。

| コマンド | 用途 |
|---|---|
| `env` / `printenv` | 環境変数の一覧を表示する |
| `set` | シェル変数、環境変数、関数の定義をすべて表示する |
| `unset 変数名` | 変数を削除する |
| `echo $変数名` | 変数の値を表示する |

> **【ひっかけ】** 代入するときは `=` の前後に空白を入れません。`MYVAR = hello` と書くと、シェルは「MYVAR というコマンドを実行する」と解釈してエラーになります。

### 4. 引用符の違い

| 書き方 | 結果(NAME=Sato の場合) |
|---|---|
| `"Hi $NAME"` | Hi Sato(ダブルクォートの中では変数が展開される) |
| `'Hi $NAME'` | Hi \$NAME(シングルクォートの中は書いたまま) |
| `` `date` `` | date コマンドの実行結果に置き換わる |

### 5. PATH

PATH は、コマンドを探すディレクトリの一覧を入れた環境変数です。ディレクトリは `:` で区切られ、左から順に探します。

``` bash
echo $PATH
/usr/local/bin:/usr/bin:/bin
# 末尾にディレクトリを追加する
export PATH=$PATH:/opt/tools/bin
```

- `$PATH:` を付け忘れると、元の PATH が消えてしまい、`ls` のような基本のコマンドも名前だけでは動かなくなります。
- カレントディレクトリ(いまいるディレクトリ)は、普通 PATH に含まれていません。そのため、自分で作ったスクリプトは `./script.sh` のように場所を付けて実行します。
- コマンドがどこにあるかは `which ls` や `type ls` で調べられます。

### 6. 設定の反映: source と .

設定ファイルを書き換えても、いま開いているシェルにはすぐには反映されません。

**［図3　source と bash の違い］**

| 実行の方法 | どこで動くか | いまのシェルへの反映 |
|---|---|---|
| `source ~/.bashrc`、`. ~/.bashrc` | いまのシェルの中で直接実行する | 反映される |
| `bash ~/.bashrc`、`./script.sh` | 新しい子シェルの中で実行し、終わると消える | 反映されない |

> **【ひっかけ】** 「設定の変更をいまのシェルに反映するコマンド」を選ぶ問題で、`bash ~/.bashrc` は誤りです。正解は `source` か `.` です。

### 7. alias(別名)

よく使うコマンドに短い別名を付けられます。

``` bash
alias ll='ls -l' # 別名を定義する
alias            # 一覧を表示する
unalias ll       # 別名を削除する
\ls              # その場だけ別名を使わずに実行する
```

alias はログアウトすると消えます。ずっと使いたいときは `~/.bashrc` に書きます。

### 8. コマンド置換

コマンドの実行結果を、別のコマンドの中に埋め込む書き方です。

``` bash
echo "今日は $(date +%F)"
# バッククォートで囲んでも同じ
echo "今日は `date +%F`"
```

### 9. コマンドのつなぎ方(lists)

| 記号 | 動作 |
|---|---|
| `A ; B` | A の結果に関係なく、A の次に B を実行する |
| `A && B` | A が **成功** したときだけ B を実行する |
| `A || B` | A が **失敗** したときだけ B を実行する |

``` bash
mkdir work && cd work
ping -c1 server || echo "接続できない"
```

> **【1.06.1 まとめ】**
>
> - ログイン時: `/etc/profile` → `~/.bash_profile` などの候補(最初に見つかった1つ)
> - bash が起動するたび: `~/.bashrc`
> - `export` しない変数は子プロセスに渡らない
> - `source` と `.` はいまのシェルに反映する
> - `&&` は成功したとき、`||` は失敗したときに次を実行する

## 1.06.2 シェルスクリプト (重要度6)

### 1. スクリプトの基本

シェルスクリプトは、コマンドをファイルに並べて書き、まとめて実行できるようにしたものです。

``` bash
#!/bin/bash
# # で始まる行はコメント
echo "Hello"
```

- 1行目の `#!`(シバン)で、スクリプトを実行するインタプリタ(ここでは bash)を指定します。
- ファイル名だけで実行するには、実行権が必要です: `chmod +x hello.sh`

| 実行の方法 | 実行権 | どこで動くか |
|---|---|---|
| `./hello.sh` | 必要 | 子シェル |
| `bash hello.sh` | 不要 | 子シェル |
| `source hello.sh` | 不要 | いまのシェル |

### 2. 引数(位置パラメータ)

スクリプトに渡した引数は、特別な変数で受け取ります。`./backup.sh /var/log 7` と実行した場合を考えます。

**［図4　位置パラメータ］**

`./backup.sh` が `$0`(スクリプト名)、`/var/log` が `$1`、`7` が `$2` に入ります。`$#`(引数の個数)は 2、`$@` は `$1 $2` です。`$0` は個数に数えません。

```text
./backup.sh /var/log 7
|           |        |
|           |        +-- $2  2 番目の引数
|           +----------- $1  1 番目の引数
+----------------------- $0  スクリプトの名前
```

| 変数 | 意味 |
|---|---|
| `$0` | スクリプトの名前 |
| `$1`〜`$9`、`${10}` | n 番目の引数(10 番目以降は波かっこで囲む) |
| `$#` | 引数の個数(`$0` は含まない) |
| `$@` | すべての引数。`"$@"` と書くと1つずつ別の値として扱う |
| `$*` | すべての引数。`"$*"` と書くと1つの文字列にまとめる |
| `$?` | 直前のコマンドの終了ステータス |
| `$$` | いまのシェルのプロセス ID |

### 3. shift

`shift` は、引数を1つずつ左にずらします。`$1` の値が捨てられ、`$#` が1つ減ります。

**［図5　shift の動き］**

shift の前: `$1=a $2=b $3=c`、`$#=3`。shift の後: a は消え、`$1=b $2=c`、`$#=2` になります。

```text
before shift:  $1=a  $2=b  $3=c  $#=3
after shift:   $1=b  $2=c         $#=2
               (a は消え、b と c が 1 つずつ前に詰まる)
```

### 4. 終了ステータス

コマンドは終わるときに、0〜255 の数値を返します。**0 が成功、0 以外が失敗** です。

``` bash
ls /nothing
echo $?   # 2(失敗)
exit 1    # スクリプトを終了ステータス 1 で終える
```

1.06.1 で学んだ `&&` と `||` も、この値で成功か失敗かを判断しています。

### 5. 条件分岐 if

``` bash
if [ -f /etc/hosts ]; then
    echo "ファイルがある"
elif [ -d /etc ]; then
    echo "ディレクトリはある"
else
    echo "ない"
fi
```

> **【ひっかけ】** `[ ]` は `test` というコマンドの別の書き方です。そのため、かっこの内側に **空白が必要** です。`[-f file]` と書くとエラーになります。if 文は `fi`(if を逆から読んだ綴り)で終えます。

### 6. test の主な判定

| 書き方 | 真になる条件 |
|---|---|
| `-e` / `-f` / `-d` | 存在する / 通常のファイルである / ディレクトリである |
| `-r` / `-w` / `-x` | 読める / 書ける / 実行できる |
| `-s` | ファイルのサイズが 0 より大きい |
| `-z 文字列` | 文字列が空 |
| `-n 文字列` | 文字列が空でない |
| `A = B` / `A != B` | 文字列が等しい / 異なる |
| `-eq` `-ne` | 数値が等しい / 異なる |
| `-lt` `-le` | 数値がより小さい / 以下 |
| `-gt` `-ge` | 数値がより大きい / 以上 |
| `!` `-a` `-o` | 否定 / かつ / または |

> **【覚え方】** 数値の比較は英字の略語です(-eq = equal、-lt = less than、-gt = greater than)。文字列の比較は記号(=、!=)を使います。

### 7. 条件分岐 case

1つの値を、いくつものパターンと比べて処理を分けます。

``` bash
case "$1" in
  start)
    echo "起動" ;;
  stop)
    echo "停止" ;;
  restart|re)
    echo "再起動" ;;
  *)
    echo "使い方: $0 start|stop" ;;
esac
```

- 各パターンは `)` で区切り、処理の最後に `;;` を書きます。
- `|` で複数のパターンを並べられます。`*` はどのパターンにも当てはまらなかったときです。
- case 文は `esac`(case を逆から読んだ綴り)で終えます。

### 8. ループ

``` bash
for i in 1 2 3; do
    echo $i
done

for f in *.log; do echo $f; done
for i in $(seq 1 5); do echo $i; done

n=1
while [ $n -le 3 ]; do
    echo $n
    n=$((n + 1))
done
```

- くり返す処理は `do` と `done` の間に書きます。
- `$(( ))` は整数の計算です。
- `seq 1 5` は 1 から 5 までの連番を出力します。
- `until` は、条件が **偽の間** くり返します(while の逆)。
- `break` でループを抜け、`continue` で次の回に進みます。

### 9. read(入力を受け取る)

``` bash
read -p "名前: " NAME
echo "こんにちは $NAME"
```

`read` はキーボードから入力された値を変数に入れます。`-p` で入力を促す文字列を表示できます。

### 10. 関数(function 文)

よく使う一連のコマンドに名前を付けて、まとめて呼び出せるようにする仕組みです。公式の出題範囲に「Bash の関数を作成する(function)」と書かれています。

**定義の書き方は3通り** あり、どれも同じ意味です。

``` bash
# ① function 文
function greet {
    echo "Hello, $1"
}
# ② 名前()  ※最も一般的
greet() {
    echo "Hello, $1"
}
# ③ 両方を付ける
function greet() {
    echo "Hello, $1"
}
# 1行で書くときは } の前に ; が必要
function greet { echo "Hello, $1"; }
```

**呼び出し** は、普通のコマンドと同じように名前を書くだけです。かっこは付けません。

``` bash
greet Sato     # Hello, Sato
greet()        # × これは定義の書き出しになる
```

**［図6　関数の引数］**

`./s.sh A B` と実行したスクリプトの中で、`greet X Y` と呼び出したとします。スクリプト本体では `$1=A $2=B $#=2` ですが、関数 greet の中では `$1=X $2=Y $#=2` になります。関数の中では、`$1`、`$#`、`$@` が関数の引数に切り替わります。`$0` は変わりません。

**戻り値** は `return` で返す終了ステータス(0〜255)です。呼び出した側は `$?` で受け取ります。

``` bash
is_root() {
    [ "$(id -u)" -eq 0 ] && return 0
    return 1
}
if is_root; then echo "root です"; fi
```

文字列や計算の結果を返したいときは、関数の中で `echo` で出力し、呼び出す側でコマンド置換を使って受け取ります。

``` bash
add() { echo $(($1 + $2)); }
sum=$(add 3 4)
echo $sum      # 7
```

| 項目 | ポイント |
|---|---|
| 定義の順番 | 呼び出すより **前** に定義します。後ろに書くと「command not found」になります |
| `return` と `exit` | `return` は関数だけを抜けます。`exit` は関数の中で使ってもスクリプト全体が終わります |
| return を省略したとき | 関数の中で最後に実行したコマンドの終了ステータスが戻り値になります |
| 変数の範囲 | 関数の中の変数は、特に指定しなければスクリプト全体から見えます(グローバル)。関数の中だけにしたいときは `local` を付けます |
| 一覧と削除 | `declare -f`(定義を表示)、`declare -F`(名前だけ)、`unset -f 名前`(削除) |
| いつも使いたいとき | `~/.bashrc` に定義を書きます |

``` bash
count=1
f() { count=5; local tmp=9; }
f
echo $count    # 5(書き換わる)
echo $tmp      # 空(local の変数は関数の外に出ない)
```

> **【alias との違い】** alias は単純な文字の置き換えで、引数を途中に挟むことはできません。関数は `$1` などで引数を自由に使え、if や for も書けます。

> **【ひっかけ】** 「関数 greet を呼び出す正しい書き方」を選ぶ問題で、`greet()` や `call greet` は誤りです。正解は `greet` だけです。

### 11. デバッグ

スクリプトが思いどおりに動かないときは、次のオプションで動きを確かめます。

| オプション | 表示される内容 |
|---|---|
| `bash -x script.sh` | 実行するコマンドを、変数などを展開した後の形で表示しながら実行する(行頭に `+`) |
| `bash -v script.sh` | 読み込んだ行を、そのままの形で表示しながら実行する |
| `bash -n script.sh` | 実行せずに、文法だけを確認する |

スクリプトの一部だけを追いたいときは、その範囲を `set -x` と `set +x` で囲みます。

### 12. 総合例

``` bash
#!/bin/bash
if [ $# -ne 1 ]; then
    echo "使い方: $0 ディレクトリ"
    exit 1
fi

count=0
for f in "$1"/*; do
    if [ -f "$f" ]; then
        echo "ファイル: $f"
        count=$((count + 1))
    fi
done
echo "合計 $count 個"
exit 0
```

引数が1つでなければ使い方を表示して終了します。1つなら、そのディレクトリの中のファイルを表示しながら数え、合計を表示します。

### 13. if にコマンドを直接書く

if が見ているのは「条件の式」ではなく、**コマンドの終了ステータス** です。0 なら真、0 以外なら偽として扱います。`[ ]` も `test` というコマンドの1つにすぎません。

``` bash
if grep -q "^sato:" /etc/passwd; then
    echo "ユーザー sato は存在する"
fi

if ping -c1 -W1 192.168.1.1 > /dev/null; then
    echo "通信できる"
fi
```

- `grep -q` は何も表示せず、見つかれば 0、見つからなければ 1 を返します。
- `> /dev/null` で出力を捨て、終了ステータスだけを使います。

### 14. スクリプトの置き場所と権限

作ったスクリプトを他のユーザーにも使わせるには、置き場所、所有者、パーミッションを整えます。

``` bash
sudo cp backup.sh /usr/local/bin/backup
sudo chown root:root /usr/local/bin/backup
sudo chmod 755 /usr/local/bin/backup
```

**［図7　配布用のスクリプトの一般的な権限］**

`chmod 755` は `rwxr-xr-x` です。所有者(root)は rwx(7: 読み・書き・実行)、グループは r-x(5: 読み・実行)、その他のユーザーは r-x(5: 読み・実行)になります。r=4、w=2、x=1 の合計で数字を決めます。

```text
sudo chmod 755 /usr/local/bin/backup
           |||
           ||+-- 5 = r-x(4+0+1)  その他のユーザー
           |+--- 5 = r-x(4+0+1)  グループ
           +---- 7 = rwx(4+2+1)  所有者(root)
```

| 項目 | ポイント |
|---|---|
| 置き場所 | 全ユーザー用は `/usr/local/bin` に置きます。PATH に含まれているので、名前だけで実行できます。自分用なら `~/bin` です |
| 所有者 | `chown root:root` にして、一般ユーザーが中身を書き換えられないようにします |
| 権限 | `755` にします。シェルスクリプトは **読み取り権と実行権** の両方が必要です |
| SUID | Linux では、シェルスクリプトに SUID を付けても **無視されます**。root の権限が必要なら sudo を使います |

> **【ひっかけ】** 実行ファイル(バイナリ)は実行権だけで動きますが、シェルスクリプトは bash が中身を読んで実行するので、**読み取り権がないと実行できません**。`chmod 711` では、他のユーザーは実行できません。

### 15. 環境に左右されない書き方

スクリプトの動きは、実行するユーザーの PATH や言語の設定に影響されます。cron などから実行すると、PATH に最小限のディレクトリしか含まれていないことがよくあります。

``` bash
#!/bin/bash
# スクリプトの中で PATH をはっきり決める
PATH=/usr/local/bin:/usr/bin:/bin
export PATH
# 出力を英語の決まった書式にする
export LANG=C

# コマンドを絶対パスで書く方法もある
/usr/bin/tar czf /backup/etc.tgz /etc
```

- スクリプトの最初で PATH を設定するか、コマンドを絶対パスで書きます。
- `LANG=C` にすると、日付やエラーの表示が英語の決まった形になり、結果を加工しやすくなります(1.08 でも出てきます)。
- 相対パスでのファイルの指定は、実行した場所によって結果が変わるので避けます。

### 16. メニュー型のスクリプト(select)

Linux に慣れていない利用者にも、決められた操作だけを番号で選ばせることができます。

``` bash
#!/bin/bash
PS3="番号: "
select item in disk user quit; do
  case "$item" in
    disk) df -h ;;
    user) who ;;
    quit) break ;;
    *) echo "番号が違う" ;;
  esac
done
```

実行すると、次のように表示されます。

``` bash
1) disk
2) user
3) quit
番号:
```

- `select` は、選択肢に番号を付けてメニューを表示し、選ばれた値を変数に入れます。
- `PS3` がメニューで入力を促す文字列です。
- `break` するまでくり返します。`case` と組み合わせるのが定番です。

### 17. 補足: 変数の扱い

| 書き方 | 意味 |
|---|---|
| `local 変数=値` | 関数の中だけで使える変数 |
| `readonly 変数=値` | 読み取り専用の変数。値の変更や unset ができない |
| `$!` | 直前にバックグラウンドで実行(&)したプロセスの ID |
| `${変数:-既定値}` | 変数が空なら既定値を使う |

``` bash
DIR=${1:-/tmp}   # 引数がなければ /tmp を使う
```

### 18. 補足: expr(計算のコマンド)

整数の計算をするコマンドです。古いスクリプトでよく使われています。公式の出題範囲には書かれていませんが、問題集には出てきます。

``` bash
expr 3 + 4      # 7
expr 10 - 3     # 7
expr 3 \* 4     # 12
expr 10 / 3     # 3(小数点以下は切り捨て)
expr 10 % 3     # 1(余り)
n=`expr $n + 1` # 1 増やす
```

- 数値と演算子の間には **空白が必要** です。`expr 3+4` と書くと、`3+4` がそのまま表示されます。
- `*` はシェルがファイル名の一覧に置き換えてしまうので、`\*` と書いてそのまま渡します。
- 整数だけを扱います。小数は使えません。

| 書き方 | 特徴 |
|---|---|
| `` `expr $n + 1` `` | 外部のコマンド。空白が必要で、掛け算は `\*` と書く |
| `$((n + 1))` | bash の機能。空白は自由で、`*` もそのまま書ける。今はこちらが主流 |

### 19. 補足: trap(シグナルを受けたときの処理)

スクリプトがシグナル(Ctrl+C や kill コマンドなどで送られる合図)を受けたときに、実行する処理を登録します。一時ファイルの後片付けによく使います。

``` bash
# 書き方: trap '処理' シグナル...
trap 'rm -f /tmp/work.$$; exit 1' INT TERM
# スクリプトが終わるときに必ず実行する
trap 'echo 終了' EXIT
# Ctrl+C を無視する
trap '' INT
# 設定を元に戻す
trap - INT
```

| シグナル | 番号 | 送られる場面 |
|---|---|---|
| `EXIT` | 0 | スクリプトが終わるとき(bash 独自) |
| `HUP` | 1 | 端末が切断されたとき |
| `INT` | 2 | Ctrl+C を押したとき |
| `KILL` | 9 | 強制終了。**trap できない** |
| `TERM` | 15 | `kill` コマンドの既定のシグナル |

> **【ひっかけ】** `KILL`(9)と `STOP` は、trap で受け取ることも無視することもできません。`trap '' KILL` は効きません。

> **【1.06.2 まとめ】**
>
> - `#!/bin/bash` で始め、`chmod +x` で実行権を付け、`./` で実行する
> - `$#` は `$0` を数えない。`shift` で引数が左にずれる
> - `$?` は 0 が成功
> - `[ ]` の内側には空白が必要。数値は `-eq`、文字列は `=` で比べる
> - if…fi、case…esac、do…done
> - 関数は `function 名前 { }` か `名前() { }` で定義し、名前だけで呼び出す。`return` で戻り、`$?` で受け取る
> - デバッグは `bash -x`、文法の確認は `bash -n`
> - if はコマンドの終了ステータスで分岐する(`grep -q` など)
> - 配布するスクリプトは `/usr/local/bin`、`root:root`、`755`。スクリプトの SUID は無効
> - スクリプトの中で PATH を設定し、環境に左右されないようにする
> - メニューは `select` と `case`、プロンプトは `PS3`
> - `expr` は空白が必要で、掛け算は `\*`。`trap` はシグナルを受けたときの処理で、KILL は受け取れない
