# LinuC 102 テキスト 1.06 シェルおよびスクリプト

## 1.06.1 シェル環境のカスタマイズ （重要度4）

### 1. ログインシェルと非ログインシェル

bashは起動のされ方で、読み込む設定ファイルが変わる。ここが最頻出。

| 種類             | 起動される場面                                                   |
|------------------|------------------------------------------------------------------|
| ログインシェル   | ssh接続、コンソールからのログイン、`su -`、`bash -l`             |
| 非ログインシェル | ログイン後に`bash`と打つ、端末アプリを開く、`su`（ハイフンなし） |

### 2. 読み込まれる設定ファイル

| ファイル           | 読まれる場面               | 対象       |
|--------------------|----------------------------|------------|
| `/etc/profile`     | ログイン時                 | 全ユーザー |
| `~/.bash_profile`  | ログイン時（第1候補）      | 自分       |
| `~/.bash_login`    | ログイン時（第2候補）      | 自分       |
| `~/.profile`       | ログイン時（第3候補）      | 自分       |
| `/etc/bash.bashrc` | bash起動のたび（Debian系） | 全ユーザー |
| `~/.bashrc`        | bash起動のたび             | 自分       |
| `~/.bash_logout`   | ログアウト時               | 自分       |

ログイン時の3候補は、上から探して**最初に見つかった1つだけ**を読む。

> **【覚え方】** `profile` はログイン時に1回、`rc` はシェル起動のたび。`/etc/` 始まりは全員用、`~/` 始まりは自分用。

実際の `~/.bash_profile` には次の記述が入っていることが多い。

``` bash
if [ -f ~/.bashrc ]; then
    . ~/.bashrc
fi
```

> **【ひっかけ】** `~/.bash_profile` と `~/.profile` が両方ある場合、ログイン時に読まれるのは `~/.bash_profile` だけ。

### 3. シェル変数と環境変数

``` bash
# シェル変数（今のシェルだけ）
MYVAR=hello
# 環境変数にする
export MYVAR
# まとめて書ける
export MYVAR=hello
```

**［図2　シェル変数と環境変数の違い］**

親シェルで `A=1`（シェル変数）と `export B=2`（環境変数）を定義する。子プロセス（bash、スクリプト等）からは A は見えず、B=2 だけが見える。export した変数だけが子に引き継がれる。

| コマンド           | 用途                             |
|--------------------|----------------------------------|
| `env` / `printenv` | 環境変数の一覧                   |
| `set`              | シェル変数も含む全変数（関数も） |
| `unset 変数名`     | 変数を削除                       |
| `echo $変数名`     | 値を表示                         |

> **【ひっかけ】** `=` の前後に空白は入れない。`MYVAR = hello` は「MYVARというコマンド」と解釈されてエラーになる。

### 4. 引用符の違い

| 書き方       | 結果（NAME=Kuro）     |
|--------------|-----------------------|
| `"Hi $NAME"` | Hi Kuro（変数を展開） |
| `'Hi $NAME'` | Hi \$NAME（そのまま） |
| `` `date` `` | コマンドの実行結果    |

### 5. PATH

コマンドを探すディレクトリの一覧。`:` 区切り。左から順に探す。

``` bash
echo $PATH
/usr/local/bin:/usr/bin:/bin
# 末尾に追加
export PATH=$PATH:/opt/tools/bin
```

- `$PATH:` を付け忘れると既存のPATHが消え、`ls` すら動かなくなる。
- カレントディレクトリは通常PATHに含まれない。だから自作スクリプトは `./script.sh` と書く。
- コマンドの場所を調べる：`which ls`、`type ls`

### 6. 設定の反映：source と .

設定ファイルを書き換えても、今開いているシェルにはすぐ反映されない。

**［図3　source と bash の違い］**

| 実行方法                          | 動く場所                         | 今のシェルへの反映 |
|-----------------------------------|----------------------------------|--------------------|
| `source ~/.bashrc`、`. ~/.bashrc` | 今のシェルで直接実行             | 反映される         |
| `bash ~/.bashrc`、`./script.sh`   | 子シェルで実行し、終わると消える | 反映されない       |

> **【ひっかけ】** 「設定変更を今のシェルに反映するコマンド」の選択肢に `bash ~/.bashrc` があっても誤り。正解は `source` または `.`。

### 7. alias

``` bash
alias ll='ls -l' # 定義
alias            # 一覧
unalias ll       # 削除
\ls              # alias無視
```

ログアウトすると消える。永続化するなら `~/.bashrc` に書く。

### 8. コマンド置換

コマンドの実行結果を、別のコマンドの中に埋め込む。

``` bash
echo "今日は $(date +%F)"
# バッククォートでも同じ
echo "今日は `date +%F`"
```

### 9. コマンドの連結（lists）

| 記号     | 動作                   |
|----------|------------------------|
| `A ; B`  | 結果に関係なく順に実行 |
| `A && B` | Aが**成功**したらB     |
| `A || B` | Aが**失敗**したらB     |

``` bash
mkdir work && cd work
ping -c1 server || echo "接続できない"
```

> **【1.06.1 まとめ】**
>
> - ログイン時：`/etc/profile` → `~/.bash_profile`系（最初の1つ）
> - 起動のたび：`~/.bashrc`
> - `export` しないと子プロセスに渡らない
> - `source` と `.` は今のシェルに反映
> - `&&` は成功時、`||` は失敗時

## 1.06.2 シェルスクリプト （重要度6）

### 1. スクリプトの基本

``` bash
#!/bin/bash
# コメント
echo "Hello"
```

- 1行目の `#!`（シバン）で、使うインタプリタを指定する。
- 実行するには実行権が必要：`chmod +x hello.sh`

| 実行方法          | 実行権 | 動く場所   |
|-------------------|--------|------------|
| `./hello.sh`      | 必要   | 子シェル   |
| `bash hello.sh`   | 不要   | 子シェル   |
| `source hello.sh` | 不要   | 今のシェル |

### 2. 引数（位置パラメータ）

`./backup.sh /var/log 7` と実行した場合：

**［図4　位置パラメータ］**

`./backup.sh` が `$0`（スクリプト名）、`/var/log` が `$1`、`7` が `$2`。`$#` は 2、`$@` は `$1 $2`。`$0` は個数に数えない。

| 変数                | 意味                           |
|---------------------|--------------------------------|
| `$0`                | スクリプト名                   |
| `$1`〜`$9`、`${10}` | 第n引数（10以上は波括弧）      |
| `$#`                | 引数の個数（\$0は含まない）    |
| `$@`                | 全引数。`"$@"` は1個ずつ別の値 |
| `$*`                | 全引数。`"$*"` は1つの文字列   |
| `$?`                | 直前のコマンドの終了ステータス |
| `$$`                | 今のシェルのプロセスID         |

### 3. shift

引数を左に1つずらす。`$1` が捨てられ、`$#` が1減る。

**［図5　shift の動き］**

shift前：`$1=a $2=b $3=c`、`$#=3`。shift後：a は消え、`$1=b $2=c`、`$#=2`。

### 4. 終了ステータス

コマンドは終了時に0〜255の数値を返す。**0が成功、0以外が失敗**。

``` bash
ls /nothing
echo $?   # 2（失敗）
exit 1    # 1で終了
```

前節の `&&`、`||` も、この値で成功・失敗を判定している。

### 5. 条件分岐 if

``` bash
if [ -f /etc/hosts ]; then
    echo "ファイルがある"
elif [ -d /etc ]; then
    echo "ディレクトリはある"
else
    echo "ない"
fi
```

> **【ひっかけ】** `[ ]` は `test` コマンドと同じ。括弧の内側に**空白が必須**。`[-f file]` はエラー。終わりは `fi`（ifの逆）。

### 6. test の主な判定

| 書き方             | 真になる条件                           |
|--------------------|----------------------------------------|
| `-e` / `-f` / `-d` | 存在する / 通常ファイル / ディレクトリ |
| `-r` / `-w` / `-x` | 読み / 書き / 実行できる               |
| `-s`               | サイズが0より大きい                    |
| `-z 文字列`        | 空文字                                 |
| `-n 文字列`        | 空でない                               |
| `A = B` / `A != B` | 文字列が等しい / 異なる                |
| `-eq` `-ne`        | 数値が等しい / 異なる                  |
| `-lt` `-le`        | より小さい / 以下                      |
| `-gt` `-ge`        | より大きい / 以上                      |
| `!` `-a` `-o`      | 否定 / かつ / または                   |

> **【覚え方】** 数値は英字（-eq = equal、-lt = less than、-gt = greater than）。文字列は記号（=、!=）。

### 7. 条件分岐 case

``` bash
case "$1" in
  start)
    echo "起動" ;;
  stop)
    echo "停止" ;;
  restart|re)
    echo "再起動" ;;
  *)
    echo "使い方: $0 start|stop" ;;
esac
```

- 各パターンは `)` で始め、`;;` で終える。
- `|` で複数パターン。`*` はどれにも当たらない場合。
- 終わりは `esac`（caseの逆）。

### 8. ループ

``` bash
for i in 1 2 3; do
    echo $i
done

for f in *.log; do echo $f; done
for i in $(seq 1 5); do echo $i; done

n=1
while [ $n -le 3 ]; do
    echo $n
    n=$((n + 1))
done
```

- 本体は `do` 〜 `done`。
- `$(( ))` は整数の計算。
- `seq 1 5` は1から5の連番を出力。
- `until` は条件が**偽の間**くり返す（whileの逆）。
- `break` でループを抜け、`continue` で次の周回へ。

### 9. read（入力を受け取る）

``` bash
read -p "名前: " NAME
echo "こんにちは $NAME"
```

### 10. 関数（function文）

よく使う一連のコマンドに名前を付けて、まとめて呼び出せるようにする仕組み。公式範囲に「Bashの関数を作成する（function）」と明記されている。

**定義の書き方は3通り**。どれも同じ意味。

``` bash
# ① function文
function greet {
    echo "Hello, $1"
}
# ② 名前()　※最も一般的
greet() {
    echo "Hello, $1"
}
# ③ 両方を付ける
function greet() {
    echo "Hello, $1"
}
# 1行で書くときは } の前に ; が必要
function greet { echo "Hello, $1"; }
```

**呼び出し**は、コマンドと同じく名前を書くだけ。括弧は付けない。

``` bash
greet Kuro     # Hello, Kuro
greet()        # × これは定義の書き出し
```

**［図6　関数の引数］**

`./s.sh A B` の中で `greet X Y` と呼ぶ。スクリプト本体では `$1=A $2=B $#=2`。関数 greet の中では `$1=X $2=Y $#=2`。関数の中では `$1` `$#` `$@` が関数の引数に切り替わる。`$0` は変わらない。

**戻り値**は `return` で返す終了ステータス（0〜255）。呼び出した側は `$?` で受け取る。

``` bash
is_root() {
    [ "$(id -u)" -eq 0 ] && return 0
    return 1
}
if is_root; then echo "rootです"; fi
```

文字列や計算結果を返したいときは、`echo` で出力し、コマンド置換で受け取る。

``` bash
add() { echo $(($1 + $2)); }
sum=$(add 3 4)
echo $sum      # 7
```

| 項目               | ポイント                                                                         |
|--------------------|----------------------------------------------------------------------------------|
| 定義の順番         | 呼び出しより**前**に定義する。後ろに書くと「command not found」                  |
| `return` と `exit` | `return` は関数だけ抜ける。`exit` は関数内でもスクリプト全体が終わる             |
| return 省略時      | 関数内で最後に実行したコマンドの終了ステータスが戻り値になる                     |
| 変数の範囲         | 関数内の変数は既定で**全体に見える**（グローバル）。関数内だけにするなら `local` |
| 一覧と削除         | `declare -f`（定義を表示）、`declare -F`（名前だけ）、`unset -f 名前`            |
| 常に使う           | `~/.bashrc` に定義を書く                                                         |

``` bash
count=1
f() { count=5; local tmp=9; }
f
echo $count    # 5（書き換わる）
echo $tmp      # 空（localは外に出ない）
```

> **【aliasとの違い】** alias は単純な置き換えで、引数を途中に挟めない。関数は `$1` などで引数を自由に使え、if や for も書ける。

> **【ひっかけ】** 「関数 greet を呼び出す正しい書き方」で `greet()` や `call greet` は誤り。正解は `greet` だけ。

### 11. デバッグ

| オプション          | 表示内容                                         |
|---------------------|--------------------------------------------------|
| `bash -x script.sh` | 実行するコマンドを展開後の形で表示（先頭に `+`） |
| `bash -v script.sh` | 読み込んだ行をそのまま表示                       |
| `bash -n script.sh` | 実行せず文法だけチェック                         |

スクリプト内で一部だけ追うなら `set -x` 〜 `set +x`。

### 12. 総合例

``` bash
#!/bin/bash
if [ $# -ne 1 ]; then
    echo "使い方: $0 ディレクトリ"
    exit 1
fi

count=0
for f in "$1"/*; do
    if [ -f "$f" ]; then
        echo "ファイル: $f"
        count=$((count + 1))
    fi
done
echo "合計 $count 個"
exit 0
```

引数が1個でなければ使い方を表示して終了。1個なら、その中のファイルを数えて表示する。

### 13. if にコマンドを直接書く

if が見ているのは「条件式」ではなく、**コマンドの終了ステータス**。0なら真、0以外なら偽。`[ ]` も `test` というコマンドの1つにすぎない。

``` bash
if grep -q "^kuro:" /etc/passwd; then
    echo "ユーザーkuroは存在する"
fi

if ping -c1 -W1 192.168.1.1 > /dev/null; then
    echo "疎通OK"
fi
```

- `grep -q` は何も表示せず、見つかれば0、なければ1を返す。
- `> /dev/null` で出力を捨てて、結果だけ使う。

### 14. スクリプトの配置と権限

作ったスクリプトを他のユーザーにも使わせるには、置き場所・所有者・パーミッションを整える。

``` bash
sudo cp backup.sh /usr/local/bin/backup
sudo chown root:root /usr/local/bin/backup
sudo chmod 755 /usr/local/bin/backup
```

**［図7　配布用スクリプトの標準的な権限］**

`chmod 755` ＝ `rwxr-xr-x`。所有者(root)は rwx（7：編集・実行）、グループは r-x（5：読む・実行）、その他は r-x（5：読む・実行）。r=4、w=2、x=1 の合計。

| 項目     | ポイント                                                                                  |
|----------|-------------------------------------------------------------------------------------------|
| 置き場所 | 全ユーザー用は `/usr/local/bin`。PATHに含まれるので名前だけで実行できる。個人用は `~/bin` |
| 所有者   | `chown root:root`。一般ユーザーが中身を書き換えられないようにする                         |
| 権限     | `755`。シェルスクリプトは**読み取り権＋実行権**の両方が必要                               |
| SUID     | Linuxではシェルスクリプトに SUID を付けても**無視される**。root権限が必要なら sudo を使う |

> **【ひっかけ】** バイナリは実行権だけで動くが、シェルスクリプトはbashが中身を読むため、**読み取り権がないと実行できない**。`chmod 711` では他人は実行できない。

### 15. 環境に依存しない書き方

スクリプトは実行するユーザーのPATHや言語設定に左右される。cronなどからの実行ではPATHが最小限しかないことも多い。

``` bash
#!/bin/bash
# スクリプト内でPATHを明示
PATH=/usr/local/bin:/usr/bin:/bin
export PATH
# 出力を英語・固定書式に
export LANG=C

# 絶対パスで書く方法もある
/usr/bin/tar czf /backup/etc.tgz /etc
```

- PATHを先頭で設定するか、コマンドを絶対パスで書く。
- `LANG=C` にすると日付やエラーの表示が英語に固定され、結果を加工しやすい（1.08で再登場）。
- 相対パスのファイル指定は、実行した場所によって結果が変わるので避ける。

### 16. メニュー型スクリプト（select）

Linuxに不慣れなユーザーにも、決められた操作だけを番号で選ばせられる。

``` bash
#!/bin/bash
PS3="番号: "
select item in disk user quit; do
  case "$item" in
    disk) df -h ;;
    user) who ;;
    quit) break ;;
    *) echo "番号が違う" ;;
  esac
done
```

実行すると次のように表示される。

``` bash
1) disk
2) user
3) quit
番号:
```

- `select` は選択肢に番号を振ってメニューを表示し、選ばれた値を変数に入れる。
- `PS3` がメニューのプロンプト文字列。
- `break` するまでくり返す。`case` と組み合わせるのが定番。

### 17. 補足：変数の扱い

| 書き方             | 意味                                             |
|--------------------|--------------------------------------------------|
| `local 変数=値`    | 関数の中だけで有効な変数                         |
| `readonly 変数=値` | 読み取り専用。変更や unset ができない            |
| `$!`               | 直前にバックグラウンド実行（&）したプロセスのPID |
| `${変数:-既定値}`  | 変数が空なら既定値を使う                         |

``` bash
DIR=${1:-/tmp}   # 引数なしなら /tmp
```

### 18. 補足：expr（計算コマンド）

整数の計算をする外部コマンド。古いスクリプトでよく使われる。公式範囲には明記されていないが、問題集には出る。

``` bash
expr 3 + 4      # 7
expr 10 - 3     # 7
expr 3 \* 4     # 12
expr 10 / 3     # 3（切り捨て）
expr 10 % 3     # 1（余り）
n=`expr $n + 1` # 1増やす
```

- 数値と演算子の間に**空白が必須**。`expr 3+4` は `3+4` とそのまま表示される。
- `*` はシェルがファイル名に展開するため、`\*` とエスケープする。
- 整数のみ。小数は扱えない。

| 書き方              | 特徴                                             |
|---------------------|--------------------------------------------------|
| `` `expr $n + 1` `` | 外部コマンド。空白必須、`\*` が必要              |
| `$((n + 1))`        | bashの機能。空白は自由、`*` もそのまま。今の主流 |

### 19. 補足：trap（シグナルを受けたときの処理）

スクリプトがシグナル（Ctrl+C や kill など）を受けたときに実行する処理を登録する。一時ファイルの後始末が定番の用途。

``` bash
# 書式：trap '処理' シグナル...
trap 'rm -f /tmp/work.$$; exit 1' INT TERM
# スクリプト終了時に必ず実行
trap 'echo 終了' EXIT
# Ctrl+C を無視する
trap '' INT
# 設定を元に戻す
trap - INT
```

| シグナル | 番号 | 送られる場面                   |
|----------|------|--------------------------------|
| `EXIT`   | 0    | スクリプトの終了時（bash独自） |
| `HUP`    | 1    | 端末が切断された               |
| `INT`    | 2    | Ctrl+C                         |
| `KILL`   | 9    | 強制終了。**trapできない**     |
| `TERM`   | 15   | `kill` の既定                  |

> **【ひっかけ】** `KILL`（9）と `STOP` は trap で捕まえることも無視することもできない。`trap '' KILL` は効かない。

> **【1.06.2 まとめ】**
>
> - `#!/bin/bash`、`chmod +x`、`./` で実行
> - `$#` は\$0を含まない。`shift` で左にずれる
> - `$?` は0が成功
> - `[ ]` の内側は空白必須。数値は `-eq`、文字列は `=`
> - if…fi、case…esac、do…done
> - 関数は `function 名前 { }` か `名前() { }`。呼び出しは名前だけ。`return` で戻り、`$?` で受ける
> - デバッグは `bash -x`、文法チェックは `bash -n`
> - if はコマンドの終了ステータスで分岐する（`grep -q` など）
> - 配布は `/usr/local/bin`、`root:root`、`755`。スクリプトのSUIDは無効
> - スクリプト内でPATHを設定し、環境に依存させない
> - メニューは `select` と `case`、プロンプトは `PS3`
> - `expr` は空白必須で `\*`。`trap` はシグナル時の処理、KILLは捕まえられない
