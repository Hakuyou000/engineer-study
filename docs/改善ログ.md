# 改善ログ

見つけた欠陥と、その対応を残す。`npm run metrics` がこの表を数える。

## 進め方

1. 見つける: 内容の検査(`npm run gen`)、網羅性の検査(`npm run coverage`)、レビュー(PR ごとに、コードは `/code-review`、問題は `/review-questions`)、学習中の指摘(アプリの「この問題に指摘する」→ エクスポート → `npm run triage`)
2. 直す: 1 件ずつ直し、下の表に 1 行足す
3. 検査に変える: 同じ分類が 2 回目に出たら、`src/lib/contentLint.ts` か網羅性の表に規則を足し、「検査」の列に規則の名前を書く。機械で見つけられないものは CLAUDE.md の書き方の規則に足す
4. 測る: 週に 1 回 `npm run metrics` を実行し、`docs/指標.md` をコミットする

## 分類

| 分類 | 意味 |
|---|---|
| 他問参照 | ほかの問題を前提にした書き方。出題の順番は入れ替わる |
| 選択肢の記号 | 選択肢を並べ替えると崩れる、解説の記号の書き方 |
| 版の不一致 | 取り決めた版(Terraform の AWS プロバイダーは 6 系など)と違う |
| 前提の不足 | 問題文の条件が足りず、正解が 1 つに決まらない |
| 別解の不足 | 入力問題で、正しい答えを不正解にする |
| 事実の誤り | 解説や正解が事実と違う |
| 網羅の不足 | 出題範囲の用語や小項目に問題がない、または少ない |
| 画面 | アプリの表示や操作の不具合 |
| 図のずれ | テキストの文字の図が、フォントによって桁がずれる |
