## 解答・解説

### 問1 `DOP-1.0-001`

**正解**: C

**テキスト**: 6. マルチアカウントのパイプライン

別のアカウントがアーティファクトを復号するには、カスタマー管理の KMS キーが必要です。AWS 管理のキー(`aws/s3`)は、キーポリシーを変更できないので、他のアカウントに共有できません。キーポリシーとバケットポリシーの両方で、本番アカウントのロールを許可します。

- A. 本番アカウントのロールの IAM ポリシーだけでは、KMS キーの側の許可がないので、復号できません。
- B. バケットを公開しても、暗号化のキーへの権限は解決しません。さらにセキュリティ上も危険です。
- C. 正しい対応です。
- D. AWS 管理のキーは、アカウントごとに別で、アーティファクトを暗号化したキーとは別物です。作り直しても復号できません。

### 問2 `DOP-1.0-002`

**正解**: B

**テキスト**: 5. ビルドとデプロイのシークレット

`buildspec.yml` の `env` の `secrets-manager` に書くと、ビルドの実行時に値が環境変数として渡されます。サービスロールに権限を付ければよく、コードにパスワードは残りません。ローテーションにも追従できます。

- A. 平文の環境変数は、コンソールやログで見えてしまいます。機密には使いません。
- B. 正しい方法です。
- C. コードにパスワードを書くと、履歴に残ります。リポジトリを非公開にしても防げません。
- D. 平文のファイルをバケットに置くと、バケットの権限の管理が増え、漏れる危険も上がります。

### 問3 `DOP-1.0-003`

**正解**: `特権モード`、`privileged`、`privileged mode`、`privilegedMode`、`PrivilegedMode`、`privileged-mode`、`--privileged-mode`

**テキスト**: 4. CodeBuild とビルド仕様(buildspec)

CodeBuild のビルドの中で Docker のデーモンを動かすには、プロジェクトの環境で「特権(privileged)」を有効にします。有効にしないと、`docker build` は Docker のデーモンに接続できず失敗します。

### 問4 `DOP-1.0-004`

**正解**: B、E

**テキスト**: 2. CodePipeline の仕組み

AWS CodeConnections の接続を作ると、GitHub のリポジトリをパイプラインのソースにできます。承認が必要な箇所には、手動承認のアクションを置き、SNS で通知します。承認されるまで、次のステージには進みません。

- A. ステージを毎回手で作る運用は、自動化に反します。
- B. 正しい設定です。
- C. 自作のポーリングは、手間が増えます。ソースのアクションで足ります。
- D. 遷移を手で操作する運用は、承認の記録が残らず、誤りやすいです。承認の専用のアクションがあります。
- E. 正しい設定です。

### 問5 `DOP-1.0-005`

**正解**: D

**テキスト**: 4. CodeBuild とビルド仕様(buildspec)

CodeBuild のプロジェクトに VPC の設定をすると、ビルドがプライベートサブネットの中で動き、RDS に接続できます。VPC の中のビルドは、インターネットに出るために NAT ゲートウェイが要ります。セキュリティグループで、ビルドから RDS への接続を許可します。

- A. データベースを公開するのは、セキュリティ上の問題があります。
- B. ホスト名を渡しても、VPC の外にあるビルドは、プライベートな RDS に届きません。
- C. 手作業のテストは、自動化の要件を満たしません。VPC の設定をしないと接続できません。
- D. 正しい構成です。

### 問6 `DOP-1.0-006`

**正解**: A

**テキスト**: 2. CodePipeline の仕組み

CodePipeline のソースのアクションに ECR を指定すると、イメージの push を、EventBridge のルールで検知して、パイプラインを自動で起動できます。ポーリングは不要です。

- A. 正しい方法です。
- B. 定期的に確認する方式は、ポーリングです。遅れもあり、自作の手間もあります。
- C. S3 のイベント通知は、ECR の push の検知には使えません。
- D. 手作業は、自動化の要件に反します。

### 問7 `DOP-1.0-007`

**正解**: B

**テキスト**: 2. プルリクエストとマージでビルドを動かす

CodeCommit のプルリクエストのイベント(作成、更新)を EventBridge のルールで検知して、CodeBuild を起動すると、マージの前にテストできます。

- A. 夜間の main のテストでは、プルリクエストの変更はマージ前に確認できません。
- B. 正しい方法です。
- C. マージの後のテストでは、壊れた変更が main に入ってしまいます。
- D. 手作業の報告は、自動化の要件を満たしません。

### 問8 `DOP-1.0-008`

**正解**: C

**テキスト**: 4. パイプラインから AWS のサービスを呼ぶテスト

CodePipeline の Lambda 呼び出しアクションは、関数が `PutJobSuccessResult` か `PutJobFailureResult` を呼んで結果を返すまで待ちます。返さないと、アクションはタイムアウトまで実行中のままです。

- A. 呼び出しの権限がなければ、アクションはすぐに失敗します。「実行中のまま」にはなりません。
- B. ランタイムの版の古さは、結果を返す必要には関係がありません(確認には成功している前提です)。
- C. 原因として最も可能性が高いものです。
- D. バケットの暗号化は、Lambda のアクションの完了の通知には関係しません。

関数の実行ロールに、`codepipeline:PutJobSuccessResult` と `codepipeline:PutJobFailureResult` の権限が要ります。

### 問9 `DOP-1.0-009`

**正解**: A、C

**テキスト**: 1. どの段で何のテストを行うか
