## 解答・解説

### 問1 `DOP-5.0-001`

**正解**: B

セキュリティグループの変更は API の呼び出しです。CloudTrail の管理イベントが EventBridge に届くので、`eventName` で絞ったルールで、すぐに Lambda を動かせます。

- A. 毎分の一覧は、常に動かす必要があり、API の呼び出しも多くなります。1 分以内の保証も難しくなります。
- C. Config のスナップショットを 1 日 1 回出力する方法は、翌日の確認になり、遅すぎます。
- D. VPC フローログは通信の記録です。ルールの追加そのものは検知できず、目で見る方法は自動ではありません。

### 問2 `DOP-5.0-002`

**正解**: D

SNS で複数の購読者に配り(ファンアウト)、購読者ごとに SQS を挟むと、各システムが自分の速さで取り出せます。1 つが遅くても、ほかのキューには影響しません。

- A. 1 つのキューを 3 つのシステムで読むと、1 つのメッセージは 1 つのシステムにしか届きません。3 つに同じ注文を配れません。
- B. Express ワークフローで順番に呼ぶと、遅いシステムが、あとのシステムを待たせます。
- C. Scheduler で 1 分ごとに起動してデータベースを確認する方法は、遅延が大きく、イベント駆動でもありません。

### 問3 `DOP-5.0-003`

**正解**: A

AWS Health の組織ビューを使うと、組織内のすべてのアカウントのイベントを、管理アカウントか委任管理者のアカウントで見られます。

- B. 各アカウントに手作業でルールを作る方法は、アカウントが増えるたびに手間が増えます。
- C. 組織の CloudTrail 証跡は、API の操作の記録です。AWS 側の障害やメンテナンスは含みません。
- D. Config のアグリゲーターは、リソースの設定と準拠状況を集めるものです。Health のイベントは集めません。

### 問4 `DOP-5.0-004`

**正解**: B、D

部分バッチ応答を使うと、失敗したメッセージだけをキューに戻せます。成功した分の重複を防げます。何度も失敗するメッセージは、最大受信回数を超えるとデッドレターキューに移るので、キューに残り続けません。移したメッセージは、あとで原因を調べられます。

- A. 可視性タイムアウトを 0 秒にすると、処理中のメッセージがすぐ別の受け手に見えるので、重複が増えます。
- C. 保持期間を短くすると、失敗したメッセージが調べる前に消えます。重複の問題も解決しません。
- E. Lambda のメモリを増やしても、処理の失敗や重複の仕組みは変わりません。

### 問5 `DOP-5.0-005`

**正解**: C

Kinesis Data Streams は、パーティションキーによって同じ機器のデータの順序をシャード内で保ちます。複数のアプリケーションが、同じデータをそれぞれ読めます。保持期間内なら、読み直せます。

- A. SQS の FIFO キューは順序を保てますが、メッセージは 1 つの受け手が取り出すと消えます。3 つのアプリが同じデータを読んだり、読み直したりする用途に向きません。
- B. SNS は、メッセージを配るだけで、保存して読み直す機能はありません。
- D. EventBridge Scheduler は、決めた時刻に処理を起動するサービスです。データの流れを受けるものではありません。

### 問6 `DOP-5.0-006`

**正解**: `リプレイ`、`Replay`、`replay`、`イベントのリプレイ`、`リプレイ機能`

EventBridge のアーカイブに保存したイベントは、リプレイで、指定した期間のものを再びイベントバスに流せます。ルールを直したあとの検証や、障害後の再処理に使います。

### 問7 `DOP-5.0-007`

**正解**: C

Standard ワークフローは最長 1 年実行できます。料金は、状態の遷移の回数で決まります。待っている時間には、料金がかかりません。コールバックのパターンでは、タスクトークンを使って、承認が届くまで待ちます。サーバーも常駐プログラムも要りません。

- A. Express ワークフローの最長は 5 分です。数日は待てません。コールバック(`.waitForTaskToken`)にも対応していません。
- B. Lambda の中で待つ方法は、関数の実行の上限(15 分)を超えます。待っている間も料金がかかります。
- D. EC2 の常駐プログラムは、サーバーの管理が必要で、待っている間も費用がかかります。

### 問8 `DOP-5.0-008`

**正解**: A

Run Command は、タグで対象を指定して、SSH なしでコマンドを実行できます。最大同時実行数とエラーのしきい値で、一度に動かす台数と止める条件を決められます。

- B. Session Manager で 1 台ずつ入る方法は、数百台では手間がかかりすぎます。
- C. Patch Manager は、パッチの適用のための仕組みです。任意の設定ファイルの更新には向きません。
- D. CodeDeploy は、アプリケーションのリビジョンをデプロイする仕組みです。1 回限りのスクリプトの実行には大げさで、事前の準備も必要です。

### 問9 `DOP-5.0-009`

**正解**: D

Config のルールが設定を継続的に評価し、非準拠のときに、自動修復として Systems Manager Automation のドキュメント(`AWS-DisableS3BucketPublicReadWrite` など)を実行できます。コードは要りません。

- A. Macie は、S3 内の機密データを見つけるサービスです。公開設定を直すものではありません。
- B. GuardDuty は、脅威を検出するサービスです。検出の確認だけでは、自動で直せません。
