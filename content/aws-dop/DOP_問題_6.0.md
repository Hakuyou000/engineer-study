## 解答・解説

### 問1 `DOP-6.0-001`

**正解**: C

属性ベースのアクセス制御(ABAC)です。人のタグとリソースのタグが同じときだけ許可する条件を書くと、プロジェクトが増えても、ポリシーは変えずに、タグを付けるだけで済みます。

- A. インスタンスの ID を列挙する方法は、インスタンスが増えるたびに、ポリシーを書き換える必要があります。
- B. すべてに `ec2:*` を許可すると、最小権限に反します。ほかのプロジェクトのインスタンスも操作できます。
- D. アカウントをプロジェクトごとに分ける方法は、管理が重く、要件に対して大げさです。SCP は権限の上限なので、タグの一致を判定する用途にも向きません。

### 問2 `DOP-6.0-002`

**正解**: A

IAM に OIDC ID プロバイダーを登録すると、GitHub が発行するトークンで、ロールを引き受けられます。信頼ポリシーで、リポジトリやブランチを条件に絞れます。長期のキーを持たなくて済みます。

- B. 暗号化して保存しても、長期のアクセスキーであることは変わりません。漏えいと、ローテーションの手間の問題が残ります。
- C. ルートユーザーのキーは、作らないことが推奨されます。
- D. 公開の S3 バケットに認証情報を置くと、誰でも読めてしまいます。

### 問3 `DOP-6.0-003`

**正解**: D

交互ユーザーのローテーションは、同じ権限の 2 つのユーザーを 1 つの秘密情報で管理し、ローテーションのたびに、使っていない側のパスワードを更新します。更新後も、もう一方のユーザーの認証情報が有効なので、接続の失敗が最も少なくなります。最初のローテーションで、元のユーザーの複製が作られます。複製の作成には、マスターの認証情報(superuser の秘密情報)が要ります。

- A. 単一ユーザーのローテーションでは、データベースのパスワードの変更から、秘密情報の更新までの短い間に、新しい認証情報への切り替えが間に合わず、接続が拒否されることがあります。
- B. アプリケーションを停止すると、サービスが止まります。接続の失敗を減らす方法としては不適切です。
- C. ローテーションをやめると、認証情報が長く使われ続けます。自動ローテーションの目的に反します。

### 問4 `DOP-6.0-004`

**正解**: B、D

ロールの作成を、指定した境界が付くときだけ許可すると、開発者のロールの権限に上限を付けられます。境界を外す操作と、境界のポリシーの変更を拒否しないと、開発者が境界を外して、昇格できてしまいます。2 つがそろって、抜け道を塞げます。

- A. IAMFullAccess を付けると、開発者が、自分に管理者権限を付けられます。昇格を防げません。
- C. パスワードポリシーは、IAM ユーザーのパスワードの強度の設定です。ロールの権限の上限とは関係しません。
- E. MFA の条件は、本人確認の強化です。作るロールの権限の上限は決められません。

### 問5 `DOP-6.0-005`

**正解**: B

IAM Roles Anywhere は、AWS の外のワークロードが、X.509 証明書で認証して、一時的な認証情報を得る仕組みです。信頼のアンカー(CA)、プロファイル、ロールを設定します。

- A. IAM ユーザーのアクセスキーは、長期の認証情報です。要件に反します。
- C. インスタンスプロファイルは、EC2 のためのもので、オンプレミスのサーバーには付けられません。
- D. バケットの公開は、セキュリティ上の大きな問題です。

### 問6 `DOP-6.0-006`

**正解**: `aws:MultiFactorAuthPresent`、`aws:multifactorauthpresent`

`"Bool": {"aws:MultiFactorAuthPresent": "true"}` のように使います。MFA で認証してからの経過時間を使うときは、`aws:MultiFactorAuthAge` です。

### 問7 `DOP-6.0-007`

**正解**: C

IAM Access Analyzer のポリシー生成は、指定した期間の CloudTrail の記録を分析し、実際に使った操作だけを許可するポリシーを作ります。最小権限に近づけるのに使います。

- A. Config のルールは、設定が基準に合っているかを評価します。使った操作の分析はしません。
- B. Inspector は、ソフトウェアの脆弱性を検出します。
- D. Macie は、S3 の機密データを検出します。

### 問8 `DOP-6.0-008`

**正解**: A

GuardDuty は、委任管理者を決めると、組織全体を管理できます。新しいアカウントに自動で有効化する設定を使うと、追加のたびの作業が要りません。リージョンごとの設定は必要ですが、委任管理者から一括で管理できます。

- B. 手作業は、アカウントとリージョンの数が多いと、現実的ではありません。
- C. VPC フローログは、通信の記録です。脅威の検出は、GuardDuty が行います。
- D. 管理アカウントだけの CloudTrail では、ほかのアカウントの脅威を検出できません。

### 問9 `DOP-6.0-009`

**正解**: D

Security Hub は、複数のサービスの検出結果を集めます。委任管理者を決めて、集約リージョンを設定すると、複数のアカウントとリージョンの結果を、1 か所で見られます。

- A. アカウントごとのメールは、集約になりません。
- B. CloudWatch Logs に出して手作業で結合する方法は、運用の手間が大きく、重大度順の画面も作れません。
- C. Detective は、検出結果を調査するためのサービスです。結果を集約して一覧にするものではありません。

### 問10 `DOP-6.0-010`

**正解**: B

Firewall Manager は、組織全体に WAF のルールを配って強制します。新しいリソースやアカウントにも自動で適用し、準拠していないリソースを検出して直せます。

- A. Shield Standard は、DDoS の基本的な保護です。WAF のルールは配りません。
- C. GuardDuty は、脅威を検出します。ルールの配布はしません。
- D. Trusted Advisor は、推奨事項を示すだけで、WAF のルールを強制しません。

### 問11 `DOP-6.0-011`

**正解**: A、D

自動ローテーションは、キーマテリアルが KMS で生成された、対称暗号化のカスタマーマネージドキーで有効にできます。古いキーマテリアルは保持されるので、既存の暗号文は、そのまま復号できます。

- B. インポートしたキーマテリアルは、自動ローテーションに対応していません。新しいキーマテリアルをインポートして、オンデマンドでローテーションします。
- C. 再暗号化は不要です。復号のときは、暗号化に使われた版のキーマテリアルが、自動で使われます。
- E. AWS マネージドキーのローテーションは、AWS が管理します。利用者は、有効と無効を切り替えられません。

### 問12 `DOP-6.0-012`

**正解**: C

CloudFront で ACM の証明書を使うときは、バージニア北部(`us-east-1`)で、証明書を発行(またはインポート)します。ほかのリージョンの証明書は、ディストリビューションで選べません。

- A. 有効期間の長さは、リージョンの制約と関係しません。
- B. 東京リージョンの証明書を、CloudFront に直接関連付ける API はありません。
- D. 検証の方法は、証明書の発行の確認の手段です。使えるリージョンは変わりません。

### 問13 `DOP-6.0-013`

**正解**: `Amazon Macie`、`Macie`、`macie`、`amazon macie`

Macie は、S3 のデータを分析し、個人情報などの機密データを自動で見つけて分類します。検出結果は、Security Hub や EventBridge に送れます。

### 問14 `DOP-6.0-014`

**正解**: A

Network Firewall には、ドメイン名のリスト(許可リスト)でトラフィックを制御するルールがあります。IP アドレスが変わっても、ドメイン名で制限できます。

- B. セキュリティグループに、頻繁に変わる IP アドレスを手作業で登録する方法は、運用が追いつきません。
- C. ネットワーク ACL は、IP アドレスとポートで制御します。ドメイン名は指定できません。
- D. Shield Advanced は、DDoS の対策です。外への通信の制限には使いません。

### 問15 `DOP-6.0-015`

**正解**: B

組織の証跡は、全アカウントの記録を 1 つのバケットに集めます。メンバーアカウントでは、証跡を止められません。ログファイルの整合性の検証を有効にすると、ダイジェストファイルで、改ざんがないかを確かめられます。

- A. 個別の証跡は、メンバーアカウントの管理者が止められます。
- C. CloudWatch のメトリクスは、API の操作の記録ではありません。
- D. VPC フローログは、通信の記録です。API の操作は記録しません。

### 問16 `DOP-6.0-016`

GuardDuty の検出結果は、EventBridge のイベントになります。重大度で絞ったルールのターゲットに SNS を指定すると、すぐに通知できます。ポーリングは要りません。

- A. 1 分ごとの Lambda は、自作のポーリングです。要件に反します。
- B. CloudTrail のログを毎日手作業で確認する方法は、すぐの通知になりません。

### 問17 `DOP-6.0-017`

**正解**: A、C

漏えいしたキーは、すぐに無効にして、悪用を止めます。そのうえで、CloudTrail で、漏えいした期間にそのキーが何に使われたかを確認し、被害の範囲を調べます。

- B. コンソールのパスワードを変えても、アクセスキーは有効なままです。
- D. S3 の暗号化は、キーの悪用を止めません。
- E. AWS は、漏えいしたキーに操作を制限するポリシーを付けることがあります。ただし、キーは有効なままです。利用者が、すぐに無効にする必要があります。

### 問18 `DOP-6.0-018`

**正解**: C

Amazon Inspector は、EC2、ECR のイメージ、Lambda を、継続的にスキャンします。新しい脆弱性が公開されると、自動で再評価します。

### 問19 `DOP-6.0-019`

### 問20 `DOP-6.0-020`

**正解**: B

ドリフト検出は、スタックのリソースの現在の設定を、テンプレートの定義と比べて、手作業の変更を検出します。

- A. 変更セットは、更新の前に、変更の内容を確認する機能です。すでに起きた手作業の変更は検出できません。
- C. スタックポリシーは、スタックの更新で、特定のリソースが変更されるのを防ぎます。手作業の変更の検出ではありません。
- D. DeletionPolicy は、スタックの削除のときに、リソースを残すか消すかを決めます。
