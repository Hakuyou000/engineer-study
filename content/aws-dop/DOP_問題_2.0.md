## 解答・解説

### 問1 `DOP-2.0-001`

**正解**: B

**テキスト**: 2. CloudFormation の基本

変更セットは、更新を実行する前に、何が追加、変更、削除されるかを一覧で確認する機能です。リソースごとに、置換されるか(Replacement)も分かります。確認してから、実行するか、破棄するかを選べます。

- A. ドリフト検出は、手作業で変えられた現在の設定と、テンプレートとのずれを見つける機能です。更新の影響の確認はできません。
- B. 正しい機能です。
- C. スタックポリシーは、更新から守るリソースを決める機能です。確認の機能ではありません。
- D. 終了保護は、スタックの削除を防ぐ機能です。更新の確認には関係しません。

### 問2 `DOP-2.0-002`

**正解**: D

**テキスト**: 2. CloudFormation の基本

`DeletionPolicy: Snapshot` を指定すると、スタックの削除のときに、スナップショットを取ってからリソースを削除します。RDS や EBS のボリュームなどで使えます。

- A. `Delete` は、そのまま削除します。データが失われます。
- B. 終了保護は、スタックの削除そのものを禁止します。「削除はするが、バックアップは残す」という要件に合いません。
- C. スタックポリシーは、スタックの更新の操作を制御します。スタックの削除のときのデータの扱いは決められません。
- D. 正しい設定です。

### 問3 `DOP-2.0-003`

**正解**: A

**テキスト**: 2. CloudFormation の基本

カスタムリソースの Lambda 関数は、作成、更新、削除のたびに呼ばれ、処理の結果を、署名付き URL に返す必要があります。返さないと、CloudFormation は、タイムアウト(既定で 1 時間)まで待ちます。削除のときの応答が漏れるのが、よくある原因です。

- A. 原因として最も可能性が高いものです。
- B. スタックポリシーは、更新の操作を守るもので、削除の途中で止めるものではありません。
- C. `Outputs` の有無は、削除の動きに関係しません。
- D. ドリフトがあっても、削除は進みます。

### 問4 `DOP-2.0-004`

**正解**: A、E

**テキスト**: 3. 再利用の仕組み

Secrets Manager のシークレットを `GenerateSecretString` で自動生成すると、パスワードを誰も知らずに済みます。RDS には、動的参照で、実行時にシークレットの値を渡します。テンプレートにパスワードは残りません。

- A. 正しい方法です。
- B. テンプレートに書いたパスワードは、Git の履歴に残ります。
- C. ユーザーデータは、インスタンスの中から読めてしまい、平文で残ります。
- D. `Outputs` に出すと、スタックの情報として見えてしまいます。
- E. 正しい方法です。

### 問5 `DOP-2.0-005`

**正解**: C

**テキスト**: 4. StackSets(複数のアカウントとリージョンへ展開)

StackSets のサービスマネージド権限は、Organizations と連携します。対象に OU を指定して、自動デプロイを有効にすると、あとから OU に参加したアカウントにも、自動でスタックが展開されます。

- A. アカウントとリージョンの数だけ手作業が必要です。新しいアカウントのたびに、繰り返しも発生します。
- B. 手で実行する運用は、新しいアカウントごとに手間が残ります。StackSets の機能で足ります。
- C. 正しい方法です。
- D. SCP は、権限の上限を決めるもので、リソースを作成しません。

### 問6 `DOP-2.0-006`

**正解**: A

**テキスト**: 6. 構成管理のサービスの選び方

AWS AppConfig は、設定や機能フラグを、検証して、段階的に配布するサービスです。配布戦略(線形など)で、割合と時間を決め、CloudWatch アラームを監視に指定すると、アラームの発火で自動でロールバックします。

- A. 正しいサービスです。
- B. Parameter Store は、値を保存するだけで、段階的な配布と自動のロールバックはありません。
- C. S3 のオブジェクトの手作業の入れ替えは、段階的な配布も自動のロールバックもできません。
- D. コードのデプロイでは、設定の変更のたびに再デプロイが必要です。要件はデプロイなしです。

### 問7 `DOP-2.0-007`

**正解**: D

**テキスト**: 7. AWS Service Catalog

Service Catalog は、承認済みのテンプレートを製品として提供します。起動制約で、製品の作成に使う IAM ロールを指定すると、開発者本人には、リソースを作る広い権限が要りません。

- A. 広い権限を渡して、ルールで禁止するだけでは、承認外の構成を作れてしまいます。
- B. テンプレートをメールで配っても、開発者がリソースを作る権限は別に必要で、承認外の変更も防げません。
- C. 広い作成の権限を渡すことになり、要件に反します。
- D. 正しい方法です。

### 問8 `DOP-2.0-008`

**正解**: B、D

**テキスト**: 3. AWS Control Tower

Account Factory で、標準のアカウントをセルフサービスで作れます。Customizations for Control Tower(CfCT)は、アカウントの作成に合わせて、StackSets と SCP を自動で適用して、標準の設定を配ります。

- A. 手順書による手作業は、自動化の要件に反します。
- B. 正しい方法です。
- C. 管理アカウントにワークロードを置くのは、ベストプラクティスに反します。SCP も管理アカウントには効きません。
- D. 正しい方法です。
- E. ルートユーザーの共有は、最も避けるべき運用です。

### 問9 `DOP-2.0-009`

**正解**: B

**テキスト**: 2. AWS Organizations

IAM や CloudFront などのグローバルサービスは、特定のリージョン(通常は米国東部(バージニア北部))で動作するため、リージョン制限の `Deny` に引っかかります。`NotAction` で、これらのグローバルサービスの操作を、拒否の対象から外します。

- A. 各アカウントの IAM ポリシーでの制限は、アカウントの管理者が変更できるので、強制になりません。
- B. 正しい修正です。
- C. SCP の `Allow` は、権限を与えません。`Deny` を打ち消すこともできません(明示的な拒否が優先されます)。
- D. 管理アカウントに付けても、SCP は管理アカウントには効かず、メンバーアカウントへの制限も外れます。

### 問10 `DOP-2.0-010`

**正解**: `aws:RequestedRegion`

**テキスト**: 2. AWS Organizations

`aws:RequestedRegion` は、リクエストの送信先のリージョンを表すグローバル条件キーです。`StringNotEquals` で、許可するリージョンの一覧を指定して、それ以外を `Deny` にします。

### 問11 `DOP-2.0-011`

**正解**: B、C

**テキスト**: 4. 大規模でのセキュリティとガバナンス

GuardDuty の委任された管理者を指定すると、1 つのメンバーアカウントから、組織全体の検出結果を管理できます。新しいアカウントで自動で有効にする設定を加えると、今後のアカウントも手間なく有効になります。

- A. ルートユーザーでの手作業は、危険で、アカウントの数だけ手間がかかります。
- B. 正しい設定です。
- C. 正しい設定です。
- D. 手作業と、進捗の管理は、運用の手間が大きく、漏れも出ます。
- E. CloudTrail のログの手作業の検索は、脅威の検出の自動化になりません。

### 問12 `DOP-2.0-012`
