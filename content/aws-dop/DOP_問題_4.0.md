## 解答・解説

### 問1 `DOP-4.0-001`

**正解**: C

**テキスト**: 2. CloudWatch エージェント

EC2 の標準の指標には、メモリ使用率がありません。メモリは OS の中の値なので、ハイパーバイザー側から測れないためです。CloudWatch エージェントをインストールして、OS の中から、カスタム指標として送ります。

- A. 詳細モニタリングは、標準の指標の間隔を 1 分にするだけです。`AWS/EC2` にメモリ使用率はありません。
- B. X-Ray のデーモンは、リクエストのトレースを送るものです。メモリは測りません。
- D. VPC フローログは、ネットワークの通信の記録です。メモリは測れません。

### 問2 `DOP-4.0-002`

**正解**: A

**テキスト**: 2. CloudWatch エージェント

設定を、パラメータストアに置くと、1 か所で管理できます。Systems Manager(Run Command や State Manager)で、全台のエージェントに、その設定を読み込ませられます。設定を変えたら、同じ手順で全台に反映できます。

- B. 1 台ずつ SSH で配るのは、数百台では手間が大きく、漏れが出ます。
- C. ユーザーデータは、インスタンスの最初の起動時に実行されます。すでに稼働しているサーバーには、設定の変更が反映されません。
- D. AMI に埋め込むと、設定を変えるたびに、全サーバーの作り直しが必要です。手間が大きくなります。

### 問3 `DOP-4.0-003`

**正解**: D

**テキスト**: 4. ログから指標を作る: メトリクスフィルター

メトリクスフィルターは、JSON のログのフィールドを指定して、一致した数を指標にできます。その指標に、アラームを付けると、「5 分間に 5 件以上」を、設定だけで検出できます。

- A. エクスポートして Athena で数える方法は、仕組みが大きく、通知までに時間がかかります。
- B. Lambda 関数で数える方法は、コードの保守が必要です。メトリクスフィルターで足ります。
- C. 動かせますが、スケジュール、クエリ、通知のコードを、自分で作って保守する必要があります。メトリクスフィルターとアラームの設定で足りるので、手間が増えます。

### 問4 `DOP-4.0-004`

**正解**: A、C

**テキスト**: 8. ログと指標の暗号化とアクセス権限

既存のロググループにも、KMS キーを関連付けられます。その際、キーポリシーで、CloudWatch Logs のサービスプリンシパル(`logs.<リージョン>.amazonaws.com`)に、暗号化と復号などの権限を与える必要があります。与えないと、関連付けに失敗します。

- B. S3 のバケットポリシーは、ロググループの暗号化とは関係ありません。
- D. 作り直す必要はありません。既存のロググループに、後からキーを関連付けられます。
- E. ログを送る側の IAM ロールに、KMS のすべての操作を許可する必要はありません。暗号化は、CloudWatch Logs のサービスが、キーポリシーに従って行います。

### 問5 `DOP-4.0-005`

**正解**: B

**テキスト**: 5. ログをほかへ流す

検索するのは直近 30 日です。CloudWatch Logs には、30 日だけ残します。古いログは、サブスクリプションフィルターと Firehose で S3 へ送り、ライフサイクルで安いストレージクラスへ移します。CloudWatch Logs に長く置くより、費用を抑えられます。

- A. 7 年間、CloudWatch Logs に置くと、保管の費用が大きくなります。
- C. 既定は、失効しないので、ログが溜まり続けて、費用が増え続けます。
- D. EBS ボリュームは、長期の保管先として、費用も管理の手間も大きくなります。

### 問6 `DOP-4.0-006`

**正解**: A

**テキスト**: 6. メトリクスストリーム

CloudWatch メトリクスストリームは、指標を、ほぼリアルタイムで、継続的に Firehose へ流します。Firehose から S3 へ配信して、Athena で検索できます。設定だけで済みます。

- B. Lambda で毎分取り出す方法は、API の呼び出しの上限と、コードの保守が問題になります。
- C. メトリクスフィルターは、ログから指標を作る機能です。既存の指標を S3 へ送る機能ではありません。
- D. 画像の保存は、分析に使えるデータになりません。

### 問7 `DOP-4.0-007`

**正解**: `CloudWatch Logs Insights`、`Logs Insights`、`Amazon CloudWatch Logs Insights`

**テキスト**: 7. ログの検索: CloudWatch Logs Insights

CloudWatch Logs Insights は、専用のクエリ言語で、ロググループのログを検索して、集計します。複数のロググループを、一度に検索できます。`stats count() by bin(5m)` のように、時間ごとの集計ができます。

### 問8 `DOP-4.0-008`

**正解**: B

**テキスト**: 1. CloudWatch アラーム

異常検知を使ったアラームは、過去のデータから、時間帯や曜日による変動を学習して、正常な範囲(バンド)を作ります。バンドから外れると、アラームになります。固定のしきい値を決めにくい指標に向いています。

- A. 最大値に合わせた固定値では、夜の異常を見逃します。
- C. 欠損データの扱いは、データが来ないときの扱いです。変動の問題は解決しません。
- D. 評価期間を短くすると、一瞬の変動で鳴るだけで、誤報は増えます。

### 問9 `DOP-4.0-009`

**正解**: C

**テキスト**: 1. CloudWatch アラーム

複合アラームは、複数のアラームの状態を、AND や OR で組み合わせます。2 つが同時に ALARM のときだけ、通知できます。元のアラームには通知を付けず、複合アラームにだけ付けます。

- A. 評価期間を短くすると、むしろ頻繁に鳴ります。
- B. 同じ SNS トピックにすると、どちらが鳴っても通知が来ます。
- D. 欠損データの扱いは、データが来ないときの判定です。2 つのアラームの組み合わせには、関係しません。

### 問10 `DOP-4.0-010`

**正解**: D

**テキスト**: 4. AWS X-Ray

AWS X-Ray は、リクエストが通ったサービスと、下流の呼び出しの時間を、トレースとして記録します。サービスマップで、遅い箇所を見つけられます。ECS では、X-Ray のデーモンを、同じタスクのサイドカーコンテナとして動かします。新しく作るときは、X-Ray デーモンの代わりに、ADOT Collector をサイドカーとして動かす方法もあります。

- A. Config は、設定の履歴を見るものです。リクエストの時間は分かりません。
- B. Inspector は、脆弱性の検査です。遅延の原因は調べられません。
- C. CloudTrail は、API の呼び出しの記録です。アプリケーションのリクエストの時間は分かりません。

### 問11 `DOP-4.0-011`

**正解**: A、B

**テキスト**: 5. リアルタイムのログ分析と、ログの検索

パーティションを使うと、検索の条件に合う期間のデータだけを読みます。Parquet のような列指向の形式は、必要な列だけを読めて、圧縮も効くので、読む量が減ります。Athena の費用は、読んだデータの量で決まります。

- C. 1 つの巨大なファイルは、期間で絞れず、毎回全体を読みます。
- D. 全期間を対象にすると、読む量は減りません。
- E. 圧縮しないテキストは、読む量が増えます。

### 問12 `DOP-4.0-012`

**正解**: A

**テキスト**: 6. Amazon Inspector

Amazon Inspector は、EC2、ECR のイメージ、Lambda 関数の脆弱性を、継続的に検査します。新しい脆弱性が公表されると、既存の対象も再検査します。

- B. AWS Config は、リソースの設定が、ルールに合っているかを評価するものです。ソフトウェアの脆弱性は検査しません。
- C. Amazon Macie は、S3 の機密データを見つけるサービスです。
- D. AWS Artifact は、AWS のコンプライアンスのレポートを入手するサービスです。

### 問13 `DOP-4.0-013`

**正解**: C

**テキスト**: 7. AWS Config と CloudTrail

オブジェクトの読み取りなどは、S3 の「データイベント」です。既定では記録されません。CloudTrail の証跡を作って、対象のバケットの S3 データイベントを有効にすると、誰が読んだかを記録できます。

- A. Config は、設定の変更を記録するものです。オブジェクトの読み取りは記録しません。
