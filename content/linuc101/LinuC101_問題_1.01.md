## 解答・解説

### 問1 `LinuC101-1.01-001`

**正解**: B

`shutdown` の時刻は、`+分` で「今から何分後」、`hh:mm` で時刻、`now` で今すぐを表します。`-h` は停止です。指定したメッセージは、ログインしているユーザーの端末に送られます。

- A. `-r` は再起動です。
- C. `10:00` は時刻の指定で、10 時に停止します。10 分後ではありません。
- D. `halt` には時刻やメッセージを指定する使い方はありません。

### 問2 `LinuC101-1.01-002`

**正解**: C

`shutdown -c` は、予約した shutdown を取り消します(cancel)。

- A. `-k` は、警告のメッセージを送るだけで、実際には止めません。
- B. 今すぐ再起動します。
- D. 今すぐ停止します。

### 問3 `LinuC101-1.01-003`

**正解**: A

接続したことのあるサーバーの公開鍵は、手元の `~/.ssh/known_hosts` に記録されます。次に接続したときに、記録と違う鍵が送られてくると、なりすましの恐れがあるとして警告します。

- B. `authorized_keys` はサーバーの側にあり、ログインを許す利用者の公開鍵を並べるファイルです。
- C. `id_rsa.pub` は、自分の公開鍵です。
- D. `sshd_config` は、ssh のサーバーの設定ファイルです。

### 問4 `LinuC101-1.01-004`

**正解**: D

サーバーの、ログインするユーザーのホームディレクトリの `~/.ssh/authorized_keys` に、公開鍵を 1 行に 1 つ書きます。`ssh-copy-id` を使うと、この追記を自動で行います。

- A. `known_hosts` は、接続先のサーバーの鍵を手元で記録するファイルです。
- B. `id_rsa` は秘密鍵で、手元に置き、人に渡しません。
- C. `ssh_host_rsa_key.pub` は、サーバー自身の公開鍵(ホスト鍵)です。

### 問5 `LinuC101-1.01-005`

**正解**: `Ctrl+D`、`^D`

`Ctrl+D` は、入力の終わり(EOF)を送ります。シェルは入力が終わったと判断して終わるので、ログアウトします。`exit` や `logout` と同じ結果になります。

### 問6 `LinuC101-1.01-006`

**正解**: B

ハイパーバイザー型は、ハードウェアの上で直接動きます。KVM、Xen、VMware ESXi、Hyper-V が例です。

- A. 普通の OS の上のアプリとして動くのは、ホスト型(タイプ 2)です。
- C. カーネルを共有するのはコンテナです。仮想マシンはそれぞれゲスト OS を持ちます。
- D. VirtualBox はホスト型です。

### 問7 `LinuC101-1.01-007`

**正解**: B

Intel の仮想化支援機能(VT-x)は `vmx`、AMD の機能(AMD-V)は `svm` として表示されます。`grep -E 'vmx|svm' /proc/cpuinfo` で確かめます。KVM を使うには、このどちらかが必要です。

- A. `ht` はハイパースレッディング、`lm` は 64 ビットに対応していることを表します。
- C. `sse` と `avx` は計算を速くする命令です。
- D. `nx` はメモリの実行の禁止、`pae` は物理アドレスの拡張の機能です。

### 問8 `LinuC101-1.01-008`

**正解**: D

`virsh destroy` は、電源を抜くように VM を強制的に止めます。名前に反して、VM の定義もディスクも消えません。もう一度 `virsh start vm1` で起動できます。

- A. 定義を消すのは `virsh undefine` です。
- B. 正常な停止を頼むのは `virsh shutdown` です。
- C. 一時停止は `virsh suspend` です。

### 問9 `LinuC101-1.01-009`

**正解**: A、C

コンテナは、ホストのカーネルを共有し、namespace と cgroups で環境を分けます。OS を起動しないので、秒単位で起動します。

- B. カーネルをコンテナごとに起動するのは仮想マシンです。
- D. カーネルを共有するので、Linux の上では Linux のコンテナしか直接は動きません。

### 問10 `LinuC101-1.01-010`

**正解**: A

最近のディストリビューションでは、PID 1 は systemd です。systemd が、決められたターゲットに必要なサービスを起動します。

- B. GRUB 2 はブートローダーで、カーネルより前に動きます。
- C. `init.d` は、古い SysVinit の起動スクリプトを置いたディレクトリの名前です。
- D. udev はデバイスファイルを管理する仕組みで、systemd から起動されます。

### 問11 `LinuC101-1.01-011`

**正解**: C

`enable` は起動のときに自動で起動する設定、`start` は今すぐ起動する操作で、別のものです。`enable --now` は両方をまとめて行います。

- A. `start` だけでは、再起動の後に起動しません。
- B. `enable` だけでは、今は起動しません。
- D. `reload` は、動いているサービスに設定を読み込み直させるだけです。

### 問12 `LinuC101-1.01-012`

**正解**: D

ランレベル 3 は `multi-user.target`、5 は `graphical.target`、1 は `rescue.target` にあたります。

- A. GUI を加えた状態で、ランレベル 5 にあたります。
- B. シングルユーザーモードで、ランレベル 1 にあたります。
- C. さらに最小の緊急用の状態で、ランレベルの対応はありません。

### 問13 `LinuC101-1.01-013`

**正解**: A

`systemctl set-default` で、次の起動からの既定のターゲットを変えます。今の既定は `systemctl get-default` で表示します。

- B. `isolate` は、今すぐそのターゲットに切り替えるだけで、既定は変わりません。
- C. ターゲットを enable しても、既定にはなりません。
- D. `get-default` は表示するだけで、引数は取りません。

### 問14 `LinuC101-1.01-014`

**正解**: `systemctl daemon-reload`

ユニットのファイルを書き換えたり追加したりした後は、`systemctl daemon-reload` で systemd に読み込み直させます。その後、`systemctl restart app` でサービスに反映します。

### 問15 `LinuC101-1.01-015`

**正解**: B

GRUB の画面で `e` を押して起動の設定を開き、`linux` で始まる行の最後に `systemd.unit=rescue.target`(または `single`、`1`)を付けて、`Ctrl+X` で起動します。

- A. `/bin/false` はすぐに終わるので、PID 1 が終わってカーネルが止まります。
- C. GUI の通常の起動です。
- D. `runlevel=5` という指定はありません。5 は GUI の状態です。

### 問16 `LinuC101-1.01-016`

**正解**: C

`bg` は、止まったジョブをバックグラウンドで再開します。`%1` はジョブ番号 1 を表します。

- A. `fg` は、フォアグラウンドに戻して再開します。
- B. `jobs` はジョブの一覧を表示するだけです。
- D. `kill %1` はジョブ 1 に SIGTERM を送ります。

### 問17 `LinuC101-1.01-017`

**正解**: B

`nohup` は、ログアウトのときに送られる SIGHUP を無視させます。出力を指定しなければ `nohup.out` に書かれます。`screen` や `tmux` の中で実行する方法もあります。

- A. `&` だけでは、ログアウトのときに SIGHUP で終わることがあります。
- C. `exec` はシェルを command に置き換えるので、終わるとログアウトします。
- D. 止めたままログアウトすると、ジョブは終わります。

### 問18 `LinuC101-1.01-018`

**正解**: D

SIGKILL(9)は、プロセスが受け取り方を変えられず、すぐに終わらせられます。後片付けができないので、まず SIGTERM を送り、終わらないときだけ使います。

- A. SIGHUP は端末が切れたことを知らせるシグナルで、デーモンでは設定の読み込み直しによく使われます。
- B. SIGINT は `Ctrl+C` で送られる割り込みで、プロセスは無視できます。
- C. SIGTERM は `kill` の既定の終了の要求で、プロセスは後片付けをして終われます。

### 問19 `LinuC101-1.01-019`

**正解**: A、C

`pkill` と `killall` は、プロセスの名前でシグナルを送ります。既定のシグナルはどちらも SIGTERM です。

- B. `pgrep` は、名前に合うプロセスの PID を表示するだけです。
- D. `kill` には PID(またはジョブ番号)を指定します。名前は使えません。

### 問20 `LinuC101-1.01-020`

**正解**: C

ロードアベレージは、実行中か実行を待っているプロセスの数の平均で、左から 1 分、5 分、15 分の値です。CPU のコアの数より大きい状態が続くと、処理が追いついていません。

- A. 使用率ではなく、プロセスの数です。
- B. メモリは関係ありません。`free` で見ます。
- D. ユーザーの数は、その前に `2 users` のように表示されます。

### 問21 `LinuC101-1.01-021`

**正解**: `pstree`

`pstree` は、プロセスの親子の関係を木の形で表示します。`-p` で PID も表示します。`ps -ef` の PPID の列でも親を調べられます。

### 問22 `LinuC101-1.01-022`

**正解**: A

X では、画面、キーボード、マウスを持ち、描画する手元の側が X サーバーです。表示したいアプリが X クライアントで、別のコンピューターで動いて、手元の X サーバーに表示することもできます。

- B. X クライアントはネットワークの先のコンピューターでも動けます(`ssh -X` での転送など)。
- C. GUI のログインの画面を出すのはディスプレイマネージャーです。ウィンドウマネージャーはウィンドウの枠や移動を受け持ちます。
- D. DISPLAY は、X クライアントの表示先の X サーバーを指定する変数です。

### 問23 `LinuC101-1.01-023`

**正解**: `startx`

`startx` は、X サーバーを起動し、設定に従ってデスクトップ環境やウィンドウマネージャーを動かします。GUI のログインの画面から使うときは、ディスプレイマネージャーが同じことを行います。
