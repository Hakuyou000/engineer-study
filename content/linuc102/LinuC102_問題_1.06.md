## 解答・解説

| 問 | 正解 | 解説 |
|---|---|---|
| 1 | C | ログインシェルの bash は、個人用の設定ファイルを `~/.bash_profile`、`~/.bash_login`、`~/.profile` の順に探し、最初に見つかった1つだけを読み込みます。`~/.bash_profile` があるので、`~/.profile` は読まれません。 |
| 2 | D | ログインした後の端末で `bash` と入力して起動したシェルは、ログインの手続きを経ていないため、非ログインシェルです。ssh での接続、`su -`(ログインし直すのと同じ動き)、`bash -l`(ログインシェルとして起動するオプション)は、どれもログインシェルになります。 |
| 3 | A、C | `source` と `.`(ドット)は、ファイルの内容をいまのシェルの中で実行するため、設定がそのまま反映されます。`bash ~/.bashrc` や `./.bashrc` は新しい子シェルの中で実行するので、終わると設定も一緒に消えてしまいます。 |
| 4 | D | 子プロセスに引き継がれるのは、`export` した環境変数だけです。`A=1` はいまのシェルだけで使えるシェル変数なので、新しい bash からは見えません。 |
| 5 | B | シェルでの変数の代入では、`=` の前後に空白を入れてはいけません。空白があると、シェルは MYVAR をコマンドの名前、`=` と hello をその引数とみなし、そのようなコマンドはないというエラーになります。 |
| 6 | C | シングルクォート(`'`)で囲んだ部分では、`$NAME` のような変数は展開されず、書いた文字がそのまま出力されます。変数を展開したいときは、ダブルクォート(`"`)で囲みます。 |
| 7 | A | この書き方では、PATH が `/opt/tools/bin` だけで上書きされます。`/usr/bin` などが PATH から消えるので、`ls` などを名前だけでは実行できなくなります。追加したいときは `export PATH=$PATH:/opt/tools/bin` のように、元の値を含めて書きます。 |
| 8 | C | `set` は、シェル変数、環境変数、関数の定義までまとめて表示します。`env` と `printenv` が表示するのは環境変数だけです。`export` は引数なしで実行すると、export されている変数の一覧を表示します。 |
| 9 | B | `&&` は「左のコマンドが成功(終了ステータスが 0)したときだけ、右のコマンドを実行する」という意味です。失敗したときだけ実行するのは `||`、結果に関係なく順に実行するのは `;` です。 |
| 10 | A | コマンド名の先頭に `\` を付けると、その場だけ alias が使われず、本来のコマンドが実行されます。`unalias -a` はすべての alias を削除してしまいます。`--no-alias` というオプションはなく、`alias ls` は ls の alias の内容を表示するだけです。 |
| 11 | B | `$#` は引数の個数で、スクリプト名(`$0`)は数えないので 3 です。`$2` は2番目の引数なので 7 です。 |
| 12 | C | `shift` を実行すると、`$1` の a が捨てられ、残りの引数が1つずつ前にずれます。そのため `$1` は b になり、引数の個数 `$#` は 2 に減ります。 |
| 13 | D | `$?` には直前のコマンドの終了ステータス(成功なら 0)が入ります。`$$` はいまのシェルのプロセス ID、`$!` は直前にバックグラウンドで起動したプロセスの ID、`$#` は引数の個数です。 |
| 14 | A | `[` は test というコマンドの別名なので、`[` の後ろと `]` の前に空白が必要です。空白がないと、`[-f` という名前のコマンドを探してしまいエラーになります。 |
| 15 | B | 数値の大小を比べるときは、`-gt`(より大きい)のような英字の演算子を使います。`-lt` は「より小さい」、`-ge` は「以上」です。`[ $n > 10 ]` の `>` は、出力を 10 というファイルに書き込むリダイレクトとして解釈されてしまいます。 |
| 16 | C | case 文は `esac`(case を逆から読んだ綴り)で閉じます。if 文は `fi` で、for や while のループは `done` で閉じます。 |
| 17 | B | `until` は条件が偽の間、処理をくり返します。`while` は逆に、条件が真の間くり返します。`for` は値の一覧を順に処理し、`select` はメニューを表示する構文です。 |
| 18 | C | シェルの関数は、普通のコマンドと同じように名前だけで呼び出します。`greet()` や `function greet` は関数を定義するときの書き出しで、`call` というコマンドはありません。 |
| 19 | A | 関数の中で代入した変数は、特に指定しなければスクリプト全体で共有されるので、count は 5 になります。`local` を付けた tmp は関数の中だけの変数なので、関数の外では空になります。そのため出力は `5:` です。 |
| 20 | C | `bash -n` はスクリプトを読み込んで文法だけを確認し、実際には実行しません。`-x` は展開した後のコマンドを表示しながら実行し、`-v` は読み込んだ行をそのまま表示しながら実行します。`-e` はエラーが起きたら止まるようにするオプションです。 |
| 21 | A | シェルスクリプトは bash がファイルの中身を読み込んで実行するので、実行権だけでなく読み取り権も必要です。755 なら他のユーザーにも読み取りと実行が許可されます。711 では他のユーザーは読めないので実行できず、700 は所有者しか使えません。シェルスクリプトに SUID(4755)を付けても Linux では無視されます。 |
| 22 | D | KILL(シグナル番号 9)と STOP は、プロセスを確実に止めるためのシグナルなので、trap で受け取ることも無視することもできません。INT(Ctrl+C)、HUP、TERM は trap で受け取って処理できます。 |
| 23 | B | `*` はシェルにとって「任意のファイル名」を表す記号なので、そのまま書くとカレントディレクトリのファイル名の一覧に置き換わってしまいます。`\` を付けると、`*` という文字のまま expr に渡せます。 |
| 24 | A | `${変数:-既定値}` は、変数が空(または未定義)のときに既定値を使う書き方です。引数がないと `$1` は空なので、DIR には `/tmp` が入ります。 |
| 25 | C | select 文のプロンプトは PS3 で設定します。PS1 は普段のコマンド入力のプロンプト、PS2 はコマンドが次の行に続くときのプロンプトです。 |
| 26 | C | if 文は、コマンドの終了ステータスで分岐します(0 なら真)。`grep -q` は何も出力せず、一致する行があれば 0、なければ 1 を返すので、ユーザーが存在するかどうかの判定に使えます。 |
| 27 | C | Debian 系では、`/etc/bash.bashrc` がすべてのユーザーに共通で、bash が起動するたびに読み込まれます。`/etc/profile` はログインしたときだけ読まれます。`~/.bashrc` と `~/.bash_profile` は、そのユーザー個人用です。 |
| 28 | `~/.bash_logout`、`.bash_logout`、`$HOME/.bash_logout` | ログアウトのときには `~/.bash_logout` が読み込まれます。ログインのときは `~/.bash_profile` などが、bash が起動するたびには `~/.bashrc` が読み込まれます。 |
| 29 | B | `$( )` はコマンド置換と呼ばれ、中のコマンドを実行して、その出力に置き換えます。バッククォート(`` ` ``)で囲んでも同じ働きです。整数の計算は `$(( ))`、変数の参照は `${ }` で書きます。 |
| 30 | D | `/etc/` にある設定ファイルは、すべてのユーザーに共通です。名前に profile が付くファイルは、ログインしたときに1回だけ読み込まれます。 |
| 31 | `#!` | この記号はシバン(shebang)と呼ばれ、`#!/bin/bash` のように書くと、そのスクリプトを bash で実行するという意味になります。スクリプトを直接実行するには、ファイルの実行権も必要です。 |
| 32 | C | cron から実行されるスクリプトは、ログインしたときとは違い、PATH に最小限のディレクトリしか含まれていません。そのため、スクリプトの中で PATH を設定するか、コマンドを絶対パスで書きます。`~/.bashrc` は cron の実行では読み込まれず、シェルスクリプトの SUID は無視されます。777 は誰でも書き換えられて危険なうえ、PATH の問題も解決しません。 |
