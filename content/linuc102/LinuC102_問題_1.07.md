## 解答・解説

| 問 | 正解 | 解説 |
|---|---|---|
| 1 | A | /27 は、アドレスを 32 個ずつの区切り(ブロック)に分けます。77 は 64〜95 のブロックに入るので、先頭の 192.168.10.64 がネットワークアドレス、末尾の 192.168.10.95 がブロードキャストアドレスです。 |
| 2 | B | /28 ではホスト部が 32 − 28 = 4 ビットなので、アドレスは 2の4乗 = 16 個です。そこからネットワークアドレスとブロードキャストアドレスの2つを引いた 14 個を、ホストに割り当てられます。 |
| 3 | C | プライベート IP アドレスの範囲は 10.0.0.0/8、172.16.0.0〜172.31.255.255、192.168.0.0/16 です。172.20.0.1 はこの範囲に入ります。172.32.1.1、192.169.0.1、11.0.0.1 は範囲の外なので、グローバルアドレスです。 |
| 4 | D | 169.254.0.0/16 はリンクローカルアドレスと呼ばれ、DHCP でアドレスを取得できなかったときに自動で付きます。このアドレスが付いていたら、DHCP サーバーとの通信に問題があると考えられます。127.0.0.0/8 はループバック、224.0.0.0/4 はマルチキャストです。 |
| 5 | B | DNS は 53 番です。SSH は 22 番、NTP は 123 番、SMTP は 25 番です。23 番は Telnet、110 番は POP3、143 番は IMAP のポートです。 |
| 6 | A | HTTPS は TCP の 443 番、NTP は UDP の 123 番を使います。80 番は HTTP、110 番は POP3、53 番は DNS です。 |
| 7 | B、D | NTP(時刻同期)と DHCP(アドレスの自動割り当て)は、短いやり取りが中心なので UDP を使います。SSH と HTTP は、確実にデータを届ける必要があるので TCP を使います。 |
| 8 | C | ICMP は、通信の状態やエラーを伝えるためのプロトコルで、ping や traceroute で使われます。ポート番号は持ちません。ポート番号でのサービスの区別は TCP と UDP、3ウェイハンドシェイクと再送による確実な配送は TCP の特徴です。 |
| 9 | C | 連続する 0 のグループは `::` で省略できますが、使えるのは1か所だけです。2か所あると、それぞれで何グループ分の 0 を省略したのか決められません。`2001:db8:1` はグループの数が足りず、省略の記号もないため誤りです。 |
| 10 | D | IPv6 にはブロードキャストがなく、その役割はマルチキャストで代わりに行います。マルチキャスト、ループバックアドレス(`::1`)、リンクローカルアドレス(`fe80::/10`)は IPv6 にあります。 |
| 11 | D | `ifup` に対応する iproute2 のコマンドは `ip link set eth0 up` です。`ip neigh` は ARP テーブル(近隣キャッシュ)を表示・操作するコマンドで、`arp` に対応します。その他の組み合わせは正しい対応です。 |
| 12 | D | `ip route` では、ゲートウェイを `via` で指定します。`gw` は古い `route` コマンドの書き方です。`ip addr` はアドレスを設定するコマンドで、経路の追加には使いません。 |
| 13 | B | `ip`、`ifconfig`、`route` で行った設定はメモリ上だけの一時的なもので、再起動すると消えます。再起動後も残したいときは、設定ファイルに書くか、nmcli で接続設定を変更します。 |
| 14 | B | `nmcli connection modify` は、接続設定を保存するだけで、すぐには反映されません。`nmcli connection up eth0` で接続を有効にし直すと、新しい設定がインターフェースに反映されます。 |
| 15 | A | Red Hat 系の ifcfg ファイルでは、`BOOTPROTO=dhcp` で DHCP を使う設定になります。`iface eth0 inet dhcp` は Debian 系の `/etc/network/interfaces` の書き方、`ipv4.method manual` は nmcli で固定のアドレスを使う設定です。`ONBOOT=no` は起動時に有効にしない設定です。 |
| 16 | B | `/etc/hosts` では、IP アドレスを先に、ホスト名を後に書きます。同じアドレスに別名を付けるときは、空白で区切って並べます。コロンや `hosts:` のような書き方はしません。 |
| 17 | A | `/etc/nsswitch.conf` の `hosts:` の行は、左から順に名前解決の方法を試します。dns が先に書かれているので、まず DNS に問い合わせ、見つからなければ `/etc/hosts`(files)を調べます。 |
| 18 | B | `hostnamectl set-hostname` は、ホスト名を `/etc/hostname` に保存するので、再起動後も変更が残ります。`hostname web01` はその場だけの変更です。`/etc/hosts` は名前とアドレスの対応表で、ホスト名の設定ではありません。 |
| 19 | D | IP アドレスでは届き、名前では届かないので、ネットワーク自体は正常で、名前解決(DNS)に問題があると考えられます。DNS サーバーの問い合わせ先は `/etc/resolv.conf` に書かれているので、最初に確認します。 |
| 20 | C | LAN の中のゲートウェイには届くのに、外部のアドレスには「ネットワークに到達できない」と出るので、外へ出るための経路、つまりデフォルトルートがないか誤っていると考えられます。DNS や `/etc/hosts` は名前解決の設定で、IP アドレスを直接指定した ping には関係しません。 |
| 21 | A | `ss` のオプションは、`-t` が TCP、`-l` が待ち受け中(LISTEN)、`-n` が名前ではなく番号で表示、`-p` がプロセスの表示です。`-u` は UDP、`-a` はすべての状態、`netstat -r` はルーティングテーブルの表示です。 |
| 22 | D | 127.0.0.1 はループバックアドレス(自分自身)なので、自分のホストからの接続だけを受け付けます。外部から接続できるのは、0.0.0.0(すべてのアドレス)や外部向けのアドレスで待ち受けている場合です。25 はポート番号で、`-t` なので TCP です。 |
| 23 | D | `nc -zv` は、指定したホストのポートに接続できるかどうかだけを確かめます。ping は ICMP を使うためポートを確認できず、`-p` はデータの中身を指定するオプションです。`host` は名前解決、`ip route get` は経路の確認に使います。 |
| 24 | C | tracepath は一般ユーザーでも使え、経路の途中で通れるパケットの最大サイズ(PMTU)も表示します。ICMP だけを使うわけではなく(UDP を使います)、root 権限も不要です。名前解決もします(しないようにするのは `-n`)。 |
| 25 | B | Destination が 0.0.0.0 の行は、どの宛先にも一致する「デフォルトルート」です。Flags の U は経路が有効(up)、G はゲートウェイを経由することを表します。 |
| 26 | A | 接続設定そのものを削除するのは `nmcli connection delete` です。`nmcli connection down` は接続を無効にするだけで、設定は残ります。`nmcli device delete` は仮想デバイスの削除に使い、`ip addr del` はアドレスの削除です。 |
| 27 | C | `/etc/resolv.conf` の nameserver は最大 3 つまで使われ、上から順に問い合わせます。4 つ目以降は無視されます。 |
| 28 | C | `getent hosts` は `/etc/nsswitch.conf` の設定に従って名前を解決するので、`/etc/hosts` も調べます。`dig` と `host` は DNS サーバーに直接問い合わせるコマンドなので、`/etc/hosts` だけに書いた名前は見つかりません。 |
| 29 | D | dig では、問い合わせ先の DNS サーバーを `@サーバー` で指定し、レコードの種類(MX など)を名前の後に書きます。`-server` や `-s` というオプションはなく、`@` のない書き方では 8.8.8.8 という名前を引こうとしてしまいます。 |
| 30 | D | IP アドレスからホスト名を調べる(逆引き)ときは PTR レコードを使います。A レコードは名前から IPv4 アドレス、AAAA レコードは名前から IPv6 アドレスを引くためのもので、CNAME は別名です。 |
| 31 | A | `search` は、ドメイン名を省略して名前を書いたときに、後ろに補うドメインを指定します。`ping www` は `www.example.com` として問い合わせられます。問い合わせる DNS サーバーや、`/etc/hosts` との順番は変わりません(順番は `/etc/nsswitch.conf` で決めます)。 |
| 32 | B | `-c` は送る回数を指定するオプションで、エコー要求を 4 回送ると終了します。送る間隔は `-i`、TTL は `-t`、データの大きさは `-s` で指定します。Linux の ping は、`-c` を付けないと Ctrl+C で止めるまで送り続けます。 |
| 33 | `/etc/network/interfaces` | Debian 系では `/etc/network/interfaces` にインターフェースの設定を書きます。Red Hat 系では `/etc/sysconfig/network-scripts/ifcfg-eth0` のようなファイルを使います(新しいバージョンでは NetworkManager の設定が中心です)。 |
| 34 | `/etc/hostname` | `/etc/hostname` にはホスト名が1行で書かれていて、起動時に読み込まれます。`hostnamectl set-hostname` で変更すると、このファイルにも書き込まれます。`hostname` コマンドだけで変更した場合は、再起動すると元に戻ります。 |
| 35 | D | traceroute は、TTL(パケットが通過できるルーターの数の上限)を 1、2、3…と増やしながらパケットを送ります。TTL が 0 になったルーターは ICMP の時間超過メッセージを返すので、それを順に集めると経路が分かります。応答しないルーターは `* * *` と表示されます。 |
