## 問題

- A. overlay
- B. host

## 解答・解説

### 問1 `Docker-4.0-001`

**正解**: B

ネットワークを指定しないコンテナは、既定の bridge(`docker0`)につながります。host と none は指定したときだけ使われ、overlay は複数のホストをまたぐためのもので、既定ではありません。

### 問2 `Docker-4.0-002`

**正解**: B

host ドライバーは、コンテナにホストのネットワークをそのまま使わせ、ネットワークの分離をしません。bridge はホストの中の仮想スイッチ、none はネットワークなし、macvlan はコンテナに LAN の MAC と IP を持たせるドライバーです。

### 問3 `Docker-4.0-003`

**正解**: C

host ネットワークでは、コンテナはホストのネットワークをそのまま使うので、ポートの転送がありません。`-p` は意味がなく(警告が出て無視される)、アプリが 80 番で待ち受ければ、ホストの 80 番でつながります。

### 問4 `Docker-4.0-004`

**正解**: A

overlay ネットワークは、複数のホストにまたがる仮想的なネットワークで、Swarm などのクラスターで使います。bridge と host は 1 台のホストの中のネットワークです。

### 問5 `Docker-4.0-005`

**正解**: A

`-p` は `ホスト:コンテナ` の順です。ホストの 8080 番に来た通信を、コンテナの 80 番に転送します。順番を逆に覚えないようにします。ホストのアドレスを書かないと、すべてのインターフェースで受け付けます。

### 問6 `Docker-4.0-006`

**正解**: D

`-p 127.0.0.1:8080:80` のように、ホストのアドレスを書くと、そのアドレスだけで受け付けます。127.0.0.1 はホスト自身なので、外のネットワークからは届きません。`-p 8080:80` と `0.0.0.0` は、すべてのインターフェースに公開します。

`--expose 80` は、コンテナのポートを記録するだけで、ホストには公開しません。ホストの中から 8080 番で使えるようにもなりません。

### 問7 `Docker-4.0-007`

**正解**: A

ホストの同じポートは、1 つのコンテナ(またはプロセス)しか使えません。8080 番がすでに使われているので、エラーになります。コンテナの 80 番は、コンテナごとに別の IP なので、複数のコンテナで重なっても問題ありません。

### 問8 `Docker-4.0-008`

**正解**: D

`-P`(大文字)は、`EXPOSE` に書いたすべてのポートを、ホストの空いているポート(番号は自動)に公開します。実際の番号は `docker port` や `docker ps` で確かめます。

### 問9 `Docker-4.0-009`

**正解**: A

Linux の Docker は、ポートを公開するために iptables(nftables)のルールを自分で追加します。この転送は ufw のルールより先に処理されることが多く、ufw で閉じたつもりでも外から届きます。外に出したくないなら、`127.0.0.1:` を付けて公開するか、公開せずにコンテナ同士で通信させます。

### 問10 `Docker-4.0-010`

**正解**: C

既定の bridge には、コンテナ名を解決する DNS がありません。ユーザー定義のブリッジネットワークでは、組み込みの DNS がコンテナ名を IP に変えるので、`db` という名前で接続できます。ポートの公開は名前の解決とは関係なく、hosts を手で書くのは IP が変わると壊れます。

### 問11 `Docker-4.0-011`

**正解**: D

同じユーザー定義のネットワークのコンテナ同士は、コンテナ名で、コンテナのポートに直接つなげます。そのため `db:5432` です。ポートの公開(`-p`)は、ホストの外から入るためのもので、コンテナ同士の通信には不要です。`localhost` は `web` 自身です。

### 問12 `Docker-4.0-012`

**正解**: C

コンテナの中の `localhost` は、そのコンテナ自身を指します。`web` の中には 5432 番で待ち受けるものがないので、接続は失敗します。別のコンテナには、同じネットワークにつないだうえで、コンテナ名(`db:5432`)で接続します。

### 問13 `Docker-4.0-013`

**正解**: C

違うネットワークのコンテナ同士は通信できません。`docker network connect back web` で、`web` を `back` にも追加でつなぐと、`web` から `api` という名前で接続できます。1 つのコンテナは複数のネットワークにつなげます。

### 問14 `Docker-4.0-014`

**正解**: D

ユーザー定義のネットワークでは、Docker の組み込みの DNS サーバー(コンテナから見て 127.0.0.11)が、コンテナ名と別名を IP アドレスに変えます。外部の名前は、ホストの設定の DNS に問い合わせます。

### 問15 `Docker-4.0-015`

**正解**: C

**入力の別解**: `--add-host host.docker.internal:host-gateway`

Docker Desktop では `host.docker.internal` が最初から使えますが、Linux では使えません。`--add-host=host.docker.internal:host-gateway` を付けると、その名前がホストの IP に解決されます。

### 問16 `Docker-4.0-016`

**正解**: B

コンテナの中からはつながり、外(公開ポート経由)からはつながらないので、ポートの転送は届いていて、アプリが受けていないと考えます。
① 公開ポートからの通信は、コンテナのネットワークのインターフェース(例: 172.17.0.2)に届きます。
② アプリが 127.0.0.1 だけで待ち受けていると、その通信を受けられず、接続が切られます。
③ アプリの待ち受けのアドレスを 0.0.0.0 にします。

`-p` が逆なら、ホストの 8080 番でそもそも待ち受けていません。`EXPOSE` は説明だけで、通信には影響しません。

### 問17 `Docker-4.0-017`

**正解**: C

PORTS の `127.0.0.1:8080->80/tcp` は、ホストの 127.0.0.1(自分自身)の 8080 番にだけ公開していることを表します。ほかの PC からは届きません。外からも使わせるなら `-p 8080:80` にし、必要に応じてファイアウォールで制限します。

### 問18 `Docker-4.0-018`

**正解**: C

`docker port コンテナ` は、ホストのポートとコンテナのポートの対応を表示します。`docker ps` の PORTS 列でも確かめられます。`network ls` はネットワークの一覧、`top` はプロセス、`history` はイメージの層です。

### 問19 `Docker-4.0-019`

**正解**: A

`docker network inspect ネットワーク名` は、ネットワークの設定(サブネット、ゲートウェイ)と、つながっているコンテナとその IP アドレスを表示します。`network ls` は一覧だけで、中のコンテナは表示しません。

### 問20 `Docker-4.0-020`

**正解**: D

名前の解決はコンテナの中の DNS で行われるので、`docker exec` でコンテナの中から `nslookup` や `getent hosts` を実行して確かめます。ホストからは、Docker の組み込みの DNS を使わないので、コンテナ名は引けません。
