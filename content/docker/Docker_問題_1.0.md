# Docker 問題 1.0 コンテナと Docker の基礎

対象: 実務の Docker / 全16問 / すべてオリジナル問題
対応テキスト: `Docker_1.0_コンテナとDockerの基礎.md`
解答・解説は末尾。

## 問題

### 1.1 コンテナとは何か

**問1** `Docker-1.0-001` コンテナと仮想マシンの違いとして、正しいものはどれか。

- A. 仮想マシンはコンテナより起動が速い
- B. コンテナの実行にはハイパーバイザーが必須である
- C. コンテナはそれぞれ専用のゲスト OS のカーネルを持つ
- D. コンテナはホストの OS のカーネルを共有する

**問2** `Docker-1.0-002` コンテナが、ほかのコンテナやホストのプロセスを見えないようにしている Linux の機能はどれか。

- A. overlay2
- B. cgroups
- C. iptables
- D. namespace

**問3** `Docker-1.0-003` コンテナが使えるメモリや CPU の量を制限している Linux の機能はどれか。

- A. SELinux
- B. systemd
- C. namespace
- D. cgroups

**問4** `Docker-1.0-004` Linux のホストで動いているコンテナについて、正しいものはどれか。

- A. ホストからはコンテナのプロセスは一切見えない
- B. ホストから見ると、分離された普通のプロセスとして見える
- C. コンテナの中から、ホストのすべてのプロセスが見える
- D. コンテナごとに別のカーネルが起動している

**問5** `Docker-1.0-005` Linux のコンテナについて、正しいものはどれか。

- A. Linux のコンテナを動かすには、必ず仮想マシンが必要である
- B. ホストと同じ系統のカーネル(Linux)で動くコンテナだけを動かせる
- C. どの OS のコンテナでも、どのホストでも動く
- D. Linux のホストの上で、Windows のカーネルが必要なコンテナもそのまま動かせる

### 1.2 Docker の構成要素

**問6** `Docker-1.0-006` `docker` コマンド(クライアント)が、命令を送る相手はどれか。

- A. Docker デーモン(dockerd)
- B. runc
- C. レジストリ
- D. カーネル

**問7** `Docker-1.0-007` namespace と cgroups を設定して、実際にコンテナのプロセスを起動する低レベルのランタイムはどれか。

- A. runc
- B. Docker Hub
- C. docker CLI
- D. dockerd

**問8** `Docker-1.0-008` イメージとコンテナの関係として、正しいものはどれか。

- B. コンテナを削除すると、元のイメージも削除される
- C. コンテナを保存したものがイメージで、イメージは書き換えられる
- D. イメージは読み取り専用のテンプレートで、コンテナはそこから作った実体である

**問9** `Docker-1.0-009` `nginx` のコンテナの中で設定ファイルを書き換えた。その後 `docker rm` でコンテナを削除し、同じイメージから新しいコンテナを作った。設定ファイルはどうなっているか。

- A. 書き換えた内容が残っている
- B. 新しいコンテナが起動しない
- C. イメージの元の内容に戻っている
- D. ファイルが消えている

**問10** `Docker-1.0-010` OCI(Open Container Initiative)について、正しいものはどれか。

- B. Docker Hub の別名である
- C. Windows 専用のコンテナの規格である

**問11** `Docker-1.0-011` Mac の Docker Desktop で Linux のコンテナを動かしている。この仕組みとして正しいものはどれか。

- A. Linux のコンテナを macOS のアプリに自動で変換している
- B. Docker Hub のサーバーの上でコンテナを動かしている
- C. 内部で小さな Linux の仮想マシンを動かし、その中でコンテナを動かしている
- D. macOS のカーネルで Linux のコンテナを直接動かしている

### 1.3 基本のコマンドと流れ

**問12** `Docker-1.0-012` ローカルにない `redis:7` のイメージで `docker run -d redis:7` を実行した。起きることとして正しいものはどれか。

- A. イメージがないのでエラーになる
- B. Dockerfile を探してビルドする
- C. 自動でイメージを pull してから、コンテナを作って起動する
- D. 空のコンテナが起動する

**問13** `Docker-1.0-013` 止まっているものも含めて、すべてのコンテナを表示するコマンドはどれか。

- A. `docker info`
- B. `docker images -a`
- C. `docker ps -a`
- D. `docker ps`

**問14** `Docker-1.0-014` `docker images` と同じ動きをするコマンドはどれか。

- A. `docker volume ls`
- B. `docker image ls`
- C. `docker container ls`
- D. `docker system df`

**問15** `Docker-1.0-015` イメージ、コンテナ、ボリューム、ビルドキャッシュが、それぞれどれだけディスクを使っているかを確かめたい。使うコマンドはどれか。

- A. `docker version`
- B. `docker info`
- C. `docker stats`
- D. `docker system df`

**問16** `Docker-1.0-016` `docker version` の出力に、Client と Server の 2 つの欄がある。Server が表すものはどれか。

- A. コンテナの中の OS のバージョン
- B. Docker Hub のバージョン
- C. ホストのカーネルのバージョン
- D. Docker デーモン(Docker Engine)のバージョン

## 解答・解説

### 問1 `Docker-1.0-001`

**正解**: D

コンテナはホストの OS のカーネルを共有し、アプリと必要なものだけを分離して動かします。そのため軽く、起動も速くなります。ゲスト OS を持つのは仮想マシンです。コンテナの実行に必要なのはコンテナエンジン(Docker など)で、ハイパーバイザーではありません。

### 問2 `Docker-1.0-002`

**正解**: D

namespace は、プロセス、ネットワーク、マウント、ホスト名などを分けて、コンテナから見えるものを限定します。cgroups は資源の制限、overlay2 はイメージの層を重ねるファイルシステム、iptables はパケットのフィルターです。

### 問3 `Docker-1.0-003`

**正解**: D

cgroups は、CPU、メモリ、プロセスの数などの使える量を制限します。namespace は見えるものを分ける機能で、量の制限はしません。SELinux はアクセス制御、systemd はサービスの管理です。

### 問4 `Docker-1.0-004`

**正解**: B

コンテナは、namespace と cgroups で分離された普通のプロセスです。ホストからは `ps` などで見えます。カーネルはホストのものを共有するので、コンテナごとに別のカーネルは動きません。コンテナの中からは、PID namespace によってホストのプロセスは見えません。

### 問5 `Docker-1.0-005`

**正解**: B

コンテナはホストのカーネルを共有するので、Linux のホストでは Linux のカーネルで動くコンテナだけを動かせます。Windows のカーネルが必要なコンテナは動きません。Linux のホストなら、仮想マシンなしで直接動かせます。

### 問6 `Docker-1.0-006`

**正解**: A

`docker` コマンドはクライアントで、利用者の命令を API で Docker デーモン(dockerd)に送ります。デーモンが containerd と runc を使ってコンテナを動かします。クライアントが runc やカーネルを直接操作することはありません。

### 問7 `Docker-1.0-007`

**正解**: A

runc は OCI のランタイムの仕様を実装した低レベルのランタイムで、namespace と cgroups を設定してコンテナのプロセスを起動します。dockerd は全体を管理するデーモン、docker CLI はクライアント、Docker Hub はレジストリです。

### 問8 `Docker-1.0-008`

**正解**: D

イメージは読み取り専用のテンプレートで、コンテナはそこから作った実体です(書き込み層を持つ)。1 つのイメージからいくつでもコンテナを作れ、コンテナを削除してもイメージは残ります。

### 問9 `Docker-1.0-009`

**正解**: C

コンテナの中での変更は、そのコンテナの書き込み層に入り、イメージは変わりません。
① 書き換えた内容は、最初のコンテナの書き込み層にあります。
② `docker rm` で、その書き込み層ごと消えます。
③ 新しいコンテナは、変わっていないイメージから作られるので、元の内容です。

変更を残すには、ボリュームを使うか、設定を含めた新しいイメージを作ります。

### 問10 `Docker-1.0-010`

**正解**: D

OCI は、コンテナのイメージの形式とランタイムの仕様を決める業界の標準です。Docker で作ったイメージは OCI の形式なので、Podman、containerd、Kubernetes などでも使えます。Docker 独自の形式でも、Windows 専用でもありません。

### 問11 `Docker-1.0-011`

**正解**: C

Linux のコンテナには Linux のカーネルが必要なので、Docker Desktop は内部で小さな Linux の仮想マシンを動かし、その中でコンテナを動かします。macOS のカーネルでは直接動かせず、アプリに変換したり、Docker Hub で動かしたりもしません。

### 問12 `Docker-1.0-012`

**正解**: C

`docker run` は、ローカルにイメージがなければ、自動でレジストリ(既定は Docker Hub)から pull してから、コンテナを作って起動します。Dockerfile からのビルドは `docker build` で行います。

### 問13 `Docker-1.0-013`

**正解**: C

`docker ps` は動いているコンテナだけを表示します。`-a` を付けると、止まっているものも含めたすべてのコンテナを表示します。`docker images -a` はイメージの一覧、`docker info` はデーモンの情報です。

### 問14 `Docker-1.0-014`

**正解**: B

`docker images` は `docker image ls` の短い書き方です。`docker container ls` は `docker ps`、`docker volume ls` はボリュームの一覧、`docker system df` はディスクの使用量です。

### 問15 `Docker-1.0-015`

**正解**: D

`docker system df` は、イメージ、コンテナ、ボリューム、ビルドキャッシュが使っている容量と、削除できる量を表示します。`docker info` はデーモンの設定、`docker stats` はコンテナの CPU とメモリの使用量、`docker version` はバージョンです。

### 問16 `Docker-1.0-016`

**正解**: D

`docker version` の Client は `docker` コマンドのバージョン、Server はそのクライアントがつないでいる Docker デーモン(Docker Engine)のバージョンです。クライアントとデーモンは別のプログラムなので、それぞれのバージョンが表示されます。
