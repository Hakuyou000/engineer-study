## 解答・解説

### 問1 `Docker-3.0-001`

**正解**: A

`--rm` を付けると、コンテナが終了したときに自動で削除されます。`-d` はバックグラウンドで動かすオプション、`--restart no` は再起動しない設定(既定)で、削除はしません。`-it` は対話の端末をつなぐオプションです。

### 問2 `Docker-3.0-002`

**正解**: C

`-i` で入力を開いたままにし、`-t` で端末を割り当てると、対話的にシェルを使えます。`-d` はバックグラウンドなので、シェルを操作できません。シェルを使うのにポートの公開は必要ありません。

`--rm` は終了したときにコンテナを消すだけで、`-it` がないので対話的には使えません。

### 問3 `Docker-3.0-003`

**正解**: C

`docker run` は、イメージからコンテナを作る `docker create` と、起動する `docker start` を続けて行うのと同じです(イメージがなければ pull もします)。`exec` は動いているコンテナでの実行、`build` はイメージの作成、`commit` はコンテナからイメージを作る操作です。

### 問4 `Docker-3.0-004`

**正解**: A

**テキスト**: 1. 状態

コンテナは、PID 1 のプロセスが終わると止まります。`echo hello` はすぐに終わるので、コンテナも exited になり、`docker ps`(動いているものだけ)には表示されません。`docker ps -a` と `docker logs` で、終了したことと出力の hello を確かめられます。

### 問5 `Docker-3.0-005`

**正解**: D

**テキスト**: 2. 止め方

`docker stop` は、まず SIGTERM を送ってアプリに終了の準備をさせ、既定で 10 秒たっても終わらなければ SIGKILL で強制終了します(`-t` で秒数を変えられる)。すぐに SIGKILL を送るのは `docker kill`、一時停止は `docker pause` です。

### 問6 `Docker-3.0-006`

**正解**: B

**テキスト**: 3. 終了コード

終了コード 137 は 128 + 9 で、SIGKILL で終わったことを表します。
① 誰も stop や kill をしていないので、外から止められたのではありません。
② 残る主な原因は、メモリの上限を超えたことによる OOM の強制終了です。
③ `State.OOMKilled` が `true` なら、メモリの不足だと確定します。

イメージの大きさやネットワーク、バージョンは、137 の原因を直接は示しません。

### 問7 `Docker-3.0-007`

**正解**: A

**テキスト**: 3. 終了コード

128 より大きい終了コードは、シグナルで終わったことを表し、128 を引くとシグナルの番号です。143 − 128 = 15 で、SIGTERM です。`docker stop` で正常に止まったときによく見られます。コマンドが見つからないのは 127、オプションの誤りは 125 です。

### 問8 `Docker-3.0-008`

**正解**: C

**テキスト**: 3. 終了コード

終了コード 127 は「コマンドが見つからない」ことを表します。CMD や ENTRYPOINT に書いたコマンドが、イメージの中にない(パッケージを入れていない、パスが違う、小さいイメージにシェルがない)場合に起きます。メモリ不足は 137、正常な終了は 0 です。

### 問9 `Docker-3.0-009`

**正解**: B

**テキスト**: 4. 再起動の方針(--restart)

`unless-stopped` は、常に再起動しますが、手で止めたコンテナは、デーモンやサーバーの再起動のときにも起動しません。`always` は、手で止めたものも、デーモンが再起動すると起動します。`on-failure` は、エラーで終わったときだけ再起動します。

### 問10 `Docker-3.0-010`

**正解**: C

**テキスト**: 4. 再起動の方針(--restart)

`on-failure:3` は、終了コードが 0 以外のときだけ、最大 3 回まで再起動します。`always` と `unless-stopped` は、正常に終わっても再起動します。`no` は再起動しません。

### 問11 `Docker-3.0-011`

**正解**: B

**テキスト**: 1. 状態

nginx は既定でデーモンとして裏に回ります。コンテナでは、最初に起動したプロセス(PID 1)がすぐに終わるので、コンテナも終了します。`daemon off;` でフォアグラウンドで動かし続ける必要があります。ポートの公開の有無は、起動してすぐ終わることとは関係ありません。

### 問12 `Docker-3.0-012`

**正解**: A

`docker exec -it コンテナ sh` は、動いているコンテナの中で新しいシェルを起動します。調査にはこれを使います。`attach` は PID 1 の入出力につなぐもので、Ctrl+C でコンテナを止めてしまうことがあります。`docker run` は新しいコンテナを作ります。

### 問13 `Docker-3.0-013`

**正解**: B

`--tail 100` で最新の 100 行から、`-f` でその後も追いかけて表示します。`docker logs` は、アプリの標準出力と標準エラー出力を表示します。`docker inspect` にログを表示する機能はありません。

### 問14 `Docker-3.0-014`

**正解**: D

`docker logs` が表示するのは、PID 1 のプロセスが標準出力と標準エラー出力に出したものです。アプリがファイルにだけログを書いていると表示されません。コンテナではログを標準出力に出すのが基本です。`docker logs` は動いているコンテナにも使えます。

### 問15 `Docker-3.0-015`

**正解**: D

`docker exec` は、動いているコンテナの中で新しいプロセスを実行するので、終了したコンテナには使えません。終了したコンテナでも、`docker logs` でログ、`docker inspect` で終了コードや OOM の記録、`docker ps -a` で状態を確かめられます。

### 問16 `Docker-3.0-016`

**正解**: D

`docker stats` は、コンテナごとの CPU、メモリ、ネットワーク、ディスクの I/O の使用量をリアルタイムで表示します。`docker top` は中のプロセスの一覧、`docker system df` はディスクの使用量、`docker history` はイメージの層です。

### 問17 `Docker-3.0-017`

**正解**: B

`docker cp コンテナ:パス ホストのパス` で、コンテナとホストの間でファイルをコピーできます。`docker exec` の `cp` はコンテナの中でコピーするだけで、ホストには出ません。`docker export` はコンテナのファイルシステム全体を tar にするコマンドです。

### 問18 `Docker-3.0-018`

**正解**: B

**テキスト**: 1. 資源の制限

`--memory` の上限を超えると、カーネルの OOM キラーがコンテナのプロセスを強制終了し、終了コードは 137 になります。上限は自動では上がりません(スワップの設定によっては、少しの間ディスクを使うこともありますが、上限を超えて動き続けることはできません)。

### 問19 `Docker-3.0-019`

**正解**: B

**テキスト**: 1. 資源の制限

制限を書かないと、コンテナはホストの CPU とメモリを上限なしに使えます。1 つのコンテナの暴走やメモリリークで、同じホストのほかのコンテナやホスト自体が遅くなったり、OOM で止まったりします。起動、ログ、ネットワークには直接は影響しません。

### 問20 `Docker-3.0-020`

**正解**: A

**テキスト**: 2. ヘルスチェック

Docker 単体では、ヘルスチェックの結果は状態として表示されるだけで、unhealthy になってもコンテナは再起動されません。再起動の方針(`--restart`)は、コンテナが**終了したとき**に働くものです。unhealthy のときの入れ替えは、Kubernetes などのオーケストレーターが行います。

### 問21 `Docker-3.0-021`

**正解**: B

**テキスト**: 2. ヘルスチェック

`--interval=30s` は確かめる間隔、`--retries=3` は unhealthy と判断するまでに続けて失敗してよい回数です。30 秒ごとに確かめ、3 回続けて失敗すると unhealthy になります。成功してもコンテナは止まりません。

### 問22 `Docker-3.0-022`

**正解**: D

**テキスト**: 3. PID 1 の問題と --init

`docker run --init` を付けると、tini という小さな init プロセスが PID 1 になり、アプリはその子になります。init がシグナルをアプリに転送し、終わった子プロセス(ゾンビ)を回収します。`--privileged` は危険な特権で、再起動やメモリはこの問題とは関係ありません。
