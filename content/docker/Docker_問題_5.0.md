## 問題

### 5.1 コンテナの書き込み層

**問1** `Docker-5.0-001` ボリュームを使わずに動かしているデータベースのコンテナで、`docker stop` と `docker start` をした。データはどうなるか。

- D. すべて消える

**問2** `Docker-5.0-002` ボリュームを使わずに動かしているデータベースのコンテナを `docker rm` で削除し、同じイメージで新しいコンテナを作った。データはどうなるか。

- A. 自動でバックアップされている

### 5.3 データのバックアップと調査

## 解答・解説

### 問1 `Docker-5.0-001`

**正解**: C

`docker stop` と `docker start` では、コンテナ自体は削除されないので、書き込み層のデータも残っています。データが消えるのは、コンテナを削除したときです。イメージやボリュームに自動で移されることはありません。

### 問2 `Docker-5.0-002`

**正解**: B

書き込み層は、そのコンテナと一緒に削除されます。新しいコンテナは、変わっていないイメージから作られるので、データはありません。データを残すには、最初からボリュームを使っておく必要があります。

### 問3 `Docker-5.0-003`

**正解**: D

書き込み層は、イメージの読み取り専用の層の上に作られる、そのコンテナ専用の層で、コンテナと一緒に削除されます。ストレージドライバーを通るので大量の読み書きには向かず、ほかのコンテナとは共有されません。

### 問4 `Docker-5.0-004`

**正解**: B

名前付きボリュームは Docker が管理する場所にデータを置き、コンテナを削除・作り直しても残ります。本番のデータに向いています。書き込み層はコンテナと一緒に消え、tmpfs はメモリなので止めると消えます。イメージに入れたデータは、実行中の変更を残せません。

### 問5 `Docker-5.0-005`

**正解**: B

バインドマウントは、ホストのディレクトリをそのままコンテナに見せるので、ホストで編集したファイルがすぐに反映されます。開発に向いています。`docker commit` はコンテナからイメージを作る操作です。

### 問6 `Docker-5.0-006`

**正解**: A

tmpfs はホストのメモリの上にファイルを置き、ディスクには書きません。コンテナが止まると消えます。バインドマウントとボリュームはディスクに書きます。

### 問7 `Docker-5.0-007`

**正解**: A

`-v` の左側が名前(`pgdata`)なら名前付きボリューム、`/` や `./` で始まるパスならバインドマウントです。
① `pgdata:` は名前なので、Docker が管理するボリュームです。
② `./conf:` はパスなので、ホストの `./conf` ディレクトリのバインドマウントです。

### 問8 `Docker-5.0-008`

**正解**: D

コンテナを削除しても、名前付きボリュームは残ります。同じボリュームを新しいコンテナにマウントすれば、データを引き継げます。ボリュームを削除するには `docker volume rm` を使います。`docker rm -v` で一緒に消えるのは、匿名ボリュームだけです。

### 問9 `Docker-5.0-009`

**正解**: C

バインドマウントは、ホストのディレクトリをそのパスにかぶせるので、イメージのそのパスにあった中身は見えなくなります。ホストのディレクトリが空なら、空に見えます。両方が合わさって見えることはありません。

### 問10 `Docker-5.0-010`

**正解**: A

空の新しいボリュームをマウントすると、イメージのそのディレクトリの中身が、ボリュームにコピーされます。これはバインドマウントとの違いです。ボリュームに中身がすでにあれば、コピーはされず、ボリュームの中身が見えます。

### 問11 `Docker-5.0-011`

**正解**: A

マウントの最後に `:ro` を付けると、読み取り専用になり、コンテナから書き換えられません。`:rw` は読み書きでき(既定)、tmpfs はメモリの一時的な場所です。`-v app.conf` だけでは、マウント先が分かりません。

### 問12 `Docker-5.0-012`

**正解**: A

バインドマウントでは、ファイルの持ち主の UID/GID がホストのままです。コンテナの中のユーザー(例: UID 1000 や root 以外)にそのディレクトリの書き込み権限がないと、`Permission denied` になります。ホストの持ち主を合わせるか、`-u` で UID を合わせます。

### 問13 `Docker-5.0-013`

**正解**: C

`--mount` は `type=…,source=…,target=…` と項目名を書くので、読みやすく誤りが分かりやすい書き方です。存在しないホストのパスを指定するとエラーになります(`-v` は空のディレクトリを作ってしまう)。書き方は長く、ボリュームは `-v` でも使えます。

### 問14 `Docker-5.0-014`

**正解**: A

ボリュームを一時的なコンテナにマウントし、ホストのディレクトリもマウントして、tar で固めます。
① `-v pgdata:/data:ro` で、ボリュームを読み取り専用で `/data` に見せます。
② `-v "$(pwd)":/backup` で、ホストのカレントディレクトリを `/backup` に見せます。
③ `tar czf /backup/pgdata.tgz -C /data .` で、`/data` の中身をホストに保存します。
④ `--rm` で、作業が終わったコンテナを消します。

`docker volume export` というコマンドはなく、`docker cp` と `docker commit` はコンテナを対象にするコマンドです。

### 問15 `Docker-5.0-015`

**正解**: A

動いているデータベースは、ファイルを書き換え続けています。そのままコピーすると、書き込みの途中の、つじつまの合わない状態が保存され、復元できないことがあります。データベースを止めてからコピーするか、`pg_dump` などのデータベースの機能でバックアップします。

### 問16 `Docker-5.0-016`

**正解**: B

`docker volume prune` は、どのコンテナ(止まっているものを含む)からも使われていない匿名ボリュームを、中のデータごと削除します。Docker Engine 23 以降、名前付きボリュームは `-a`(`--all`)を付けたときだけ対象になります。元に戻せないので、何が消えるかを確かめてから実行します。

### 問17 `Docker-5.0-017`

**正解**: B

`docker system prune` は、止まっているコンテナ、使われていないネットワーク、名前のないイメージ、ビルドキャッシュを削除します。ボリュームは、データを失う危険があるため、`--volumes` を付けたときだけ削除の対象になります。

### 問18 `Docker-5.0-018`

**正解**: A

`docker system df` は、イメージ、コンテナ、ボリューム、ビルドキャッシュの使用量と、削除できる量を表示します。`docker volume ls` は一覧だけ、`docker stats` は CPU とメモリ、`docker ps -s` はコンテナの書き込み層の大きさだけです。
