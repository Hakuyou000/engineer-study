# Docker 問題 7.0 レジストリとイメージの配布

対象: 実務の Docker / 全18問 / すべてオリジナル問題
対応テキスト: `Docker_7.0_レジストリとイメージの配布.md`
解答・解説は末尾。

## 問題

### 7.1 レジストリの種類

- D. レジストリはイメージを保存して配るサーバーで、その中に、同じ名前のイメージ(タグ違い)の集まりであるリポジトリがある

**問2** `Docker-7.0-002` AWS で、IAM で権限を管理できるプライベートなコンテナのレジストリはどれか。

- A. Amazon EFS
- B. AWS CodeCommit
- C. Amazon ECR
- D. Amazon S3

- B. イメージの大きさが自動で半分になる
- C. コンテナの起動が必ず速くなる
- D. Dockerfile が不要になる
- E. 権限を管理し、承認したイメージだけを使わせられる

### 7.4 イメージの信頼性

- A. docker compose

- C. docker tag
- D. Docker Scout

- B. タグを `latest` に保つため

- D. イメージの名前を変えるため

## 解答・解説

### 問1 `Docker-7.0-001`

**正解**: D

レジストリはイメージを保存して配るサーバー(Docker Hub、ECR など)で、その中に、同じ名前でタグの違うイメージの集まりであるリポジトリ(例: `nginx`)があります。Git のリポジトリとは別のものです。

### 問2 `Docker-7.0-002`

**正解**: C

Amazon ECR(Elastic Container Registry)は、AWS のプライベートなコンテナのレジストリで、IAM で push と pull の権限を管理できます。S3 はオブジェクトストレージ、CodeCommit は Git のリポジトリ、EFS はファイルシステムです。

### 問3 `Docker-7.0-003`

**正解**: A、E

自社のプライベートレジストリに置くと、Docker Hub などの外部の障害や pull の回数の制限に左右されず、権限を管理して承認したイメージだけを使わせられます。イメージが小さくなったり、Dockerfile が不要になったり、起動が必ず速くなったりはしません。

### 問4 `Docker-7.0-004`

**正解**: B

**テキスト**: 1. 手順

push 先は、イメージの名前(先頭のホスト名)で決まります。
① `docker tag` で、レジストリのホスト名を含む名前 `registry.example.com/team/myapp:1.0` を付けます。
② その名前で `docker push` します。

`docker push` に送り先を別に指定するオプションはありません。`docker save` はイメージを tar に書き出すだけです。

### 問5 `Docker-7.0-005`

**正解**: C

**テキスト**: 1. 手順

イメージの名前にレジストリのホスト名がないと、Docker Hub(`docker.io`)に送られます。ここでは Docker Hub の `yamada` という名前空間の `myapp` リポジトリです。最後にログインしたレジストリに送られるわけではありません。社内のレジストリに送るには、ホスト名を含む名前を付けます。

### 問6 `Docker-7.0-006`

**正解**: B

**テキスト**: 1. 手順

push と pull は層ごとに行われ、相手のレジストリにすでにある層は送りません。2 回目は、変わった層(多くはアプリのコードの層)だけが送られるので速くなります。ベースイメージの層を共有するのも同じ仕組みです。

### 問7 `Docker-7.0-007`

**正解**: D

**テキスト**: 2. Amazon ECR の例

`--password-stdin` は、パスワードを標準入力から受け取ります。`-p` で引数に書くと、シェルの履歴やプロセスの一覧に残り、漏れる危険があります。ECR では `aws ecr get-login-password` の出力をパイプで渡します。

### 問8 `Docker-7.0-008`

**正解**: A

**テキスト**: 3. 認証情報の保存

`docker login` の認証情報は `~/.docker/config.json` に保存されます。認証情報ヘルパー(OS のキーチェーン、`docker-credential-ecr-login` など)を設定しないと、Base64 で書かれるだけで暗号化されません。ファイルの権限を守り、ヘルパーを使うのが安全です。

### 問9 `Docker-7.0-009`

**正解**: C

**テキスト**: 1. タグの付け方

`latest` は付け替えられる既定のタグなので、どの版が動いているかが分からず、同じ指定でも pull した時期によって中身が変わります。再現や切り戻しが難しくなります。セマンティックバージョンや Git のコミットの ID、ダイジェストで指定します。

### 問10 `Docker-7.0-010`

**正解**: D

**テキスト**: 1. タグの付け方

タグは、後から別のイメージに付け替えられます。同じ `myapp:1.4` でも、誰かが別のイメージを push すると中身が変わります。1 つのイメージには複数のタグを付けられます。中身から計算されるのはダイジェストです。

### 問11 `Docker-7.0-011`

**正解**: B

**テキスト**: 1. タグの付け方

ECR のタグのイミュータビリティを有効にすると、すでにあるタグへの上書きの push が拒否されます。同じタグの中身が変わらないことを保証できます。ライフサイクルポリシーは古いイメージの自動削除、レプリケーションは別のリージョンへの複製です。

### 問12 `Docker-7.0-012`

**正解**: A

**テキスト**: 2. ダイジェスト

ダイジェストは、イメージ(マニフェスト)の中身から計算した SHA-256 のハッシュ値です。中身が 1 バイトでも違えば変わるので、ダイジェストで指定すれば、必ず同じイメージを使えます。人が付ける名前はタグです。

### 問13 `Docker-7.0-013`

**正解**: D

**テキスト**: 2. ダイジェスト

`docker images --digests` で、ローカルのイメージのダイジェストを表示できます。`docker image inspect --format '{{.RepoDigests}}' 名前` でも確かめられます。`docker ps` と `docker logs` に `--digests` はありません。

### 問14 `Docker-7.0-014`

**正解**: A

**テキスト**: 3. マルチアーキテクチャのイメージ

複数のアーキテクチャをまとめたイメージ(マニフェストリスト)を pull すると、Docker がホストのアーキテクチャに合うものを自動で選びます。arm64 のサーバーでは arm64 用が取得されます。

### 問15 `Docker-7.0-015`

**正解**: D、E

**テキスト**: まとめ: よく出る判断

Docker Scout と Trivy は、イメージの中のパッケージを調べ、既知の脆弱性(CVE)を報告するツールです。`docker compose` は複数のコンテナの管理、`docker stats` は使用量の表示、`docker tag` は名前の付与です。

### 問16 `Docker-7.0-016`

**正解**: A

**テキスト**: まとめ: よく出る判断

イメージの署名には、Sigstore(Cosign)や Notation を使い、デプロイの前に検証します。Docker Content Trust(`DOCKER_CONTENT_TRUST=1`)は廃止されたので、新しく使うことはできません。タグの名前や `docker commit` は署名ではありません。

### 問17 `Docker-7.0-017`

**正解**: B

**テキスト**: まとめ: よく出る判断

`docker buildx build` の `--sbom=true` と `--provenance=true` で、SBOM と来歴(provenance)の記録をイメージに付けられます(attestation)。`run`、`push`、`history` にはこれらのオプションはありません。

### 問18 `Docker-7.0-018`

**正解**: A

**テキスト**: まとめ: よく出る判断

ベースイメージの OS やライブラリにも、新しく脆弱性が見つかります。ベースイメージは修正版に更新されるので、定期的にビルドし直して、その修正を自分のイメージに取り込みます。タグや名前、ログとは関係ありません。
