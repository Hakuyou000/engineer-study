## 解答・解説

| 問 | 正解 | 解説 |
|---|---|---|
| 1 | A | Intelligent-Tiering は、オブジェクトごとのアクセス状況を見て、読まれなくなったものを自動で安い層に移し、読まれると元に戻します。アクセス傾向が分からないデータに最適で、取り出し料金もかかりません。Deep Archive はすぐには読めず、手作業は手間がかかります。One Zone-IA は1つの AZ だけで、頻繁に読まれる画像では取り出し料金がかさみます。 |
| 2 | B | 30日後に Standard-IA に移すと、すぐに読める状態のまま保存料金が下がります。365日後の削除もライフサイクルで自動化できます。Standard のままでは割高で、手作業の削除は忘れの原因になります。Deep Archive や Flexible Retrieval はすぐに読めず、削除しないと費用が残り続けます。 |
| 3 | D | Deep Archive は最も安いストレージクラスで、取り出しは標準で12時間以内、大容量なら48時間以内です。2日待てるなら要件を満たします。Standard-IA、Glacier Instant Retrieval、Intelligent-Tiering は、すぐに読める代わりに Deep Archive より保存料金が高くなります。 |
| 4 | B | Glacier Instant Retrieval は、ほとんど読まれないデータをアーカイブの安い料金で保存しつつ、ミリ秒で取り出せます。Flexible Retrieval と Deep Archive は取り出しに分〜時間単位かかり、すぐには表示できません。Standard はすぐ読めますが、ほとんど読まれないデータには割高です。 |
| 5 | C | One Zone-IA は1つの AZ だけに保存するため、Standard-IA より安くなります。作り直せるデータなら、AZ 障害で失われる危険を受け入れられます。Standard と Standard-IA は複数の AZ に保存する分、高くなります。Intelligent-Tiering はアクセス傾向が分からないデータ向けで、監視料金もかかります。 |
| 6 | D | リクエスタ支払いを有効にすると、データを取得する側がリクエストと転送の料金を負担します。Transfer Acceleration は転送を速くする機能で費用は増えます。署名付き URL は一時的なアクセス許可で、費用の負担者は変わりません。レプリケーションはデータの複製です。 |
| 7 | A | バージョニングでは上書きや削除のたびに古いバージョンが残り、その分の料金がかかります。ライフサイクルルールで非現行バージョンを一定期間後に削除(または安いクラスに移動)すると、費用を抑えられます。リージョンの移動、暗号化の無効化、ポリシーの長さは、増え続ける原因の解決になりません。 |
| 8 | B | ユーザーが付けたタグは、請求コンソールでコスト配分タグとして有効にしてから、Cost Explorer やレポートでタグごとの集計に使えるようになります。Budgets は予算の通知、リージョンの移動は無関係で、Config はリソースの設定の評価です。 |
| 9 | C | Budgets は予算を設定し、実績や予測がしきい値(例: 80%)を超えたときに、メールや SNS で通知します。Cost Explorer は費用の分析と予測、Cost and Usage Report は詳しい明細の出力で、通知の機能はありません。Trusted Advisor はコスト削減などの推奨を出すサービスです。 |
| 10 | `180`、`180日` | Glacier Deep Archive の最低保存期間は180日です。それより前に削除すると、残りの日数分の料金がかかります。Glacier Instant Retrieval と Flexible Retrieval は90日、Standard-IA と One Zone-IA は30日です。 |
| 11 | D | 3年間同じ構成で動き続けるなら、3年の契約で全額前払いにすると割引が最も大きくなります。オンデマンドは割引がなく、スポットは中断されるため基幹システムには向きません。1年の前払いなしは、3年の全額前払いより割引が小さくなります。 |
| 12 | A | Compute Savings Plans は、インスタンスファミリー、サイズ、リージョン、OS を問わず、Fargate と Lambda にも適用されるため、最も柔軟です。スタンダード RI は構成の変更に制限があります。Dedicated Hosts はライセンスや規制のための物理サーバーの専有で、キャパシティ予約は容量の確保で割引ではありません。 |
