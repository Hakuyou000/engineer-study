## 解答・解説

| 問 | 正解 | 解説 |
|---|---|---|
| 1 | D | 計画、ツールの利用、複数手順の自律的な実行がエージェント型の特徴。文章の生成は生成 AI、将来の値の予測は予測 AI。 |
| 2 | D | Human-in-the-loop、最小権限、監査ログが基本の対策。 |
| 3 | A | 検知から調査、修正案、適用、検証までを進める。MAC アドレスによる転送や SPF 計算は、データプレーン・コントロールプレーンの機能。 |
| 4 | C | ペルソナ、コンテキスト、指示、入力データ、出力形式がそろい、機密情報を含まない。パスワードのハッシュを含む設定を貼り付けるのはデータ分類に反する。 |
| 5 | D | 認証情報と、組織や顧客を特定できる情報は入力しない。 |
| 6 | C | AI に担わせる役割の指定はペルソナ。 |
| 7 | C | 出力は提案。存在しないコマンドを生成することがある。検証と変更管理を経る。 |
| 8 | D | アプリケーション側はノースバウンド。REST API が一般的。 |
| 9 | D | HSRP はゲートウェイ冗長化のプロトコル。管理用のインターフェースではない。 |
| 10 | A | クラウドにあるのは管理プレーン。データプレーンは現地の機器にある。 |
| 11 | A | コードで定義、バージョン管理、Single Source of Truth。 |
| 12 | B | 宣言的は最終状態を書く。手続き的は手順を書く。 |
| 13 | A | 冪等性により、繰り返し実行しても安全。 |
| 14 | B | どちらもエージェントが送る通知。Inform は応答がなければ再送する。 |
| 15 | C | authPriv が認証 + 暗号化。 |
| 16 | A | Set には RW のコミュニティが要る。UDP 162 は Trap の受信用。 |
| 17 | B | Ansible はエージェントレス、プッシュ型、YAML。エージェントを導入するプル型は Puppet / Chef。 |
| 18 | B | `ios_command` は EXEC コマンドを実行する。`ios_config` は設定の投入。 |
| 19 | C | changed=0 は変更なし。冪等性による。 |
| 20 | B | `hosts` がインベントリのホスト・グループを指定する。 |
| 21 | A | `%ファシリティ-重大度-ニーモニック`。3 は errors。critical は 2。 |
| 22 | B | 指定したレベルと、それより数値の小さい(重大な)レベルが対象。UDP 514。SSH で見るには `terminal monitor`。 |
