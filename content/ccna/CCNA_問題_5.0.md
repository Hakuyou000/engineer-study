## 解答・解説

| 問 | 正解 | 解説 |
|---|---|---|
| 1 | D | エージェント型 AI は、目標に向けて自分で計画を立て、ツールや API を使って複数の手順を実行し、結果を見て次の行動を決めます。文章を作るだけなのはチャット型の生成 AI、過去の値から将来を予測するのは予測 AI の特徴です。 |
| 2 | D | 影響の大きい変更は人が承認する(Human-in-the-loop)、エージェントに与える権限を必要最小限にする、操作を監査ログに残す、の3つが基本の対策です。すべての権限を与えたり、ログを止めたり、出力を確かめずに適用したりすると、誤った操作の被害が大きくなります。 |
| 3 | A | エージェント型 AI は、アラートを受けて関係する機器から情報を集め、原因の候補を絞り込み、修正案を示し、承認された後に適用して結果を確かめる、といった一連の流れを進められます。MAC アドレスによる転送や OSPF の経路計算は機器そのものの機能で、光の増幅は物理的な処理です。 |
| 4 | C | よいプロンプトには、役割(ペルソナ)、状況(コンテキスト)、具体的な指示、入力データ、出力の形式がそろっています。さらに、アドレスを仮の値に置き換えるなど、機密情報を含めないことが大切です。パスワードのハッシュや SNMP のコミュニティを含む設定をそのまま貼り付けるのは、情報の取り扱いとして不適切です。 |
| 5 | D | パスワードのハッシュ、SNMP のコミュニティ文字列、VPN の事前共有鍵のような認証情報や、グローバル IP アドレス、顧客名のように組織や顧客を特定できる情報は、外部の AI サービスに入力しません。コマンドのキーワードやコメントは、設定の確認に必要な情報です。 |
| 6 | C | AI にどんな立場や専門家として答えてほしいかを指定する部分は、ペルソナと呼ばれます。出力形式は答えの形(表や箇条書きなど)、例示は答えの例を示す部分です。 |
| 7 | C | 生成 AI の出力は、あくまで提案です。存在しないコマンドを作ってしまうこともあるため、構文と影響を公式のドキュメントや検証環境で確かめ、普段の変更管理の手順に従って適用します。そのまま本番に入れたり、多数決で決めたりしてはいけません。 |
| 8 | D | アプリケーションやスクリプトがコントローラーとやり取りするのは、ノースバウンド API です。REST API が一般的に使われます。コントローラーが機器を設定・監視するのはサウスバウンドのインターフェースで、NETCONF や SNMP はそちらで使われます。 |
| 9 | D | HSRP は、デフォルトゲートウェイを冗長化するためのプロトコルで、機器の管理には使いません。NETCONF、RESTCONF、SNMP は、コントローラーが機器を設定したり状態を集めたりするサウスバウンドのインターフェースで使われます。 |
| 10 | A | クラウドベースの管理では、管理の機能(管理プレーン)がクラウドにあり、機器はインターネットを通してクラウドから設定を取得します。利用者のデータの通信(データプレーン)は現地の機器が処理し、クラウドを経由しません。コントローラーを自社に置くのは、オンプレミス型の管理です。 |
| 11 | A | Infrastructure as Code は、ネットワークやサーバーの構成をコードとして書き、Git などのバージョン管理システムで変更の履歴を残し、そのコードを唯一の正しい情報(Single Source of Truth)として扱う方法です。手作業や口頭での引き継ぎ、画面キャプチャでの記録とは反対の考え方です。 |
| 12 | B | あるべき最終の状態だけを書き、今との違いをツールに判断させて適用する方式を、宣言的(declarative)と呼びます。どのコマンドをどの順番で実行するかという手順を書く方式は、手続き的(imperative)です。 |
| 13 | A | 冪等性とは、同じ操作を何度実行しても結果が同じになることです。すでに望む状態になっていれば何も変更しないので、自動化の処理を繰り返し実行しても安全です。 |
| 14 | B | Trap と Inform は、どちらもエージェント(管理される機器)からマネージャーに送る通知です。Trap は確認の応答がなく、届いたかどうか分かりません。Inform は応答があり、応答がなければ再送します。どちらも UDP を使います。 |
| 15 | C | SNMPv3 の authPriv は、認証(auth)と暗号化(priv)の両方を行うセキュリティレベルです。noAuthNoPriv はどちらも行わず、authNoPriv は認証だけで暗号化はしません。privOnly というレベルはありません。 |
| 16 | A | 値の取得(Get)はできるので、通信やコミュニティ文字列自体は合っています。値の変更(Set)には、書き込みができる RW のコミュニティが必要です。RO(読み取り専用)のコミュニティでは変更できません。UDP 162 は Trap を受け取るためのポートです。 |
| 17 | B | Ansible は、管理対象にエージェントを入れずに(エージェントレス)、コントロールノードから SSH などで接続して設定を送る(プッシュ型)ツールです。プレイブックは YAML で書きます。管理対象にエージェントを入れて設定を取りに行かせる(プル型)のは、Puppet や Chef です。 |
| 18 | B | `cisco.ios.ios_command` は、`show` などの EXEC のコマンドを実行して出力を取得するモジュールです。`ios_config` は設定を投入するモジュールで、`debug` は変数などの表示、`copy` はファイルのコピーに使います。 |
| 19 | C | PLAY RECAP の項目を順に読みます。<br>① `ok=2`:2 つのタスクが正常に終わりました。<br>② `changed=0`:変更を行ったタスクは 0 個です。<br>③ `unreachable=0`:接続できなかったホストはありません。<br>④ `failed=0`:失敗したタスクはありません。<br>⑤ 1 回目の実行で R1 はすでに望む状態になっていたので、2 回目は何も変えませんでした。同じ結果になるまで何度実行しても安全という性質を冪等性と呼びます。<br>接続できなければ unreachable、タスクが失敗すれば failed が増えます。構文エラーなら、PLAY RECAP が出る前にエラーで止まります。 |
| 20 | B | プレイブックを上から順に読みます。<br>① `- name: Set logging host`:プレイの説明のための名前です。対象には影響しません。<br>② `hosts: routers`:プレイの対象です。インベントリの routers グループに属する機器が対象になります。<br>③ `gather_facts: false`:機器の情報(facts)を最初に集めないという指定です。<br>④ `tasks:` の下:実行するタスクです。`cisco.ios.ios_config` モジュールで、`lines:` に書いた `logging host 10.1.1.100` を設定します。<br>`lines` は投入する設定の内容で、どの機器に投入するかは `hosts` で決まります。 |
| 21 | A | メッセージの形 `%ファシリティ-重大度-ニーモニック` に当てはめます。<br>① `LINK`:ファシリティ(メッセージを出した機能)です。重大度ではありません。<br>② `3`:重大度です。<br>③ `UPDOWN`:ニーモニック(メッセージの種類)です。<br>④ 重大度は 0〜7 で、0 emergencies、1 alerts、2 critical、3 errors、4 warnings、5 notifications、6 informational、7 debugging です。<br>⑤ 3 は errors です。<br>critical は 2 で 1 つずれています。notifications は 5 で、インターフェースの line protocol の状態変化(`%LINEPROTO-5-UPDOWN`)と混同しやすい値です。 |
| 22 | B | `logging trap 4` は、重大度 4(warnings)と、それより数値の小さい、より重大なメッセージ(0〜4)を送るという意味です。`%SYS-5-CONFIG_I` は重大度 5 なので送られません。syslog の送信は UDP の 514 番で、SSH のセッションに表示するには別に `terminal monitor` が必要です。 |
| 23 | `LINEPROTO` | メッセージは `%ファシリティ-重大度-ニーモニック` の形なので、ファシリティは LINEPROTO です。重大度は 5(notifications)、ニーモニック(メッセージの種類)は UPDOWN です。 |
| 24 | C | SSH や Telnet のセッション(VTY)にログを表示するには、そのセッションで `terminal monitor` を実行する必要があります。表示をやめるときは `terminal no monitor` です。`logging console` はコンソールポートへの出力の設定で、SSH の画面には関係しません。 |
| 25 | B | syslog の重大度は、0 emergencies、1 alerts、2 critical、3 errors、4 warnings、5 notifications、6 informational、7 debugging の順です。数値が小さいほど重大です。 |
| 26 | D | Cisco の機器は、既定では UDP の 514 番で、informational(6)以下のメッセージを syslog サーバーに送ります。送り先は `logging host`、送るレベルは `logging trap` で変えられます。UDP 162 は SNMP の Trap のポートです。 |
