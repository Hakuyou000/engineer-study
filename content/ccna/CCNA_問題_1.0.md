## 解答・解説

### 問1 `CCNA-1.0-001`

**正解**: B

PC とルーターは、どちらも同じピン(1番と2番)で送信する機器(MDI)です。同じ種類の機器同士をつなぐときは、送信と受信の線を入れ替えたクロスケーブルを使います。ストレートケーブルは PC とスイッチのように種類の違う機器をつなぐもの、ロールオーバーケーブルはコンソール接続用です。

### 問2 `CCNA-1.0-002`

**正解**: B

オートネゴシエーションの側は、相手が固定でも、電気信号から速度(100 Mbps)は検出できます。しかしデュプレックス(全二重か半二重か)は検出できないので、10/100 Mbps では半二重になります。その結果、デュプレックスが一致しない状態になります。

### 問3 `CCNA-1.0-003`

**正解**: D

全二重の側は、相手が送信中でも構わず送信します。半二重の相手はそれを衝突とみなして送信を途中でやめるため、全二重の側には壊れたフレームが届き、CRC エラーと runts(短すぎるフレーム)が増えます。late collisions が増えるのは、半二重の側です。

### 問4 `CCNA-1.0-004`

**正解**: C

出力を上から順に読みます。
① `is up, line protocol is up`:物理層もデータリンク層も正常です。ケーブルが抜けている場合は down/down、相手が `shutdown` されている場合も down/down になるので、どちらも当てはまりません。
② `Half-duplex, 100Mb/s`:このポートは半二重で動いています。
③ `1250 collisions, 312 late collision`:衝突が多く、特に late collision(フレームの先頭 64 バイトを送ったあとに検出された衝突)が出ています。
④ 半二重の側は衝突を検出して送り直しますが、全二重の相手は衝突を気にせず送ってくるため、late collision が増えます。これはデュプレックス不一致の典型的な症状です。

ポートセキュリティ違反なら、ポートは err-disabled(down)になるか、違反のカウンターが増えます。衝突の数には表れません。

### 問5 `CCNA-1.0-005`

**正解**: D

`administratively down` は、管理者が `shutdown` コマンドでインターフェースを無効にしている状態です。ケーブルが接続されていない場合は down/down、BPDU ガードが働いた場合は err-disabled と表示されます。

### 問6 `CCNA-1.0-006`

**正解**: C

10GBASE-LR はシングルモードファイバーで約 10 km まで届くので、8 km の接続に使えます。10GBASE-SR はマルチモードファイバーで数百 m まで、10GBASE-T は銅線で 100 m まで、1000BASE-SX は 1 Gbps の規格です。

### 問7 `CCNA-1.0-007`

**正解**: D

受信する光が弱くなっているので、途中で光が失われていると考えられます。コネクタの汚れ、ファイバーの曲げすぎ、規格の距離を超えた配線などが原因です。デュプレックス不一致は銅線のオートネゴシエーションでよく起きる問題で、この症状には当てはまりません。

### 問8 `CCNA-1.0-008`

**正解**: C

giants は、最大の長さ(通常 1518 バイト)を超えるフレームを受信した回数です。64 バイト未満の短すぎるフレームは runts、FCS(誤り検出の値)が一致しないフレームは CRC エラーとして数えられます。

### 問9 `CCNA-1.0-009`

**正解**: D

Type 1 ハイパーバイザーは、ハードウェアの上で直接動きます(ベアメタル型。例: VMware ESXi)。ホスト OS の上でアプリケーションとして動くのは Type 2 です(例: VirtualBox)。コンテナエンジンはハイパーバイザーとは別のものです。

### 問10 `CCNA-1.0-010`

**正解**: C

コンテナはホスト OS のカーネルを共有し、それぞれにゲスト OS を持たないため、仮想マシンより軽く、起動も速くなります。コンテナの実行に必要なのはコンテナエンジン(Docker など)で、ハイパーバイザーは必須ではありません。

### 問11 `CCNA-1.0-011`

**正解**: A

VM の vNIC は、ハイパーバイザーの中の仮想スイッチにつながり、物理 NIC を通って外部へ出ます。複数の VLAN の通信が1本のリンクを通るので、物理スイッチ側のポートはトランクにします。アクセスポートでは1つの VLAN しか通せません。

### 問12 `CCNA-1.0-012`

**正解**: A

手順どおりに計算します。
① /20 は、第 3 オクテットのうち上位 4 ビットまでがネットワーク部です(8 + 8 + 4 = 20)。
② 第 3 オクテットのマスクは 11110000 = 240 で、ブロックの大きさは 256 − 240 = 16 です。
③ 第 3 オクテットを 16 ずつ区切ると、0〜15、16〜31、32〜47、48〜63 … となります。
④ 45 は 32〜47 のブロックに入ります。
⑤ ネットワークアドレスは 172.16.32.0、ブロードキャストアドレスは 172.16.47.255(第 4 オクテットは 255)です。

172.16.40.0 は、ブロックの先頭を 16 の倍数にしなかった場合の誤りです。172.16.45.0 / .45.255 は /24 として計算した場合、172.16.32.0 / .63.255 は /19(32 ずつの区切り)として計算した場合の答えです。

### 問13 `CCNA-1.0-013`

**正解**: B

必要なホスト数から、ホスト部のビット数を決めます。
① ホストに使えるアドレスの数は、2 の(ホスト部のビット数)乗 − 2 です。ネットワークアドレスとブロードキャストアドレスの 2 つを引きます。
② ホスト部 5 ビット(/27):2 の 5 乗 − 2 = 30 台。50 台に足りません。
③ ホスト部 6 ビット(/26):2 の 6 乗 − 2 = 62 台。50 台が入ります。
④ 50 台が入る最小は /26 です。

/25 は 126 台入りますが、最小ではありません。/28 は 14 台しか入りません。/27 を選ぶのは、2 の 5 乗の 32 を 50 と比べたり、− 2 を忘れたりした誤りです。

### 問14 `CCNA-1.0-014`

**正解**: C

まず 130 が属するサブネットを求めます。
① /26 は第 4 オクテットの上位 2 ビットまでがネットワーク部で、マスクは 255.255.255.192 です。
② ブロックの大きさは 256 − 192 = 64 で、区切りは 0〜63、64〜127、128〜191、192〜255 です。
③ 130 は 128〜191 のブロックに入ります。ネットワークアドレスは .128、ブロードキャストアドレスは .191 で、ホストに使えるのは .129〜.190 です。
④ 選択肢のうち、この範囲に入るのは 192.168.1.190 だけです。

126 は 64〜127 の別のサブネットのホストです。127 はそのサブネットのブロードキャストアドレスです。193 は 192〜255 の別のサブネットです。/24 と考えると全部同じサブネットに見えるので注意が必要です。

### 問15 `CCNA-1.0-015`

**正解**: A

手順どおりに計算します。
① /27 はマスクが 255.255.255.224 で、ブロックの大きさは 256 − 224 = 32 です。
② 10.1.1.64/27 の範囲は、64 から 32 個分の 64〜95 です。
③ 先頭の 64 がネットワークアドレス、末尾の 95 がブロードキャストアドレスです。
④ ホストに割り当てられる最後のアドレスは、ブロードキャストアドレスの 1 つ前の 10.1.1.94 です。

10.1.1.95 はブロードキャストアドレスなので、ホストには使えません。10.1.1.96 は次のサブネット(96〜127)のネットワークアドレスです。10.1.1.126 は、/26(64 個の区切りで 64〜127)として計算した場合の答えです。

### 問18 `CCNA-1.0-018`

**正解**: C

大きいサブネットから順に、アドレスの先頭から割り当てます。
① 100 台用:ホストが 100 台入るのは、2 の 7 乗 − 2 = 126 台の /25 です(/26 は 62 台で足りません)。192.168.5.0〜.127 を使います。
② 50 台用:2 の 6 乗 − 2 = 62 台の /26 で足ります。続きの 192.168.5.128〜.191 を使います。
③ 20 台用:2 の 5 乗 − 2 = 30 台の /27 で足ります。続きの 192.168.5.192〜.223 を使います。
④ そのため 20 台用は 192.168.5.192/27 です。

192.168.5.128/27 は、50 台用のサブネットを飛ばして割り当てた場合の誤りで、50 台用と重なります。192.168.5.160/27 も 50 台用(.128〜.191)と重なります。192.168.5.192/26 は大きさが 64 個で、20 台用としては必要最小限ではありません。

### 問19 `CCNA-1.0-019`

### 問20 `CCNA-1.0-020`

**正解**: D

省略のルールを順に当てはめます。
① 各グループの先頭の 0 を省略します:2001:db8:0:0:a0:0:0:1。00a0 は a0 になります(末尾の 0 は省略できません)。
② 0 だけのグループの連続は、3〜4 番目と 6〜7 番目の 2 か所で、どちらも 2 個ずつです。
③ `::` で省略できるのは 1 か所だけです。長さが同じときは左側を省略します。
④ 3〜4 番目を `::` にして、2001:db8::a0:0:0:1 です。

2001:db8::a0::1 は `::` を 2 回使っていて、元のアドレスが一つに決まらないため使えません。2001:db8::a:0:0:1 は、a0 の末尾の 0 を省略した誤りです。2001:db8:0:0:a::1 は、a0 を a にしたうえ、右側を省略しています。

### 問21 `CCNA-1.0-021`

**正解**: A

EUI-64 の手順どおりに作ります。
① MAC アドレス 0050.56ab.cdef を、前半 3 バイト 00 50 56 と後半 3 バイト ab cd ef に分けます。
② 真ん中に ff fe を入れます:00 50 56 ff fe ab cd ef(64 ビット)。
③ 先頭のバイト 00 を 2 進数にすると 00000000 です。左から 7 番目のビット(U/L ビット)を反転すると 00000010 = 02 になります。
④ インターフェース ID は 0250:56ff:feab:cdef です。各フィールドの先頭の 0 は省略できるので 250:56ff:feab:cdef になります。
⑤ プレフィックスとつなげて 2001:db8:1:1:250:56ff:feab:cdef です。

2001:db8:1:1:50:56ff:… は、7 番目のビットの反転を忘れた場合の誤りです。fffe を末尾に付けたもの、fffe の位置や順序を崩したものは、真ん中に ff fe を入れるという手順と違います。

### 問22 `CCNA-1.0-022`

**正解**: D

### 問23 `CCNA-1.0-023`

### 問28 `CCNA-1.0-028`

### 問41 `CCNA-1.0-041`
