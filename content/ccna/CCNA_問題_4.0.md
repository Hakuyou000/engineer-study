## 解答・解説

| 問 | 正解 | 解説 |
|---|---|---|
| 1 | D | タイプ 9(scrypt)のハッシュが最も強く、推測されにくい保護です。タイプ 5 は MD5 のハッシュで、タイプ 9 より弱くなります。タイプ 7 は簡単に元に戻せる暗号化で、`enable password` は設定によっては平文のまま保存されます。 |
| 2 | C | SSH の通信を暗号化するには RSA の鍵が必要で、`crypto key generate rsa` で作ります。鍵の名前にホスト名とドメイン名が使われるので、その2つは先に設定しておく必要があります。`ip ssh version 2` は鍵を作った後に使うバージョンの指定です。 |
| 3 | D | `login local` で、ルーターのローカルのユーザーデータベースを使って認証します。`transport input ssh` で、VTY への接続を SSH だけに限定します。`transport output` は VTY から外へ接続するときの設定、`no login` は認証をしない危険な設定です。 |
| 4 | A | TACACS+ は TCP の 49 番を使い、パケットの本体全体を暗号化し、認証・認可・アカウンティング(AAA)を別々に扱えます。UDP 1812 を使う、パスワードだけを暗号化する、認証と認可をまとめて扱う、802.1X でよく使われる、という特徴は RADIUS のものです。 |
| 5 | C | AAA の方式の一覧(ここでは TACACS+ の次に local)で次の方式に進むのは、前の方式が応答しなかったときだけです。TACACS+ サーバーが「認証失敗」を返した場合は、その結果で拒否が確定し、ローカルのデータベースは使われません。 |
| 6 | D | TACACS+ サーバーが応答しないので、一覧の次の方式である `local`(ローカルのデータベース)で認証します。ローカルに正しいパスワードで登録されているので、ログインできます。サーバーが止まっても管理者がログインできるように、このように local を後ろに書いておくのが一般的です。 |
| 7 | A | 通信はできていて、ユーザー名とパスワードも正しいので、ルーターとサーバーの間の設定が合っていないと考えられます。共有鍵(key)が一致していないか、サーバー側にこのルーターがクライアントとして登録されていないと、サーバーは要求を受け付けません。 |
