## 解答・解説

### 問1 `K8s-2.0-001`

**正解**: C

Deployment の `selector.matchLabels` は、`template.metadata.labels` と一致させる必要があります。selector が `app: web`、Pod のラベルが `app: frontend` なので、自分の作る Pod を選べず、検証のエラーになります。`containerPort` は省略でき、`apiVersion` は `apps/v1` が正しい値です。

### 問2 `K8s-2.0-002`

**正解**: B

`kubectl set image deployment/名前 コンテナ名=イメージ` の形で、コンテナ名を指定してイメージを変えます。Pod の雛形が変わるので、ローリングアップデートが始まります。`scale` は数を変えるコマンドで、`--image` はありません。

### 問3 `K8s-2.0-003`

**正解**: A

`kubectl rollout undo deployment/名前` で、1 つ前のリビジョン(ReplicaSet)に戻します。特定の版には `--to-revision` を付けます。`restart` は同じ設定のまま Pod を入れ替え、`pause` はロールアウトを一時停止するだけです。

### 問4 `K8s-2.0-004`

**正解**: B

`maxSurge` は希望の数を超えて追加してよい数、`maxUnavailable` は希望の数より減ってよい数です。
① `maxUnavailable: 0` なので、Pod は 4 個より減りません。
② `maxSurge: 1` なので、最大 4 + 1 = 5 個まで増えます。
③ 新しい Pod を 1 個作り、Ready になったら古い Pod を 1 個消す、を繰り返します。

一度 0 個になるのは Recreate の戦略です。

### 問5 `K8s-2.0-005`

**正解**: C

ローリングアップデートは、Pod の雛形(`spec.template`)が変わったときにだけ起きます。`replicas` は雛形の外なので、今の ReplicaSet の Pod の数が増えるだけです。設定を変えずに入れ替えたいときは `kubectl rollout restart` を使います。

### 問6 `K8s-2.0-006`

**正解**: C

環境変数は、コンテナを起動するときに一度だけ設定されます。ConfigMap を変えても、動いているコンテナの環境変数は変わりません。Pod を作り直す必要があります。ボリュームとしてマウントした場合は、しばらくして自動で反映されます(`subPath` を除く)。

### 問7 `K8s-2.0-007`

**正解**: A

Secret の `data` の値は Base64 で書かれているだけで、誰でも元に戻せます。Secret を読める権限を RBAC で絞り、etcd の保存時の暗号化を有効にして守ります。Secret は環境変数でもボリュームでも渡せますが、参照できるのは同じ Namespace の Secret だけです。

### 問8 `K8s-2.0-008`

**正解**: B

`CreateContainerConfigError` は、コンテナの設定を作れなかったことを表し、参照している ConfigMap や Secret(またはその中のキー)がないことが多い原因です。メモリの不足は Pending や OOMKilled、イメージのタグの誤りは ImagePullBackOff になります。

### 問9 `K8s-2.0-009`

**正解**: C

`envFrom` に `configMapRef` を書くと、ConfigMap のすべてのキーが、同じ名前の環境変数になります。1 つずつ渡すなら `env` の `valueFrom.configMapKeyRef` です。ボリュームにすると、環境変数ではなくファイルになります。

### 問10 `K8s-2.0-010`

**正解**: A

DaemonSet は、各ノードに 1 つずつ Pod を動かし、ノードが追加されると自動で Pod も追加します。ログの収集や監視のエージェント、CNI のプラグインに使われます。Deployment は数を指定するもので、ノードごとの配置は保証しません。

### 問11 `K8s-2.0-011`

**正解**: D

StatefulSet は、Pod に順番の付いた固定の名前(`db-0`、`db-1`…)を与え、`volumeClaimTemplates` で Pod ごとに専用の PVC を作ります。Pod が作り直されても、同じ名前と同じ PVC が使われます。Deployment の Pod の名前はランダムです。

### 問12 `K8s-2.0-012`

**正解**: B

readinessProbe が失敗すると、Pod は Ready でなくなり、Service のエンドポイントから外されて通信が来なくなります。コンテナは再起動されません。再起動されるのは livenessProbe が失敗したときです。

### 問13 `K8s-2.0-013`

**正解**: C

livenessProbe が続けて失敗すると、kubelet がコンテナを再起動します。固まって応答しなくなったアプリを自動で復旧させるのに使います。readinessProbe は振り分けから外すだけ、PodDisruptionBudget は計画的な中断の数の制限です。

### 問14 `K8s-2.0-014`

**正解**: C

startupProbe を設定すると、成功するまで livenessProbe と readinessProbe が止まります。起動の遅いアプリが、起動の途中で liveness の失敗により再起動されるのを防げます。readiness を消しても liveness の問題は解決しません。

### 問15 `K8s-2.0-015`

**正解**: C

CronJob は、cron 形式の `schedule`(例: `"0 2 * * *"`)で、決まった時刻に Job を作ります。Job は一回だけの処理、DaemonSet は各ノードに常駐、Deployment は常に動かし続けるアプリです。

### 問16 `K8s-2.0-016`

**正解**: C

`Init:0/1` は、1 つある初期化コンテナのうち、0 個が終わったことを表します。初期化コンテナが失敗を繰り返しているか、依存先を待ち続けています。`kubectl logs Pod名 -c 初期化コンテナ名` で原因を確かめます。メインのコンテナは、初期化コンテナが全部終わるまで起動しません。

### 問17 `K8s-2.0-017`

**正解**: D

メモリの limits を超えると、コンテナは OOMKilled で強制終了されます(終了コード 137)。速度が制限されるだけなのは CPU の limits の場合です。limits は自動では変わりません。

### 問18 `K8s-2.0-018`

**正解**: A

`Insufficient cpu` は、Pod の CPU の requests を満たす空きのあるノードがないことを表します。スケジューラーは使用量ではなく、各ノードの requests の合計で空きを計算します。requests を下げる、ほかの Pod を減らす、ノードを増やすなどで解決します。イメージの誤りなら ImagePullBackOff になります。

### 問19 `K8s-2.0-019`

**正解**: C

taint のあるノードには、その taint に合う toleration を持つ Pod しか置かれません(effect が NoSchedule)。nodeSelector はノードを選ぶ仕組みで、taint を許可するものではないので、toleration がないと置けません。

### 問20 `K8s-2.0-020`

**正解**: C

toleration は「taint があっても置いてよい」という許可だけで、そのノードに引き寄せはしません。ほかのノードに空きがあれば、そちらに置かれることもあります。特定のノードに置くには、nodeSelector や nodeAffinity も組み合わせます。taint は消えません。

### 問21 `K8s-2.0-021`

**正解**: A

`nodeSelector` に `disktype: ssd` を書くと、そのラベルを持つノードにだけ置かれます。より細かい条件(否定、複数の値、できれば、など)が必要なら nodeAffinity を使います。`nodeName` はノードの名前を直接指定するもので、ラベルではありません。

### 問22 `K8s-2.0-022`

**正解**: D

ResourceQuota は、Namespace 全体で使える CPU、メモリ、Pod の数などの合計に上限を決めます。LimitRange は、1 つのコンテナや Pod の既定値と最小・最大を決めるもので、合計の上限ではありません。

### 問23 `K8s-2.0-023`

**正解**: D

すべてのコンテナで、CPU とメモリの requests と limits が同じ値なら Guaranteed です。一部だけ設定されていれば Burstable、何も設定されていなければ BestEffort です。Guaranteed は、ノードのメモリが足りなくなったときに最後まで追い出されません。

### 問24 `K8s-2.0-024`

**正解**: D、E

HPA の CPU の使用率は、metrics-server から取った使用量を、Pod の CPU の requests で割って計算します。metrics-server がない、または requests が設定されていないと計算できず、`<unknown>` と表示されます。replicas や Service の種類は関係ありません。

### 問25 `K8s-2.0-025`

**正解**: C

希望の数は ceil(今の数 × 今の使用率 ÷ 目標の使用率)で計算します。
① 4 × 90 ÷ 60 = 6
② 切り上げても 6 です。
③ そのため 6 個を目指します。

5 は 1 個だけ足した場合、8 は 2 倍にした場合で、式とは合いません。

### 問26 `K8s-2.0-026`

**正解**: C

Cluster Autoscaler や Karpenter は、資源が足りずに Pending になった Pod があると、ノードを追加します。使われなくなったノードは減らします。HPA は Pod の数、VPA は Pod の requests を変えるもので、ノードは増やしません。
