## 解答・解説

### 問1 `K8s-1.0-001`

**正解**: B

kube-scheduler は、ノードが決まっていない Pod を見つけ、資源の空きや条件からノードを選んで割り当てます。実際に起動するのは、そのノードの kubelet です。API サーバーは入口、コントローラーマネージャーは Deployment などのコントローラーを動かします。

### 問2 `K8s-1.0-002`

**正解**: A

etcd は、クラスタのすべての状態を保存するキーバリューストアです。etcd を失うとクラスタの定義を失うので、バックアップが重要です。kube-proxy は Service の振り分け、CoreDNS は DNS、kubelet は Pod の起動です。

### 問3 `K8s-1.0-003`

**正解**: B

kubelet は各ノードで動くエージェントで、自分のノードに割り当てられた Pod を、CRI を通してコンテナランタイムで起動し、状態を報告します。kube-proxy は Service のための通信のルールを作る部品です。

### 問4 `K8s-1.0-004`

**正解**: A

Kubernetes の部品は、すべて kube-apiserver を通して情報をやり取りします。etcd に読み書きするのも API サーバーだけです。スケジューラーは API サーバーに割り当てを書き、kubelet はそれを API サーバーから受け取ります。

### 問5 `K8s-1.0-005`

**正解**: D

kubeadm のクラスタでは、kube-apiserver は静的 Pod で、`/etc/kubernetes/manifests/kube-apiserver.yaml` の YAML から kubelet が起動しています。このファイルを編集すると、kubelet が自動で作り直します。kube-apiserver は Deployment ではないので、`kubectl edit deployment` では変えられません。

### 問6 `K8s-1.0-006`

**正解**: C

静的 Pod は kubelet が `/etc/kubernetes/manifests/` の YAML から直接管理しています。`kubectl` で見えるのはミラー Pod で、削除しても kubelet が作り直します。静的 Pod を本当に止めるには、YAML をそのディレクトリから移します。

### 問7 `K8s-1.0-007`

**正解**: C

`--dry-run=client` はクラスタに作らずに、`-o yaml` で YAML を出力します。試験で YAML を一から書く時間を減らせます。`kubectl get … -o yaml` はすでにあるリソースの出力、`kubectl apply` に `deployment` という使い方はありません。

### 問8 `K8s-1.0-008`

**正解**: B

`kubectl explain` は、リソースのフィールドの説明と型を表示します。`pod.spec.containers` のようにドットでたどれます(`--recursive` で下の階層も)。`describe` は動いているリソースの状態を表示するコマンドです。

### 問9 `K8s-1.0-009`

**正解**: A

`kubectl config use-context` は、kubeconfig の中のコンテキスト(クラスタ、ユーザー、Namespace の組み合わせ)を切り替えます。試験は複数のクラスタで行われるので、切り替えを忘れると別のクラスタで作業してしまい、点になりません。

### 問10 `K8s-1.0-010`

**正解**: B

`kubectl config set-context --current --namespace=web` で、今のコンテキストの既定の Namespace を変えます。`use-context` はコンテキストの切り替えで、Namespace の名前を渡すものではありません。

### 問11 `K8s-1.0-011`

**正解**: A

1 つの Namespace の中だけの権限は、その Namespace の Role で権限を決め、同じ Namespace の RoleBinding でユーザーに結び付けます。ClusterRole と ClusterRoleBinding だと、全 Namespace に権限を与えてしまいます。ServiceAccount は Pod のための ID で、ユーザー `alice` には使いません。

### 問12 `K8s-1.0-012`

**正解**: C

RoleBinding に ClusterRole を結び付けると、その ClusterRole の権限を、RoleBinding の Namespace の中だけで与えます。
① ClusterRole `secret-reader` は、Secret の get と list の権限です。
② それを `team-a` の RoleBinding で `alice` に結び付けています。
③ そのため、`alice` は `team-a` の Secret だけを読めます。

全 Namespace に効くのは ClusterRoleBinding の場合です。作成や削除の動詞は与えていません。

### 問13 `K8s-1.0-013`

**正解**: A

`kubectl auth can-i 動詞 リソース -n Namespace --as ユーザー` で、その権限があるかを yes / no で確かめます。ServiceAccount は `system:serviceaccount:<Namespace>:<名前>` の形で指定します。

### 問14 `K8s-1.0-014`

**正解**: C

RBAC は許可だけを足していく仕組みで、拒否のルールはありません。どのルールでも許可されていない操作は拒否されます。Role はその Namespace の中だけで、ClusterRoleBinding はクラスタ全体に効きます。

### 問15 `K8s-1.0-015`

**正解**: D

`automountServiceAccountToken: false` を Pod(または ServiceAccount)に書くと、トークンが Pod にマウントされません。API を使わない Pod では、トークンを盗まれる危険を減らせます。

### 問16 `K8s-1.0-016`

**正解**: C

CNI プラグイン(Calico、Cilium、Flannel など)を入れるまで、Pod のネットワークが準備できないので、ノードは NotReady、CoreDNS は Pending のままです。`kubeadm init` の後に CNI のマニフェストを適用します。

### 問17 `K8s-1.0-017`

**正解**: B

`kubeadm token create --print-join-command` で、新しいトークンを作り、そのまま使える `kubeadm join` のコマンドを表示します。トークンの有効期限は既定で 24 時間です。`kubeadm reset` はノードの初期化を元に戻すコマンドです。

### 問18 `K8s-1.0-018`

**正解**: A

アップグレードは、まず kubeadm を新しいバージョンに上げ、`kubeadm upgrade plan` で確認してから、`kubeadm upgrade apply` でコントロールプレーンの部品を上げます。その後、ノードを drain して kubelet と kubectl を上げ、kubelet を再起動して uncordon します。

kubelet を先に上げると、API サーバーより新しくなってしまいます。`kubeadm upgrade node` は 2 台目以降のコントロールプレーンとワーカーで使います。マイナーバージョンは 1 つずつ上げます。

### 問19 `K8s-1.0-019`

**正解**: D

`kubectl drain` は、ノードを cordon(新しい Pod を置かない)にしたうえで、Pod を退避させます。DaemonSet の Pod は退避できないので、`--ignore-daemonsets` を付けます。`cordon` だけでは既存の Pod は残り、`delete node` はノードをクラスタから外してしまいます。

### 問20 `K8s-1.0-020`

**正解**: A、B

etcd は TLS で守られているので、`--endpoints` に加えて、`--cacert`、`--cert`、`--key` の 3 つが必要です。値は `/etc/kubernetes/manifests/etcd.yaml` の起動の引数で確かめられます。スケジューラーの設定、Pod の CIDR、Helm は関係ありません。

### 問21 `K8s-1.0-021`

**正解**: D

復元したデータは新しいディレクトリにあるので、etcd の静的 Pod の YAML(`/etc/kubernetes/manifests/etcd.yaml`)で、データのディレクトリ(`hostPath` の path や `--data-dir`)を新しい場所に変えます。保存すると kubelet が etcd を作り直し、復元したデータで動きます。

### 問22 `K8s-1.0-022`

**正解**: A

etcd は過半数(クォーラム)が動いていないと書き込めないので、台数は奇数にします。3 台なら 1 台の故障に耐えられます。2 台は 1 台壊れると過半数を割り、1 台の構成と耐障害性が変わりません。4 台も 1 台の故障にしか耐えられず、3 台と同じです。

### 問23 `K8s-1.0-023`

**正解**: C

`helm template` は、チャートに値を当てはめたマニフェストを、クラスタに入れずに表示します。`--dry-run=server` を付けた `install` も入れずに確かめられますが、クラスタへの接続が必要です。`list` はリリースの一覧、`rollback` は前の版に戻すコマンドです。

### 問24 `K8s-1.0-024`

**正解**: D

`helm rollback リリース リビジョン` で、指定したリビジョンの設定に戻します。戻した結果も新しいリビジョンとして記録されます。`uninstall` は削除で、`kubectl rollout undo` は Deployment のロールバックです。

### 問25 `K8s-1.0-025`

**正解**: B

`kubectl apply -k ディレクトリ` で、kustomization.yaml のあるディレクトリを Kustomize で組み立てて適用します。`-f kustomization.yaml` だと、Kustomize の設定ファイル自体をリソースとして適用しようとして失敗します。結果を見るだけなら `kubectl kustomize ディレクトリ` です。

### 問26 `K8s-1.0-026`

**正解**: A

CRI(Container Runtime Interface)はコンテナランタイム、CNI(Container Network Interface)はネットワーク、CSI(Container Storage Interface)はストレージのためのインターフェースです。名前の真ん中の語(Runtime、Network、Storage)で覚えます。

### 問27 `K8s-1.0-027`

**正解**: A

マネージドの Kubernetes では、コントロールプレーン(etcd、証明書、API サーバーの可用性)の運用はクラウドが行います。ただし、Kubernetes のバージョンにはサポートの期間があるので、アップグレードは利用者が計画して実行します(ノードやアドオンも含めて)。静的 Pod の YAML は利用者からは見えません。
