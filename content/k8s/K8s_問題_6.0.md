## 解答・解説

### 問1 `K8s-6.0-001`

**正解**: A

カナリアリリースは、新しい版を一部の通信にだけ出し、メトリクスを見て問題がなければ割合を増やす戦略です。問題があっても影響は一部に限られます。Argo Rollouts や Flagger で、割合の変更と判断を自動化できます。

- B. ロールバックは、前の版に戻す操作で、新しい版を出す戦略ではありません。
- C. Recreate は、古い Pod をすべて止めてから新しい Pod を作る戦略で、一時的にすべてが止まり、段階的には出せません。
- D. ブルーグリーンデプロイは、新しい環境を丸ごと用意して、通信を一度に切り替える戦略です。一部の利用者だけに出すものではありません。

### 問2 `K8s-6.0-002`

**正解**: B

ブルーグリーンは、2 つの環境を並べて一度に切り替えるので、切り替えの間は 2 つ分の資源が必要です。その代わり、戻すときは通信を元に戻すだけなので速く、停止の時間もほぼありません。

### 問3 `K8s-6.0-003`

**正解**: B

GitOps は、Git に書いた望ましい状態を正とし、クラスタの中のエージェントが Git を見て、クラスタの状態を合わせ続ける方法です。変更は Git のプルリクエストで行うので、レビューと履歴が残り、Git を戻せばロールバックになります。CI に本番の強い権限を渡さずに済みます。

### 問4 `K8s-6.0-004`

**正解**: A

Argo CD は Git とクラスタの状態を比べ、違いを OutOfSync(ドリフト)として表示します。self-heal が有効なら、クラスタを Git の内容に自動で戻します。手で変えた内容は残らないので、変更は Git で行います。HPA が replicas を変える場合は、replicas を Git の管理から外す設定にします。

### 問5 `K8s-6.0-005`

**正解**: C、E

External Secrets Operator は、外部の保管庫の値から Kubernetes の Secret を作るので、Git には参照だけを書きます。Sealed Secrets や SOPS は、値を暗号化して Git に置き、クラスタの中で復号します。Base64 は暗号化ではないので、Git に置くと値が漏れます。

### 問6 `K8s-6.0-006`

**正解**: A

kube-prometheus-stack は、Prometheus Operator、Prometheus、Alertmanager、Grafana、node-exporter、kube-state-metrics などを、まとめて入れる Helm のチャートです。metrics-server は HPA と `kubectl top` のための部品で、監視の基盤ではありません。

### 問7 `K8s-6.0-007`

**正解**: D

metrics-server は、各ノードの kubelet から今の CPU とメモリの使用量だけを集め、HPA や `kubectl top` に提供します。履歴は持ちません。Prometheus は、多くのメトリクスを時系列で保存し、PromQL での検索やアラートに使います。

### 問8 `K8s-6.0-008`

**正解**: C

SLI(Service Level Indicator)は、成功率や遅延のような、信頼性を計る指標です。SLO(Service Level Objective)は、その指標の目標(99.9% など)です。SLA は利用者との契約で、守れなかったときの返金などを決めます。

### 問9 `K8s-6.0-009`

**正解**: A

担当者を呼び出すアラートは、利用者に影響が出ている(または出そうな)症状に絞ります。SLO のエラーバジェットの消費の速さ(バーンレート)でのアラートが代表的です。原因の候補の細かいメトリクスはダッシュボードで調べます。アラートが多すぎると、本当に重要なものを見逃します。

### 問10 `K8s-6.0-010`

**正解**: A

分散トレーシングは、1 つのリクエストが通ったサービスと、それぞれにかかった時間を記録します。OpenTelemetry でアプリを計測し、Jaeger や Grafana Tempo で見ます。メトリクスやログだけでは、サービスをまたぐ遅延の場所を特定しにくいです。

- B. `kubectl top` は Pod の CPU とメモリの使用量で、リクエストがどこで遅くなったかは分かりません。
- C. ResourceQuota は、Namespace の資源の合計に上限を付けるものです。
- D. etcd のスナップショットは、クラスタのバックアップです。

### 問11 `K8s-6.0-011`

**正解**: C

PDB は、drain のような計画的な中断(eviction)のときに、残す Pod の数を守ります。
① replicas は 3、minAvailable は 2 です。
② 1 個を追い出すと残りは 2 個で、これ以上は追い出せません。
③ 追い出した Pod がほかのノードで Ready になってから、次の 1 個を追い出せます。

ノードの故障のような計画外の中断は防げません。

### 問12 `K8s-6.0-012`

**正解**: B

minAvailable が replicas と同じだと、1 個も追い出せないので、drain が止まったままになります。マネージドのクラスタのノードのアップグレードも進まなくなります。`maxUnavailable: 1` のように、少なくとも 1 個は中断できる設定にします。

- A. 設定は通りますが、drain やアップグレードのときに問題になります。
- C. PDB は Pod の数を増やしません。数を決めるのは Deployment の replicas です。
- D. PDB は Pod を削除しません。自主的な追い出しを制限するだけです。

### 問13 `K8s-6.0-013`

**正解**: B

`topologySpreadConstraints` で、`topologyKey`(ゾーンやノードのラベル)ごとに Pod の数の差(maxSkew)を制限し、均等に分けて置きます。1 つのゾーンの障害で、すべての Pod が止まるのを防げます。

### 問14 `K8s-6.0-014`

**正解**: B、C

Pod の削除と、エンドポイントからの除外は同時に進むので、終了を始めた Pod に、しばらく通信が届くことがあります。`preStop` で数秒待ってから終了処理を始め、アプリは SIGTERM で新しい受け付けをやめ、処理中のリクエストを終えてから終了します。猶予を 0 にすると、処理中のリクエストが切られます。

### 問15 `K8s-6.0-015`

**正解**: C

requests はスケジューリングの基準なので、実際の使用量に近い値にします。大きすぎるとノードが無駄になり、小さすぎるとノードに詰め込みすぎて性能が落ちたり、追い出されたりします。Prometheus の履歴や VPA の推奨値を参考に、定期的に見直します。

### 問16 `K8s-6.0-016`

**正解**: D

CPU の limits は、短い期間(既定で 100 ミリ秒)ごとの使用量の上限で、超えると残りの時間は待たされます(スロットリング)。平均の使用率が低くても、一瞬の負荷で遅延が大きくなることがあります。そのため、CPU の limits を付けないか、余裕を持たせる運用もあります。メモリの limits を超えた場合が OOMKilled です。

### 問17 `K8s-6.0-017`

**正解**: B

Pod Security Admission は、Namespace のラベルで、Pod Security Standards(privileged、baseline、restricted)を適用します。`enforce` は違反した Pod を拒否し、`warn` と `audit` は警告と記録だけです。PodSecurityPolicy は v1.25 で削除されました。

### 問18 `K8s-6.0-018`

**正解**: A、C

restricted では、root 以外で動かす(`runAsNonRoot: true`)、権限の昇格を禁止する(`allowPrivilegeEscalation: false`)、Linux の capabilities をすべて外す(`drop: [ALL]`)、seccompProfile を RuntimeDefault にする、などが求められます。privileged や hostNetwork、root での実行は禁止です。

### 問19 `K8s-6.0-019`

**正解**: B

EKS Pod Identity や IRSA は、ServiceAccount に IAM ロールを結び付け、Pod に一時的な認証情報を渡します。長期間のアクセスキーを Secret やイメージに置く必要がありません。ノードの IAM ロールに強い権限を付けると、そのノードのすべての Pod がその権限を使えてしまいます。

### 問20 `K8s-6.0-020`

**正解**: C

マネージドの Kubernetes の各バージョンにはサポートの期間があります。EKS では、標準のサポートが終わると延長サポートの追加料金がかかり、その後は自動でアップグレードされます。アップグレードの前には、削除される API を使っていないかを確かめ(pluto など)、マイナーバージョンを 1 つずつ上げます。

### 問21 `K8s-6.0-021`

**正解**: A、E

requests を実際の使用量に合わせると、同じノードにより多くの Pod を置けて、ノードの数を減らせます。中断に強いワークロード(バッチ、ステートレスで複数の Pod があるもの)には、安いスポットのインスタンスを使えます。使わない時間の開発のクラスタは、ノードを減らしたり止めたりします。

### 問22 `K8s-6.0-022`

**正解**: D

Kubecost や OpenCost は、Pod の requests や使用量とノードの料金から、Namespace、ラベル、チームごとのコストを按分して表示します。チームにコストを見せると、requests の見直しが進みます。

- A. kubeadm はクラスタを作り、管理するコマンドで、コストは見えません。
- B. CoreDNS はクラスタの中の DNS のサーバーです。
- C. etcdctl は etcd のデータを操作するコマンドです。
