# sre-drill

資格試験(LinuC 101、LinuC 102、CCNA、AWS SAA、AWS DevOps Engineer – Professional、Terraform Associate、CKA)と SRE の基礎知識(Docker、Kubernetes など)を身につけるための学習アプリです。ブラウザだけで動く静的な SPA で、サーバーは必要ありません。解答の履歴は、使っているブラウザの中に保存されます。

AI に作業させるときのルールは [CLAUDE.md](CLAUDE.md) にあります。

## 機能

- 画面: 上の帯で試験を切り替え、目次・問題演習・計算ドリル・テキスト・成績を開きます。スマホでは、この 5 つのタブが画面の下に並びます。分野ごとの学習の状態は 4 色のランプ(未着手、学習中、要復習あり、定着)で表示します

- 目次: 試験(LinuC 101、LinuC 102、CCNA、AWS SAA、AWS DOP、Terraform、Docker、K8s、すべて)を選び、問題演習・計算ドリル・テキスト・成績を開きます。起動したときは目次から始まります。選んだ試験は次回も引き継がれ、目次で「選択中」と表示されます。画面を移ると履歴に残るので、左上の「戻る」やブラウザの戻る(スマホのスワイプ)で前の画面に戻れます
- ロードマップ: SRE を目指す学習の段階(Linux → ネットワーク → クラウド → コンテナと IaC → Kubernetes と監視 → SRE の実践)と、段階ごとのチェックリスト、資格、おすすめの本を表示します。チェックはブラウザに保存されます。アプリで学べる試験は、進み具合と問題演習へのボタンも表示します
- 資格の表紙: ロードマップに載せた資格ごとに、試験の概要、出題範囲と割合、勉強の進め方、公式サイトをまとめたページです。ロードマップの資格名から開き、表紙からロードマップの段階に戻れます。アプリで学べる試験は、問題演習・テキスト・計算ドリル・成績へのボタンと進み具合も表示します
- 問題演習: 4 択と複数選択。出題範囲は分野ごとに選べます
- 間隔反復: 間違えた問題は 10 分後、正解した問題は 1 日後 → 3 日後 → だんだん間を空けて、もう一度出題します(SM-2 の簡略版)
- 入力問題: 選択肢を見ずに、コマンド名やファイル名を入力して答えます。「入力で解く」では、答えが1語になる選択問題も入力で出題します
- 間違えた問題の演習: 最後に間違えた問題と、2 回以上解いて正答率が 70% 未満の問題を出題します。成績画面の小項目ごとの「解く」からも始められます
- 選択肢の並べ替え: 出題のたびに選択肢の順番を入れ替えます。答えの位置で覚えてしまうのを防ぎます
- 模擬試験: 1 問 90 秒の制限時間で解きます。提出するとまとめて採点し、解説を表示します
- 用語集: 全試験の重要な用語 450 語余りを、分類と小分類の索引、検索、試験での絞り込みで引けます。一覧は 1 行の要約で、押すと詳しい説明、例、注意が開きます。テキストと解説の中の用語には点線が付き、押すと説明が出ます(用語ごとに最初の 1 回だけ)
- 計算ドリル: パーミッション(8 進と記号、chmod 記号モード、umask)、cron の次の実行日時、IPv4 サブネット、IPv6 省略表記、EUI-64、VPC のサブネットで使える IP 数(AWS は5個を予約)。問題は毎回新しく作られます
- テキスト: 試験の範囲を解説したテキストを読めます。問題に答えた後は、その問題に対応する節をその場で開けます。テキストの最後から、その章の問題を解くか、「前のページ | 次のページ」で前後のテキストに移れます
- 成績: 分野と小項目ごとに、解いた数、正答率、復習待ちの数を表示します
- 履歴のエクスポートとインポート(JSON)ができます

## 必要なもの

- Node.js 22.12 以上(https://nodejs.org/ の LTS 版を推奨)。今のバージョンはターミナルで `node -v` を実行すると分かります。古いと起動できません
- Git

## 使い方

```
npm install
npm run dev
```

表示された URL(既定は http://localhost:5173/)をブラウザで開いてください。

Windows では、`start.bat` をダブルクリックしても起動できます。必要なパッケージの確認、開発サーバーの起動、ブラウザを開くところまでを自動で行います。終わるときは、画面右上の「終了」を押してください。開発サーバーが止まり、黒いウィンドウも閉じます。ブラウザのタブは、Ctrl+W(Mac は ⌘W)で閉じます(ブラウザは、スクリプトで開いていないタブを、履歴が 2 件以上あると閉じさせないため)。「終了」は、開発サーバーで動かしているときだけ表示されます。

macOS では、`start.command` をダブルクリックすると起動できます。動きは `start.bat` と同じで、「終了」を押すとターミナルのウィンドウも閉じます。初回だけ、「“ターミナル”から“ターミナル”を制御しようとしています」という確認が出るので、「OK」を押してください。断ったときや、それでもウィンドウが残るときは、ターミナルの「設定」→「プロファイル」→「シェル」の「シェルの終了時」を「シェルが正常に終了した場合は閉じる」にすると、確実に閉じます。

- `git clone` で取得すると、そのままダブルクリックで動きます。
- ZIP をダウンロードして展開した場合は、初回に「開発元を確認できない」などの警告が出ることがあります。Finder で `start.command` を右クリックして「開く」を選んでください。それでも開けないときは、「システム設定」→「プライバシーとセキュリティ」の下に出る「このまま開く」を押してください。この許可は最初の 1 回だけです。ターミナルでこのフォルダに移動して `xattr -d com.apple.quarantine start.command` を実行しても、警告を出さないようにできます。
- 「実行する権限がない」と出たときは、ターミナルでこのフォルダに移動して `chmod +x start.command` を実行してください。

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー |
| `npm test` | 単体テスト |
| `npm run lint` | ESLint |
| `npm run build` | 型検査と本番ビルド(`dist/`) |
| `npm run gen` | `content/` から `src/data/questions.json` を生成 |

`dev`、`test`、`build` は、実行する前に `gen` を自動で呼びます。

## 問題の追加

`content/<試験>/` に Markdown のファイルを置きます。書式は次のとおりです。合わないところがあると `npm run gen` が失敗し、ファイル名と問番号を表示します。

````
# CCNA 問題 1.0 分野名

対象: 全2問

## 問題

### 1.1 小項目

**問1** `CCNA-1.0-001` 問題文。コードブロックと表が使える。

```
show interfaces の出力など
```

- A. 選択肢
- B. 選択肢
- C. 選択肢
- D. 選択肢

**問2** `CCNA-1.0-002` 正しいものを**2つ**選べ。

- A. 選択肢
- B. 選択肢
- C. 選択肢

## 解答・解説

### 問1 `CCNA-1.0-001`

**正解**: B

解説。

### 問2 `CCNA-1.0-002`

**正解**: A、C

解説。
````

- YAML の穴埋めは入力問題として書きます。問題文の YAML の空欄を `____` にし、先頭に「【YAML の穴埋め】」と書きます
- 入力問題は選択肢を書かず、`**正解**:` の後ろに答えをコードの形で書きます。正解が複数あれば「`atq`、`at -l`」のように並べます
- 入力でも出題される選択問題で、正解と同じ意味の別の書き方(長い形のオプションなど)があれば、正解の行の次に「**入力の別解**: `--create-home`」のように書きます
- 解説で選択肢ごとに誤りの理由を書くときは、「- A. …」の形で 1 行ずつ書きます。選択肢を並べ替えて出題すると、この記号も表示に合わせて付け替わります。文の中で「A は」のように記号で選択肢を指すのは避けます
- 問題文で他の問題を参照しない(「問3」「前の問題」など)。出題の順番は入れ替わるため、必要な設定や状況は問題文に書きます
- タイトル行の最初の語が試験名、次が分野番号になります
- 問番号の後ろに、問題 ID を `<試験名>-<分野番号>-<問番号 3 桁>` の形で書きます(例: `LinuC102-1.06-019`)。問題番号と合わないと `npm run gen` が失敗します。問題 ID は画面に表示され、「問題演習」の「問題 ID で 1 問だけ開く」からその問題だけを解けます
- 問題 ID の後ろに `[CKA]` や `[実務]` のタグを書けます(Kubernetes の問題で、試験の範囲か実務の知識かを見分けるため)。画面では問題 ID の横に表示されます。使えるタグは `src/lib/parser.ts` の `TAGS` にあるものだけです
- 履歴のキーは `<試験名(小文字)>-<分野番号>-q<問番号>` です
- 公開した後に問番号を振り直すと、その問題の履歴が別の問題に付いてしまいます
- 選択肢は出題のたびに並べ替えられます(設定で止められます)。そのため解説では選択肢の記号(「A は…」)を使わず、内容で書きます。テストで検査しています
- 解答は問題ごとに `### 問N 問題ID` の見出しを立て、`**正解**:` の行と解説を書きます。解説は次の見出しまで続き、改行も段落もそのまま画面に表示されます(Obsidian と同じ表示)。出力を読む問題や計算する問題は、手順を ①② … と 1 行ずつ書き、誤りの選択肢の説明は空行を入れて別の段落にします
- 解説は、エンジニアになって1年以内の人にも分かるように、です・ます調で書きます。正解の理由だけでなく、ほかの選択肢がなぜ違うのかも書きます

## テキストの追加

`texts/<試験>/<試験名>_<番号>_<題名>.md` の名前で置きます。例: `texts/ccna/CCNA_1.0_ネットワークインフラストラクチャと接続.md`。

- 目次は `## ` の見出しから作られます
- 問題との対応は、試験名と番号(問題側の分野番号)、それに節番号で決まります。問題の小項目が `1.1 …` なら、テキストの `## 1.1 …` の節を開きます

## 用語集の追加

`glossary/` に Markdown で書きます。ファイルごとに `# 用語集 <分類>` を付け、`## 小分類` の下に、用語ごとに次の形で書きます。`npm run gen` で `src/data/glossary.json` になります。

```
## モデルとプロトコル

### TCP
別名: Transmission Control Protocol
試験: LinuC102、CCNA
要約: 一覧に出す 1 文(です・ます。。で終える)
詳しい説明(です・ます。1〜3 文)
例: `ss -tan`(1 行に 1 つ。何行でも)
注意: 試験や実務で間違えやすい点(1 文)
関連: UDP、ポート番号
```

- 要約、例、注意はすべての用語に書きます(テストで確かめます)

- 別名、試験、関連は省略できます。試験を書くと、その試験のテキストと解説でだけ印が付きます。書かなければ、すべての試験で付きます
- 名前と別名は、用語集全体で重複させません。関連には用語集にある名前だけを書きます
- 一般的すぎる語(「ポート」「ロール」など)は別名にしません。別の意味の箇所にも印が付くためです

## 構成

```
content/            問題の正本(Markdown)
texts/              テキスト(Markdown)
glossary/           用語集(Markdown)
scripts/            Markdown → JSON の変換
src/lib/parser.ts   問題 Markdown の解析
src/lib/srs.ts      間隔反復と出題順
src/lib/weak.ts     間違えた問題の抽出
src/lib/shuffle.ts  選択肢の並べ替え
src/lib/input.ts    入力問題の判定、選択問題の入力化
src/lib/stats.ts    成績の集計
src/lib/texts.ts    テキストの一覧と節の切り出し
src/lib/glossary.ts 用語集の解析と、本文の用語の検出
src/lib/roadmap.ts  ロードマップの内容
src/lib/certs.ts    資格の表紙の内容
src/lib/order.ts    試験の表示順(LinuC → CCNA → AWS SAA → AWS DOP → Terraform → Docker → K8s)
src/lib/drills/     計算ドリルの生成と採点
src/lib/db.ts       IndexedDB(解答履歴、カード、ドリル履歴)
src/components/     画面
```

## データの保存先

履歴はブラウザの IndexedDB にだけ保存されます。ブラウザのサイトデータを消すと、履歴も消えます。別の PC やブラウザに移すときは、成績画面のエクスポートとインポートを使ってください。

## CI

`.github/workflows/ci.yml` が、push と pull request のたびに lint、テスト、ビルドを実行します。
