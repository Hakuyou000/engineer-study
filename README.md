# engineer-study — ITエンジニアのための勉強アプリ

IT の資格試験の勉強と、仕事で使う基礎の知識を、ブラウザだけで学べるアプリです。問題を解き、テキストを読み、間違えたところを繰り返して、知識を定着させます。

- 自分のパソコンの中だけで動きます。サーバーの用意やアカウントの登録は要りません
- 解いた記録は、使っているブラウザの中にだけ保存されます。外には送りません
- 問題とテキストはすべてオリジナルです。実際の試験の問題を写したものではありません

## こんな人に向いています

- IT の仕事に就いたばかりの人、これから就きたい人
- ITパスポート試験や基本情報技術者試験から始めて、Linux、ネットワーク、クラウドの資格に進みたい人
- 資格の勉強だけでなく、Docker や Kubernetes など現場で使う技術も身につけたい人

用語には短い説明が付いているので、エンジニアになって 1 年以内の人でも読み進められます。

## 学べる資格と分野

| 分野 | 学べるもの |
|---|---|
| IT の基礎 | ITパスポート試験、基本情報技術者試験 |
| Linux | LinuC レベル1(101、102)、LinuC レベル2(201、202)、LinuC レベル3(3PS、3SS) |
| ネットワーク | CCNA |
| クラウド(AWS) | AWS Certified Solutions Architect – Associate(SAA)、AWS Certified DevOps Engineer – Professional(DOP) |
| インフラのコード化 | HashiCorp Certified: Terraform Associate |
| コンテナ | Docker(資格ではなく実務の基礎)、Kubernetes(CKA と実務) |

全部で 3,200 問余りの問題、試験の範囲を解説したテキスト、2,300 語余りの用語集(12 の分類)があります。

## できること

- **問題演習**: 4 択、複数選択、コマンド名などを打ち込む入力問題があります。分野を選んで解けます。答えた後は、解説と、テキストの該当する節をその場で読めます
- **復習の自動化**: 間違えた問題は 10 分後に、正解した問題は 1 日後、3 日後と間を空けて、もう一度出ます(間隔反復)。忘れかけたころに出るので、覚えたことが長く残ります
- **苦手の演習**: 最後に間違えた問題や、正答率の低い問題だけを集めて解けます
- **模擬試験**: 1 問 90 秒の制限時間で、本番のように通して解きます
- **テキスト**: 試験の範囲を章ごとに解説しています。最後から、その章の問題に進めます
- **用語集**: 分類、検索、試験で絞り込んで引けます。テキストや解説の中の用語は、押すと説明が出ます
- **計算ドリル**: パーミッション、cron、IPv4 のサブネット、IPv6 の省略表記などの計算を、毎回新しい問題で練習できます
- **成績**: 分野ごとの正答率と、復習が必要な問題の数を見られます。学習の状態は、分野ごとに 4 色のランプで分かります
- **ロードマップ**: インフラの仕事から SRE(サービスの信頼性を守るエンジニア)を目指す人向けに、学ぶ順番と資格、おすすめの本をまとめています。資格ごとの概要と公式サイトも見られます
- スマホでも使えます。タブは画面の下に並びます

## はじめかた

パソコンで動かします。必要なのは Node.js だけです。

1. Node.js 22.12 以上を入れます(https://nodejs.org/ の LTS 版がおすすめです)。入っている版は、ターミナルで `node -v` を実行すると分かります
2. このリポジトリの GitHub のページで、緑の「Code」ボタン →「Download ZIP」を押してダウンロードし、好きな場所に展開します

Git を使える人は、ZIP の代わりに `git clone` で取得してもかまいません。新しい問題が増えたときに、`git pull` だけで最新にできます。ZIP の場合は、もう一度ダウンロードして展開し直します(解いた記録はブラウザの中にあるので、同じブラウザで同じ URL を開けば続きから使えます)。

### Windows

1. 展開したフォルダの中の `start.bat` をダブルクリックします
2. 必要なものが自動で入り、ブラウザでアプリが開きます

終わるときは、画面右上の「終了」を押してください。黒いウィンドウも閉じます。ブラウザのタブは Ctrl+W で閉じます。

### macOS

1. 展開したフォルダの中の `start.command` をダブルクリックします
2. 必要なものが自動で入り、ブラウザでアプリが開きます

終わるときは、画面右上の「終了」を押してください。ターミナルのウィンドウも閉じます。

- 初回だけ、「“ターミナル”から“ターミナル”を制御しようとしています」という確認が出ます。「OK」を押してください。断ったときや、それでもウィンドウが残るときは、ターミナルの「設定」→「プロファイル」→「シェル」の「シェルの終了時」を「シェルが正常に終了した場合は閉じる」にしてください

### セキュリティの設定で起動できないとき

インターネットから取ってきたファイルは、OS が「信頼できるか分からないもの」として扱います。そのため、初めて `start.bat` や `start.command` を開くと、止められることがあります。中身は、Node.js の確認、`npm ci`(`package-lock.json` に書かれた版の依存パッケージを入れる。入れ直しが要らないときは飛ばす)、`npm run dev` を順に行うだけの短いスクリプトです。気になる人は、テキストエディターで開いて確かめてから実行してください。

#### Windows

- **「Windows によって PC が保護されました」と青い画面が出る**(Microsoft Defender SmartScreen): 「詳細情報」を押し、出てきた「実行」を押します
- **「開いているファイル - セキュリティの警告」「発行元を確認できませんでした」と出る**: 「実行」を押します。毎回出るときは、この画面の「このファイルを開く前に常に警告する」のチェックを外すか、次の方法で印を外します
- **何度も警告が出る**: ZIP に「インターネットから取ってきた」という印が付いたまま展開すると、中のファイルすべてに印が残ります。次のどちらかで印を外します
  - 展開する前に、ZIP のファイルを右クリック →「プロパティ」→「全般」の下の「セキュリティ」の「許可する」にチェックを入れ、「OK」を押します。それから展開し直します
  - 展開したフォルダで PowerShell を開き、`Get-ChildItem -Recurse | Unblock-File` を実行します
- **「Node.js が見つからない」、または「'npm' は、内部コマンドまたは外部コマンド…として認識されていません」と出る**: Node.js が入っていないか、入れた直後で設定が読み込まれていません。Node.js を入れてから、パソコンを再起動してやり直してください
- **会社や学校のパソコンで、管理者が実行を止めている**: 自分では外せません。下の「コマンドで起動する」を試し、それでも動かなければ管理者に相談してください

#### macOS

- **「開発元を確認できない」「悪質なソフトウェアかどうかを Apple で確認できない」などと出て開けない**(Gatekeeper): 一度「完了」で閉じます。「システム設定」→「プライバシーとセキュリティ」を開き、下の方に出る「`start.command` は…ブロックされました」の横の「このまま開く」を押します。もう一度ダブルクリックし、確認が出たら「開く」を押します。この許可は最初の 1 回だけです
  - macOS 14 までは、Finder で `start.command` を右クリック(Control キーを押しながらクリック)して「開く」を選んでも開けます。macOS 15 以降は、この方法では開けないので、上の手順を使ってください
  - ターミナルでこのフォルダに移動して `xattr -d com.apple.quarantine start.command` を実行しても、警告を出さないようにできます
- **「実行する権限がない」「アクセス権がない」と出る**: ターミナルでこのフォルダに移動して、`chmod +x start.command` を実行してください
- **ターミナルが開いてすぐ閉じる、または何も起きない**: 下の「コマンドで起動する」で起動すると、止まった理由が画面に出ます

#### どちらでも起動できないとき

スクリプトを使わず、コマンドで起動できます。手順は次の「コマンドで起動する」にあります。

- フォルダに移動するには、Windows ではエクスプローラーでフォルダを開き、上のアドレスバーに `cmd` と打って Enter を押します。そのフォルダでコマンドプロンプトが開きます
- macOS では、ターミナルに `cd `(後ろに空白)と打ち、Finder からフォルダをターミナルにドラッグして Enter を押します
- Windows の PowerShell で「このシステムではスクリプトの実行が無効になっている」と出たときは、PowerShell ではなくコマンドプロンプトを使ってください

### コマンドで起動する

```
npm ci
npm run dev
```

`npm ci` は、`package-lock.json` に書かれた版だけを入れます。`npm install` と違い、版が勝手に変わりません。2 回目からは、`git pull` などで `package-lock.json` が変わったときだけ実行すれば十分です。

表示された URL(ふつうは http://localhost:5173/)をブラウザで開いてください。終わるときは、画面右上の「終了」を押すか、コマンドの画面で Ctrl+C を押します。

## 使い方の例

1. 「目次」で、勉強する試験を 1 つ選びます。迷ったら「ロードマップ」で順番を確かめます
2. 「テキスト」で章を読み、章の最後から問題に進みます
3. 毎日「問題演習」を開き、復習が来た問題を解きます
4. 「成績」で正答率の低い分野を見つけ、苦手の演習や計算ドリルで補います
5. 仕上げに模擬試験で、時間内に解けるかを確かめます

## 記録の保存と引っ越し

解いた記録は、ブラウザの中(IndexedDB)にだけ保存されます。アプリのフォルダには入らないので、フォルダを入れ替えても、同じブラウザで同じ URL(ふつうは http://localhost:5173/)を開けば続きから使えます。ブラウザのサイトデータを消すと、記録も消えます。

別のパソコンやブラウザに移すときや、控えを取るときは、「成績」の画面のエクスポートとインポート(JSON のファイル)を使ってください。

## 誤りを見つけたら

答えの誤り、別の正解、古くなった情報などを見つけたら、作者に知らせてください。GitHub の Issues で受け付けています(GitHub のアカウントが要ります)。

1. このリポジトリの GitHub のページで「Issues」を開き、「New issue」を押して「教材の誤りの報告」を選びます
2. 題名に、問題 ID と、何がおかしいかを短く書きます。問題 ID は、問題文の上に `CCNA-1.0-012` のような形で出ています
3. 本文に、どこが誤りか、正しいと思う答えと、その根拠(公式の資料の URL など)を書きます。テキストや用語集の誤りなら、ページの題名と節の見出しを書きます

メールアドレスなど、個人の情報は書かないでください。Issues は、リポジトリを見られる人に公開されます。

## 開発者向けの情報

ここから下は、問題やテキストを足したり、アプリを直したりする人のための情報です。AI に作業させるときのルールは [CLAUDE.md](CLAUDE.md) にあります。

アプリは Vite + React + TypeScript で作った静的な SPA で、サーバーは要りません。教材は Markdown が正本で、`npm run gen` が `content/`、`texts/`、`glossary/` から `src/data/*.json` を作ります。

### コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー |
| `npm test` | 単体テスト |
| `npm run lint` | ESLint |
| `npm run build` | 型検査と本番ビルド(`dist/`) |
| `npm run gen` | `content/` から `src/data/questions.json` を生成し、内容を検査する |
| `npm run coverage` | 出題範囲の用語が問題に出てくるかを表示する。`-- --check` で検査、`-- --update` で基準を更新 |
| `npm run triage -- <バックアップ>` | エクスポートした履歴から、正答率の低い問題を一覧にする |
| `npm run metrics` | 改善ループの指標を `docs/指標.md` に記録する |
| `npm run check` | lint、テスト、網羅性の検査、ビルドをまとめて実行する(CI と同じ) |
| `npm run check-chapter -- <問題> <テキスト> [用語の表.json]` | 1 章ぶんの問題とテキストだけを検査する(内容の検査、テキストの節との対応、正解の位置、用語の出現)。教材を章ごとに書くときに使う |

`dev`、`test`、`build`、`coverage`、`triage`、`metrics` は、実行する前に `gen` を自動で呼びます。

### 改善の進め方

欠陥を見つけたら直し、同じ種類が二度と入らないように検査に変えます。手順と記録は [docs/改善ログ.md](docs/改善ログ.md)、指標は [docs/指標.md](docs/指標.md) にあります。

- 内容の検査(`src/lib/contentLint.ts`): `npm run gen` のたびに実行します。ほかの問題を前提にした書き方、並べ替えで崩れる解説の記号、複数選択の数の食い違い、同じ問題文、取り決めた版との違いなどを見つけると、生成が失敗します
- 網羅性の検査(`scripts/coverage/`): 試験ごとの用語の表(`terms/`)と基準(`baseline.json`)を比べ、出てこなくなった用語、問題のない小項目、2 問未満の小項目があると失敗します
- 学習した人からの指摘: GitHub の Issues で受け付けます(「誤りを見つけたら」)。直したら、Issue に直した PR を書いて閉じます
- 正答率の低い問題: `npm run triage -- <バックアップ>` で、何度解いても正答率の低い問題を一覧にします。問題そのものが誤っていることがあります

### 問題の追加

`content/<試験>/` に Markdown のファイルを置きます。書式は次のとおりです。合わないところがあると `npm run gen` が失敗し、ファイル名と問番号を表示します。

````
# CCNA 問題 1.0 分野名

対象: 全2問

## 問題

### 1.1 小項目

**問1** `CCNA-1.0-001` 問題文。コードブロックと表が使える。

```
show interfaces の出力など
```

- A. 選択肢
- B. 選択肢
- C. 選択肢
- D. 選択肢

**問2** `CCNA-1.0-002` 正しいものを**2つ**選べ。

- A. 選択肢
- B. 選択肢
- C. 選択肢

## 解答・解説

### 問1 `CCNA-1.0-001`

**正解**: B

解説。

### 問2 `CCNA-1.0-002`

**正解**: A、C

解説。
````

- YAML の穴埋めは入力問題として書きます。問題文の YAML の空欄を `____` にし、先頭に「【YAML の穴埋め】」と書きます
- 入力問題は選択肢を書かず、`**正解**:` の後ろに答えをコードの形で書きます。正解が複数あれば「`atq`、`at -l`」のように並べます
- 入力でも出題される選択問題で、正解と同じ意味の別の書き方(長い形のオプションなど)があれば、正解の行の次に「**入力の別解**: `--create-home`」のように書きます
- 問題に対応するテキストの小見出し(`###` の見出しの文字そのまま)を、正解(と入力の別解)の行の次に「**テキスト**: 2. 引数(位置パラメータ)」のように書きます。問題画面の「テキストの該当節を読む」で、その小見出しの範囲だけを出します。見出しは問題の小項目と同じ番号の節(`##`)の中にある必要があります(テストで検査します)。対応が決まらなければ書きません(節全体を出します)
- 解説で選択肢ごとに誤りの理由を書くときは、「- A. …」の形で 1 行ずつ書きます。選択肢を並べ替えて出題すると、この記号も表示に合わせて付け替わります。文の中で「A は」のように記号で選択肢を指すのは避けます
- 問題文で他の問題を参照しない(「問3」「前の問題」など)。出題の順番は入れ替わるため、必要な設定や状況は問題文に書きます
- タイトル行の最初の語が試験名、次が分野番号になります
- 問番号の後ろに、問題 ID を `<試験名>-<分野番号>-<問番号 3 桁>` の形で書きます(例: `LinuC102-1.06-019`)。問題番号と合わないと `npm run gen` が失敗します。問題 ID は画面に表示され、「問題演習」の「問題 ID で 1 問だけ開く」からその問題だけを解けます
- 問題 ID の後ろに `[CKA]` や `[実務]` のタグを書けます(Kubernetes の問題で、試験の範囲か実務の知識かを見分けるため)。画面では問題 ID の横に表示されます。使えるタグは `src/lib/parser.ts` の `TAGS` にあるものだけです
- 履歴のキーは `<試験名(小文字)>-<分野番号>-q<問番号>` です
- 公開した後に問番号を振り直すと、その問題の履歴が別の問題に付いてしまいます
- 選択肢は出題のたびに並べ替えられます(設定で止められます)。そのため解説では選択肢の記号(「A は…」)を使わず、内容で書きます。テストで検査しています
- 解答は問題ごとに `### 問N 問題ID` の見出しを立て、`**正解**:` の行と解説を書きます。解説は次の見出しまで続き、改行も段落もそのまま画面に表示されます(Obsidian と同じ表示)。出力を読む問題や計算する問題は、手順を ①② … と 1 行ずつ書き、誤りの選択肢の説明は空行を入れて別の段落にします
- 解説は、エンジニアになって1年以内の人にも分かるように、です・ます調で書きます。正解の理由だけでなく、ほかの選択肢がなぜ違うのかも書きます

### テキストの追加

`texts/<試験>/<試験名>_<番号>_<題名>.md` の名前で置きます。例: `texts/ccna/CCNA_1.0_ネットワークインフラストラクチャと接続.md`。

- 目次は `## ` の見出しから作られます
- 問題との対応は、試験名と番号(問題側の分野番号)、それに節番号で決まります。問題の小項目が `1.1 …` なら、テキストの `## 1.1 …` の節を開きます
- 図は ```` ```text ```` のコードブロックに、文字で描きます。アプリ、Obsidian、claude.ai の Project のどこでも同じに見えるようにするためです(Mermaid はアプリと Project で描画されません)
  - 線と矢印は ASCII(`|`、`+--`、`` `-- ``、`-->`、`v`)で描きます。罫線の文字(`│`、`─`)は、フォントによって幅が 1 文字にも 2 文字にもなり、ずれます
  - 日本語は、行の最後に置きます。日本語の後ろに、桁をそろえる空白や線を置きません。日本語の幅はフォントによって半角 2 文字ぶんにならず、後ろの桁がずれます
  - 右側の枠線(`|` で囲む箱)は描きません
- 文字では形が崩れる図(グラフ、格子、重なる円など)だけ、SVG の画像にします
  - ファイルは `texts/<試験>/images/<節番号>-<名前>.svg` に置き、本文から `![図の説明](images/<名前>.svg)` で参照します。アプリ、Obsidian、GitHub で表示されます
  - 説明(alt)には、図の中身を文で書きます。claude.ai の Project では画像が本文に出ないため、説明だけで分かるようにします
  - SVG は viewBox と `<title>` を持ち、白の背景を敷きます。`<script>`、外のファイルへの参照、画像の埋め込みは使いません(テストで確かめます)
  - どのテキストからも参照されない画像は置きません

### 用語集の追加

`glossary/` に Markdown で書きます。ファイルごとに `# 用語集 <分類>` を付け、`## 小分類` の下に、用語ごとに次の形で書きます。`npm run gen` で `src/data/glossary.json` になります。

```
## モデルとプロトコル

### TCP
別名: Transmission Control Protocol
試験: LinuC102、CCNA
要約: 一覧に出す 1 文(です・ます。。で終える)
詳しい説明(です・ます。1〜3 文)
例: `ss -tan`(1 行に 1 つ。何行でも)
注意: 試験や実務で間違えやすい点(1 文)
関連: UDP、ポート番号
```

- 要約、例、注意はすべての用語に書きます(テストで確かめます)

- 別名、試験、関連は省略できます。試験を書くと、その試験のテキストと解説でだけ印が付きます。書かなければ、すべての試験で付きます
- 名前と別名は、用語集全体で重複させません。関連には用語集にある名前だけを書きます
- 一般的すぎる語(「ポート」「ロール」など)は別名にしません。別の意味の箇所にも印が付くためです
